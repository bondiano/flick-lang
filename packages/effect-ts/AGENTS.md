# packages/effect-ts

`@flick-lang/effect-ts`: the TypeScript adapter that runs compiled programs
on Effect; its [README](README.md) states the dependency contract.
Programs on Flick's own runtime (`runtime/`) reach it through `./bridge`
for exports that runtime lacks.

## Layout

- `src/effect/<M>.ts` — what `flick:<M>` foreign keys bind; `src/ui`,
  `runner`, `cli` and `sql` serve their own `flick:` keys.
- `compiler-bindings.json`, `compiler-families.json` — routing compiled
  into the official backends by `flick-backend-support/build.rs`.
- `rt_bridge_stubs.txt` — generated by `pnpm -C runtime build && node
  tools/rt-exports.mjs`.
- `coverage/` — the pinned Effect's surface and the review of each export,
  linted by `tools/surface` (`flick-effect-surface`).

## Rules

- Programs import `dist/`: run `pnpm -C runtime build`, then
  `pnpm -C packages/effect-ts build`, before a direct `cargo test` or
  `flick run`; the just e2e recipes do it.
- After editing the routing or stub files, run `just check-component js`
  and `go`, and `just update-component <name>` for an image that differs.
- Keep loading a module free of effects (`"sideEffects": false`); mark a
  top-level call `/*#__PURE__*/`.
- Move the Effect pin with `just effect-bump <version>`, then review
  `coverage/surface/` until the coverage test passes.
- A `wrapped` entry names a std export that a test in `tests/run/stdlib/`
  uses.

## Checks

- `pnpm -C packages/effect-ts typecheck`, `lint` and `test`.
- `cargo test -p flick-effect-surface --test coverage`
  (`just effect-coverage` prints the counters).
- The "Runtime, cancellation or cleanup" row of the
  [validation matrix](../../docs/agents/validation.md); `just bundle-size`.
