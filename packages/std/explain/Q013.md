The migrations of a module are applied in the order written, and each
statement must apply to the schema the ones before it built: a table or
column it names exists, one it creates does not yet, and the versions
increase. The module's tables are that schema, so a statement that does not
apply would leave them unknown.

```flick
sql migration 1 "people" {
  create table people (id bigint primary key generated always as identity, name text not null);
}

sql migration 2 "pets" {
  create table pets (owner bigint not null references people, name text not null);
}
```
