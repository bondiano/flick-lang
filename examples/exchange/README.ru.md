# Биржевой стакан, который трейдеры заполняют одновременно

Лимитный стакан с движком сопоставления заявок. Несколько трейдеров
одновременно отправляют заявки строками JSON через одну очередь. Секвенсор
восстанавливает порядок строк и передаёт их бирже. Результат сессии одинаков
при каждом запуске и на обоих таргетах, поэтому пример работает ещё и как
бенчмарк и как тест бэкендов: `tools/bench` замеряет его на Node и как
исполняемый файл Go и требует, чтобы оба напечатали один и тот же отчёт.

| Часть | Где |
| - | - |
| заявки, команды и события: варианты, конструктор с записью, `deriving Schema` | `src/Book/Order.fl` |
| приоритет цены и времени: `PriorityQueue` на каждую сторону; для покупок `Ord`, при котором первой идёт самая высокая цена | `src/Book/Book.fl` |
| отмена без поиска: `HashMap` живых заявок; мёртвые выбрасываются, когда оказываются наверху | `src/Book/Book.fl` |
| команда для каждого номера, одинаковая на всех таргетах, и её строка JSON; плохая строка даёт типизированную ошибку `Malformed` | `src/Book/Feed.fl` |
| биржа как `service`, который предоставляет `Layer` поверх `Ref` | `src/App/Exchange.fl` |
| трейдеры и секвенсор: `parallel`, `parallel_all`, ограниченная `Queue` и вторая `PriorityQueue`, которая восстанавливает порядок | `src/App/Session.fl` |
| отчёт и экраны `watch`, только ANSI-последовательности | `src/App/View.fl` |
| командная строка: блок `cli` с подкомандами `run` и `watch`, флаги проверяются | `src/App/Main.fl` |

## Запуск из корня репозитория

Подготовьте [сборку из исходников](../../README.md#try-it-from-source):
закреплённый тулчейн Rust, Node.js и pnpm.

```sh
pnpm install --frozen-lockfile
pnpm -C runtime build
pnpm -C packages/effect-ts build
cargo build -p flick

./target/debug/flick run --project examples/exchange -- run --orders 5000
./target/debug/flick run --project examples/exchange -- watch
./target/debug/flick run --project examples/exchange -- --help
./target/debug/flick test --project examples/exchange
./target/debug/flick test --project examples/exchange --target go
```

Если `flick` уже есть в `PATH`, замените `./target/debug/flick` на `flick`.
`run --orders 5000` печатает отчёт из [`expected.stdout`](expected.stdout):

```text
5000 commands from 4 traders
trades 3263, volume 34116
rested 2557, dropped 1, cancelled 326, refused 473, malformed 0
checksum 1249589472
best bid 1047, best ask 1050
resting 418 bids, 108 asks
```

Контрольная сумма сворачивает все события в том порядке, в котором их выдал
стакан. Если у двух запусков сумма одна, они одинаково ответили на одни и те
же команды. `--traders` меняет число трейдеров, которые отправляют команды,
и только первую строку отчёта.

`watch` запускает сессию поменьше и перерисовывает стакан на месте каждые
`--every` команд: прогресс, итоги и восемь лучших ценовых уровней каждой
стороны. Продажи выводятся красным над спредом, покупки зелёным под ним.
`--pause` задаёт паузу после каждой перерисовки в миллисекундах.

## Приоритет цены и времени

У каждой стороны стакана своя `PriorityQueue`. Очередь отдаёт первой пару с
наименьшим приоритетом, а при равных приоритетах ту, что добавлена раньше.
Для продаж это самая низкая цена, а при равной цене самая ранняя заявка.
Для покупок правило то же, только порядок цен обратный:

```flick
type BidPrice = BidPrice Int
  deriving Eq

instance Ord BidPrice =
  let compare (BidPrice a) (BidPrice b) = compare b a
```

Из очереди с приоритетом можно вынуть только первую пару. Отмена или
исполнение убирает заявку из словаря `live`. Мёртвая заявка остаётся в
очереди, пока не окажется наверху, где цикл сопоставления её выбрасывает.
При частичном исполнении заявка остаётся наверху, а её количество в `live`
уменьшается.

## Почему сессия детерминирована

`Book.Feed.command seq` — чистая функция номера команды. Она перемешивает
биты `seq` финализатором MurmurHash3 на 32-битном `Int` с переполнением,
которое на обоих таргетах заворачивается одинаково. Трейдер `t` отправляет
команды с номерами, равными `t` по модулю числа трейдеров. Очередь получает
строки в том порядке, который даст планировщик. Секвенсор держит каждую
строку в `PriorityQueue` по номеру и передаёт её только после всех
предыдущих, поэтому стакан видит команды по порядку. Тесты сессии проверяют
это для 1, 3 и 7 трейдеров, сравнивая с теми же командами, применёнными по
одной.

## Тесты

- `test/Book/BookTest.fl`: случай на каждое правило, через `test.each`.
  - Лимитная заявка встаёт в стакан, если не пересекает цену.
  - Сделка идёт по цене стоящей заявки, а лучшая цена исполняется первой.
  - Равные цены исполняются в порядке прихода.
  - Рыночная заявка выбрасывает то, что не смогла исполнить.
  - Отмена сообщает остаток.
  - Исполненную или неизвестную заявку отменить нельзя.
  - Команда без количества, без цены или с id стоящей заявки отклоняется.
- `test/Book/PropertyTest.fl`: свойства на сгенерированных потоках до 60
  команд, с небольшим числом цен и малыми количествами:
  - каждый шаг даёт те же события и оставляет тот же стакан, что и наивный
    стакан из `test/Book/Reference.fl`, который перебирает отсортированные списки;
  - лучшая цена покупки остаётся ниже лучшей цены продажи;
  - каждая сделка идёт по цене стоящей заявки и не хуже лимита той, что её
    забрала;
  - каждая единица каждой заявки исполнена, выброшена, отменена или всё ещё стоит.
- `test/App/SessionTest.fl`:
  - конкурентная сессия совпадает с командами, применёнными по порядку;
  - каждая команда переживает свою строку JSON;
  - плохая строка падает с `Malformed`;
  - продажи стоят над спредом, а покупки под ним.

## Как бенчмарк

```sh
just bench
```

`tools/bench/index.mjs` собирает пример в release для обоих таргетов и
замеряет `run`, по умолчанию 200 000 команд, рядом с однофайловыми
программами. Строка таблицы измеряет всю программу: кодирование и
декодирование JSON, очередь и fiber'ы, персистентные кучу и словарь стакана.
