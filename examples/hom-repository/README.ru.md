# Фабрика репозитория и адаптер логирования

Пример использует статические модули высшего порядка и инструментированный
драйвер БД в памяти. Подключение к внешней базе данных не выполняется.

`Make(Database)` экспортирует операции репозитория и `Layer`. `WithLogging`
принимает эту фабрику и возвращает анонимную фабрику; `Instances` применяет
возвращённую фабрику и создаёт алиас результата. Применение фабрик создаёт
отложенный код слоя. Соединение приобретается только при построении слоя.
Приобретение и регистрация финализатора выполняются вместе под маской
прерывания; затем область слоя владеет соединением до завершения его тела.

`Domain.Repo` — намеренно общий номинальный API сервиса. Оба контракта
репозитория требуют именно это объявление. Другой сервис с такой же операцией
`get` не подходит. `Logged.get` явно требует и этот `Repo`, и `Log.Log`;
передача `Base.layer` сохраняет тождество сервиса и владение ресурсом.

Из каталога примера:

```sh
flick check --warnings-as-errors
flick build
node dist/flick-main.js
```

`expected.stdout` задаёт контракт жизненного цикла, проверяемый на JS и Go
в профилях debug и release. Начальные счётчики подтверждают, что создание
модулей и фабрик не приобретает ресурсы. Успех, ошибка тела, ошибка после
приобретения и прерывание освобождают ровно одно соединение до передачи
результата вызывающему коду. При ошибке приобретения освобождать нечего.
Два перекрывающихся запуска слоя одновременно держат два соединения и закрывают
каждый отдельный ID ровно один раз. Алиас логирующего модуля использует уже
построенный сервис, не приобретая новое соединение.

Интеграционный тест также проверяет отказ `FLICK-E002` для вызывающего кода,
который предоставляет только слой репозитория: ему по-прежнему требуется `Log`.
