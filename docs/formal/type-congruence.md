# Type congruence in typing and GADT branches

This extends the row equality of [core.md §1.2](core.md#12-types-and-rows) through
monotypes. It records how the Lean typing relation uses that equality. The
checker and reference interpreter remain separate implementations; a Lean
proof does not certify their Rust code or a backend.

## Equality inside a type

`Ty.Equiv` is the congruence generated by the row laws and ordinary type
constructors. In particular, commuting or regrouping a row remains equality
inside a reference, a nominal argument, a record field, a dictionary index or
a polymorphic body. `LeLive.equiv` admits this equality as subtyping, and
`Typ.conv` converts an expression's value type while keeping its stage and
term. Stage comparisons and variance rules retain their existing premises.

This does not add covariance to mutable storage. `Ref a` and `Ref b` can be
converted only when `a ≡ b`; a strict inclusion between their computation
requirements does not suffice. Nominal heads, scalar types, regions and the
pure/runtime distinction remain observable type structure.

The row unit and idempotence laws require `Ty.RowForm`. A bare unkinded type
variable is not a row form: substitution must not turn a row law into an
equality between an ordinary value type and a row. `Ty.asIndexedRow` retains
nominal arguments modulo congruence. The older `Ty.asRow` projection used by
liveness records names and reachability; it does not independently establish
equality of nominal arguments.

The definitions are in `formal/Formal/TypeEquality.lean`; algebra,
substitution and constructor inversion are in `TypeEquiv*.lean`.
`Live/Views.lean` inverts subtyping through conversion. `ShapeEquivalence`,
`ValueTyping`, `FunctionTyping` and `HandlerTyping` preserve the observable
forms used by Progress and Preservation.

## Facts, dictionaries and storage

A declared fact `Θ C a` answers a query about `b` when `a ≡ b`.
`Facts.close` supplies this equality closure to `Outl`. Capture sets are
unchanged, and facts are not transitively chained. Age facts still mean
exactly their previous strict order: congruence preserves reachability
(`Facts.age_close`).

`Facts.Equiv`, `Scheme.Equiv` and `CtxEquiv` relate equivalent presentations
of checked facts, schemes and contexts. `Typ.context_equiv` transports an
unevaluated term under the existing `NoIns` premise. It handles locations
and continuation values through the actual type of the store cell.

A converted reference value may expose a content type congruent to its
cell's actual type. Reading converts the stored value to the requested
presentation. Writing converts the new value back to the cell's fixed type.
The store typing still grows by appending cells; old cells keep their types.
Dictionary fields similarly retain their checked schemes and facts, with
equivalent arguments transported before instantiation.

`Ty.YF n` is syntactic freshness under `kill n`. It is not invariant under
congruence: a row can erase an unobservable dictionary index containing a
region. Intermediate derivations use `Ty.YFMod n`, freshness modulo
congruence. An allocated cell uses the actual killed type, which satisfies
syntactic `YF`. The public `rt_preservation`, Preservation and region-safety
theorems keep their guarantees. `FreshEquivExamples.lean` pins this distinction.

## GADT branches

Read the equation in [Branch-GADT](core.md#24-patterns-and-exhaustiveness)
as `(T ρ̄)θ ≡ (T ῡ)θ`. A branch is dead only when there is no fitting unifier
modulo this equality. A raw syntax mismatch between equivalent row indices
cannot justify dropping a branch.

The primary rule `Typ.aref` still checks every fitting unifier. A most general
unifier is sufficient when every other fitting unifier factors through it
pointwise modulo `Ty.Equiv`. `Mgu`, `Typ.aref_mgu` and `Typ.aref_dead` prove
these derived rules. This is conditional admissibility: it does not assert
that every row equation has one most general unifier.

`PatTy.conv` converts a completed pattern's input type while retaining its
bindings. The arm can therefore reuse its checked body and binding types at
an equivalent presentation of the constructor's fields. Unsaturated
constructor spines keep their original rules and signature premises.
`TypingContextEquiv` and `ContextSubstitution` carry the surrounding schemes
and facts without adding a restriction to Branch-GADT.

The source elaboration's `CUnif`, `Unify.most` and `Clash.none` also use
congruence. Its occurs-check proof uses `Ty.shapeSize`, which ignores row
syntax and is invariant under congruence. Ordinary application and arrow
constructors strictly increase this measure. Raw AST size would not be a
valid measure after row idempotence and subtraction.

## Checks and limits

`Formal.ConversionExamples` includes a closed index problem whose two sides
are unequal syntax under every substitution but whose identity substitution
is a most general unifier modulo congruence. It also checks conversion of a
completed pattern and the resulting binding. `Live.ConversionExamples`,
`RowEquivExamples` and `FreshEquivExamples` cover invariant references,
guarded row algebra and actual allocation freshness.

`lake build --wfail` checks the existing safety, elaboration, axiom and
certificate gates. `just model` checks the reference implementation and its
compiler/runtime comparisons. The bilingual reference examples separately
accept reordered requirements under `Ref` and reject widening them.

This transition changes the formal typing contract. It does not add typing,
effect or UI facts to `flick_ir::Program`, establish an IR 1.0.0 baseline,
change the memory ABI, or complete backend-component conformance.
