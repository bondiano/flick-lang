<TourLesson locale="en" id="errors">

`type error` declares an expected failure. `find` names both possibilities
after `;`. `try` catches the failure (postfix `expr catch | NotFound _ -> …`
also works when handling typed errors alone); its arm receives a value of
`Errors {NotFound, Unavailable}`. A pure `match` then takes that value apart.
The `match` itself catches nothing and removes no error from a function's row.

`to_http` returns one error where a row containing it is expected.
`Exit.map_error` uses that function to translate an outcome.
See [error values](../../reference/effects/#expected-errors).

```flick fail T009
type error NotFound = NotFound String
type error Unavailable = Unavailable
problem : Errors {NotFound, Unavailable} -> String
let problem err = match err with | NotFound name -> name
```

**Try:** add the missing `Unavailable` arm.

</TourLesson>
