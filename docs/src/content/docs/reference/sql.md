---
title: "SQL"
---

Flick checks queries for PostgreSQL against tables declared in source. A
query is a pure value: building and binding it does no I/O. Only
`Database.query` and `Database.execute` talk to the database.

The dialect is `[sql] dialect` in `flick.toml` (see
[project.md](../project/)); `postgresql`, the default, is the only supported
one. The dialect gives the column types below, the functions of queries and
the tag of templates (`Sql.Template Pg p r`).

## Tables

```flick
# type UserId = UserId BigInt
# user_id : PureCodec BigInt UserId
# let user_id = Sql.codec (fun n -> Ok (UserId n)) (fun (UserId n) -> n)
#
sql table Users "users" {
  id : bigint primary key generated always as UserId via user_id
  name : text not null as String
  email : text as String
}
```

`sql table Name "table" { … }` declares the type `Name` of a row (each
column's type, in `Option` when the column may be `NULL`) and the table
`Name.table : Sql.Table "table" { column : Sql.Column t n w, … }`, exported
with the type. The block is the plugin `sql` of std, which every module has
without an import; `flick expand` shows its code. The indices say whether the column may be `NULL`
(`Sql.NonNull`, `Sql.Nullable`) and what an insert must give it
(`Sql.Required`, `Sql.Defaulted`, `Sql.Generated`).

A column is its SQL type (`std/Q010` for another word, `std/Q001` for a
name given twice, and the column is left out), then any of `not null`, `null`, `primary key`,
`unique`, `default`, `generated always` and `generated by default`. A column
is nullable unless it is `not null` or a primary key; a nullable column or
one with a default may be left out of an insert; a `generated always` one is
never written.

| SQL type | Flick type |
| - | - |
| `bigint`, `int8`, `bigserial` | `BigInt` |
| `integer`, `int`, `int4`, `smallint`, `int2`, `serial` | `Int` |
| `real`, `double precision`, `float8` | `Float` |
| `numeric`, `decimal` | `BigDecimal` |
| `text`, `varchar`, `character varying`, `uuid`, `date`, `timestamp`, `timestamptz` | `String` |
| `boolean`, `bool` | `Bool` |
| `json`, `jsonb` | `Json` |

A column of another type needs `via codec`, a `PureCodec` from the Flick
type of its SQL type (`std/Q011` otherwise). `Sql.codec decode encode`
makes one; `decode` may refuse a value with a `SchemaError`. A `Float` never
holds a `bigint` or a `numeric` without such a checked codec. An enum of the
column's Flick type needs none: `role : text not null as Role` reads the
column through `Role.parse`, so a value the enum does not know is a
`DecodeError`.

The compiler never connects to a database: tables are written, or come
from the module's migrations (below).

## Queries

```flick
# import Sql exposing (Pg, EncodeError, DbError, DecodeError)
# import Database exposing (Database)
# import BigDecimal exposing (BigDecimal)
# type UserId = UserId BigInt
# user_id : PureCodec BigInt UserId
# let user_id = Sql.codec (fun n -> Ok (UserId n)) (fun (UserId n) -> n)
# sql table Users "users" {
#   id : bigint primary key generated always as UserId via user_id
#   name : text not null as String
# }
# sql table Accounts "accounts" {
#   id : bigint primary key generated always as BigInt
#   user_id : bigint not null as UserId via user_id
#   balance : numeric not null as BigDecimal
# }
# type alias BalanceRow = { name : String; balance : Option BigDecimal }
#
balances : Sql.Template Pg { user_id : UserId } BalanceRow
let balances =
  sql params {
    from user in Users
    left_join account in Accounts on account.user_id == user.id
    where user.id == params.user_id
    select { name = user.name; balance = account.balance }
  }
```

`sql [p] { … }` is a `Sql.Template Pg params row`, a block of the plugin
`sql` of std as `sql table` is; `flick expand` shows its code. The name after `sql`
binds the parameters: `p.x` is the parameter `x`, whose type follows from
where it is used. With a signature, a parameter the signature does not
declare is `std/Q009`. A query without a name has no parameters.

`$name` captures a value of the program, a local or a top-level one, as a
placeholder; `$name.field` captures a field of it and `$(e)` the value of any
expression `e`, both written right after `$`: its type follows from where it is used, as a parameter's does,
and it passes through the codec of the column it is compared with or
written to. A capture of an `Option t` is a `t` that may be `NULL`: `None`
is `NULL`, so `where is_null $tag || t.name == $tag` is a filter that may be
absent. Of a base type it is cast to its SQL type (`CAST($1 AS text)`), as
PostgreSQL cannot type `$1 IS NULL` alone. Beside a column with a codec a
capture has the column's own type, never an `Option` of it (`FLICK-T003`),
and a value whose type has no SQL form is `FLICK-C001`: the class
`Sql.Param` has no instance for it. A capture is no parameter of the
template, so a function builds the template from its arguments:

```flick
# import Sql exposing (Pg, EncodeError, DbError, DecodeError)
# import Database exposing (Database)
# import BigDecimal exposing (BigDecimal)
# type UserId = UserId BigInt
# user_id : PureCodec BigInt UserId
# let user_id = Sql.codec (fun n -> Ok (UserId n)) (fun (UserId n) -> n)
# sql table Users "users" {
#   id : bigint primary key generated always as UserId via user_id
#   name : text not null as String
# }
# sql table Accounts "accounts" {
#   id : bigint primary key generated always as BigInt
#   user_id : bigint not null as UserId via user_id
#   balance : numeric not null as BigDecimal
# }
# type alias BalanceRow = { name : String; balance : Option BigDecimal }
#
balances_of : UserId -> Sql.Template Pg {} BalanceRow
let balances_of id =
  sql {
    from user in Users
    left_join account in Accounts on account.user_id == user.id
    where user.id == $id
    select { name = user.name; balance = account.balance }
  }
```

A bare name inside `sql { … }` is always a column: `$` is what makes it a
value of the program, and `$` outside `sql { … }` is a syntax error.

Clauses come one per line or separated by `;`, and are checked in SQL's
order whatever order they are written in:

| Clause | Meaning |
| - | - |
| `from x in T` | the first table; `T` is a `sql table` or a table of migrations, by its name (`std/Q010` otherwise) |
| `join x in T` / `left_join x in T`, then `on e` | inner and left joins |
| `where e` | a `Bool` condition without aggregates |
| `group_by e, …` | grouping keys |
| `having e` | a condition on groups |
| `select { label = e; … }`, `select a.x, b.y`, `select a` | the results; written as a list each takes its column's name, an alias alone selects all its columns |
| `order_by e, asc e, desc e` | ordering |
| `limit e`, `offset e` | `Int`s |
| `union (sql { … })`, `union_all (sql { … })` | a query with the same results in the same order |
| `insert_into T`, `values { column = e; … }` | an insert |
| `update T`, `set { column = e; … }`, `where e` | an update |
| `delete_from T`, `where e` | a delete |
| `returning …` | results of an insert, update or delete, like `select` |

In an insert, update or delete the table's name is its alias: `Users.id`.

Expressions are columns (`alias.column`, or `column` when exactly one table
has it: `std/Q003` otherwise), parameters, captures, literals, `== != < <= > >=`,
`&&`, `||`, `not`, `+ - * / %` on `Float`, `BigInt` and `BigDecimal`, `++` on
`String`, and the functions:

| Function | Meaning |
| - | - |
| `is_null e`, `is_not_null e` | `IS NULL`, `IS NOT NULL` |
| `is_not_distinct_from a b` | null-safe equality |
| `coalesce a b` | the first that is not `NULL` |
| `count e`, `count_all` | `COUNT(e)`, `COUNT(*)`: a `BigInt`, never `NULL` |
| `sum e`, `avg e` | `NULL` over no rows: an `Option`; they take a column of a numeric SQL type (`std/Q010` otherwise) or a value of a type of the class `Sql.Numeric` (`FLICK-C001` otherwise) |
| `min e`, `max e` | the least and the greatest value of any type, `NULL` over no rows: an `Option` of it |
| `exists (sql { … })`, `is_in e (sql { … })` | uncorrelated subqueries |

`==` is SQL's comparison: it is `NULL` when either side is, and `where` keeps
only rows where the condition is true. A comparison's sides have the same
Flick type: comparing a `UserId` with a `Date` is a type error even when
both are numbers in SQL.

## Nullability

Every expression knows whether it may be `NULL`: a nullable column, a column
of a `left_join`ed table, an aggregate other than `count`, an operation on a
nullable operand. A result that may be `NULL` has type `Option t`, once:
two left joins do not make `Option (Option t)`. With `join` a `not null`
column stays plain.

## Phases

`group_by`, `having` or an aggregate in `select` make the query grouped:
then every column a result, `having` or `order_by` uses outside an aggregate
must be a grouping key (`std/Q005`). Aggregates belong to `select`,
`having` and `order_by`; in `where`, `on`, `group_by` or inside another
aggregate they are `std/Q006`.

## Scopes

Each `sql { … }` has its own aliases. A subquery sees the parameters of the
query around it, never its aliases, and a query never sees the aliases of a
subquery or a union (`std/Q002`).

## Running queries

```flick
# import Sql exposing (Pg, EncodeError, DbError, DecodeError)
# import Database exposing (Database)
# import BigDecimal exposing (BigDecimal)
# import App.Queries exposing (UserId, BalanceRow, balances)
#
load : UserId ->{Async, Database; EncodeError, DbError, DecodeError} List BalanceRow
let load id = Database.query (Sql.bind balances { user_id = id })
```

`Sql.bind template params` is a `Sql.Query Pg row`, without I/O.
`Sql.text` gives its SQL, `Sql.template_text` the same SQL of a template; values are never in it: each parameter and each
literal is a `$n` placeholder whose value the driver passes beside the
text. Tables, aliases and columns come from metadata and are quoted.

`Database.query` returns the rows, `Database.execute` the number of rows
changed. Parameters that a codec refuses are `EncodeError`; a response that
does not match the query (a column of another SQL type, `NULL` where the
query has none, a value a codec refuses) is `DecodeError`; what the server
or driver refuses is `DbError { code; message; constraint }` with the
SQLSTATE and the violated constraint as inert data.

`Database.pg (Database.config url)` is a layer of a pool of `pg`
connections, ended with the scope of its `provide`. `Database.config url`
gives 10 connections and no timeouts; set the fields of the record to
change them: `{ Database.config url with max_connections = 4;
statement_timeout_ms = Some 5000 }`. The `pg` package is an optional peer
dependency of `@flick-lang/runtime`, loaded only by this layer. On the go
target the pool is pgx's: the Go module of a program that reaches
`Database` requires pgx v5.7.6, which the first `go build` downloads into
Go's module cache, checked against the pinned `go.sum`; later builds need
no network. Other programs carry no driver and build offline.

## Transactions

```flick
# import Sql exposing (Pg, EncodeError, DbError, DecodeError)
# import Database exposing (Database)
# import BigDecimal exposing (BigDecimal)
# import App.Queries exposing (withdraw, deposit)
#
transfer : BigInt -> BigInt -> BigDecimal ->{Async, Database; EncodeError, DbError, DecodeError} Unit
let transfer source target amount =
  Database.transaction (task {
    ignore (Database.query (Sql.bind withdraw { account = source; amount = amount }))
    ignore (Database.query (Sql.bind deposit { account = target; amount = amount }))
  })
```

`Database.transaction body` runs `body` on one connection between `BEGIN`
and `COMMIT`. When `body` fails, with a refused statement or an error of its
own, or is interrupted, the transaction is rolled back and the failure goes
on. Other callers take other connections and see none of its writes before
the commit.

Inside another transaction, `Database.transaction` is a savepoint: catching
its failure undoes only its writes, and the outer transaction goes on. A
statement refused outside a savepoint leaves the transaction unable to run
more, as PostgreSQL does; let the failure end it.

A commit waits for the server's answer. If the connection breaks before the
answer arrives, it is `DbError` with the code `"commit_unknown"`: the
transaction may or may not have happened, and only the data tells. Nothing
is retried.

## Migrations

A module's schema can be its history: `sql migration` declarations hold the
DDL, and the tables are the schema they build, in the order written. Each
table it leaves is a type of the module, its row, with the companion
`table`, as `sql table` declares them: `article_tags` is `ArticleTags`. The
module also has the value `migrations : List Migration`, every statement as
written, for `Database.Migrate.run`. The block is the plugin `sql` of std,
as `sql table`.

```flick
# import Sql
sql migration 1 "people" {
  create table people (
    id bigint primary key generated always as identity,
    name text not null
  );
  create table pets (
    owner bigint not null references people on delete cascade,
    name text not null,
    primary key (owner, name)
  );
}

sql migration 2 "species" {
  alter table pets add column species text not null default "cat";
}

# let example = task {
let applied = Database.Migrate.run migrations
# ()
# }
```

- The DDL is `create table`, `create index`, `alter table` (add, drop,
  rename or alter a column, rename the table), `drop table` and
  `drop index`. Anything else is `std/Q010`.
- Each statement applies to the schema before it: a table or column it
  names exists, one it creates does not, and the versions increase;
  otherwise `std/Q013`.
- A column's SQL type gives its Flick type, as the table above; a nullable
  one, a `default`, a `serial` or `generated by default` may be left out of
  an `INSERT`, and `generated always` may not be written.
- A string, `"cat"`, is a SQL text literal, `'cat'`, as in queries;
  identifiers are not quoted.

`Database.Migrate.run steps` brings the schema up to date: each
`{ version; name; statements }` whose version is above the latest one the
table `flick_migrations` records runs its statements in order, and is
recorded. It answers the versions it applied, none when the schema is
current. All of a run is one transaction under an advisory lock, so servers
that start together apply each step once, and a failing step leaves the
schema as it was. Steps not in increasing order of version, and a database
already past the last step, are refused with `MigrationError`. Written by
hand, the statements of a step are raw SQL.

```flick
import Database.Migrate exposing (Migration)

steps : List Migration
let steps = [
  { version = 1; name = "users"; statements = ["create table users (id serial primary key, name text not null)"] },
  { version = 2; name = "emails"; statements = ["alter table users add column email text"] },
]

# let example = task {
let applied = Database.Migrate.run steps
# ()
# }
```

## Cancellation and limits

An interrupted query is cancelled on the server with the protocol's
CancelRequest, sent on a connection of its own, which takes no slot of the
pool. Its connection is then closed, never returned to the pool, and the
interruption completes once it is, so the backend is free at that point.
Outside a transaction, what the query wrote is not rolled back.

`statement_timeout_ms` makes the server end a statement that runs longer,
as `DbError` `57014`. `acquire_timeout_ms` bounds how long a query waits
for a connection when all `max_connections` are taken; a query that waits
longer fails. Together they bound how many backends the program holds and
for how long.

## Raw SQL

Outside the checked subset, `Sql.unsafe_query pieces decoder` runs raw SQL:
`Sql.unsafe_text` pieces are SQL as written, `Sql.param codec value` a
placeholder, `Sql.ident identifier` a quoted identifier. Only an
`Sql.Identifier`, made by `Sql.identifier` from a checked name, names a
table or a column: a `String` never does. Rows are objects of `int2`,
`int4` and floats as numbers, `bool` as booleans, `json` parsed and anything
else as text, decoded by `decoder`.

```flick
# type alias Count = { n : Int }
#   deriving Schema
# count_rows : Sql.Identifier -> Sql.Query Sql.Pg Count
let count_rows table =
  Sql.unsafe_query
    [Sql.unsafe_text "select count(*)::int as n from ", Sql.ident table]
    (Codec.json Count.schema)
```

Not supported: correlated and `LATERAL` subqueries, recursive
CTEs, window functions, `RIGHT` and `FULL` joins, and DDL outside
`sql migration`.
