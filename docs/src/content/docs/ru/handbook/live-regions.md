По умолчанию проверка спрашивает, что замыкание, задача или конструктор **держат**: значение, которое держит дескриптор из `scope`, не может выйти из этого scope, хотя регион вовсе не использует (см. [Регионы и захваты](../../reference/regions/)). Живые регионы спрашивают вместо этого, где значение **использует** регион. Функция, которая только носит с собой файл, может тогда пересечь конец scope, которому принадлежит регион; та, что читает файл, не может.

Режим экспериментальный: его правила могут измениться, и ни один выпуск не включает его по умолчанию.

## Как включить

```toml
[build]
regions = "live"
```

| `build.regions` | Что проверяется |
| - | - |
| `"captures"` | что значение держит, как описано в [Регионах и захватах](../../reference/regions/); по умолчанию |
| `"live"` | что стадия использует от региона |
| остальное | `FLICK-P005` |

Режим охватывает модули сборки. Встроенные модули и `std` в обоих случаях проверяются по `"captures"`.

## Держать — не значит использовать

```flick live
# module App.LiveHeld exposing (..)
#
# type File (s : Region)
#
# service Files =
#   open_scoped : forall s. String ->{Scope s;} File s
#
held_task : String ->{Files;} Eff none none Unit
let held_task path = scope {
  let file = Files.open_scoped path
  task { ignore file }
}
```

Задача выходит из `scope`, держа `file`, и её строка пуста: ничего из того, что она выполняет, не использует `s`. По умолчанию эта программа — `FLICK-G001`, так как задача держит то, чего её пустая строка не разрешает.

То, что использует регион, остаётся внутри его scope и в обеих дисциплинах читается одинаково:

```flick
# module App.LiveUse exposing (..)
#
# type File (s : Region)
#
# type error ReadError = ReadError String
#
# service Files =
#   open_scoped : forall s. String ->{Scope s;} File s
#   read_all : forall s. File s ->{; ReadError} String
#
used_inside : String ->{Files; ReadError} String
let used_inside path = scope {
  let file = Files.open_scoped path
  let read = fun () -> Files.read_all file
  let later = task { Files.read_all file }
  ignore later
  read ()
}
```

Использование, которое переживает свой регион, — это `FLICK-G002`:

```flick live fail G002
# module App.LiveAfterClose exposing (..)
#
# type File (s : Region)
#
# type error ReadError = ReadError String
#
# service Files =
#   open_scoped : forall s. String ->{Scope s;} File s
#   read_all : forall s. File s ->{; ReadError} String
#
read_later : String ->{Files;} (Unit ->{Files; ReadError} String)
let read_later path = scope {
  let file = Files.open_scoped path
  fun () -> Files.read_all file
}
```

Замыкание выходит из `scope`, а строка его типа не держит `s` живым:

```text
FLICK-G002: this uses region `s`, which the expected type `Unit ->{Files; ReadError} String` does not keep live: a function or a task uses a region only while the region is live
```

## Что спрашивает проверка

- **Стадия сигнатуры говорит, что она использует.** Читайте сигнатуру так, как её видит вызывающий: каждой runtime-стадии нужно `Live` того, до чего достают параметры перед ней. Поэтому `read_all : File s ->{; ReadError} String` требует, чтобы `s` был жив там, где её вызывают, и того же требует стадия внутри функции, возвращающей замыкание над параметром.
- **Квалификатор — это то, что нужно для использования значения.** Вызов функции `(τ₁ →⋯)^C` или ожидание задачи `(Eff ⋯)^C` требует `Live C`. В этом режиме квалификатор больше не говорит, что значение держит: замыкание `(Unit ->{} Unit)^{s}` — то, для использования которого нужен живой `s`.
- **`scope` — это место, где его регион жив.** `Scope s` в строке держит `s` живым (в ядре это одни и те же атомы строки: `Row.scope s` — это `Row.ofCaps s.reach`), а конец `scope s` снимает `Live s`. Строка, которая использует регион и не держит его живым, — это `FLICK-G002`.
- **Работа, которую держит владелец, переживает его самого.** Дочерняя задача (`Fiber.spawn`), финализатор, подписчик или группа работают до закрытия владельца, поэтому каждый регион, который им нужен живым, должен кончаться не раньше (`Fiber.Outlives`). Иначе `FLICK-G003`.
- **Приобретение по-прежнему требует владельца.** `Live s` не даёт `Scope s`: функция, которая приобретает в регион, называет `Scope s`, как и в дисциплине по умолчанию (`FLICK-G004`).

## Ошибки

| Код | Когда сообщается |
| - | - |
| `FLICK-G001` | значение держит то, чего его граница не разрешает; дисциплина меняет то, что считается содержимым |
| `FLICK-G002` | значение использует регион, который граница там не держит живым, либо значение покинуло бы свой `scope` со строкой, которой нужен живой регион |
| `FLICK-G003` | работе, которую держит владелец, нужен регион, который может кончиться раньше владельца |
| `FLICK-G004` | приобретению нужен `Scope s`, которого не даёт ни сигнатура, ни место, как и в дисциплине по умолчанию |

Вторая форма `FLICK-G002` новая: по умолчанию значение, держащее регион, вообще не может покинуть свой `scope`, а здесь может, если ни одна его строка не использует регион.

## Две дисциплины рядом

| Программа | `"captures"` | `"live"` |
| - | - | - |
| задача или замыкание держит дескриптор после своего scope и не использует его | `FLICK-G001` | принимается |
| замыкание читает дескриптор после своего scope | `FLICK-G001` | `FLICK-G002` |
| у вспомогательной функции в строке `Scope s`, и она использует приобретённое в `s` | принимается | принимается |
| дочерняя задача `outer` использует то, что открыл внутренний `scope` | `FLICK-G003` | `FLICK-G003` |
| функция над `File inner` там, где ожидается функция над `File outer` | `FLICK-T008` | `FLICK-T008` |

## Сравнение с Rust

| Rust | Flick |
| - | - |
| время жизни `'a` | регион: тот, что открывает `scope`, или параметр `forall s` |
| `T: 'a` | `Fiber.Outlives c s` для строки захватов `c` значения или работы, которую держит владелец; решает проверка, а программа не объявляет экземпляров |
| `fn(&'lt ())` | `File inner -> Unit` |
| `for<'r> fn(&'r ())` | `forall r. File r -> Unit` |

Rust решает `T: 'a` синтаксически, как это сделал RFC 1214: каждое время жизни, которое тип упоминает или скрывает, должно переживать `'a`, включая аргумент указателя на функцию, который значение никогда не вызывает. Комментарий в собственных тестах rustc на `outlives` называет это правило строже необходимого: сам указатель на функцию всегда `'static`, поэтому он мог бы быть бивариантным по своему аргументу. И там же сказано, почему правило оставлено: оно чисто синтаксическое.

Дисциплина Flick по умолчанию — это то же правило: достижимость функционального типа включает регионы её параметров и результата, поэтому `fn(&'lt ())` — не тип, свободный от `'lt`, а `File inner -> Unit` — функция, которая не может покинуть scope `inner`. `"live"` — то прочтение, которое предпочитает комментарий: держать такой тип не значит ничего использовать, поэтому `File inner -> Unit` может уйти. Звучит это не за счёт вариантности, а за счёт доказательства live-суждения: `T4'_live` в `formal/Formal/Live/T4Live.lean` показывает, что программа, типизированная так, не доходит до шага, которому нужен регион после закрытия его `scope`, и до операции, которую обслуживает обработчик закрытого региона. Компилятор сравнивается с моделью тестами, а не доказывается равным ей.

Rust принимает `outlives::<'static, _>((|_| ()) as fn(&'lt ()))`, потому что аргумент типа `&'static ()` подходит для параметра `&'lt ()` (контравариантность), и `T` выводится как `fn(&'static ())`. В Flick между регионами нет подтипирования: `File inner` — не `File outer` (`FLICK-T008`). Вместо этого есть параметр-регион, `forall r. File r -> Unit`, который принимают обе дисциплины.

## Что пока не проверяется

- **Компоненты.** Строка с `Setup s` не держит живым ничего, а `Setup` — сервис, который может предоставить любая программа, поэтому проверка не может считать его открытым регионом. `Ui.on_mount`, `Ui.watch` и `Atom.value` внутри setup компонента требуют `Live` региона экземпляра, а их закрытые строки его не держат, так что такой компонент — `FLICK-G002`. Компоненты проверяются по `"captures"`, пока правило не привяжет `Setup` к setup своего региона.
- **Использование через чистую операцию.** Ленивая последовательность `for` и подписчик фонового канала достают до захваченного региона только через чистую операцию, а чистая стадия не несёт `Live`: обе принимаются в `"live"`, хотя используют регион поздно. Дисциплина по умолчанию отклоняет их.
- **`std`.** Его нельзя проверить как проект в `"live"`: его блок `@lang` — это `FLICK-R016`. Встроенные модули проверяются по `"captures"`.
