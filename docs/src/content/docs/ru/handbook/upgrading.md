До версии 1.0 минорные выпуски могут содержать несовместимые изменения.
Версия 0.2 содержит несколько таких изменений: проект загружает `std` как
отдельный пакет; блоки `cli`, `codec` и `server fn`, а также автоматическое
построение экземпляров `Schema`, `Url`, `Form`, `HttpApi` и `Cli.Value`
перенесены из компилятора в плагин `std`; библиотеки компилируются из исходников.
На этой странице перечислены все изменения после 0.1.0 и способы обновления
проекта.

## Как обновиться

Соберите компилятор из локальной копии исходников ветки `main` (см.
[Начало работы](../../start/getting-started/#из-исходников)). Он использует `std`
из той же локальной копии (см.
[следующий раздел](#std-устанавливается-как-пакет)). Затем выполните в проекте:

```sh
flick install
flick check --fix
```

Команда `flick check --fix` применяет безопасные исправления: заменяет
`schema T`, удаляет импорты имён, начинающих блоки плагинов и доступных в каждом
модуле, а также выполняет остальные стандартные автоисправления. Оставшиеся
проблемы команда перечисляет в диагностике. Способы их исправления описаны ниже.

## `std` устанавливается как пакет

В версии 0.1.0 `std` был встроен в компилятор. Теперь компилятор содержит
только модули ядра, а `std` поставляется как пакет. Если проект не указывает
`std` в `[dependencies]`, используется тег `std-v<версия>`, соответствующий
выпуску компилятора. Команда `flick install` загружает пакет и фиксирует его
версию в `flick.lock`. Добавьте `flick.lock` в систему контроля версий.
До выполнения `flick install` любая команда, проверяющая модули, завершается
с диагностикой:

```text
error[FLICK-P034]: `std` from `git+https://github.com/bondiano/flick-lang?tag=std-v0.1.0&subdir=packages/std` is not installed: run `flick install`
```

Компилятор, собранный из локальной копии исходников, использует `std` из этой
копии вместо пакета по тегу, пока исходники остаются по пути, использованному
при сборке. В этом случае устанавливать `std` через `flick install` не нужно.
Если пакет `std` предназначен для другого компилятора, команды завершаются с
`FLICK-P043`; диагностика указывает модуль, который не проходит проверку.
Тогда явно укажите `std` из исходников используемого компилятора:

```toml
[dependencies]
std = { path = "../flick-lang/packages/std" }
```

Либо задайте путь к этому каталогу в переменной окружения `FLICK_STD_PATH`.

## `schema T` стало `T.schema`

Свидетельство схемы типа теперь доступно как `T.schema`, а `schema` больше
не является ключевым словом. В версии 0.1 использовалась такая запись:

```flick fail T001
type alias Profile = { email : String }
  deriving Schema

profile_schema : Schema Profile
let profile_schema = schema Profile
```

Теперь компилятор воспринимает `schema Profile` как вызов неизвестной функции
`schema` и сообщает `FLICK-T001`. Автоисправление заменяет его на `Profile.schema`:

```flick
type alias Profile = { email : String }
  deriving Schema

profile_schema : Schema Profile
let profile_schema = Profile.schema
```

Команда `flick check --fix` выполняет эту замену автоматически.

## Блокам `std` импорт не нужен

Блоки `cli`, `codec`, `server fn` и `sql` (запросы, `sql table` и
`sql migration`) теперь реализованы плагином `std`. Имена, начинающие эти блоки,
доступны в каждом модуле. Как и в версии 0.1, импорт для таких блоков не нужен:

```flick
type alias Profile = { email : String; nickname : Option String }
  deriving Schema

profile_json : PureCodec Json Profile
let profile_json =
  codec Profile.schema {
    email = field "email_address" String.json;
    nickname = field "nickname" (option_as_null String.json);
  }
```

Импорт такого имени, например `import Codec exposing (plugin codec)`,
приводит к диагностике `FLICK-R012`. Команда `flick check --fix` удаляет этот
импорт. Он по-прежнему нужен только для формы блока без `{`, например `cli Main`.
Другим плагинам запрещено предоставлять эти имена: попытка импортировать
такое имя из другого плагина приводит к `FLICK-P044`.

Слова `cli`, `codec`, `server` и `fn` больше не являются ключевыми. Они начинают
блок перед `{` или в начале объявления, как в `server fn` и `sql table`,
а в остальных местах остаются обычными именами. Слово `plugin` является
ключевым только в списке имён, открываемых импортом.

## Коды диагностик с префиксом `std/`

Плагин использует собственные коды диагностик с префиксом имени пакета.
Правила блоков и автоматического построения экземпляров, перенесённых
в плагин, не изменились. Изменились только коды диагностик:

| 0.1 | Теперь | Причина диагностики |
| - | - | - |
| `FLICK-L001` … `FLICK-L007` | `std/L001` … `std/L007` | нарушение правил блока `cli` |
| `FLICK-S007` в блоке `cli` | `std/L009` | неправильно записанная конструкция |
| `FLICK-C013` у `deriving Cli.Value` | `std/L010` | невозможно автоматически построить экземпляр класса `Cli.Value` для указанного типа |
| `FLICK-D001`, `FLICK-D009`, `FLICK-D010` у `deriving` | `std/D001`, `std/D009`, `std/D010` | невозможно автоматически построить экземпляр `Schema`, `Url` или `Form`; диагностика указывает класс в `deriving` |
| `FLICK-D002` … `FLICK-D005`, `FLICK-D007` | `std/D002` … `std/D005`, `std/D007` | нарушение правил блока `codec` |
| несовпадение типов в блоке `codec` | `std/D012` | кодек поля декодирует тип, отличный от типа соответствующего поля записи |
| `FLICK-D011` | `std/D011` | `deriving HttpApi` не может интерпретировать запись как набор эндпоинтов |
| `FLICK-E010` | `std/E010` | нарушение правил объявления `server fn`; для `server name`, ссылающегося на значение, которое не является `server fn`, сохраняется `FLICK-E010` |
| `FLICK-Q001`, `FLICK-Q010` в `sql table` | `std/Q001`, `std/Q010` | столбец указан дважды либо SQL-тип или атрибут не поддерживается диалектом |
| `FLICK-Q011` | `std/Q011` | тип значения столбца не соответствует его SQL-типу и не указан `via` |
| `FLICK-Q010`, `FLICK-Q013` в `sql migration` | `std/Q010`, `std/Q013` | инструкция не относится к DDL миграций либо неприменима к схеме перед её выполнением |
| `FLICK-Q001` … `FLICK-Q010` в запросе | `std/Q001` … `std/Q010` | нарушение правил `sql { … }`; тексты диагностик прежние |
| `FLICK-Q012` | `FLICK-C001` | у типа значения нет представления в SQL: отсутствует экземпляр класса `Sql.Param` |
| несовпадение типа захвата рядом с базовым столбцом, `sum` или `avg` столбца с кодеком | `FLICK-C001` | у типа нет экземпляра класса `Sql.Param` или `Sql.Numeric` |
| `FLICK-E012`, `FLICK-L008` | — | больше не используются: плагин `std` есть в каждой сборке |

Команда `flick explain std/D001` объясняет новый код. Команда
`flick explain FLICK-L001` сообщает, что старый код больше не используется,
и указывает его замену — `std/L001`. Обновите скрипты и фильтры CI, которые
ищут старые коды. Исходный код программы из-за смены кодов менять не нужно.

## `deriving HttpApi` строже

Плагин `std` по-прежнему формирует те же эндпоинты, маршруты и документацию,
но проверяет три случая иначе:

- Значение, названное по типу в его модуле, например `credentials` для
  `Credentials`, используется как кодек части запроса или успешного ответа,
  только если оно имеет тип `PureCodec Json` для этого типа. Иначе используется
  JSON-кодек схемы типа. Если схемы нет, плагин сообщает `std/D011` для
  соответствующей части.
- Функция проверки группы эндпоинтов `Authed` и `MaybeAuthed` получает только
  заголовки запроса — значение типа `HttpApi.Request Unit Unit Credentials Unit`.
- Если для типа ошибки нет экземпляра класса `Problem` или параметры пути
  `:name` не соответствуют полям части `path`, компилятор сообщает `FLICK-C001`
  вместо прежнего `FLICK-D011`.

Исправьте эти случаи вручную.

## Запросы SQL строже

Плагин `std` формирует тот же текст SQL, но проверяет три случая иначе:

- В конструкции `from x in T` после `in` нужно указать имя таблицы: объявленной
  через `sql table` или в миграциях, с квалификатором или без него. Любое другое
  выражение приводит к `std/Q010`. Укажите имя самой таблицы.
- Рядом со столбцом с кодеком захват должен иметь тип самого столбца, а не
  `Option` от него. Несоответствие приводит к `FLICK-T003`. Проверьте `None`
  в коде Flick и для этого случая сформируйте запрос без фильтра.
- Тип `Option` захвата сохраняется в строке результата только при выборе самого
  захвата, как в `select { tag = $tag }`. В остальных случаях захват не делает
  поле результата опциональным. Код, который сопоставляет такое поле
  с конструкторами `Option`, приводит к `FLICK-T003`.

Исправьте эти случаи вручную.

## Эффект `Async` обозначает возможность приостановки

Функция, которая ожидает срабатывания таймера, завершения ввода-вывода или
другого файбера, должна указывать `Async` в строке эффектов
([Эффекты](../../reference/effects/#что-может-приостановиться-async)). В `std`
этот эффект есть у `Effect.sleep`, `Fiber.join`, `Queue.take`, операций
`Database`, `FileSystem` и `Terminal`, `Http.Client`, серверов и клиентов `Http`,
`Rpc` и `HttpApi`. Типы задач для действий, событий, атомов и тестов допускают
этот эффект. Слой, передаваемый в `Test.suite`, тоже может его требовать.
Эффект разрешён и в сигнатуре `main` раннера.

В объявлениях `foreign` больше не используются слова `sync` и `async`.
Если режим не указан, его определяет сигнатура: наличие `Async` в строке
эффектов обозначает внешний вызов, возвращающий Promise.

```sh
flick check --fix --only E002,F001,T003
```

Эта команда удаляет слова `sync` и `async` и добавляет `Async` в строку эффектов
каждого объявления `foreign async`. Затем она добавляет `Async` в строки
эффектов вызывающих функций, повторяя проходы до `main`, и в типы
с соответствующими строками, например
`Cli.Command {Async, File.FileSystem} {AppError}`. Других изменений команда
не вносит.

Один случай требует ручной правки. Если функция получает значения с разными
строками эффектов в позиции, к которой неприменима подтипизация, используйте
переменную строки вместо фиксированной строки. Например, это требуется для
`Channel.Channel none …`, когда в функцию передают канал из очереди:
`Channel.Channel r e … ->{r; e} …`.

## Библиотеки компилируются из исходников

В версии 0.1.0 npm-пакет поставлял модули Flick в виде скомпилированных
интерфейсов:

```json
{ "name": "@acme/text", "flick": { "iface-dir": "iface" } }
```

Теперь проект компилирует каждую библиотеку Flick из исходников.
Поле `iface-dir` больше не читается, поэтому импорт модуля такого пакета
приводит к `FLICK-R003` — неизвестный модуль. Вместо интерфейсов пакет должен
поставлять исходники:

```json
{ "name": "@acme/text", "flick": { "source-dir": "src" } }
```

Другой вариант — оформить библиотеку как пакет Flick и указать её в
`[dependencies]` по пути, git-тегу или архиву (см.
[Зависимости Flick](../../reference/project/#зависимости-flick)).
Команда `flick pack` для библиотеки теперь создаёт архив исходников.
Для неё нужен раздел `[package]` с полями `name` и `version`; без них
возникает `FLICK-P032`. Приложение по-прежнему упаковывается в npm-пакет
с модулями запуска. Эту миграцию выполняет автор библиотеки.

## Ветка `tail` не приостанавливается

Ветка `tail` выполняется в стеке вызывающего кода, который может относиться
к Sync-стадии. Поэтому вызовы внутри ветки не должны приостанавливаться.
Если вызову нужен `Async`, эффект с операцией `control` или переменная
строки эффектов, компилятор сообщает `FLICK-E018`:

```flick fail E018
# effect Ask =
#   ask : Unit ->{} Int
#
# pause : Unit ->{Async} Unit
# foreign pause from "./pause.mjs" "pause"
#   arity 0
#
waits : (Unit ->{Ask; none} Int) ->{Async; none} Int
let waits body =
  try body () with
  | Ask.ask () ->
    pause ()
    1
```

Укажите эффекты, которые нужны ветке, в строке эффектов операции, как в примере
ниже, или объявите операцию `control`. Также можно перехватить такой эффект
обработчиком внутри ветки.

```flick
# pause : Unit ->{Async} Unit
# foreign pause from "./pause.mjs" "pause"
#   arity 0
#
effect Ask =
  ask : Unit ->{Async} Int

waits : (Unit ->{Ask, Async; none} Int) ->{Async; none} Int
let waits body =
  try body () with
  | Ask.ask () ->
    pause ()
    1
```

Команда `flick check --fix` не исправляет этот код: операцию и вызывающий её код нужно менять согласованно.

## `Scope.current` больше не экспортируется

Функция `Scope.current` возвращала текущего владельца с произвольно выбранным
регионом в типе. Поэтому вычисление могло продолжаться дольше времени жизни
этого региона, а дочерний файбер — использовать уже освобождённый ресурс.
Теперь функция доступна только компилятору; её вызов из программы приводит
к `FLICK-T001`. Получайте владельца из `scope s { … }` или принимайте его
параметром типа `Fiber.Owner s`.

## Код, привязанный к региону, не допускает эффектов `control`

Функции `Scope.add_finalizer`, `Resource.acquire_release`, слушатели и серверы
теперь требуют `Detached r`, как и `Fiber.spawn`. Раньше финализатор с операцией
`control` мог остановиться на ней без ошибки, если обработчик не возобновлял
продолжение. Теперь компилятор сообщает `FLICK-E017`: обработайте эффект внутри
передаваемого вычисления. Функция, которая передаёт дальше переменную строки
эффектов, должна явно указать ограничение `Detached r` в своей сигнатуре.
Команда `flick check --fix` не добавляет это ограничение.

## В IR нет `Try`, `Provide`, `Scope` и `Operation`

Команда `flick build --emit-ir` выводит IR в новой версии формата — `0.7.0`.
Конструкция `try` с ветками только для ошибок представляется как `Handle`,
`provide layer { body }` — как вызов `Layer.run`, `scope s { body }` — как
вызов `Scope.run`, а операция — как `Perform { effect, op }`.
Переменной `let mut` соответствует `Stmt::Var`, присваиванию — `Stmt::Assign`,
а чтению переменной — `ExprKind::Var`. Последовательные циклы используют
`ControlLoop`. Узел `LoopExit` хранит цель выхода и необязательное значение
`break`. Исходный код программы менять не нужно.

## Слово `mut` стало ключевым

Конструкция `let mut name = value` объявляет изменяемую переменную функции,
а инструкция `name = value` присваивает ей новое значение (см.
[Переменные](../../reference/types/#переменные)). Слово `mut` теперь является
ключевым. Параметр, значение или поле записи с именем `mut` приводит к
`FLICK-S007`, а конструкция `let mut = …` — к `FLICK-S016`. Переименуйте такие
объявления. После точки, как в `r.mut`, это имя по-прежнему допустимо.

Слова `break` и `continue` тоже зарезервированы для управления локальными
циклами; переименуйте объявления с такими именами. Слова `loop` и `while`
контекстные, поэтому существующие имена `Loop.loop` и `Schedule.while`
продолжают работать.

## Дочерние элементы в `ui` передаются отдельными аргументами

Внутри `ui { … }` дочерние элементы передаются не литералом списка,
а отдельными аргументами вызова. Их можно записывать на строке вызова
или на отдельных строках под ним (см. [Элементы](../../reference/ui/)):

```flick
# view : Float -> Ui
# let view n = ui {
#   let shown = show n
// было: div { class_name = "counter" } [heading [text shown], spacer []]
  div { class_name = "counter" }
    heading (text shown)
    div { class_name = "spacer" }
# }
```

Команда `flick check --fix --only T073` переписывает литералы списков,
записанные в прежнем синтаксисе. Следующие случаи требуют внимания:

- **Список среди других дочерних элементов** (`[header] ++ rows`, записанное
  как два аргумента) приводит к `FLICK-T003`. Сначала объедините списки
  или создайте узел для каждого элемента с помощью `each rows row`.
- **Вызов, разбитый на строки**, внутри `ui` трактует каждую строку под ним
  как один аргумент. Вызов `View.classed "name" (text "x")`, записанный
  в три строки, по-прежнему работает. Строка `text "x"` без скобок,
  ранее содержавшая два аргумента, теперь задаёт один дочерний элемент.
- **`div props` внутри `ui`** создаёт элемент без дочерних элементов,
  а не частично применённую функцию. Чтобы получить функцию, вынесите
  выражение за пределы `ui` или напишите `fun children -> div props children`.

Слово `ui` больше не зарезервировано: оно начинает блок перед `{`,
а в остальных местах остаётся обычным именем. Вне `ui` форма вызова
не меняется: `Ui.div props [a, b]`.

## `refined type` — объявление плагина std

`refined type Port = Float where fun n -> n > 0` пишется как раньше, но его
код теперь даёт плагин `std`: тип, `Port.parse`, `Port.value` и предикат в
виде `Port.check : Float -> Bool`. Что меняется для программы:

- `refined` — не зарезервированное слово: значение можно назвать `refined`.
- Плагин объявляет в модуле функцию-предикат `Port.check`. Если модуль
  объявлял собственное `Port.check` рядом с типом, определений с этим
  именем станет два.
- Объявление, в котором не хватает части, даёт `FLICK-P036` в месте, где
  оно обрывается; раньше это была синтаксическая ошибка.
- Класс в `deriving` уточнённого типа не принимает аргументов.
- Программе с уточнёнными типами больше не нужен Effect ради них: `parse` —
  код языка, а не функция среды выполнения.

Собранный JavaScript и Go меняется только для этих объявлений;
`flick expand` показывает код.

## Фигурные скобки после `then` и `else` содержат инструкции

Фигурные скобки сразу после `then` или `else` — это блок инструкций, как
после `do` и `loop`, поэтому ветвь может присвоить несколько переменных:

```flick
# ordered : Int -> Int -> (Int, Int)
# let ordered a b =
#   let mut low = a
#   let mut high = b
  if low > high then {
    low = b
    high = a
  }
#   (low, high)
```

Запись сразу после `then` или `else` теперь пишется в круглых скобках,
`then ({ r with done = true })`. Записанная по-старому, она вызывает
`FLICK-T074`, а `flick check --fix --only T074` добавляет скобки.

## Экземпляр принадлежит одному пакету

При проверке типов библиотека считается отдельным пакетом, в том числе
если она подключена по пути. Экземпляр класса может объявить только пакет,
которому принадлежит этот класс или тип из заголовка экземпляра. В версии
0.1.0 проект мог объявить экземпляр класса из библиотеки, подключённой по пути,
для типа из той же библиотеки. Теперь такое объявление считается
экземпляром-сиротой и приводит к `FLICK-C006`. Перенесите экземпляр
в библиотеку, которой принадлежит класс или тип, либо оберните исходный
тип в собственный тип проекта:

```flick
# type Id = Id String
# class Label a =
#   label : a -> String
#
type LocalId = LocalId Id

instance Label LocalId =
  label : LocalId -> String
  let label wrapped =
    match wrapped with
    | LocalId (Id raw) -> raw
```

## Плагины получают только разрешённое

Плагины появились в версии 0.2. Плагин зависимости может читать файлы
и переменные окружения, а также отправлять HTTP-запросы только в пределах
разрешений, заданных проектом в `flick.toml`:

```toml
[plugins.pairs]
fs-read = ["schema/"]
net = ["api.example.com"]
env = ["API_TOKEN"]
```

Попытка доступа без разрешения приводит к `FLICK-P038`. Диагностика указывает
строку, которую нужно добавить для предоставления доступа. Ответы HTTP
сохраняются в `.flick/plugin-snapshots/`; добавляйте эти снимки в систему
контроля версий. Флаг `--offline` теперь доступен у каждой команды.
С этим флагом или при заданной переменной окружения `CI` запрос без сохранённого
снимка приводит к `FLICK-P039`. Плагин `std` не обращается к внешним ресурсам,
поэтому для проекта, использующего только `std`, разрешения не нужны.
См. [Доступ вовне](../../reference/plugins/#доступ-вовне).

## `LogLevel` стал перечислением

В версии 0.2 появились перечисления. Например,
`untagged type Method = Get = "GET" | Post = "POST"` объявляет тип, значения
которого представлены заданными литералами (см.
[Генерация кода](../../reference/codegen/)). `LogLevel` стал таким перечислением.
Его конструкторы объявлены от наименее строгого уровня к наиболее строгому:

| 0.1.0 | 0.2 |
| - | - |
| `LogLevel.all`, `trace`, `debug`, `info`, `warn`, `error`, `fatal` | `LogLevel.All`, `Trace`, `Debug`, `Info`, `Warn`, `Error`, `Fatal` |
| `LogLevel.none_` | `LogLevel.Off`, литерал которого — `"None"` |
| `LogLevel.values` | `LogLevel.all`, список уровней по возрастанию строгости |
| `LogLevel.name level` | `LogLevel.value level` |
| `LogLevel.get_ordinal a < LogLevel.get_ordinal b` | `a < b`, через автоматически построенный экземпляр класса `Ord` |

Вызов `compare a b` возвращает `Ordering`, а не `Bool`, поэтому для прежнего
булева сравнения используйте `a < b`.

Функция `show` возвращает имя конструктора уровня: `Off` там, где в версии
0.1.0 выводилось `None`. Удалённые имена приводят к `FLICK-T001`; замените их
вручную. Имя `LogLevel.all` сохранено, но теперь это значение типа
`List LogLevel`. Для прежнего значения уровня используйте `LogLevel.All`.

## Плагины следуют интерфейсу компилятора

При автоматическом построении экземпляра для перечисления плагин получает
литералы его конструкторов, а в `check` плагина передаётся базовый тип
перечисления. При построении экземпляров также доступны сведения
о конструкторах GADT — признаки `refined` и `constrained` у варианта.
Во время раскрытия плагин может запросить, является ли тип перечислением,
через `literal-of`. Пересоберите компонент с тем же `flick-plugin`, который
использует компилятор, запускающий этот компонент.

## `CallSite` вместо записей с `_at`

Класс типов ядра `CallSite` предоставляет функции информацию о месте её
использования (см. [Место вызова](../../reference/classes/#место-вызова)).
Функции `Atom.set`, `update` и `modify` получают её автоматически, поэтому
`Atom.set_at`, `update_at` и `modify_at` удалены. Их вызов приводит к
`FLICK-T001`. Вызывайте `Atom.set atom value` или добавьте ограничение
`CallSite =>` в сигнатуру своей функции, чтобы она сообщала место вызова
вызывающего кода. Ключ сериализуемого атома по-прежнему имеет вид `Module.name`;
теперь это его `CallSite.definition`.

## Регионы проверяются по использованию

Компилятор проверяет, где значение **использует** регион, а не только какие
дескрипторы оно **хранит** (см. [Регионы и захваты](../../reference/regions/)).
Замыкание, задача или значение, созданное конструктором, теперь могут хранить
дескриптор после завершения его `scope`, если выполняемый ими код
не использует дескриптор после этого. Поэтому программы, отклонявшиеся
с `FLICK-G001` только из-за такого хранения, теперь принимаются. Замыкание,
которое читает дескриптор после завершения его области владения ресурсами,
приводит к `FLICK-G002` вместо прежнего `FLICK-G001`.
При проверке поздней стадии каррированной функции предыдущие параметры
не считаются удерживаемыми. Значения, доступные через них, должны оставаться
действительными; компилятор отражает это требование в сигнатуре.

- **Файлы `.iface`** с прежними правилами проверки отклоняются: версия формата
  теперь 12. Пересоберите библиотеки.
- **Компонент** снова может использовать регион своего экземпляра в коде
  инициализации (`setup`): `Setup s` сохраняет действительность региона `s`.
  Вычисления, запускаемые `Ui.on_mount` и `Ui.watch`, должны использовать
  только значения, которые остаются действительными после завершения времени
  жизни экземпляра (`FLICK-G003`). Тип `Lifecycle` теперь указывает регион
  экземпляра: `Lifecycle s`.
- **Обработчик, устанавливаемый программой** для сервиса, индексированного
  регионом, требует действительности этого региона в месте установки
  (`FLICK-G002`).
- **`Option.map`** возвращает `(Option b)^c`: результат функции обратного
  вызова не удерживает её аргумент.

## Данные, хранящие функцию, держат то, до чего дотягиваются параметры

Данные, которые хранят функцию или `task`, например `type G s a = G (s -> a)`,
записанные в сигнатуре без квалификатора, теперь получают скрытую строку так
же, как `Live`: в параметре — любую строку, в результате — то, до чего
дотягиваются предыдущие параметры, и так же в стадиях параметра-функции (см. [Регионы и захваты](../../reference/regions/#квалификаторы)).

- **Обратный вызов, возвращающий такие данные,** держит то, до чего
  дотягиваются его собственные параметры: `(File s -> G String) -> …`
  позволяет обратному вызову вернуть замыкание над файлом, и то, что
  возвращает внешняя функция, тогда держит регион файла.

- **Функция, возвращающая новые данные** после параметра, который
  дотягивается до региона, держит этот регион: `make : Handle r -> G Unit Int`
  не может покинуть `scope` региона `r` (`FLICK-G001`). Если она ничего не
  держит, напишите `(G Unit Int)^{}`.
- **Обратный вызов, вынутый из таких данных,** использует их строку, поэтому
  передать его параметру-обратному вызову без квалификатора — `FLICK-G002`:
  принимайте сами данные или запишите строку у параметра.
- **Файлы `.iface`** версии 20 отклоняются: пересоберите библиотеки.

## Для сборки компилятора нужен Rust 1.95

Для сборки ветки `main` требуется Rust 1.95; для версии 0.1.0 было достаточно
Rust 1.94. Нужная версия закреплена для rustup в `rust-toolchain.toml`.
Возможность сборки Cargo `server-stdlib` удалена: плагин `std` входит
в каждую сборку.

## Сборки без среды выполнения больше нет

`[build] effect = "none"` удалён: `flick.toml` с этим значением даёт
`FLICK-P005`. Уберите ключ или напишите `effect = "rt"`: программа, которая
ничего не выполняет во время выполнения, собирается на собственной среде
выполнения Flick, а в бандл попадают только вызываемые ею вспомогательные
функции. Библиотека больше не пишет `_core/` рядом со своими модулями, а в её
файлах `.iface` нет `abi.core`; их версия теперь 22, поэтому библиотеки нужно
пересобрать. `FLICK-E008` больше не сообщается.

## Предоставленный экземпляр не оставляет телу другого

Обработчик находит сервис по имени, поэтому `provide` слоя `Store Int` отвечал
на каждый `Store` в своём теле, в том числе на `Store String`, который вызывающий
передал через переменную строки: проверка типов это принимала, и программа
получала `Int` там, где написано `String`. Теперь такое тело — `FLICK-E019`.
Уберите сервис из переменной, `Eff {-Store | r} …` (`-` теперь убирает сервис
с аргументами по имени), или назовите экземпляр, нужный телу,
`Eff {Store Int | r} …`.

## Бэкенды находят встроенные типы по lang item

Читатель `flick build --emit-ir` встретит новую версию, `0.9.0`: в программе
есть `lang` — где её модули объявляют каждый lang item, например
`{ "lang": "option", "module": "Prelude", "namespace": "type", "name": "Option" }`.
Бэкенд находит `Option`, `Some` или `Int` там, а не по имени, которое
библиотека может поменять. Плагин с `hooks = ["ir"]` возвращает таблицу такой,
какой её получил; изменённая — `FLICK-P047`.

У встроенных типов больше нет `@ts`: формы TypeScript им даёт JS-бэкенд.
У `@ts` пакета одна форма, одинаковая на любой среде выполнения, а импорт
называет модуль спецификатором: `rt "…"` после формы или экспорта и
`@ts import runtime` или `ui` — `FLICK-S014`. Файлы `.iface` версии 23
отвергаются: пересоберите библиотеки.

## Модуль IR называет свой пакет

Читатель `flick build --emit-ir` встретит новую версию, `0.10.0`: у модуля есть
`package` — пакет, которому он принадлежит (собственные модули проекта берут имя
из его `package.json`); бэкенды пишут его в теги конструкторов модуля.
У встроенного модуля и модуля проекта без имени его нет. Плагин
с `hooks = ["ir"]` возвращает пакеты такими, какими их получил; изменённый —
`FLICK-P047`.

## Модуль IR перечисляет свои экспорты

Читатель `flick build --emit-ir` встретит новую версию, `0.11.0`: у модуля есть
`exports` — то, что экспортирует его интерфейс. В `values` — собственные
экспортируемые значения модуля, у каждого число стрелок, которые передаёт
вызов, если последняя стадия — Sync, иначе `null`. В `reexports` — то, что он
экспортирует из других модулей, например
`{ "module": "Http.Url", "namespace": "type", "name": "Url" }`. По ним
JS-бэкенд пишет строки `export … from` модуля и обёртки его Sync-экспортов.
Плагин с `hooks = ["ir"]` возвращает экспорты такими, какими их получил;
изменённые — `FLICK-P047`.
