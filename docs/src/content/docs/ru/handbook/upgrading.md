До 1.0 минорный релиз может ломать программы, и 0.2 ломает: `std` стал
пакетом, который проект скачивает, блоки `cli`, `codec` и `server fn` и derive
для `Schema`, `Url`, `Form`, `HttpApi` и `Cli.Value` переехали из компилятора
в плагин `std`, а библиотеки компилируются из исходников. На этой странице
перечислены все изменения после 0.1.0 и сказано, как обновить проект.

## Как обновиться

Соберите компилятор из checkout ветки `main` (см.
[Начало работы](../../start/getting-started/#из-исходников)); он берёт `std` из
того же checkout (см. [следующий раздел](#std-устанавливается-как-пакет)). Затем
выполните в проекте:

```sh
flick install
flick check --fix
```

`flick check --fix` применяет безопасные исправления: заменяет `schema T`,
убирает импорты голов плагинов, которые есть в каждом модуле, и выполняет
остальные стандартные автоисправления. Команда сообщает о проблемах, которые
не удалось исправить; дальнейшие действия описаны в разделах ниже.

## `std` устанавливается как пакет

В 0.1.0 `std` был встроен в компилятор. Теперь в компиляторе только модули
ядра, а `std` — пакет. Проект, который не называет `std` в `[dependencies]`,
зависит от тега `std-v<версия>` релиза своего компилятора: `flick install`
скачивает его и закрепляет в `flick.lock`. Коммитьте `flick.lock`. Пока
`flick install` не выполнен, любая команда, которая проверяет модули,
останавливается:

```text
error[FLICK-P034]: `std` from `git+https://github.com/bondiano/flick-lang?tag=std-v0.1.0&subdir=packages/std` is not installed: run `flick install`
```

Компилятор, собранный из checkout, вместо тега берёт `std` этого checkout,
пока checkout лежит там же, где его собирали, поэтому `flick install` для
`std` ему не нужен. `std`, написанный для другого компилятора, останавливает
любую команду с `FLICK-P043` и называет модуль, который не проверяется. Тогда
назовите `std` из исходников самого компилятора:

```toml
[dependencies]
std = { path = "../flick-lang/packages/std" }
```

или задайте этот каталог в `FLICK_STD_PATH`.

## `schema T` стало `T.schema`

Свидетельство схемы типа доступно как `T.schema`, а `schema` больше не ключевое
слово. В 0.1:

```flick fail T001
type alias Profile = { email : String }
  deriving Schema

profile_schema : Schema Profile
let profile_schema = schema Profile
```

Теперь `schema Profile` — вызов неизвестного `schema`, `FLICK-T001`, и его
исправление пишет `Profile.schema`:

```flick
type alias Profile = { email : String }
  deriving Schema

profile_schema : Schema Profile
let profile_schema = Profile.schema
```

`flick check --fix` переписывает это сам.

## Блокам `std` импорт не нужен

Блоки `cli`, `codec`, `server fn` и `sql` (запросы, `sql table` и
`sql migration`) теперь плагин `std`, и их головы есть в каждом модуле:
блоку импорт не нужен, как и в 0.1.

```flick
type alias Profile = { email : String; nickname : Option String }
  deriving Schema

profile_json : PureCodec Json Profile
let profile_json =
  codec Profile.schema {
    email = field "email_address" String.json;
    nickname = field "nickname" (option_as_null String.json);
  }
```

Импорт такой головы, `import Codec exposing (plugin codec)`, —
`FLICK-R012`, и `flick check --fix` его убирает. Импорт нужен только блоку
без `{`, например `cli Main`. Другой плагин эти головы дать не может: его
импорт такой головы — `FLICK-P044`.

`cli`, `codec`, `server` и `fn` больше не ключевые слова: они начинают блок
перед `{` или в начале объявления, как `server fn` и `sql table`, а в
остальных местах это обычные имена. `plugin` — ключевое слово только среди
открытых имён импорта.

## Коды диагностик с префиксом `std/`

Плагин сообщает об ошибках своими кодами с префиксом имени пакета. Правила
блоков и автоматического построения реализаций, перенесённых в плагин, не
изменились; изменились только коды диагностик:

| 0.1 | Теперь | О чём сообщает |
| - | - | - |
| `FLICK-L001` … `FLICK-L007` | `std/L001` … `std/L007` | правила блока `cli` |
| `FLICK-S007` в блоке `cli` | `std/L009` | неправильно записанная конструкция |
| `FLICK-C013` у `deriving Cli.Value` | `std/L010` | тип, для которого `Cli.Value` не выводится |
| `FLICK-D001`, `FLICK-D009`, `FLICK-D010` у `deriving` | `std/D001`, `std/D009`, `std/D010` | тип, для которого не выводится `Schema`, `Url` или `Form`, — на классе в `deriving` |
| `FLICK-D002` … `FLICK-D005`, `FLICK-D007` | `std/D002` … `std/D005`, `std/D007` | правила блока `codec` |
| несовпадение типов в блоке `codec` | `std/D012` | поле, кодек которого декодирует не тот тип, что у поля записи |
| `FLICK-D011` | `std/D011` | запись, которую `deriving HttpApi` не может прочитать как эндпоинты |
| `FLICK-E010` | `std/E010` | форма `server fn`; `server name` для значения, которое не `server fn`, остаётся `FLICK-E010` |
| `FLICK-Q001`, `FLICK-Q010` в `sql table` | `std/Q001`, `std/Q010` | столбец указан дважды, тип SQL или атрибут, которого нет в диалекте |
| `FLICK-Q011` | `std/Q011` | столбец другого типа, чем у его типа SQL, без `via` |
| `FLICK-Q010`, `FLICK-Q013` в `sql migration` | `std/Q010`, `std/Q013` | инструкция вне DDL миграций или такая, что не применяется к схеме перед ней |
| `FLICK-Q001` … `FLICK-Q010` в запросе | `std/Q001` … `std/Q010` | правила `sql { … }`, тексты те же |
| `FLICK-Q012` | `FLICK-C001` | значение, у типа которого нет формы SQL: для него нет инстанса `Sql.Param` |
| захват не того типа рядом с базовым столбцом, `sum` или `avg` столбца с кодеком | `FLICK-C001` | для типа нет инстанса `Sql.Param` или `Sql.Numeric` |
| `FLICK-E012`, `FLICK-L008` | — | больше не используются: плагин `std` есть в каждой сборке |

`flick explain std/D001` объясняет новый код, а `flick explain FLICK-L001`
говорит, что старый код больше не используется, и называет `std/L001`.
Обновите скрипты и фильтры CI, которые ищут старые коды; сам код менять не
нужно.

## `deriving HttpApi` строже

Плагин `std` выводит те же эндпоинты, маршруты и документы, с тремя
отличиями:

- Значение, названное по типу в его модуле, `credentials` для
  `Credentials`, служит кодеком части запроса или успешного ответа, только
  если это `PureCodec Json` этого типа. Иначе берётся JSON-кодек схемы типа,
  а без неё часть — `std/D011`.
- Проверка группы эндпоинтов `Authed` и `MaybeAuthed` получает только
  заголовки запроса, `HttpApi.Request Unit Unit Credentials Unit`.
- Ошибка без экземпляра `Problem` и путь, параметры `:name` которого не поля
  его части `path`, — `FLICK-C001` (раньше были `FLICK-D011`).

Это нужно поправить вручную.

## Запросы SQL строже

Плагин `std` пишет тот же текст SQL, с тремя отличиями:

- `from x in T` читает таблицу только по имени: `sql table` или таблицу
  миграций, с квалификатором или без. Любое другое выражение после `in` —
  `std/Q010`; назовите саму таблицу.
- Рядом со столбцом с кодеком у захвата тип самого столбца, а не `Option`
  от него (`FLICK-T003`). Проверьте `None` во Flick и соберите там запрос
  без этого фильтра.
- `Option` захвата попадает в строку результата, только если захват выбран
  сам, как в `select { tag = $tag }`. В остальных случаях он не делает поле
  строки `Option`, и код, который сопоставлял такое поле с `Option`, —
  `FLICK-T003`.

Это нужно поправить вручную.

## Эффект `Async` обозначает возможность приостановки

Функция, которая ожидает срабатывания таймера, завершения ввода-вывода или
другого файбера, несёт эффект
`Async` в своей строке ([Эффекты](../../reference/effects/#что-может-приостановиться-async)).
В `std` он есть у функций, которые ждут: `Effect.sleep`, `Fiber.join`,
`Queue.take`, операции `Database`, `FileSystem` и `Terminal`, `Http.Client`,
серверы и клиенты `Http`, `Rpc` и `HttpApi`. Его принимают задачи действий,
событий, атомов и тестов, `Test.suite` принимает слой, которому он может
понадобиться, и он может быть у `main` раннера.

В объявлениях `foreign` больше не используются слова `sync` и `async`. Если
режим не указан, его определяет сигнатура: строка с `Async` обозначает вызов,
возвращающий Promise.

```sh
flick check --fix --only E002,F001,T003
```

удаляет эти слова и добавляет `Async` в строку каждого объявления `foreign
async`. Затем команда добавляет `Async` в строки вызывающих функций, повторяя
проходы до `main`, и в типы с соответствующими строками, например `Cli.Command
{Async, File.FileSystem} {AppError}`. Других изменений эта команда не вносит.
Один случай требует ручной правки: функция, которой
передают строки обоих видов в позиции, куда не доходит подтипизация, как
`Channel.Channel none …`, получившая канал из очереди, берёт переменную
строки: `Channel.Channel r e … ->{r; e} …`.

## Библиотеки компилируются из исходников

В 0.1.0 npm-пакет отдавал свои модули Flick как скомпилированные
интерфейсы:

```json
{ "name": "@acme/text", "flick": { "iface-dir": "iface" } }
```

Теперь проект компилирует каждую библиотеку Flick из исходников, а
`iface-dir` не читается: импорт модулей такого пакета — `FLICK-R003`,
неизвестный модуль. Вместо этого пакет поставляет исходники:

```json
{ "name": "@acme/text", "flick": { "source-dir": "src" } }
```

или становится библиотекой Flick, которую проект называет в
`[dependencies]` по пути, git-тегу или архиву (см.
[Зависимости Flick](../../reference/project/#зависимости-flick)).
`flick pack` для библиотеки теперь пишет архив её исходников, и ему нужен
`[package]` с `name` и `version` (без них — `FLICK-P032`); приложение
по-прежнему упаковывается в npm-пакет со своими раннерами. Это изменение
для автора библиотеки.

## Ветка `tail` не приостанавливается

Ветка `tail` выполняется в стеке вызывающего кода, который может относиться к
Sync-стадии, поэтому вызовы внутри ветки не должны приостанавливаться. Вызов в
ней, которому нужен `Async`, эффект с операцией `control` или переменная
строки, теперь даёт `FLICK-E018`:

```flick fail E018
# effect Ask =
#   ask : Unit ->{} Int
#
# pause : Unit ->{Async} Unit
# foreign pause from "./pause.mjs" "pause"
#   arity 0
#
waits : (Unit ->{Ask; none} Int) ->{Async; none} Int
let waits body =
  try body () with
  | Ask.ask () ->
    pause ()
    1
```

Объявите то, что нужно ветке, в строке операции, как ниже, или сделайте операцию
`control`. Такой эффект может поймать и handler внутри ветки.

```flick
# pause : Unit ->{Async} Unit
# foreign pause from "./pause.mjs" "pause"
#   arity 0
#
effect Ask =
  ask : Unit ->{Async} Int

waits : (Unit ->{Ask, Async; none} Int) ->{Async; none} Int
let waits body =
  try body () with
  | Ask.ask () ->
    pause ()
    1
```

`flick check --fix` этого не переписывает: операция и её вызовы меняются вместе.

## `Scope.current` больше не экспортируется

`Scope.current` возвращал текущего владельца с произвольно выбранным регионом
в типе. Поэтому работа могла продолжаться дольше времени жизни этого региона,
а дочерняя задача — использовать уже освобождённый ресурс. Теперь функция
доступна только компилятору; её вызов из программы даёт `FLICK-T001`.
Получайте владельца из `scope s { … }` или принимайте его параметром типа
`Fiber.Owner s`.

## Код, привязанный к региону, не допускает эффектов `control`

`Scope.add_finalizer`, `Resource.acquire_release`, слушатели и серверы теперь
требуют `Detached r`, как и `Fiber.spawn`. Финализатор с операцией `control`
останавливался на ней без ошибки, если обработчик не возобновлял продолжение.
Теперь это `FLICK-E017`: обработайте эффект внутри самой работы. Функция, которая передаёт
дальше переменную строки, называет `Detached r` в своей сигнатуре; `flick check
--fix` его не добавляет.

## В IR нет `Try`, `Provide`, `Scope` и `Operation`

Команда `flick build --emit-ir` выводит IR в новой версии формата — `0.5.0`. `try` с ветками
только для ошибок — это `Handle`, `provide layer { body }` — вызов `Layer.run`,
`scope s { body }` — вызов `Scope.run`, а операция — `Perform { effect, op }`.
Переменная `let mut` — это `Stmt::Var`, присваивание ей — `Stmt::Assign`, а её
чтение — `ExprKind::Var`. Исходный код не меняется.

## Слово `mut` стало ключевым

`let mut name = value` объявляет переменную функции, которой присваивает
`name = value` (см. [Переменные](../../reference/types/#переменные)). Слово
`mut` теперь ключевое: параметр, значение или поле записи с именем `mut` —
это `FLICK-S007`, а `let mut = …` — `FLICK-S016`; переименуйте их. После точки
`r.mut` по-прежнему имя.

## Экземпляр принадлежит одному пакету

Для проверки типов библиотека — другой пакет, и зависимость по пути тоже.
Объявить экземпляр может только пакет класса или пакет типа в голове
экземпляра. В 0.1.0 проект мог объявить экземпляр класса своей библиотеки
по пути для типа этой же библиотеки; теперь это `FLICK-C006`,
экземпляр-сирота. Перенесите экземпляр в библиотеку, которой принадлежит класс или тип, или
оберните тип в собственный тип проекта:

```flick
# type Id = Id String
# class Label a =
#   label : a -> String
#
type LocalId = LocalId Id

instance Label LocalId =
  label : LocalId -> String
  let label wrapped =
    match wrapped with
    | LocalId (Id raw) -> raw
```

## Плагины получают только разрешённое

Плагины появились в 0.2. Плагин зависимости может читать файлы и переменные
окружения, а также отправлять HTTP-запросы только в пределах разрешений,
заданных проектом в `flick.toml`:

```toml
[plugins.pairs]
fs-read = ["schema/"]
net = ["api.example.com"]
env = ["API_TOKEN"]
```

Всё остальное — `FLICK-P038` со строкой, которую нужно добавить. Ответы по
HTTP сохраняются в `.flick/plugin-snapshots/`, и проект их коммитит. С
`--offline`, который теперь есть у каждой команды, или при заданной `CI`
запрос, на который нет снимка, — `FLICK-P039`. Плагин `std` ничего вовне не
достаёт, поэтому проекту, который использует только `std`, разрешать ничего
не нужно. См. [Доступ вовне](../../reference/plugins/#доступ-вовне).

## `LogLevel` стал перечислением

Перечисления появились в 0.2: `untagged type Method = Get = "GET" | Post =
"POST"` — тип, значения которого — их литералы (см.
[Генерация кода](../../reference/codegen/)). `LogLevel` — такое
перечисление, его конструкторы объявлены от наименее к наиболее строгому:

| 0.1.0 | 0.2 |
| - | - |
| `LogLevel.all`, `trace`, `debug`, `info`, `warn`, `error`, `fatal` | `LogLevel.All`, `Trace`, `Debug`, `Info`, `Warn`, `Error`, `Fatal` |
| `LogLevel.none_` | `LogLevel.Off`, литерал которого — `"None"` из Effect |
| `LogLevel.values` | `LogLevel.all`, по возрастанию строгости |
| `LogLevel.name level` | `LogLevel.value level` |
| `LogLevel.get_ordinal a < LogLevel.get_ordinal b` | `compare a b`, выведенный `Ord` |

`show` уровня даёт имя конструктора: `Off` там, где 0.1.0 печатал `None`.
Каждое старое имя даёт `FLICK-T001`; замените его вручную.

## Плагины следуют интерфейсу компилятора

Вывод для перечисления получает литералы его конструкторов, а `check`
плагина — базовый тип перечисления; вывод знает, какие конструкторы
принадлежат GADT (`refined`, `constrained` у варианта), а плагин во время
раскрытия спрашивает, перечисление ли тип (`literal-of`). Пересоберите
компонент тем же `flick-plugin`, что и компилятор, в котором он работает.

## `CallSite` вместо записей с `_at`

Класс ядра `CallSite` даёт функции место её использования (см.
[Место вызова](../../reference/classes/#место-вызова)). `Atom.set`,
`update` и `modify` берут его сами, поэтому `Atom.set_at`, `update_at` и
`modify_at` удалены (`FLICK-T001`): вызывайте `Atom.set atom value` или
дайте своей функции `CallSite =>`, чтобы она сообщала место вызывающего.
Ключ serializable-атома по-прежнему `Module.name`, теперь это его
`CallSite.definition`.

## Захваты ошибок учитываются в типах замыканий

Значение `Errors e`, `Exit e a` или `Failure e` удерживает то, что
удерживают ошибки `e`, а переменная строки ошибок `e` удерживается так же,
как переменная типа. В 0.1.0 такое значение не удерживало ничего, и
замыкание над пойманной ошибкой могло скрыть регион из её данных.
Каррированная стадия сохраняет переменную, поэтому
`keep : forall e. Errors e -> (Unit -> Unit)` по-прежнему проходит проверку
и читается как удерживающее `e`. В позиции, не относящейся к стадии
каррирования, например в типе поля, тип без аннотации захватов теперь не
допускает такое замыкание:

```flick fail G001
keep_field : forall e. Errors e -> { run : Unit -> Unit }
let keep_field x = { run = fun () -> ignore x }
```

```text
error[FLICK-G001]: this function uses `x`, which holds `e`, but the expected type `Unit -> Unit` holds no captures
```

Укажите захваты явно, как для переменной типа (см.
[Захваты](../../reference/regions/#захваты)):

```flick
keep_field : forall c e. (Errors e)^c -> { run : (Unit -> Unit)^c }
let keep_field x = { run = fun () -> ignore x }
```

`flick check --fix` это не переписывает: строка захватов появляется сразу
в `forall`, в параметре и в поле.

## Для сборки компилятора нужен Rust 1.95

Для сборки ветки `main` нужен Rust 1.95 (для 0.1.0 хватало 1.94); эта версия
закреплена для rustup в `rust-toolchain.toml`. Cargo-фичи
