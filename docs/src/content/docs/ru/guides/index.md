## Запустить программу

Создайте приложение для Node.js и запустите его точку входа `main`.
Вам понадобятся компилятор Flick, Node.js 24.18 или новее и pnpm.
Подготовка описана в разделе [Начало работы](../start/getting-started/).

```sh
flick new my-app
cd my-app
flick install
flick check
flick run
```

`flick new` создаёт настройки проекта, `package.json`, модуль с точкой
входа и пример теста. `flick install` устанавливает зависимости с
закреплёнными версиями. Команды `check`, `build` и `run` сами пакеты не устанавливают.

1. Измените `src/App/Main.fl`. Сохраните сигнатуру `main` и обработайте
   ошибки приложения до выхода из этой функции.
2. Проверьте код командой `flick check`. Она не запускает программу.
3. Передайте аргументы приложению через `flick run -- args`. Для
   пересборки и перезапуска после изменений используйте `flick dev`.
4. Если нужны файлы сборки без запуска процесса, выполните `flick build`.
   По умолчанию среди них будет `flick-main.js` — файл запуска точки входа.

**Подробнее:** [Командная строка](../reference/cli/),
[Проект и пакеты](../reference/project/),
[Генерация кода](../reference/codegen/). Если версии инструментов или
зависимостей не совпадают, начните с `flick doctor`. Не меняйте
закреплённую версию среды выполнения наугад.

## Внедрить сервис и обработать предметную ошибку

Сервис позволяет менять реализацию внешних операций без изменения
логики приложения. Строка ошибок в сигнатуре показывает вызывающему коду,
какие ошибки нужно обработать.

1. Объявите ошибки через `type error`. В их полях храните только данные,
   не ссылки на ресурсы с ограниченным временем жизни. Перечислите
   возможные ошибки в эффектной стрелке вызывающей функции.
2. Опишите внешние операции в `service`. Их сигнатуры используют эффектные
   стрелки: например, вызов `Users.get` добавляет `Users` в строку сервисов.
3. Реализуйте сервис записью `S.Impl`, создайте слой через
   `Layer.succeed S impl` и предоставьте его в блоке `provide layer { ... }`.
   Если слою нужны другие сервисы или его создание может завершиться
   ошибкой, эти требования и ошибки останутся у окружающего вычисления.
4. Обработайте ожидаемые ошибки через `try ... with`. Чтобы удалить ошибку
   из строки, обработчик должен покрыть все её значения. Частичной
   обработки или ветки с условием недостаточно.
5. В тесте предоставьте реализацию того же сервиса в памяти.
   Сигнатуру функции приложения менять не нужно.

Каждый шаг описан в [справочнике эффектов](../reference/effects/).
[Примеры сервисов и ошибок](../learn/flick-and-effect/) показывают полные
модули рядом с эквивалентами на TypeScript/Effect. Для тестового окружения
используйте [API тестирования стандартной библиотеки](../reference/stdlib/)
и `flick test`.

**Важно:** `try ... with` обрабатывает типизированные ошибки, но не
произвольные дефекты и прерывание. Если исключение внешнего кода нужно
обрабатывать как ошибку приложения, явно преобразуйте его; см.
[Внешние функции](../reference/ffi/).

## Выполнить конкурентную работу и освободить ресурсы

Запустите группу задач так, чтобы ресурсы освободились только после
завершения всей работы, которая ими пользуется.

1. Отложите работу через `task { ... }`. Если передать эффектный вызов
   прямо в аргументе, он выполнится до входа в принимающую функцию.
2. Используйте `parallel` для пары задач или `parallel_all limit` для
   списка с ограничением числа одновременно выполняемых задач. Если
   типизированная ошибка одной ветки не должна завершать всю группу,
   выберите `parallel_results`: она станет результатом этой ветки.
   Дефекты и прерывание по-прежнему завершают группу с ошибкой.
3. Получайте ресурсы внутри `scope`. Область предоставляет сервис `Scope`
   своего региона и хранит зарегистрированные финализаторы.
4. Чтобы запустить дочернюю задачу отдельно, назовите область и вызовите
   `Fiber.spawn owner supervisor task`. Укажите, как супервизор должен
   обрабатывать её ошибки. У дочерней задачи всегда остаётся владелец.
5. Не возвращайте ресурс, захватывающее его замыкание или задачу за
   пределы времени жизни региона: компилятор отклонит такой код.

Статические правила описаны в разделе
[Регионы и захваты](../reference/regions/), а параллелизм, гонки, тайм-ауты
и порядок завершения — в разделе
[Адаптер среды выполнения](../reference/runtime/).
[Обзор стандартной библиотеки](../reference/stdlib/) указывает на `File`,
`Resource`, `Fiber` и функции конкурентности.

**Важно:** при закрытии области владения, созданной через `scope`,
её дочерние задачи получают запрос на прерывание. Среда выполнения
дожидается их завершения и только затем освобождает ресурсы.
Она также ждёт завершения внешнего Promise, даже если тот игнорирует
отмену. Поэтому тайм-аут не гарантирует мгновенной остановки — учитывайте
это при подключении JavaScript-ресурса или сетевого клиента.

## Вызвать другой процесс с типизированным контрактом

Начните с полного [примера RPC](../reference/rpc/): опишите процедуру
кодеками запроса, результата и ошибок, добавьте её в группу и предоставьте
точную запись обработчиков внутри области. Клиент использует то же
значение процедуры.

Транспорт выбирается отдельно: HTTP для запросов и ответов, WebSocket
для общего соединения с сообщениями, TCP для участников на Node,
`serve_stdio`/`spawn` для дочернего процесса. Настройки начинайте
с `Rpc.defaults` и `Rpc.call_defaults`, явно выбирая формат и транспорт.
`call_local` проверяет логику обработчика; кодеки и заголовки проверяйте
через настоящее соединение.

## Узнать, куда уходят время и ошибки

В разделе [Наблюдаемость](../reference/observability/) сначала выберите
сигнал, затем получателя: спаны для пути запроса, логи для событий,
метрики для агрегатов. Слой OTLP вокруг приложения экспортирует данные
коллектору, `Prometheus.route "/metrics"` предоставляет их для опроса,
а слой DevTools позволяет наблюдать спаны.

**Важно:** общий слой OTLP принимает базовый URL, а слой одного сигнала —
полный адрес приёма. Экспорт из конфигурации включается отдельно
для каждого сигнала. Для вычислительной рекурсии прочитайте
[генерацию кода](../reference/codegen/): цикл избавляет от роста стека,
но не от времени синхронного выполнения.

## Создать браузерный интерфейс

Выведите представление Flick через React и выберите, как обрабатывать
повторные события, пока предыдущий обработчик ещё работает.

1. Настройте импорт `.fl` по разделу
   [Начало работы](../start/getting-started/): через `@flick-lang/astro`
   в Astro или его Vite-плагин в Vite. Интеграция вызывает локальный
   компилятор, а код страницы запускает точку входа через `runMain`.
2. Создайте DOM-контейнер и получите его через `Ui.Dom.container`.
   Установите React 19 и React DOM в приложении: для среды выполнения
   это необязательные peer-зависимости.
3. Храните состояние в атомах (`Atom.make`), а представления создавайте
   через `Ui.view`. Функция рендера читает атомы через `Atom.value`
   и возвращает `Ui`: она не обращается к DOM и не запускает обработчики.
4. Выберите политику событий: `Ui.Event.exhaust`, `latest`, `queue`
   с ограничением очереди или `concurrent` с ограничением числа задач.
   Изменяйте атомы в задаче события, а не во время рендера.
5. Внутри `provide Atom.layer { … }` запустите
   `Ui.Dom.mount container supervisor ui`. Вызов работает до прерывания
   и передаёт ошибки обработчиков супервизору. Область, владеющая корнем
   интерфейса, дожидается завершения обработчиков перед освобождением
   ресурсов.

[Справочник UI](../reference/ui/) описывает свойства компонентов,
безопасные URL, внешние React-компоненты, политики событий
и порядок завершения работы корня.

**Важно:** `text` отображает текст, не HTML. Обычная строка не имеет типа
`SafeUrl` или `SanitizedHtml`. Создавайте такие значения через
документированные функции. `Ui.trusted_html` используйте только тогда,
когда доверяете передаваемому HTML.

## Использовать библиотеки JavaScript и TypeScript

При вызове внешнего кода важно не только совпадение типов, но и то,
когда он выполняется, как отменяется и сколько хранит переданные значения.

### Вызвать JavaScript

Выберите режим привязки по разделу [Внешние функции](../reference/ffi/):
`pure` — для функции, чистоте которой вы доверяете; `sync` — для
синхронной эффектной операции; `async` — для функции, создающей Promise;
`effect` — для функции, создающей Effect. Где этого требует API, укажите
арность аргументов, преобразование ошибок, необязательные значения,
правила отмены и срок хранения переданной функции.

Для установленного пакета `flick ffi import` генерирует привязки из `.d.ts`.
Прочитайте отчёт и задайте политики, которые нельзя вывести из объявлений.
Если форма TypeScript не поддерживается или политики не хватает,
импортёр сообщает об этом и блокирует экспорт — вызвать такую привязку
нельзя. После изменения зависимостей проверьте привязки командой
`flick ffi check`.

### Экспортировать в TypeScript или для вызывающего кода с Promise

В разделе [Генерация кода](../reference/codegen/) выберите публичную форму:

- `flick build --emit ts` создаёт модули TypeScript.
- `--emit-dts` записывает декларации рядом со сгенерированным JavaScript.
- `--promise-facade` добавляет Promise-точки входа для подходящих
  экспортированных эффектных функций без требований к сервисам.
  Ожидаемая ошибка становится значением Effect `Result`; дефекты
  и прерывание отклоняют Promise. То есть не любая ошибка приводит
  к отклонению Promise.

TypeScript не сохраняет все свойства регионов, скрытых захватов,
переменных типов высших порядков и открытых записей. Оставьте такие
типы внутри модуля, а наружу предоставьте небольшой представимый
интерфейс. Ограничения описаны в справочнике генерации кода;
нужные имена выберите по [правилам экспорта модулей](../reference/modules/).

## Настроить редактор и исследовать проблему

Для диагностики используйте исходные типы и сообщения компилятора Flick.
Сгенерированный JavaScript полезен, когда нужно понять само преобразование.

- Настройте `flick lsp --stdio` или Zed по разделу
  [Редакторы](../reference/editor/). Подсказки при наведении, переход
  к определению, автодополнение и диагностика используют анализ проекта.
  Исходники встроенных библиотек можно открыть для чтения, но не редактировать.
- Найдите объяснение кода диагностики командой `flick explain FLICK-E001`.
- Посмотрите результат компиляции через `flick inspect App.Main --emit js`
  или `--emit ts`. Для проекции редактора и соответствий исходным позициям
  используйте `--emit mapping`.
- Проверяйте форматирование через `flick fmt --check`, типы — через
  `flick check`, поведение — через `flick test`. Эти команды не заменяют друг друга.

Параметры и коды завершения перечислены в
[справочнике командной строки](../reference/cli/). Если вы ещё выбираете
между Flick и TypeScript, прочитайте [Flick и Effect](../learn/flick-and-effect/).
