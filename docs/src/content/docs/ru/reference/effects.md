Как проверка определяет, где допустим вызов среды выполнения и какие сервисы
и ошибки ему нужны (см. [Прямые эффектные вызовы](../../spec/03-direct-calls/), [Значения вычислений и их выполнение](../../spec/04-computations/), [Ошибки сервисы ресурсы и конкурентность](../../spec/07-errors-and-concurrency/)). Типы и кинды описаны в разделе
[о типах](../types/).

## Стадии

Вызов среды выполнения происходит, когда передан последний аргумент стрелки
среды выполнения. Каждая стрелка каррированной функции — *стадия*:
`A -> B ->{R; E} C` — чистое частичное применение, за которым следует вызов
среды выполнения; `A ->{R; E} (B -> C)` выполняется после первого аргумента.
Тело функции выполняется на её последней стадии, поэтому его вызовы
учитываются в последней стрелке её сигнатуры.

```flick
greet : String -> String ->{Log; none} String
let greet prefix name =
  Log.info name
  prefix ++ name

hello : String ->{Log; none} String
let hello =
  greet "Hello"
```

Вызов среды выполнения там, где допустим только чистый код, — `FLICK-E001`:
в функции, последняя стрелка которой — `->`, в колбэке, ожидаемом чистым,
и при инициализации модуля. Пустая строка не делает вызов чистым: вызов
функции `a ->{} b` в чистой функции — всё ещё `FLICK-E001`, а её передача
туда, где ожидается `a -> b`, — `FLICK-T003`. Значения верхнего уровня
вычисляются при загрузке модуля, поэтому создаются чисто; `task` на верхнем
уровне допустим, поскольку его тело отложено.

`let user = Users.get id` связывает результат вызова — значение `User`.
Аргументы и стадии выполняются строго слева направо.

## Строки, необходимые телу

Строки вызовов на одной стадии объединяются, а сигнатура задаёт для них
верхнюю границу (см. [Запись и объединение строк](../../spec/05-types-and-classes/#запись-и-объединение-строк)): телу может требоваться
меньше сервисов и ошибок, чем разрешает сигнатура, но никогда не больше.
Превышение границы — `FLICK-E002`, перечисляющая все лишние сервисы и ошибки:

```flick
load_name : UserId ->{Users, Log; NotFound} String
let load_name id =
  let user = Users.get id
  Log.info user.name
  user.name
```

Порядок элементов строки не имеет значения, а повторяющийся элемент
учитывается один раз. `r1 + r2` объединяет две строки одного кинда:

```flick
both : Eff r1 e1 a -> Eff r2 e2 b ->{r1 + r2; e1 + e2} (a, b)
let both left right =
  (await left, await right)
```

Колбэк получает строки стрелки, на соответствие которой его проверяют;
если это переменные строк вызываемой функции, их определяют его вызовы:

```flick
log_all : List Number ->{Log; none} Unit
let log_all numbers =
  each (fun n -> Log.info "number") numbers
```

Когда ожидаемый тип не задан, последняя стрелка лямбды относится к среде
выполнения тогда и только тогда, когда её тело делает вызов среды выполнения:
`fun x -> normalize_name x` имеет тип `String -> String`,
`fun x -> task { Users.get x }` — чистая функция, создающая `Eff`, а
`fun x -> Users.get x` имеет тип `UserId ->{Users; NotFound} User`.

Стрелка среды выполнения и `Eff` принимают значение, которому нужно меньше
сервисов и ошибок; чистая функция принимается там, где ожидается функция среды
выполнения (компилятор поднимает её). Функция среды выполнения никогда не
считается чистой.

## Пустые строки: `none`

`none` — литерал пустой строки: без сервисов или без ожидаемых ошибок
(см. [Unit Never и пустые строки](../../spec/04-computations/#unit-never-и-пустые-строки)). Он подходит любому строчному кинду, поэтому
один и тот же `none` оказывается строкой сервисов, ошибок или захватов
в зависимости от позиции. Все записи ниже обозначают одну и ту же закрытую
строку без элементов и хвоста:

| Запись | Где используется |
| - | - |
| `none` | любая позиция строки: `->{none; E}`, `Eff none none a`, `Layer none none {Clock}` |
| ничего | одна сторона стрелки: в `->{; E}` нет сервисов, в `->{R;}` нет ошибок |
| `->{}`, `->{;}` | стрелка с двумя пустыми строками |
| `{}` | строка в фигурных скобках: `Eff {} {} a` |

В стрелке сторона перед `;` всегда является строкой сервисов, а сторона после
него — строкой ошибок, поэтому `->{; AppError}` и `->{none; AppError}` — один
тип, а `->{AppError}` без `;` — синтаксическая ошибка, а не попытка угадать,
к какой строке относится `AppError`. `flick fmt` записывает пустую строку
сервисов стрелки как отсутствие записи: `->{none; E}` становится `->{; E}`,
а стрелку с двумя пустыми строками — как `->{}`. В остальных местах `none`
сохраняется, поэтому `->{Log; none}` и `Eff none none a` остаются как есть.

```flick
fail : String ->{; AppError} a

log_line : String ->{Log;} Unit
```

Пустая строка не делает вызов чистым. `a ->{} b` всё ещё является стрелкой
среды выполнения: она может выполнять ввод-вывод, хранить состояние,
завершаться из-за дефекта или прерываться; она лишь не запрашивает сервисов
и не объявляет ожидаемых ошибок. Это не `a -> b`: её вызов там, где допустим
только чистый код, — `FLICK-E001`, а передача туда, где ожидается `a -> b`, —
`FLICK-T003`. У чистой стрелки вообще нет строк, и это не то же самое,
что две пустые строки.

`none` — не тип. Это не `Unit` (одно значение), не `Never` (нет значений)
и не `None` из `Option`: `x : none` и `none -> Number` — `FLICK-T002`,
как и `Eff Unit Unit a`, поскольку `Unit` имеет кинд `Type`, а не является
строкой. Внутри строки `none` обозначает всю строку, как переменная строки:
`{Log, none}` — `FLICK-T002`, нужно писать `{Log}`.

Проверка связывает `none` с остальными конструкциями следующим образом:

- `Errors none` — это `Never`; когда `Errors e` с неизвестным `e`
  сопоставляется с `Never`, `e` становится `none`.
- Сигнатура задаёт верхнюю границу, поэтому тело, которому ничего не нужно,
  подходит для любой строки, а функция с `none` подходит везде, где разрешено
  больше сервисов или ошибок.
- Строка, которую ограничения оставляют неизвестной в конце объявления,
  становится `none`: выведенная функция, не вызывающая ни одного сервиса,
  получает пустую строку сервисов, а не свободную переменную строки.
- В сгенерированном коде пустая строка — это `never` в `Effect<A, E, R>`:
  так [Effect](https://effect.website/docs/v4/getting-started/the-effect-type)
  записывает отсутствие требования или ошибки.

## `task` и `await`

`task { body }` создаёт `Eff r e a`, не выполняя его; вызовы тела
учитываются в `r` и `e`. `await t` выполняет `t` один раз в текущем файбере
и снимает ровно один слой: ожидание `Eff r e (Eff r2 e2 a)` даёт
`Eff r2 e2 a`. Ожидание значения, которое не является `Eff`, — `FLICK-T003`.

Функция, принимающая `Eff`, решает, когда его выполнять. Вызов среды
выполнения, записанный как её аргумент, уже выполнен к моменту начала функции:
предупреждение `FLICK-E003` предлагает вместо него передать `task { … }`.

## Ожидаемые ошибки

`type error E = E T …` объявляет ошибку с номинальной идентичностью — её
модулем и именем — и полями её единственного конструктора `E`; у
`type error E` полей нет. Поля — это данные, которые живут дольше кода,
породившего ошибку: ячейка (`Ref`), вычисление (`Eff`), слой, функция среды
выполнения или `Unknown` в них приводят к `FLICK-E005`, в том числе через
используемые ими типы.

Ошибка может иметь параметры типа: `type error RetryExhausted e =
RetryExhausted e Number` сохраняет последнюю причину, а `type error SendFailed a =
SendFailed a` возвращает значение, которое не удалось отправить. Строка различает
ошибки по имени, а не по аргументам, поэтому содержит не более одной
`RetryExhausted`: две такие ошибки в одной строке должны иметь одинаковые
аргументы (`FLICK-T003`). Проекция в TypeScript устроена так же, поскольку
`_tag` ошибки не зависит от её аргументов: объединение ошибок содержит
каждый тег один раз, а `catchTag` сужает его до одного типа.

`try … with` обрабатывает ошибки своего тела. Ошибка покидает строку,
только когда ветвь без условия `when` соответствует всем её значениям;
ветвь с условием или частичный образец оставляет её возможной. Переменная
или `_` соответствует любой ошибке как значению `Errors e`. Требования
обработчиков добавляются:

```flick
find_optional : UserId ->{Users; DbUnavailable} Option User
let find_optional id =
  try
    Some (find_user id)
  with
  | NotFound _ -> None
```

Ветвь, соответствующая чему-либо, кроме ошибки, — `FLICK-E007`.

`Errors e` превращает строку ошибок в тип: `Errors none` — это `Never`,
`Errors {NotFound}` — это `NotFound`. `from_result` завершается с ошибкой
из `Err`; строка ошибок у `Result NotFound a` — `{NotFound}`, а
`Result String a` отклоняется, пока строка не станет объявленной ошибкой:

```flick
checked : Result NotFound User ->{; NotFound} User
let checked result =
  from_result result
```

## Сервисы

`service` перечисляет операции с полными сигнатурами. При выполнении
операции происходит поиск сервиса, поэтому у каждой операции есть стрелка
среды выполнения (`FLICK-E006`), а `S.op` требует `S` на каждой из них:
если в `Users` объявлено `get : UserId ->{; NotFound} User`, то `Users.get`
имеет тип `UserId ->{Users; NotFound} User`. Операции — не методы классов:
методу класса, например `show`, сервис не нужен.

`S.Impl` — запись операций в том виде, как они объявлены. `Layer.succeed S impl`
создаёт из неё слой; имя сервиса используется как значение:

```flick
service Clock =
  now : Unit ->{} Number

clock_impl : Clock.Impl
let clock_impl =
  { now = js_now }

clock_layer : Layer none none {Clock}
let clock_layer =
  Layer.succeed Clock clock_impl
```

## Слои и `provide`

`Layer inputs errors outputs` создаёт сервисы `outputs` из `inputs`
и может завершиться с ошибками `errors`. `provide layer { body }` строит
слой до выполнения тела: телу могут требоваться сервисы, создаваемые слоем,
а блоку нужны входы и ошибки слоя в дополнение к остальным требованиям тела.

```flick
application : UserId ->{Config, Log; NotFound, ConnectError} String
let application id =
  provide users_live {
    load_name id
  }
```

При `users_live : Layer {Config} {ConnectError} {Users}` и `load_name`,
которой нужны `{Users, Log}` и `{NotFound}`, блоку требуются `{Config, Log}`
и `{NotFound, ConnectError}`.

`Layer.merge a b` создаёт сервисы обоих слоёв; два слоя, создающие один
и тот же сервис, — `FLICK-E004`. `Layer.override a b` тоже объединяет их,
но позволяет `b` заменить то, что создаёт `a`.

## Пока не проверяется

| Конструкция | Сейчас |
| - | - |
| `Layer.merge`, использованный без применения к обоим слоям | конфликты не сообщаются |
| имя сервиса как значение с квалификатором модуля | не принимается; укажите имя без квалификатора |
