Flick проверяет запросы к PostgreSQL по объявлениям таблиц в исходном коде.
Запрос — чистое значение: ни его построение, ни связывание параметров
не выполняют ввод-вывод. К базе данных обращаются только `Database.query`
и `Database.execute`.

Диалект задаётся ключом `[sql] dialect` в `flick.toml`
(см. [проект](../project/)). Поддерживается только `postgresql`;
он же используется по умолчанию. Диалект определяет соответствие типов
столбцов, доступные функции запросов и метку в типе шаблона
(`Sql.Template Pg p r`).

## Таблицы

```flick
# type UserId = UserId BigInt
# user_id : PureCodec BigInt UserId
# let user_id = Sql.codec (fun n -> Ok (UserId n)) (fun (UserId n) -> n)
#
sql table Users "users" {
  id : bigint primary key generated always as UserId via user_id
  name : text not null as String
  email : text as String
}
```

`sql table Name "table" { … }` объявляет тип строки `Name` и значение таблицы
`Name.table : Sql.Table "table" { column : Sql.Column t n w, … }`.
Они экспортируются вместе. Блок — плагин `sql` из std, который есть в
каждом модуле без импорта; его код показывает `flick expand`. Если столбец допускает `NULL`, его тип в `Name`
оборачивается в `Option`.
Индексы `Sql.Column` указывают, допускает ли столбец `NULL`
(`Sql.NonNull`, `Sql.Nullable`) и как он заполняется при вставке
(`Sql.Required`, `Sql.Defaulted`, `Sql.Generated`).

После типа SQL в объявлении столбца могут идти `not null`, `null`,
`primary key`, `unique`, `default`, `generated always` и `generated by default`.
Другое слово даёт `std/Q010`, повторное имя — `std/Q001`, и такой столбец в
таблицу не входит.
Столбец допускает `NULL`, если для него не задано `not null` и он
не является первичным ключом. Столбец, допускающий `NULL` или имеющий
значение по умолчанию, можно не указывать при вставке.
Запись в столбец `generated always` никогда не выполняется.

| Тип SQL | Тип Flick |
| - | - |
| `bigint`, `int8`, `bigserial` | `BigInt` |
| `integer`, `int`, `int4`, `smallint`, `int2`, `serial` | `Int` |
| `real`, `double precision`, `float8` | `Float` |
| `numeric`, `decimal` | `BigDecimal` |
| `text`, `varchar`, `character varying`, `uuid`, `date`, `timestamp`, `timestamptz` | `String` |
| `boolean`, `bool` | `Bool` |
| `json`, `jsonb` | `Json` |

Если тип Flick отличается от указанного в таблице соответствий, нужен
`via codec` — `PureCodec` из типа Flick, соответствующего типу SQL столбца.
Без него возникает `std/Q011`.
Такой кодек создаётся через `Sql.codec decode encode`; функция `decode`
может отклонить значение с ошибкой `SchemaError`.
Без такого проверяемого кодека значения `bigint` и `numeric`
не представляются типом `Float`. Перечислению над типом Flick столбца кодек
не нужен: `role : text not null as Role` читает столбец через `Role.parse`,
поэтому значение, которого перечисление не знает, даёт `DecodeError`.

Компилятор никогда не подключается к базе данных. Объявления таблиц
записываются вручную или берутся из миграций модуля (ниже).

## Запросы

```flick
# import Sql exposing (Pg, EncodeError, DbError, DecodeError)
# import Database exposing (Database)
# import BigDecimal exposing (BigDecimal)
# type UserId = UserId BigInt
# user_id : PureCodec BigInt UserId
# let user_id = Sql.codec (fun n -> Ok (UserId n)) (fun (UserId n) -> n)
# sql table Users "users" {
#   id : bigint primary key generated always as UserId via user_id
#   name : text not null as String
# }
# sql table Accounts "accounts" {
#   id : bigint primary key generated always as BigInt
#   user_id : bigint not null as UserId via user_id
#   balance : numeric not null as BigDecimal
# }
# type alias BalanceRow = { name : String; balance : Option BigDecimal }
#
balances : Sql.Template Pg { user_id : UserId } BalanceRow
let balances =
  sql params {
    from user in Users
    left_join account in Accounts on account.user_id == user.id
    where user.id == params.user_id
    select { name = user.name; balance = account.balance }
  }
```

Блок `sql [p] { … }` имеет тип `Sql.Template Pg params row`; это блок
плагина `sql` из std, как и `sql table`, и `flick expand` показывает его код.
Имя после `sql` позволяет обращаться к параметрам: `p.x` обозначает
параметр `x`, тип которого определяется местами использования.
Если у запроса есть сигнатура, обращение к не объявленному в ней параметру
приводит к `std/Q009`. У запроса без имени параметров нет.

`$name` захватывает локальное значение или значение верхнего уровня
и передаёт его как параметр SQL. `$name.field` захватывает поле значения,
а `$(e)` — результат любого выражения `e`; пробел после `$` не ставится.
Тип захвата, как и тип параметра, определяется местом использования.
Значение обрабатывается кодеком столбца, с которым оно сравнивается
или в который записывается. Захват `Option t` — это `t`, который может быть
`NULL`: `None` — это `NULL`, поэтому `where is_null $tag || t.name == $tag` —
фильтр, которого может не быть. Захват базового типа приводится к своему
типу SQL (`CAST($1 AS text)`): PostgreSQL сам не выводит тип `$1 IS NULL`.
Рядом со столбцом с кодеком захват имеет собственный тип столбца, а не
`Option` от него (`FLICK-T003`), а значение типа без формы SQL — это
`FLICK-C001`: у класса `Sql.Param` нет для него инстанса.

Захват не входит в параметры шаблона. Поэтому функция может строить
шаблон из своих аргументов:

```flick
# import Sql exposing (Pg, EncodeError, DbError, DecodeError)
# import Database exposing (Database)
# import BigDecimal exposing (BigDecimal)
# type UserId = UserId BigInt
# user_id : PureCodec BigInt UserId
# let user_id = Sql.codec (fun n -> Ok (UserId n)) (fun (UserId n) -> n)
# sql table Users "users" {
#   id : bigint primary key generated always as UserId via user_id
#   name : text not null as String
# }
# sql table Accounts "accounts" {
#   id : bigint primary key generated always as BigInt
#   user_id : bigint not null as UserId via user_id
#   balance : numeric not null as BigDecimal
# }
# type alias BalanceRow = { name : String; balance : Option BigDecimal }
#
balances_of : UserId -> Sql.Template Pg {} BalanceRow
let balances_of id =
  sql {
    from user in Users
    left_join account in Accounts on account.user_id == user.id
    where user.id == $id
    select { name = user.name; balance = account.balance }
  }
```

Имя без `$` внутри `sql { … }` всегда обозначает столбец.
Значение программы нужно явно пометить `$`. Вне `sql { … }` знак `$`
приводит к синтаксической ошибке.

Конструкции запроса записываются по одной на строку или разделяются `;`.
Проверяются они в порядке SQL независимо от порядка записи:

| Конструкция | Назначение |
| - | - |
| `from x in T` | первая таблица; `T` — это `sql table` или таблица миграций, по имени (иначе `std/Q010`) |
| `join x in T` / `left_join x in T`, затем `on e` | внутреннее и левое соединения |
| `where e` | условие типа `Bool` без агрегатных функций |
| `group_by e, …` | ключи группировки |
| `having e` | условие для групп |
| `select { label = e; … }`, `select a.x, b.y`, `select a` | задаёт результат; в списке каждый столбец сохраняет своё имя, а отдельный псевдоним таблицы выбирает все её столбцы |
| `order_by e, asc e, desc e` | задаёт порядок строк |
| `limit e`, `offset e` | принимают значения `Int` |
| `union (sql { … })`, `union_all (sql { … })` | объединяет с запросом, у которого такие же результирующие столбцы в том же порядке |
| `insert_into T`, `values { column = e; … }` | вставка |
| `update T`, `set { column = e; … }`, `where e` | обновление |
| `delete_from T`, `where e` | удаление |
| `returning …` | результаты вставки, обновления или удаления, как у `select` |

При вставке, обновлении или удалении имя таблицы служит её псевдонимом: `Users.id`.

В выражениях допустимы столбцы, параметры, захваты, литералы, сравнения
`== != < <= > >=`, логические операции `&&`, `||`, `not`,
арифметические операции `+ - * / %` над `Float`, `BigInt` и `BigDecimal`,
конкатенация `++` над `String` и функции из таблицы ниже.
Столбец можно указать как `alias.column` или просто `column`, если он есть
ровно в одной таблице; иначе возникает `std/Q003`.

| Функция | Значение |
| - | - |
| `is_null e`, `is_not_null e` | `IS NULL`, `IS NOT NULL` |
| `is_not_distinct_from a b` | равенство, безопасное при `NULL` |
| `coalesce a b` | первое значение, отличное от `NULL` |
| `count e`, `count_all` | `COUNT(e)`, `COUNT(*)`: `BigInt`, никогда не `NULL` |
| `sum e`, `avg e` | `NULL` при отсутствии строк: `Option`; берут столбец числового типа SQL (иначе `std/Q010`) или значение типа класса `Sql.Numeric` (иначе `FLICK-C001`) |
| `min e`, `max e` | наименьшее и наибольшее значение любого типа, `NULL` при отсутствии строк: `Option` от него |
| `exists (sql { … })`, `is_in e (sql { … })` | некоррелированные подзапросы |

`==` следует правилам SQL: результат равен `NULL`, если хотя бы одна сторона
равна `NULL`. Условие `where` оставляет только строки, для которых оно
истинно. Обе стороны сравнения должны иметь один тип Flick.
Например, сравнение `UserId` с `Date` — ошибка типов, даже если в SQL
оба типа представлены числами.

## Допустимость NULL

Проверка типов учитывает, может ли выражение быть `NULL`. Это возможно
для столбца, допускающего `NULL`, любого столбца таблицы из `left_join`,
агрегатной функции, кроме `count`, и операции над операндом, который
допускает `NULL`.

Такой результат имеет тип `Option t` с одной обёрткой:
два левых соединения не создают `Option (Option t)`.
При `join` столбец `not null` остаётся без обёртки.

## Группировка и агрегатные функции

`group_by`, `having` или агрегатная функция в `select` делают запрос
сгруппированным. Тогда любой столбец в результате, `having` или `order_by`,
используемый вне агрегатной функции, должен быть ключом группировки;
иначе возникает `std/Q005`.

Агрегатные функции допустимы в `select`, `having` и `order_by`.
В `where`, `on`, `group_by` и внутри другой агрегатной функции
они приводят к `std/Q006`.

## Области видимости

У каждого `sql { … }` свои псевдонимы таблиц. Подзапрос видит параметры
окружающего запроса, но не его псевдонимы. Запрос не видит псевдонимы
из подзапроса или объединения. Нарушение этих правил приводит к `std/Q002`.

## Выполнение запросов

```flick
# import Sql exposing (Pg, EncodeError, DbError, DecodeError)
# import Database exposing (Database)
# import BigDecimal exposing (BigDecimal)
# import App.Queries exposing (UserId, BalanceRow, balances)
#
load : UserId ->{Async, Database; EncodeError, DbError, DecodeError} List BalanceRow
let load id = Database.query (Sql.bind balances { user_id = id })
```

`Sql.bind template params` создаёт `Sql.Query Pg row`, не выполняя ввод-вывод.
`Sql.text` возвращает SQL запроса, а `Sql.template_text` — SQL шаблона.
В тексте никогда нет значений: каждый параметр и литерал заменяется
заполнителем `$n`, значение которого драйвер передаёт отдельно.
Имена таблиц, псевдонимов и столбцов берутся из метаданных и заключаются
в кавычки.

`Database.query` возвращает строки результата, а `Database.execute` —
число изменённых строк. Если кодек отклоняет параметр, возникает `EncodeError`.
Если ответ не соответствует запросу — у столбца другой тип SQL,
пришёл недопустимый `NULL` или кодек отклонил значение, — возникает
`DecodeError`. Ошибки сервера и драйвера передаются как
`DbError { code; message; constraint }` с SQLSTATE и нарушенным ограничением
в виде инертных данных.

`Database.pg (Database.config url)` создаёт слой пула соединений `pg`.
Пул существует до закрытия области его `provide`. `Database.config url`
даёт 10 соединений без таймаутов; чтобы изменить их, задайте поля записи:
`{ Database.config url with max_connections = 4; statement_timeout_ms =
Some 5000 }`. Пакет `pg` — необязательная peer-зависимость
`@flick-lang/runtime`; его загружает только этот слой. На Go-target пул —
из pgx: Go-модуль программы, которая обращается к `Database`, требует pgx
v5.7.6, его скачивает первый `go build` в кэш модулей Go со сверкой по
зафиксированному `go.sum`; дальше сеть не нужна. Остальные программы
драйвер не несут и собираются офлайн.

## Транзакции

```flick
# import Sql exposing (Pg, EncodeError, DbError, DecodeError)
# import Database exposing (Database)
# import BigDecimal exposing (BigDecimal)
# import App.Queries exposing (withdraw, deposit)
#
transfer : BigInt -> BigInt -> BigDecimal ->{Async, Database; EncodeError, DbError, DecodeError} Unit
let transfer source target amount =
  Database.transaction (task {
    ignore (Database.query (Sql.bind withdraw { account = source; amount = amount }))
    ignore (Database.query (Sql.bind deposit { account = target; amount = amount }))
  })
```

`Database.transaction body` выполняет `body` на одном соединении между
`BEGIN` и `COMMIT`. Если `body` завершается неудачей — отвергнутым
оператором или собственной ошибкой — или прерыванием, транзакция
откатывается, а неудача идёт дальше. Другие вызывающие берут другие
соединения и не видят её записей до коммита.

Внутри другой транзакции `Database.transaction` — точка сохранения:
перехваченная неудача отменяет только её записи, а внешняя транзакция
продолжается. Оператор, отвергнутый вне точки сохранения, оставляет
транзакцию неспособной выполнять дальше, как в PostgreSQL; пусть неудача
её завершит.

Коммит ждёт ответа сервера. Если соединение обрывается раньше ответа, это
`DbError` с кодом `"commit_unknown"`: транзакция могла произойти, а могла и
нет, и ответ есть только в данных. Ничего не повторяется.

## Миграции

Схема модуля может быть его историей: объявления `sql migration` содержат
DDL, а таблицы — это схема, которую они строят в порядке записи. Каждая
оставшаяся таблица — тип модуля, её строка, с компаньоном `table`, как их
объявляет `sql table`: `article_tags` — это `ArticleTags`. У модуля есть и
значение `migrations : List Migration` — все инструкции как написаны — для
`Database.Migrate.run`. Блок — плагин `sql` из std, как и `sql table`.

```flick
# import Sql
sql migration 1 "people" {
  create table people (
    id bigint primary key generated always as identity,
    name text not null
  );
  create table pets (
    owner bigint not null references people on delete cascade,
    name text not null,
    primary key (owner, name)
  );
}

sql migration 2 "species" {
  alter table pets add column species text not null default "cat";
}

# let example = task {
let applied = Database.Migrate.run migrations
# ()
# }
```

- DDL — это `create table`, `create index`, `alter table` (добавить,
  удалить, переименовать или изменить колонку, переименовать таблицу),
  `drop table` и `drop index`. Остальное — `std/Q010`.
- Каждая инструкция применяется к схеме перед ней: таблица или колонка,
  которую она называет, существует, создаваемая — ещё нет, а версии
  возрастают; иначе `std/Q013`.
- SQL-тип колонки даёт её тип Flick, как в таблице выше; колонку с `null`,
  `default`, `serial` или `generated by default` можно не указывать в
  `INSERT`, а в `generated always` писать нельзя.
- Строка `"cat"` — текстовый литерал SQL `'cat'`, как в запросах;
  идентификаторы не берутся в кавычки.

`Database.Migrate.run steps` приводит схему к актуальной: каждый шаг
`{ version; name; statements }` с версией выше последней, записанной в
таблице `flick_migrations`, выполняет свои инструкции по порядку и
записывается. Ответ — версии применённых шагов, пустой список, если схема
актуальна. Весь запуск — одна транзакция под advisory-блокировкой, поэтому
серверы, которые стартуют одновременно, применяют каждый шаг один раз, а
упавший шаг оставляет схему прежней. Шаги не по возрастанию версии и база,
которая уже дальше последнего шага, отклоняются с `MigrationError`.
Шаги, записанные вручную, — произвольный SQL.

```flick
import Database.Migrate exposing (Migration)

steps : List Migration
let steps = [
  { version = 1; name = "users"; statements = ["create table users (id serial primary key, name text not null)"] },
  { version = 2; name = "emails"; statements = ["alter table users add column email text"] },
]

# let example = task {
let applied = Database.Migrate.run steps
# ()
# }
```

## Отмена и ограничения

Прерванный запрос отменяется на сервере запросом CancelRequest протокола,
отправленным по отдельному соединению, которое не занимает место в пуле.
Затем его соединение закрывается и не возвращается в пул, и прерывание
завершается только после этого, так что backend к этому моменту свободен.
Вне транзакции записанное запросом не откатывается.

`statement_timeout_ms` заставляет сервер завершить оператор, который
выполняется дольше, — `DbError` `57014`. `acquire_timeout_ms` ограничивает,
сколько запрос ждёт соединения, когда заняты все `max_connections`; запрос,
ждущий дольше, завершается неудачей. Вместе они ограничивают, сколько
backend держит программа и как долго.

## Произвольный SQL

Для запросов за пределами проверяемого подмножества есть
`Sql.unsafe_query pieces decoder`. В нём части `Sql.unsafe_text` передаются
как SQL без изменений, `Sql.param codec value` задаёт заполнитель,
а `Sql.ident identifier` — идентификатор в кавычках.
Для имени таблицы или столбца требуется `Sql.Identifier`,
созданный через `Sql.identifier` из проверенного имени.
`String` для этой цели никогда не используется.

Строки результата передаются объектами: `int2`, `int4` и числа с плавающей
точкой представлены числами, `bool` — логическими значениями, `json` —
разобранным значением, а всё остальное — текстом.
Эти строки декодирует `decoder`.

```flick
# type alias Count = { n : Int }
#   deriving Schema
# count_rows : Sql.Identifier -> Sql.Query Sql.Pg Count
let count_rows table =
  Sql.unsafe_query
    [Sql.unsafe_text "select count(*)::int as n from ", Sql.ident table]
    (Codec.json Count.schema)
```

Не поддерживаются коррелированные подзапросы, подзапросы `LATERAL`,
рекурсивные CTE, оконные функции, соединения `RIGHT` и `FULL` и DDL вне
`sql migration`.
