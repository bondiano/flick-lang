---
title: "Запросы SQL"
---

Flick проверяет запросы к PostgreSQL по таблицам, объявленным в исходном коде.
Запрос — чистое значение: его построение и связывание параметров не выполняют
ввод-вывод. Только `Database.query` и `Database.execute` обращаются к базе данных.

## Таблицы

```flick
sql table Users "users" {
  id : bigint primary key generated always as UserId via user_id
  name : text not null as String
  email : text as String
}
```

`sql table Name "table" { … }` объявляет тип строки `Name` (с типом каждого
столбца, обёрнутым в `Option`, если столбец допускает `NULL`) и таблицу
`Name$table : Sql.Table "table" { column : Sql.Column t n w, … }`, экспортируемую
вместе с типом. Индексы указывают, допускает ли столбец `NULL`
(`Sql.NonNull`, `Sql.Nullable`) и что для него требуется при вставке
(`Sql.Required`, `Sql.Defaulted`, `Sql.Generated`).

Столбец задаётся его типом SQL, за которым могут следовать `not null`, `null`, `primary key`,
`unique`, `default`, `generated always` и `generated by default`. Столбец
допускает `NULL`, если не задано `not null` и он не является первичным ключом;
столбец, допускающий `NULL` или имеющий значение по умолчанию, можно не указывать
при вставке; запись в столбец `generated always` никогда не выполняется.

| Тип SQL | Тип Flick |
| - | - |
| `bigint`, `int8`, `bigserial` | `BigInt` |
| `integer`, `int`, `int4`, `smallint`, `int2`, `serial`, `real`, `double precision`, `float8` | `Number` |
| `numeric`, `decimal` | `BigDecimal` |
| `text`, `varchar`, `character varying`, `uuid`, `date`, `timestamp`, `timestamptz` | `String` |
| `boolean`, `bool` | `Bool` |
| `json`, `jsonb` | `Json` |

Для столбца другого типа требуется `via codec` — `PureCodec` из типа Flick,
соответствующего его типу SQL (иначе `FLICK-Q011`). `Sql.codec decode encode`
создаёт такой кодек; `decode` может отклонить значение с `SchemaError`. `Number` никогда
не содержит `bigint` или `numeric` без такого проверяемого кодека.

Компилятор никогда не подключается к базе данных: таблицы записываются вручную
или генерируются из миграций в ту же форму.

## Запросы

```flick
balances : Sql.Template Pg { user_id : UserId } BalanceRow
let balances =
  sql params {
    from user in Users
    left_join account in Accounts on account.user_id == user.id
    where user.id == params.user_id
    select { name = user.name; balance = account.balance }
  }
```

`sql [p] { … }` — это `Sql.Template Pg params row`. Имя после `sql`
связывает параметры: `p.x` — параметр `x`, тип которого определяется
местами его использования. При наличии сигнатуры параметр, не объявленный
в ней, даёт `FLICK-Q009`. Запрос без имени не имеет параметров.

`$name` захватывает значение программы, локальное или верхнего уровня, как
заполнитель; `$name.field` захватывает его поле, а `$(e)` — значение любого
выражения `e`, оба пишутся сразу после `$`. Тип захвата определяется местом
использования, как у параметра, а значение проходит через codec столбца, с
которым его сравнивают или в который его пишут. Захват не является
параметром шаблона, поэтому функция строит шаблон из своих аргументов:

```flick
balances_of : UserId -> Sql.Template Pg {} BalanceRow
let balances_of id =
  sql {
    from user in Users
    left_join account in Accounts on account.user_id == user.id
    where user.id == $id
    select { name = user.name; balance = account.balance }
  }
```

Голое имя внутри `sql { … }` всегда означает столбец: именно `$` делает его
значением программы, а `$` вне `sql { … }` — синтаксическая ошибка.

Предложения записываются по одному на строку или разделяются `;` и проверяются
в порядке SQL независимо от порядка записи:

| Предложение | Значение |
| - | - |
| `from x in T` | первая таблица; `T` — это `sql table` или любое значение `Sql.Table` |
| `join x in T` / `left_join x in T`, затем `on e` | внутреннее и левое соединения |
| `where e` | условие типа `Bool` без агрегатных функций |
| `group_by e, …` | ключи группировки |
| `having e` | условие для групп |
| `select { label = e; … }`, `select a.x, b.y`, `select a` | результаты; при записи списком каждый получает имя своего столбца, а отдельный псевдоним выбирает все свои столбцы |
| `order_by e, asc e, desc e` | упорядочивание |
| `limit e`, `offset e` | значения `Number` |
| `union (sql { … })`, `union_all (sql { … })` | запрос с такими же результатами в том же порядке |
| `insert_into T`, `values { column = e; … }` | вставка |
| `update T`, `set { column = e; … }`, `where e` | обновление |
| `delete_from T`, `where e` | удаление |
| `returning …` | результаты вставки, обновления или удаления, как у `select` |

При вставке, обновлении или удалении имя таблицы служит её псевдонимом: `Users.id`.

Выражения — это столбцы (`alias.column` или `column`, если он есть ровно в одной
таблице; иначе `FLICK-Q003`), параметры, захваты, литералы, `== != < <= > >=`,
`&&`, `||`, `not`, `+ - * / %` над `Number`, `BigInt` и `BigDecimal`, `++` над
`String`, а также функции:

| Функция | Значение |
| - | - |
| `is_null e`, `is_not_null e` | `IS NULL`, `IS NOT NULL` |
| `is_not_distinct_from a b` | равенство, безопасное при `NULL` |
| `coalesce a b` | первое значение, отличное от `NULL` |
| `count e`, `count_all` | `COUNT(e)`, `COUNT(*)`: `BigInt`, никогда не `NULL` |
| `sum e`, `avg e`, `min e`, `max e` | `NULL` при отсутствии строк: `Option` |
| `exists (sql { … })`, `is_in e (sql { … })` | некоррелированные подзапросы |

`==` — сравнение SQL: его результат равен `NULL`, если хотя бы одна сторона равна
`NULL`, а `where` оставляет только строки, для которых условие истинно. Стороны
сравнения имеют один и тот же тип Flick: сравнение `UserId` с `Date` — ошибка типов,
даже если в SQL оба представлены числами.

## Допустимость NULL

Каждое выражение знает, может ли оно быть `NULL`: столбец, допускающий `NULL`, столбец
таблицы из `left_join`, агрегатная функция, кроме `count`, операция над операндом,
допускающим `NULL`. Результат, который может быть `NULL`, имеет тип `Option t` с одной
обёрткой: два левых соединения не создают `Option (Option t)`. При `join` столбец
`not null` остаётся без обёртки.

## Фазы

`group_by`, `having` или агрегатная функция в `select` делают запрос сгруппированным:
тогда каждый столбец, используемый результатом, `having` или `order_by` вне агрегатной
функции, должен быть ключом группировки (`FLICK-Q005`). Агрегатные функции допустимы
в `select`, `having` и `order_by`; в `where`, `on`, `group_by` или внутри другой
агрегатной функции они дают `FLICK-Q006`.

## Области видимости

У каждого `sql { … }` свои псевдонимы. Подзапрос видит параметры окружающего
запроса, но не его псевдонимы, а запрос никогда не видит псевдонимы подзапроса
или объединения (`FLICK-Q002`).

## Выполнение запросов

```flick
load : UserId ->{Database; EncodeError, DbError, DecodeError} List BalanceRow
let load id = Database.query (Sql.bind balances { user_id = id })
```

`Sql.bind template params` — это `Sql.Query Pg row`, без ввода-вывода.
`Sql.text` возвращает его SQL, `Sql.template_text` — тот же SQL шаблона; значений в нём никогда нет: каждый параметр и
каждый литерал — заполнитель `$n`, значение которого драйвер передаёт отдельно
от текста. Имена таблиц, псевдонимов и столбцов берутся из метаданных и заключаются в кавычки.

`Database.query` возвращает строки, `Database.execute` — число изменённых
строк. Параметры, отклонённые кодеком, дают `EncodeError`; ответ, не соответствующий
запросу (столбец другого типа SQL, `NULL` там, где запрос его не допускает,
значение, отклонённое кодеком), — `DecodeError`; то, что отклоняет сервер
или драйвер, — `DbError { code; message; constraint }` с SQLSTATE и нарушенным
ограничением в виде инертных данных.

`Database.pg { connection_string; max_connections }` — слой пула соединений
`pg`, время жизни которого заканчивается вместе с областью его `provide`. Пакет `pg` —
необязательная peer-зависимость `@flick-lang/runtime`, загружаемая только этим
слоем. Прерванный запрос не откатывается: его соединение закрывается и
никогда не возвращается в пул, а прерывание завершается после закрытия соединения.

## Непосредственный SQL

За пределами проверяемого подмножества `Sql.unsafe_query pieces decoder` выполняет
непосредственный SQL: части `Sql.unsafe_text` — SQL в записанном виде, `Sql.param codec value` —
заполнитель, `Sql.ident identifier` — идентификатор в кавычках. Имя таблицы
или столбца задаёт только `Sql.Identifier`, созданный `Sql.identifier` из проверенного
имени: `String` для этого никогда не используется. Строки — объекты, в которых `int2`,
`int4` и числа с плавающей точкой представлены числами, `bool` — логическими значениями,
`json` разобран, а всё остальное представлено текстом; их декодирует `decoder`.

```flick
let count_rows table =
  Sql.unsafe_query
    [Sql.unsafe_text "select count(*)::int as n from ", Sql.ident table]
    (Codec.json (schema Count))
```

В первой версии отсутствуют: коррелированные подзапросы и подзапросы `LATERAL`, рекурсивные
CTE, оконные функции, соединения `RIGHT` и `FULL`, DDL.
