`flick` — единый исполняемый файл поверх ядра компилятора. Каждая команда принимает
глобальные параметры `--project <path>`, `--diagnostics human|json`,
`--warnings-as-errors`, `--color auto|always|never`, `--quiet`/`--verbose`
и `--help`; `flick help <command>` выводит справку по команде, а
`flick --version` — версию компилятора (остальные сведения показывает `flick doctor`).

## Команды

| Команда | Действие |
| - | - |
| `new <dir> [--template app\|lib]` | создаёт проект: `flick.toml`, `package.json`, пример модуля и его тест |
| `init [--template app\|lib]` | создаёт те же файлы в рабочем каталоге; обо всех уже существующих файлах сообщается до начала записи (`FLICK-P019`) |
| `check [paths] [--watch]` | выполняет проверку; без путей проверяет корневые каталоги исходников и тестов |
| `build [paths] [--profile] [--emit js\|ts] [--emit-dts] [--schema-aot] [--out-dir] [--watch]` | записывает ESM, карты исходников и файлы `.iface` |
| `run [--entry M] [--profile] -- args` | собирает JavaScript и запускает `main` |
| `dev [--entry M] [--profile] -- args` | пересобирает при изменениях и заменяет работающее приложение |
| `test [paths] [--filter] [--jobs] [--seed] [--reporter human\|json] [--watch] [--profile]` | запускает тесты из корневого каталога тестов |
| `fmt [paths] [--check] [--stdin --stdin-filepath f]` | форматирует; без путей обрабатывает корневые каталоги исходников и тестов |
| `clean [--cache]` | удаляет артефакты сборки; с `--cache` — также кеш сборки |
| `install [--locked] [--offline]` | устанавливает с помощью pnpm (`--frozen-lockfile`, `--offline`) |
| `add <pkg>… [--dev]`, `remove <pkg>…`, `update [pkg]…` | изменяет зависимости с помощью pnpm |
| `deps [--why <pkg>]` | показывает установленный граф зависимостей и модули Flick каждой прямой зависимости |
| `pack --out-dir <dir>` | выполняет сборку в профиле release и создаёт её tar-архив npm |
| `ffi import`, `ffi check` | создаёт привязки из `.d.ts`, см. [FFI](../ffi/) |
| `schema export <M.codec> --target json-schema-2020-12 --out <file>` | выводит строгую JSON Schema кодека |
| `doc --out-dir <dir>` | создаёт Markdown-страницы публичного API: типы, кинды, ограничения, эффекты, захваты |
| `explain <code>` | выводит объяснение кода диагностики |
| `doctor` | показывает компилятор, Node.js, pnpm, установленные среду выполнения и Effect, необязательные адаптеры |
| `inspect <M> --emit ast\|typed-ir\|js\|ts\|iface\|mapping` | выводит одно представление модуля |

`check`, `build` и этапы сборки в `run`, `dev` и `test` ничего не устанавливают,
не запускают `main` и не загружают внешние модули. Если установленные
`@flick-lang/runtime` или `effect` имеют версию, отличную от закреплённой
компилятором, эти команды останавливаются с `FLICK-P015` (код выхода 2).
`schema export` загружает только модуль, создающий кодек, верхний уровень
которого чистый, и ничего больше.

## Выходные файлы и кеш

Сборка записывает файлы в `build.out-dir` (или `--out-dir`) и сохраняет их
список в `.flick/artifacts.json`. `clean` удаляет ровно эти файлы и каталоги,
которые после этого остаются пустыми: остальные файлы в общем выходном
каталоге сохраняются.

Кеш в `.flick/cache/` хранит артефакты каждой сборки по ключу, учитывающему
исходники проекта, его действующую конфигурацию, профиль, настройки генерации
и вывода, компилятор (версию и исполняемый файл), установленные среду выполнения
и Effect, `package.json`, `pnpm-lock.yaml`, а также манифесты и интерфейсы
установленных зависимостей. Любое изменение этих данных означает промах кеша;
при попадании записываются ровно те файлы, которые создала бы сборка.

## Запуск и замена приложения

`run` и `dev` всегда собирают JavaScript независимо от значения `emit`. Каждая
сборка попадает в отдельное поколение `.flick/run/<n>/`, которое больше не
перезаписывается после запуска его процесса, поэтому поздний `import()` видит
те же файлы, с которыми процесс был запущен. Пока процесс работает, поколение
удерживает блокировку, а после его завершения удаляется; `clean` сохраняет
заблокированные поколения.

`dev` собирает следующую версию, пока текущая работает. Неудачная сборка
оставляет текущую версию запущенной. Успешная сборка сначала останавливает
текущую версию так же, как SIGTERM: запускающий процесс прерывает `main`,
ожидает завершения его файберов и выполняет его финализаторы. Только после
этого запускается новая версия. Неудачное завершение работы (любой код выхода,
кроме 143) прекращает перезапуски с `FLICK-P021`, а сообщение запускающего
процесса о причине остаётся в stderr.

SIGINT и SIGTERM передаются приложению; `flick` завершается только после него
и с его кодом выхода.

## Зависимости

Команды работы с зависимостями передают выполнение pnpm. Каждая команда,
изменяющая манифест, файл блокировки или дерево зависимостей, сначала проверяет,
что `pnpm --version` совпадает с версией, закреплённой в `packageManager`
(`FLICK-P016`, код выхода 2, без изменений). `install --locked` без
`pnpm-lock.yaml` или с устаревшим файлом приводит к `FLICK-P017` с кодом выхода 2.

`pack` собирает модули проекта в профиле release во временный пакет без
запускающего кода, проверяет, что у каждого модуля есть `.iface` (и `.d.ts`
при `emit-dts`), что интерфейсы внутри пакета согласованы по отпечаткам друг
друга и что пути, указанные в `exports`, существуют (`FLICK-P020`), а затем
записывает tar-архив с помощью `pnpm pack`. В подготовленном `package.json`
указано `"flick": { "iface-dir": "dist" }`.

## Потоки и коды выхода

stdout содержит только результат: вывод приложения, отчёт о тестах,
напечатанное представление. Диагностика и служебные сообщения идут в stderr.
При `--diagnostics json` stderr имеет формат NDJSON: по одному событию на строку,
у каждого события есть `schema-version`. Типы событий: `diagnostic`, `log`
(служебные сообщения), `application-stderr` (stderr приложения или тестов) и
`package-manager-output` (pnpm); последние три имеют вид
`{ "type", "channel", "text" }` без ANSI-кодов.

| Код | Значение |
| - | - |
| `0` | успех |
| `1` | ошибки в коде, неудачные тесты, неотформатированный файл, ошибка приложения или очистки |
| `2` | неверный вызов или конфигурация, отсутствующая или неподходящая зависимость либо набор инструментов |
| `3` | внутренняя ошибка Flick |
| `130` / `143` | SIGINT / SIGTERM остановил приложение, и его очистка завершилась успешно |
