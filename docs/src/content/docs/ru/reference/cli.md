`flick` — исполняемый файл с командами компилятора. Все команды принимают
глобальные параметры `--project <path>`, `--diagnostics human|json`,
`--warnings-as-errors`, `--color auto|always|never`, `--quiet`/`--verbose`
и `--help`. Команда `flick help <command>` выводит справку по выбранной команде,
а `flick --version` — версию компилятора. Остальные сведения показывает `flick doctor`.

## Команды

| Команда | Действие |
| - | - |
| `new <dir> [--template app\|lib]` | создаёт проект: `flick.toml`, `package.json`, пример модуля и его тест |
| `init [--template app\|lib]` | создаёт те же файлы в рабочем каталоге; перед записью сообщает обо всех файлах, которые уже существуют (`FLICK-P019`) |
| `check [paths] [--watch] [--fix]` | проверяет код; если пути не указаны, проверяет корневые каталоги исходников и тестов; `--fix` применяет к этим файлам исправления, не меняющие смысла программы (например, убирает избыточную аннотацию типа, `FLICK-T021`), и сообщает об оставшихся проблемах |
| `build [paths] [--profile] [--labels all\|components\|none] [--emit js\|ts] [--emit-dts] [--schema-aot] [--out-dir] [--watch]` | записывает ESM, карты исходников и файлы `.iface` |
| `run [--entry M] [--profile] -- args` | собирает JavaScript и запускает `main` |
| `dev [--entry M] [--profile] -- args` | пересобирает при изменениях и заменяет работающее приложение |
| `test [paths] [--filter] [--jobs] [--seed] [--reporter human\|json] [--watch] [--profile]` | запускает тесты из корневого каталога тестов |
| `fmt [paths] [--check] [--stdin --stdin-filepath f]` | форматирует код; если пути не указаны, обрабатывает корневые каталоги исходников и тестов |
| `clean [--cache]` | удаляет артефакты сборки; с `--cache` — также кеш сборки |
| `install [--locked] [--offline]` | устанавливает зависимости с помощью pnpm (`--frozen-lockfile`, `--offline`) |
| `add <pkg>… [--dev]`, `remove <pkg>…`, `update [pkg]…` | изменяет зависимости с помощью pnpm |
| `deps [--why <pkg>]` | показывает установленный граф зависимостей и модули Flick каждой прямой зависимости |
| `pack --out-dir <dir>` | собирает проект в профиле release и создаёт tar-архив npm-пакета; отказывает при `todo` и `echo` (`FLICK-P024`) и предупреждает, если публичный API ломает импортёров со времени последнего тега |
| `diff [ref]` | изменения публичного API со времени ревизии git (по умолчанию последнего тега): `MAJOR` (удалено или изменено) или `MINOR` (добавлено), и версия, которую они требуют, от версии в `package.json` |
| `ffi import`, `ffi check` | создаёт привязки из `.d.ts`, см. [FFI](../ffi/) |
| `schema export <M.codec> --target json-schema-2020-12 --out <file>` | выводит строгую JSON Schema кодека |
| `doc --out-dir <dir>` | создаёт Markdown-страницы публичного API: типы, кинды, ограничения, эффекты, захваты |
| `explain <code>` | объясняет сообщение диагностики по его коду |
| `doctor` | показывает сведения о компиляторе, Node.js, pnpm, установленной среде выполнения и Effect, а также о необязательных адаптерах |
| `inspect <M> --emit ast\|typed-ir\|js\|ts\|iface\|mapping` | выводит одно представление модуля |

`check`, `build` и этапы сборки в `run`, `dev` и `test` ничего не устанавливают,
не запускают `main` и не загружают внешние модули. Если версия установленного
`@flick-lang/runtime` или `effect` отличается от закреплённой компилятором,
эти команды завершаются с `FLICK-P015` (код выхода 2).
`schema export` загружает только модуль, создающий кодек, и ничего больше.
Код верхнего уровня этого модуля чистый.

## Выходные файлы и кеш

Сборка записывает файлы в `build.out-dir` (или `--out-dir`) и сохраняет их
список в `.flick/artifacts.json`. Команда `clean` удаляет только файлы из этого
списка и каталоги, которые после удаления остаются пустыми. Остальные файлы
в общем выходном каталоге сохраняются.

Кеш в `.flick/cache/` хранит артефакты каждой сборки. Ключ кеша учитывает
исходники проекта, его итоговую конфигурацию, профиль, настройки генерации
и вывода, компилятор (версию и исполняемый файл), установленные среду выполнения
и Effect, `package.json`, `pnpm-lock.yaml`, а также манифесты и интерфейсы
установленных зависимостей. Если любые из этих данных изменились, сборку
нельзя взять из кеша. При использовании кеша записываются ровно те файлы,
которые создала бы сборка.

## Запуск и замена приложения

`run` и `dev` всегда собирают JavaScript независимо от значения `emit`. Каждая
сборка хранится в отдельном каталоге поколения `.flick/run/<n>/`. После запуска
процесса файлы этого поколения больше не перезаписываются, поэтому поздний
`import()` видит те же файлы, с которыми процесс был запущен. Пока процесс
работает, поколение заблокировано; после завершения процесса оно удаляется.
Команда `clean` сохраняет заблокированные поколения.

`dev` собирает следующую версию, пока текущая работает. Если сборка не удалась,
текущая версия продолжает работать. После успешной сборки `dev` сначала
останавливает текущую версию так же, как SIGTERM: запускающий процесс прерывает
`main`, ждёт завершения его файберов и выполняет финализаторы. Только после
этого запускается новая версия. Если завершение работы не удалось (код выхода
отличается от 143), `dev` прекращает перезапуски с `FLICK-P021`.
Сообщение запускающего процесса о причине остаётся в stderr.

SIGINT и SIGTERM передаются приложению; `flick` завершается только после него
и с его кодом выхода.

## Зависимости

Команды работы с зависимостями используют pnpm. Перед изменением манифеста,
файла блокировки или дерева зависимостей каждая команда проверяет,
что `pnpm --version` совпадает с версией, закреплённой в `packageManager`.
При несовпадении команда завершается с `FLICK-P016` и кодом выхода 2,
ничего не меняя. Вызов `install --locked` без `pnpm-lock.yaml`
или с устаревшим файлом приводит к `FLICK-P017` с кодом выхода 2.

`pack` собирает модули проекта в профиле release во временный пакет без
кода запуска. Затем команда проверяет, что у каждого модуля есть `.iface`
(и `.d.ts` при `emit-dts`), отпечатки интерфейсов внутри пакета согласованы
друг с другом, а пути из `exports` существуют (`FLICK-P020`).
После этого `pack` записывает tar-архив с помощью `pnpm pack`.
В подготовленном `package.json` указано `"flick": { "iface-dir": "dist" }`.

## Потоки и коды выхода

В stdout попадает только результат работы команды: вывод приложения, отчёт
о тестах или запрошенное представление модуля. Диагностика и служебные сообщения
идут в stderr. При `--diagnostics json` stderr имеет формат NDJSON: по одному
событию на строку, у каждого события есть `schema-version`. Типы событий:
`diagnostic`, `log` (служебные сообщения), `application-stderr` (stderr приложения
или тестов) и `package-manager-output` (pnpm). Последние три имеют вид
`{ "type", "channel", "text" }` без ANSI-кодов.

| Код | Значение |
| - | - |
| `0` | успех |
| `1` | ошибки в коде, неудачные тесты, неотформатированный файл, ошибка приложения или очистки |
| `2` | неверный вызов или конфигурация, отсутствующая или неподходящая зависимость либо набор инструментов |
| `3` | внутренняя ошибка Flick |
| `130` / `143` | приложение остановлено сигналом SIGINT / SIGTERM, очистка завершилась успешно |
