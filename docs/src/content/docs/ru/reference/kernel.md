Ядро примитивов — это то, что каждый бэкенд реализует сам: операции
переносимого IR, lang items, которые бэкенд сопоставляет по роли, и
небольшой набор привязок `foreign`. Всё остальное, что привязывает
стандартная библиотека, — либо возможность хоста, либо то, что код на Flick
может сделать поверх ядра. Поэтому новый бэкенд реализует ядро и те
возможности хоста, которые поддерживает, и запускает стандартную библиотеку
по мере того, как её привязки переходят на Flick.

Просто «ядро» в этом репозитории означает другое: файберы, владельцев и
причины собственной среды выполнения Flick для JS
(`runtime/src/rt/kernel.ts`) и ABI среды выполнения, которое проверяет
`FLICK-P015`. Эта страница — только о *ядре примитивов*.

## Версия и рукопожатие

У ядра есть версия, сейчас `0.1.0`. Запрос сборки называет её как ABI среды
выполнения `flick.kernel` рядом с `flickrt`, а бэкенд объявляет версии,
которые он реализует, среди `runtime-abis` своего дескриптора, как это
делают `flick/js`, `flick/go` и тестовый бэкенд `test/literal`:

```rust
NamedRange { name: "flick.kernel".into(), versions: range("0.1.0", "0.2.0") }
```

Рукопожатие отклоняет бэкенд без подходящего диапазона до того, как
запустится его `check-target` или `generate`, поэтому ничего не
записывается: сборка сообщает `FLICK-P013` с
``incompatible runtime ABI `flick.kernel` ``. Новый примитив или изменение
того, что делает существующий, — это новая версия ядра.

## Инвентаризация

`flick-backend-support/src/kernel/manifest.txt` относит каждую привязку,
которую называет `foreign` из `packages/*/src`, — пару
`(спецификатор, экспорт)`, где `global` означает глобальное имя JS, — к
одному классу:

| Класс | Привязка — это |
| - | - |
| `kernel` | примитив, который реализует каждый бэкенд |
| `flick` | то, что выражается на Flick поверх ядра |
| `host` | возможность хоста, которую дают хост-пакеты: вывод, файлы, процессы, сеть, часы, случайность, локаль |
| `adapter` | привязка к значениям одной библиотеки хоста, которую держит адаптер этого бэкенда: промисы и потоки JS, React, атомы и формы UI |

Строка `[спецификатор] класс` задаёт класс всех экспортов спецификатора, а
строка `экспорт класс` под ней — другой класс одного экспорта; у экспорта
ядра всегда своя строка. `cargo test -p flick-backend-support kernel`
падает на привязке, которую манифест не классифицирует, и на той, которую
он называет, хотя стандартная библиотека её больше не привязывает, и
печатает число привязок каждого класса (с `-- --nocapture`). При ядре
`0.1.0` из 3 084 пар в 3 275 объявлениях 67 относятся к `kernel`, 2 516 —
к `flick`, 366 — к `host` и 135 — к `adapter`.

## Что сопоставляет бэкенд

Бэкенд находит встроенные сущности через `Program.lang` по их роли (см.
[Генерация кода](../codegen/)). Ядру нужны типы `unit`, `bool`, `int`,
`float`, `bigint`, типы фиксированной ширины от `int8` до `uint64` и
`float32`, `string`, `list` и `ref`; конструкторы `some`, `none`, `ok` и
`err` и `Ordering` прелюдии (`LT`, `EQ`, `GT`); и классы `eq`, `ord`,
`hash` и `show`, экземпляры которых для записей и кортежей бэкенд выводит
из хуков ниже.

Операции IR тоже примитивны: арифметика на каждом числовом типе (`Binary`
с `Arith` и `Num`), `==` и `!=` (структурные; SameValueZero на числах с
плавающей точкой), `===`, сравнения, `++` на строках и на списках, `-` и
`not`, литералы всех типов, а также кортежи, списки, записи и конструкторы
с их полями, обновлениями и образцами.

## Ядро данных

### Числа

Арифметика, деление на ноль, переполнение по модулю, `**` и преобразования
следуют
[числовой политике](https://github.com/bondiano/flick-lang/blob/main/docs/backends/numeric-policy.md).
Привязки:

| Привязка | В стандартной библиотеке | Что делает |
| - | - | - |
| `global Number` | `Int.to_float`, `BigInt.to_number` | `Int` — точно; `BigInt` — с округлением до ближайшего `Float`, при равенстве к чётному |
| `global BigInt` | `into : Int -> BigInt` | точно |
| `global String` | `BigInt.to_string` | десятичные цифры, `-` у отрицательного числа, без суффикса |
| `global Math.floor`, `Math.sqrt` | `Float.floor`, `Float.sqrt` | IEEE 754: `-0` остаётся `-0`, NaN остаётся NaN, `sqrt (-1)` — NaN |
| `stringFromNumber` | `Int.to_string`, `Float.to_string` | `Int` — в десятичной записи; `Float` — так, как его пишет `show` |
| `stringToNumber` | `String.to_number` | JS `Number` от текста без пробельных символов JS по краям: десятичная запись, `0x`, `0o`, `0b`, `Infinity`; пустой или некорректный текст — `None`, `NaN` — `Some NaN` |
| `showInt64`, `showUInt64` | `show` у `Int64`, `UInt64` | в десятичной записи, без суффикса |
| `intTruncate` | `Int.truncate` | целая часть по модулю 2^32; NaN и бесконечности дают `0` |
| `bigintFromNumber` | `BigInt.from_number` | `Some` для конечного целого `Float`, `-0` даёт `0n` |
| `toInt8` … `toUInt64`, `toBigInt`, `toFloat32`, `toFloat64` | `wrapping_from_*`, `to_*`, `into` | по модулю ширины, точно в `BigInt`, с одним округлением до binary32 или binary64 |
| `bitAnd`, `bitOr`, `bitXor`, `bitNot`, `shiftLeft`, `shiftRight`, `shiftRightUnsignedInt` | `Int.bit_*`, `Int.shift_*` | на 32-битном дополнительном коде; счётчик берётся по маске 5 бит; `shift_right` сохраняет знак, `shift_right_unsigned` заполняет нулями и читает свои биты обратно как `Int` |
| `int64BitAnd` … `int64ShiftRightUnsigned` | `Int64.bit_*`, `Int64.shift_*` | то же на 64 битах, счётчик по маске 6 бит |

Все эти привязки — из `flick:rt`, кроме `global`. `Float` записывается так,
как JS записывает число: кратчайшими цифрами, которые читаются обратно, с
экспонентой начиная с `1e21` и ниже `1e-6`, `-0`, `NaN`, `Infinity` и
`-Infinity`.

### Строки

Строка — это последовательность кодовых единиц UTF-16, и каждая длина и
каждый индекс считают кодовые единицы, как в JS. Скалярное значение вне BMP
занимает две единицы; срез может его разрезать, его половины — одиночные
суррогаты, и они снова соединяются в него. NUL — единица, как любая другая.
UTF-8 — то, что несут байты, входящие в хост и выходящие из него.

| Привязка | В стандартной библиотеке | Что делает |
| - | - | - |
| `flick:String length` | `String.length` | число кодовых единиц |
| `flick:String charCodeAt` | `String.char_code_at` | единица по индексу, `None` вне строки |
| `flick:String slice` | `String.slice` | JS `slice`: отрицательный индекс отсчитывается от конца, индекс за концом — это конец, обратный диапазон пуст |
| `flick:String indexOf`, `lastIndexOf` | `String.index_of`, `String.last_index_of` | индекс в единицах первого или последнего вхождения при сравнении единиц, так что одиночный суррогат находит половину пары; пустая строка — на `0` или на длине |
| `flick:rt bytesFromList`, `bytesToList` | `Bytes.from_list`, `Bytes.to_list` | упакованные байты списка, `Err` с индексом и значением первого вне `0..255` |
| `flick:rt bytesEncodeUtf8` | `Bytes.encode_utf8` | UTF-8, одиночный суррогат — как U+FFFD |
| `flick:rt bytesDecodeUtf8` | `Bytes.decode_utf8` | строгий UTF-8: некорректные, избыточные и суррогатные последовательности дают `None`; метка порядка байтов остаётся |

Вместе с ними `++` соединяет строки, `==` и сравнения идут по кодовым
единицам, а `show` заключает строку в кавычки.

### Массивы

`List` — неизменяемый массив. `listLength` — его длина, `listGet` —
элемент по индексу (`None` вне списка, в том числе при отрицательном
индексе), а `listInitialize` строит `[f 0, …, f (n - 1)]`, вызывая `f` в
этом порядке; `n <= 0` даёт `[]`. Литералы, `++` и образцы — операции IR.

### Изменяемые ячейки

`refMake`, `refGet` и `refSet` создают, читают и пишут ячейку; `refSame` —
одна ли это ячейка. `refModify` — один шаг, который ни один другой файбер
не видит наполовину выполненным: R7
[контракта среды выполнения](https://github.com/bondiano/flick-lang/blob/main/docs/formal/runtime.md).

### Строки записей

`recordGet`, `recordExtend` и `recordRemove` читают, добавляют и удаляют
поле по метке, которую создаёт `recordLabel`; `recordProject` сужает запись
до типа с меньшим числом полей, `recordMergeDisjoint` объединяет две записи
с непересекающимися метками, а `recordLabels` перечисляет метки по порядку.

### Хуки встроенных классов

Встроенные экземпляры `Eq`, `Ord`, `Hash` и `Show` на примитивных значениях
вызывают `equals`, `compare`, `hash` и `show` из `flick:rt`:

- `equals` — SameValueZero на числах с плавающей точкой (NaN равен NaN,
  `-0` равен `0`), строки сравнивает по кодовым единицам;
- `compare` полон: NaN больше любого числа с плавающей точкой, `-0` равен
  `0`, строки идут по кодовым единицам, а не по кодовым точкам, а `false`
  идёт раньше `true`;
- `hash` согласован с `equals`; его значения у каждой среды выполнения свои;
- `show` записывает значение как литерал JS: строку — в кавычках, как
  `JSON.stringify`, одиночный суррогат — экранированием `\u` в нижнем
  регистре, `BigInt` — с его `n`, `Float` — как выше, `Ordering` — по его
  конструктору.

## Ядро управления

Три примитива, поверх которых строится среда выполнения файберов. Каждый
бэкенд реализует их по-своему; таблица называет реализации нынешних сред
выполнения.

| Примитив | В стандартной библиотеке | JS (`runtime/src/rt`) | Go (`runtime-go/flickrt`) |
| - | - | - | - |
| приостановить файбер и один раз возобновить его | `Effect.never` приостанавливает его так, что возобновить его нечему; на обоих построены `Deferred` и `Fiber.join` | инструкция `Suspend` (`fiber.ts`): её запуск получает функции, возобновляющие файбер, и возвращает то, что отменяет ожидание | `wait` (`fiber.go`): файбер блокируется, пока не закроется канал или его не прервут |
| таймер | `Effect.sleep` | `clock().timer`, который возвращает свою отмену (`duration.ts`) | `clockOf(fb).timer`: канал и его отмена (`concurrency.go`) |
| ход цикла событий хоста | `Effect.yield_now` и корневой раннер, который выполняет `main` до конца | `schedule` (`fiber.ts`) и `runMain` (`entry.ts`) | `runtime.Gosched` в `EffectYieldNow` и `Main` (`platform.go`) |

Привязки — `sleep`, `flickNever` и `flickYieldNow` из `flick:Effect`.
Неположительная задержка уступает ход; бесконечная никогда не возобновляет
файбер; прерывание ожидающего файбера завершает его ожидание и отменяет его
таймер, так что цикл событий хоста его не ждёт. То, что построено поверх
ядра управления, сохраняет законы R1–R9 контракта среды выполнения.

## Соответствие

- `tests/kernel` содержит случай для каждого примитива с ожидаемым
  значением, выведенным из контракта, а не из того, что даёт другой бэкенд.
  `just kernel` запускает его на JS, в обеих средах выполнения, как
  исполняемый файл Go и в общей тир-независимой библиотеке примитивов
  `flick-vm` (`flick_vm::stdlib`), в debug и release; затем он запускает
  модули `tests/language`, перечисленные в `tests/kernel/language.txt`,
  которые закрепляют ещё часть числовых и строковых примитивов (`just language`
  запускает их в debug; `just kernel` — в release на JS и Go, а на `flick-vm` —
  в debug и release с проверкой нулевых утечек кучи).
- Случаи ядра управления — это случаи `tests/run/runtime`, которые
  запускает `just conformance`; `control_kernel` проверяет задержки,
  порядок таймеров, ожидание, которое завершает только прерывание, и
  отменённый таймер.
- Случай `kernel` тестового бэкенда `test/literal` — это бэкенд, у которого
  нет ничего, кроме ядра. Он выполняет чистые тесты тестового корня в
  переносимом вычислителе только с примитивами ядра, а раннер тестов
  сообщает их результаты. Тест из `tests/kernel`, который достигает привязки
  вне ядра, проваливает свою сборку. Тестовый бэкенд пропускает тесты
  эффектов и тесты, которые достигают `listInitialize`, ячейки, строки
  записи или ядра управления, — их вычислитель выполнить не может, — а из
  перечисленных модулей `tests/language` выполняет только тесты, которые
  достигают одного лишь ядра.

- Бэкенд Lua запускает модули `tests/kernel` и `tests/language`,
  перечисленные в их `lua.txt`, через `flick test --target lua` на Lua 5.1.5 и на
  LuaJIT 2.1 с включённым и выключенным JIT (`just kernel-lua`); каждый тест
  должен дать тот же результат, что на тех же модулях на JS, кроме эффектного:
  его раннер Lua сообщает пропущенным с причиной
  `an effect test needs the Lua runtime`, пока его не исполнит рантайм Lua.
  Список растёт вместе с ядром Lua.

Новый бэкенд запускает `flick test --target <backend>` в `tests/kernel` и
случаи `tests/run/runtime`; оба должны пройти, прежде чем он объявит
`flick.kernel`.
