## Языковой сервер

`flick lsp --stdio` запускает языковой сервер. В stdout он передаёт только
сообщения протокола, а журналы пишет в stderr. Сервер выполняет тот же анализ,
что `flick check` и `flick build`, для проекта, которому принадлежит документ
(ближайший `flick.toml`). При анализе вместо файлов используются открытые буферы.

Подсказки и навигация учитывают несохранённые изменения открытых импортируемых
модулей, в том числе отдельных файлов без `flick.toml`. После закрытия буфера
зависимые запросы снова используют версию модуля с диска.

| Запрос | Ответ |
| - | - |
| диагностика | в точности та же, что у `flick check`, с кодами `FLICK-` и позициями в UTF-16, публикуется при открытии и сохранении документа; строки help идут после сообщения, связанные места (откуда взялся ожидаемый тип) — в `relatedInformation`, неиспользуемый код помечен `Unnecessary` |
| `textDocument/hover` | сигнатуры из исходников и документация `///` для публичных и приватных значений в местах объявлений и использования; документация модуля при наведении на квалификаторы вроде `Sql`; выведенные типы локальных привязок и значений, псевдонимов SQL, столбцов и параметров, а также тип `ignore`; в объявлениях различаются `type error` и `service` |
| `textDocument/definition` | переходы между модулями: квалификаторы модулей ведут к заголовку модуля, члены — к своему объявлению; встроенные определения открываются как файлы `.fl` только для чтения; для установленных пакетов используются опубликованные `.fl`, а при их отсутствии — `.iface`; сопутствующие значения ведут к своему типу, методы классов при известном экземпляре класса — к этому экземпляру |
| `textDocument/references` | все вхождения в проекте |
| `textDocument/rename` | собственные значения, типы, конструкторы и локальные привязки проекта, только в исходниках `.fl`; имена встроенных модулей и пакетов, операции сервисов и методы экземпляров классов не имеют точного отображения, поэтому переименование для них отклоняется |
| `textDocument/completion` | у вариантов есть документация `///` и сниппет параметров функции, локальные имена идут первыми; значение из модуля, который файл не импортирует, предлагается как `Module.name` (встроенным модулям импорт не нужен, для модуля проекта добавляется `import`); после `x.` — поля записи, после `M.` — экспорты модуля или операции сервиса, в остальных случаях — имена в области видимости; в блоках SQL — таблицы, псевдонимы, столбцы, параметры, предложения и функции; для столбцов `sql table` — типы SQL из диалекта проекта, затем ещё не указанные совместимые модификаторы; после `as` — типы Flick; после `via` — доступные в области видимости кодеки, тип которых можно конкретизировать до `PureCodec` столбца, в том числе импортированные кодеки в виде `Module.codec` |
| `textDocument/codeAction` | быстрые исправления для диагностик, к которым есть правка: ближайшее имя вместо опечатки, удаление неиспользуемых импортов и определений, `_` для неиспользуемой переменной, недостающие ветки `match`, определение отсутствующей функции через `todo`, выведенный тип вместо дыры `_`; при `FLICK-T004` вставляет выведенную сигнатуру `name : T` прямо над `let`, сохраняя его отступ; сигнатура включает строки эффектов, переменные типов, ограничения классов и имена с квалификаторами, допустимыми при импортах модуля; если привязка не прошла проверку типов, исправление недоступно |
| `textDocument/codeAction` (рефакторинги) | добавить сигнатуру значения `let`; сопоставить с образцом переменную, которая стоит результатом блока; квалифицировать импортированное имя во всех местах или убрать квалификатор и импортировать имя; вынести выделенное выражение в `let`; встроить локальный `let` в его использования |
| `textDocument/formatting` | `flick fmt` |
| `textDocument/documentSymbol`, `workspace/symbol` | объявления, конструкторы и методы — под своим типом или классом; символы рабочей области подбираются по буквам запроса по порядку |
| `textDocument/signatureHelp` | в вызове `f a b` — сигнатура `f` с отмеченным аргументом, который сейчас пишется |
| `textDocument/typeDefinition` | объявление типа выражения под курсором |
| `textDocument/semanticTokens/full` | чем является каждое имя: модуль, тип, конструктор, функция, переменная, метод или параметр |
| `textDocument/foldingRange` | объявления, `match`, записи, списки, встроенные блоки и группа импортов |
| `textDocument/inlayHint` | тип каждого `let` без сигнатуры и каждой стадии конвейера, записанного в несколько строк |

Подсказки при наведении учитывают привязки в исходном коде, а не только
публичные экспорты. У приватных вспомогательных функций — например, функции
представления или обработчика сообщений об ошибках — тоже видны явно
написанные сигнатуры и документация. Для этого не нужно делать функции
публичными. При наведении на `ignore` сервер показывает тип функции,
отбрасывающей значение в этом месте (например, `Never -> Unit` вокруг
`Ui.Dom.mount`). Отбрасывание результата не отменяет эффекты и ошибки выражения.
[Справочник языкового сервера Gleam](https://gleam.run/documentation/language-server-reference/)
служит ориентиром для подсказок по символам и навигации; это не означает,
что возможности серверов полностью совпадают.

Для псевдонима типа подсказка показывает параметры и определение из исходника,
даже если псевдоним приватный. При наведении на имя в объявлении диапазон
подсказки включает параметры (`Planner a`); навигация и семантические токены
по-прежнему относятся к имени `Planner`. На метке поля внутри `codec` виден
тип декодированного поля записи — например, `email : Email` или
`nickname : Option String`, — а не тип кодека поля. Сигнатуры оформлены блоком
кода `flick` для синтаксической подсветки в редакторе.

При наведении на `sql table` подсказка показывает тип строки и тип
`Name$table` с исходным порядком столбцов. На имени она показывает тип строки
и таблицу SQL, на строке с именем таблицы — указанную таблицу, на типе SQL
столбца — соответствующий тип Flick в выбранном диалекте, на модификаторе,
`as` и `via` — их смысл.

Подсказки и автодополнение столбцов SQL учитывают допустимость `null`.
Столбец из `left_join` имеет тип `Option`, но если столбец уже допускает
`null`, второй `Option` не добавляется. У вложенных запросов собственные
псевдонимы таблиц.

Встроенные определения используют обычные URI `file://` и в Zed, и в VS Code.
Сервер сохраняет встроенные исходники в подкаталоге `flick-lsp` системного
временного каталога. Имя файла зависит от содержимого; файлы доступны только
для чтения. При открытии сервер проверяет их как исходники библиотеки
и не добавляет в проект приложения.

### Журналирование

LSP пишет журналы через `tracing-subscriber` в stderr: с временными метками
UTC и без ANSI-кодов. Уровень по умолчанию — `info`: запуск, завершение и ошибки.
Для подробностей о запросах и анализе:

```sh
RUST_LOG=flick::lsp=debug flick lsp --stdio
```

События `debug` содержат метод, ID запроса, URI и позицию в документе, время
обработки, сведения о повторном использовании анализа, количество модулей,
диагностик и вариантов автодополнения. Ошибки запросов включают код JSON-RPC.
При panic выводятся контекст активного запроса и backtrace, даже без
`RUST_BACKTRACE`. `RUST_LOG=off` отключает обычные журналы; для panic остаётся
стандартный отчёт Rust.

В Zed задайте `lsp.flick.binary.env` равным
`{ "RUST_LOG": "flick::lsp=debug" }`. В stdout остаётся только протокол.
Обычные события не содержат тела документов и полные RPC-пакеты, но сообщение
panic может включать фрагмент исходника: проверяйте журналы перед публикацией.

## Zed

Если задан `lsp.flick.binary.path`, расширение использует этот путь.
Иначе оно ищет `flick` в `PATH` рабочего дерева, а если не находит — загружает
из GitHub релиз с тегом `v<extension version>` для текущей платформы
в свой рабочий каталог. Установленная копия используется повторно.
Если релиз недоступен, расширение использует самую новую из ранее
загруженных версий.

Чтобы использовать локальную копию репозитория, выполните в ней `cargo build -p flick`
и добавьте в настройки Zed следующий фрагмент, указав абсолютный путь к своей копии:

```json
{
  "lsp": {
    "flick": {
      "binary": {
        "path": "/absolute/path/to/flick-lang/target/debug/flick",
        "arguments": ["lsp", "--stdio"]
      }
    }
  }
}
```

Явный путь отключает поиск и загрузку релиза, в том числе для приватного
репозитория или при отсутствии подходящего релиза. Если путь неверен,
запуск завершается ошибкой: расширение не переключается на другой
исполняемый файл. Параметр `binary.arguments` заменяет стандартные
аргументы `["lsp", "--stdio"]`, а `binary.env` переопределяет переменные
окружения оболочки рабочего дерева.

## Проекция TypeScript

Для редакторов TypeScript компилятор создаёт виртуальное представление
каждого модуля — например, `App/Main.flick.ts`. Оно содержит по одному
объявлению на экспорт, в том же виде TypeScript, что и при `--emit-dts`.
Тип, который нельзя так представить, заменяется на `unknown` с указанием
причины. Компилятор также создаёт карты соответствия диапазонов между этой
проекцией и исходником `.fl`. Для имён соответствие точное: текст с обеих
сторон одинаков. Для типов это не так. Переносить переименование между
языками можно только при точном соответствии.

Первая строка проекции содержит отпечаток анализа, по которому она создана.
Тот же анализ используется при компиляции исполняемой сборки.
Команда `flick inspect <module> --emit mapping` выводит проекцию
с её картами в JSON (версия формата 1).

## Content Mapper

TypeScript 7.1 проверяет `.ts` и `.tsx`, импортирующие модуль Flick, по
типам этого модуля через Content Mapper: `@flick-lang/content-mapper`
(`tools/content-mapper`) запускает `flick content-mapper` (`FLICK_BIN`,
иначе `flick` из PATH), и тот отвечает на каждый `.fl`, до которого дошёл
TypeScript, его проекцией, построенной по несохранённому тексту редактора.
Подключение в `tsconfig.json`:

```json
{
  "compilerOptions": { "module": "esnext", "moduleResolution": "bundler", "strict": true },
  "contentMappers": [{ "package": "@flick-lang/content-mapper", "extensions": [".fl"] }]
}
```

```ts
import { greet } from "./src/App/Greeting.fl";
greet(1); // error TS2345, как велит сигнатура Flick
```

Маппер — отдельная программа, поэтому `tsc` запускает его только с
`--runExternalCode`, а VS Code (с TypeScript 7.1) — только в доверенном
workspace; `js/ts.contentMappers.enabled` его отключает. Hover, переход к
определению и ссылки переходят из TypeScript в исходник `.fl` по картам
соответствия; переименование и исправления — только по точным, чтобы правка
никогда не переписала текст Flick через тип. Модули проекта импортируют
`.fl` друг друга, и маппер проецирует их тоже; у встроенных модулей и
модулей пакетов нет `.fl`-файла, поэтому их проекции записываются в
`.flick/projections` проекта. Маппер необязателен: `flick doctor` сравнивает
установленный TypeScript с проверенным релизом (7.1.0-beta), а проверка
типов Flick от маппера не зависит.
