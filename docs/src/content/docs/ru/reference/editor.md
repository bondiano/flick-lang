## Языковой сервер

`flick lsp --stdio` — языковой сервер. Его stdout содержит только протокол;
журналы идут в stderr. Он выполняет тот же анализ, что `flick check` и
`flick build`, для проекта, которому принадлежит документ (ближайший
`flick.toml`), подставляя открытые буферы вместо файлов.

| Запрос | Ответ |
| - | - |
| диагностика | в точности та же, что у `flick check`, с кодами `FLICK-` и позициями в UTF-16, публикуется при открытии и сохранении документа; строки help идут после сообщения, связанные места (откуда взялся ожидаемый тип) — в `relatedInformation`, неиспользуемый код помечен `Unnecessary` |
| `textDocument/hover` | сигнатуры из исходников и документация `///` для публичных и приватных значений, в местах объявлений и использования; документация модуля на квалификаторах вроде `Sql`; выведенные типы локальных привязок и значений, псевдонимов SQL, столбцов и параметров, а также тип `ignore`; объявления различают `type error` и `service` |
| `textDocument/definition` | переходы между модулями; квалификаторы модулей ведут к заголовку модуля, члены — к своему объявлению; встроенные определения открываются как настоящие файлы `.fl` только для чтения; для установленных пакетов используются опубликованные `.fl`, а при их отсутствии — `.iface`; сопутствующие значения ведут к своему типу, методы классов при известном экземпляре класса — к этому экземпляру |
| `textDocument/references` | все вхождения в проекте |
| `textDocument/rename` | собственные значения, типы, конструкторы и локальные привязки проекта, только в исходниках `.fl`; имена встроенных модулей и пакетов, операции сервисов и методы экземпляров классов не имеют точного отображения, поэтому переименование для них отклоняется |
| `textDocument/completion` | поля записи после `x.`, экспорты модуля или операции сервиса после `M.`, в остальных случаях — имена в области видимости; в блоках SQL предлагаются таблицы, псевдонимы, столбцы, параметры, предложения и функции; для столбцов `sql table` предлагаются типы SQL диалекта проекта, затем ещё не написанные и не противоречащие им модификаторы, после `as` — типы Flick, после `via` — кодеки из области видимости, тип которых конкретизируется до `PureCodec` столбца, импортированные — также как `Module.codec` |
| `textDocument/codeAction` | быстрые исправления диагностик, у которых есть правка: ближайшее имя вместо опечатки, удаление неиспользуемых импортов и определений, `_` для неиспользуемой переменной, недостающие ветки `match`, определение отсутствующей функции через `todo`, выведенный тип вместо дыры `_`; на `FLICK-T004` вставляет выведенную сигнатуру `name : T` прямо над `let` с его отступом, со строками эффектов, переменными типов, ограничениями классов и именами, квалифицированными так, как позволяют импорты модуля; для привязки, которую отверг checker, исправления нет |
| `textDocument/codeAction` (рефакторинги) | добавить сигнатуру значения `let`; сопоставить с образцом переменную, которая стоит результатом блока; квалифицировать импортированное имя во всех местах или убрать квалификатор и импортировать имя; вынести выделенное выражение в `let`; встроить локальный `let` в его использования |
| `textDocument/formatting` | `flick fmt` |
| `textDocument/documentSymbol`, `workspace/symbol` | объявления, конструкторы и методы — под своим типом или классом; символы рабочей области подбираются по буквам запроса по порядку |
| `textDocument/signatureHelp` | в вызове `f a b` — сигнатура `f` с отмеченным аргументом, который сейчас пишется |
| `textDocument/typeDefinition` | объявление типа выражения под курсором |
| `textDocument/semanticTokens/full` | чем является каждое имя: модуль, тип, конструктор, функция, переменная, метод или параметр |
| `textDocument/foldingRange` | объявления, `match`, записи, списки, встроенные блоки и группа импортов |
| `textDocument/inlayHint` | тип каждого `let` без сигнатуры и каждой стадии конвейера, записанного в несколько строк |

Подсказки при наведении разрешают привязки исходного кода, а не только список
публичных экспортов. Приватные вспомогательные функции, например представление
или обработчик сообщений об ошибках, показывают явно написанные сигнатуры и
документацию, не становясь публичными. Ключевое слово `ignore` показывает тип
отбрасывания в данном месте использования (например, `Never -> Unit` вокруг
`Ui.Dom.run`); отбрасывание результата не отбрасывает эффекты или ошибки выражения.
[Справочник языкового сервера Gleam](https://gleam.run/documentation/language-server-reference/)
служит образцом поведения для подсказок по символам и навигации, а не заявлением
о полном совпадении возможностей.

Подсказка на `sql table` показывает тип строки и тип `Name$table` в порядке
столбцов; на имени — тип строки и таблицу SQL; на строке с именем таблицы —
таблицу, которую она называет; на типе SQL столбца — тип Flick, который даёт
ему диалект; на модификаторе, `as` и `via` — их смысл.

Подсказки и автодополнение столбцов SQL сохраняют допустимость `null`: столбец
из `left_join` имеет тип `Option`, причём уже допускающему `null` столбцу не
добавляется второй `Option`. Вложенные запросы имеют собственные псевдонимы таблиц.

Встроенные определения используют обычные URI `file://` и в Zed, и в VS Code.
Сервер сохраняет встроенные исходники в подкаталоге `flick-lsp` системного
временного каталога, адресуя их по содержимому и делая доступными только для
чтения. При открытии они проверяются как исходники библиотеки, без добавления
в проект приложения.

## Zed

Расширение сначала использует `lsp.flick.binary.path`, если этот параметр задан,
затем `flick` из `PATH` рабочего дерева. Иначе оно загружает релиз GitHub с тегом
`v<extension version>` для текущей платформы в свой рабочий каталог.
Установленная копия используется повторно; если релиз недоступен, используется
самая новая из ранее загруженных версий.

Чтобы использовать локальную копию репозитория, выполните в ней `cargo build -p flick`
и добавьте в настройки Zed следующее, заменив путь абсолютным путём к своей копии:

```json
{
  "lsp": {
    "flick": {
      "binary": {
        "path": "/absolute/path/to/flick-lang/target/debug/flick",
        "arguments": ["lsp", "--stdio"]
      }
    }
  }
}
```

Явный путь отключает поиск и загрузку релиза, в том числе если репозиторий
приватный или подходящего релиза нет. Если явный путь неверен, запуск завершается
ошибкой, а не молча переключается на другой исполняемый файл.
`binary.arguments` заменяет стандартные аргументы `["lsp", "--stdio"]`;
`binary.env` переопределяет переменные окружения оболочки рабочего дерева.

## Проекция TypeScript

Для редакторов TypeScript компилятор проецирует каждый модуль в виртуальный
`App/Main.flick.ts`: по одному объявлению на каждый экспорт, в том же виде
TypeScript, что и при `--emit-dts` (тип без такого представления становится
`unknown` с указанием причины), а также карты диапазонов между проекцией и
исходником `.fl`. Имя отображается точно (одинаковый текст с обеих сторон),
тип — нет; только точное отображение позволяет переносить переименование
между языками. Первая строка указывает отпечаток анализа, из которого получена
проекция; этот же анализ используется при компиляции исполняемой сборки.
`flick inspect <module> --emit mapping` выводит проекцию с её картами в JSON
(версия формата 1).

## Content Mapper

`tools/content-mapper` адаптирует проекцию для typescript-go через API
TypeScript 7; работа проверена с TypeScript 7.0.2: он предоставляет проекции
как виртуальную файловую систему и отображает позиции в обе стороны, чтобы
TypeScript отвечал исходя из видимой ему части модуля Flick. Это необязательный
компонент: `flick doctor` сообщает о нём, а проверяющий модуль Flick никогда
от него не зависит.
