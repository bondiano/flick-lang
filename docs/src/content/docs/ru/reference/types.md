После разрешения имён компилятор проверяет типы в каждом модуле без
синтаксических ошибок (см. [Значения вычислений и их выполнение](../../spec/02-computations/),
[Типовое ядро HKT и классы типов](../../spec/03-types-and-classes/),
[Schema и стандартные типы данных](../../spec/07-schema/)).
Для проверки используются только интерфейсы других модулей, а не их
исходный код ([интерфейсы модулей](../iface/)).

## Встроенные типы

Встроенные типы объявлены в `Prelude`. Его имена доступны в каждом модуле
без импорта; локальное определение с тем же именем затеняет имя из `Prelude`.

| Тип | Кинд |
| - | - |
| `Unit`, `Never`, `Bool`, `Int`, `Float`, `BigInt`, `String`, `Unknown`, `Ordering` | `Type` |
| `List`, `Option`, `Ref`, `Redacted`, `Schema` | `Type -> Type` |
| `Result`, `PureCodec` | `Type -> Type -> Type` |
| `ServiceTag`, `ServiceImpl` | `ServiceRow -> Type` |
| `Scope` (сервис) | `Region -> Service` |
| `Eff` | `ServiceRow -> ErrorRow -> Type -> Type` |
| `Layer` | `ServiceRow -> ErrorRow -> ServiceRow -> Type` |
| `Codec` | `ServiceRow -> ServiceRow -> Type -> Type -> Type` |
| `Errors` | `ErrorRow -> Type` |

`Option a = None | Some a`, `Result e a = Err e | Ok a` и
`type error AppError = AppError { message : String; details : Option String }` —
обычные объявления, а `identity : a -> a` — функция. `from_result` переносит
ошибку из `Result` в строку ожидаемых ошибок ([эффекты](../effects/)).
Имена встроенных модулей можно использовать с квалификатором без импорта:
`Ref.make`, `Ref.get`, `Ref.set`, `Ref.modify`, `String.trim`,
`Platform.stdout_line`, `Platform.stderr_line`, `App.fail`, `Layer.succeed`,
`Layer.merge`, `Layer.override`, примитивы строк модуля `Record`
и `Fiber.spawn` с типами `Fiber.Owner`, `Fiber.Fiber` и `Failure`
([регионы](../regions/)). Классы `Eq`, `Ord`, `Hash` и `Show` тоже объявлены
в `Prelude` ([классы](../classes/)).

## Кинды

Кинд — тип самого типа. В Flick есть кинды `Type`, `ServiceRow`, `ErrorRow`,
`CaptureRow`, `Row k` (`Row Type` — кинд строки полей записи), `Symbol`,
`Region`, `Constraint`, конечные кинды из объявлений `kind` и стрелки
между киндами.

Кинд параметра типа можно указать явно. Иначе он выводится из того,
как используется параметр; если данных для вывода нет, выбирается `Type`.
Кинды параметров всех объявлений модуля выводятся совместно, поэтому
объявления могут ссылаться друг на друга в любом порядке.

```flick
type alias Box (f : Type -> Type) a = { value : f a }

kind Nullability = NonNull | Nullable

type Js (n : Nullability) a
```

Строки здесь — наборы элементов на уровне типов, а не значения `String`.
Три кинда строк эффектов не смешиваются: строка сервисов содержит сервисы,
строка ошибок — типы, объявленные с `error`, строка захватов — регионы.
`none` обозначает пустую строку любого кинда строк, а не тип.
`Eff Unit Unit a`, `Option` без аргумента и `Float String` вызывают `FLICK-T002`.

## Сигнатуры

У каждой именованной функции верхнего уровня должна быть полная сигнатура
(см. [Прямые эффектные вызовы](../../spec/01-direct-calls/)).
Её записывают непосредственно над `let`, в том числе для функции, созданной
частичным применением. Локальная функция может обойтись без сигнатуры: компилятор
выводит для неё мономорфный тип, поэтому вызов с другим типом вызывает `FLICK-T003`.
Рекурсивной локальной функции сигнатура нужна. Метод экземпляра берёт сигнатуру из класса; её повторение — `FLICK-T059`.
Функция верхнего уровня без сигнатуры вызывает `FLICK-T004`; сообщение предлагает выведенный
тип. Типы в заголовке `let` вызывают `FLICK-T005`, а сигнатура без определения
непосредственно под ней — `FLICK-T006`. Значениям, которые не являются
функциями, сигнатура не нужна. Локальное `let x : T = …` задаёт подсказку типа.

При редактировании `todo` может заменять всю сигнатуру или её часть. Пока
`todo` не заменён, это ошибка: проверка и сборка не пройдут. Редактор предлагает
выведенный тип, если может проверить готовую сигнатуру. В отличие от `_`,
`todo` в типе никогда не бывает только предупреждением.

Новые переменные типа квантифицируются по всей сигнатуре, а их кинды
выводятся. В теле определения то же имя во вложенной сигнатуре
обозначает тот же тип:

```flick
compose : (b -> c) -> (a -> b) -> a -> c
let compose f g x =
  apply : (a -> b) -> b
  let apply h = h x
  f (apply g)
```

Реализация функции должна подходить для любого типа, который может выбрать
вызывающий код. Если она требует конкретного типа, возникает `FLICK-T008`.

`_` в сигнатуре или аннотации — дыра: чекер выводит эту часть типа и сообщает её
(`FLICK-T024`) с исправлением, которое вписывает выведенный тип. Дыра нужна для
черновика; в объявлении типа её быть не может.

```flick
swap : (Float, String) -> _
let swap (a, b) = (b, a)
```

## Функции и высшие ранги

Чистая стрелка `a -> b` отличается от эффектных `a ->{r; e} b` и `a ->{} b`.
Пустые строки не делают эффектную стрелку чистой
(см. [Значения вычислений и их выполнение](../../spec/02-computations/)).
При проверке лямбды компилятор использует стрелки ожидаемого типа.
Требования вызовов в теле и условия, при которых допустим эффектный вызов,
описаны в разделе [об эффектах](../effects/).

`forall` можно записать внутри типа в сигнатуре. В этом случае аргумент
проверяется по сигнатуре, и одну переданную функцию можно использовать
с несколькими типами:

```flick
apply_twice :
  (forall a. a -> a) -> (Float, String)
let apply_twice transform =
  (transform 42, transform "hello")
```

Инстанцирование предикативно: переменная типа не может обозначать
полиморфный тип. Переменная, связанная `forall`, не должна выходить за его
пределы. Например, её нельзя сохранить в типе ячейки, созданной вне
переданной функции (`FLICK-T007`).

## Записи

Записи структурные: их совместимость определяется полями
(см. [Типовое ядро HKT и классы типов](../../spec/03-types-and-classes/)).
`type alias User = { … }` — прозрачный псевдоним; порядок полей не имеет
значения. При этом типы записей точные: запись с дополнительными полями
не подходит для закрытого типа. Чтобы принимать дополнительные поля,
используйте открытую строку:

```flick
name : forall fields. { name : String | fields } -> String
let name value = value.name
```

`{ r with f = v }` заменяет значения существующих полей, сохраняя их типы.
Повтор одной метки в типе записи, литерале, обновлении или образце
вызывает `FLICK-T014`.

## Образцы

`match` должен охватывать все значения. Ошибка `FLICK-T009` показывает
значение, которому не соответствует ни одна ветвь. Ветви с условием
`when` не учитываются при проверке полноты. Для ветви, которая никогда
не выполнится, выдаётся предупреждение `FLICK-T010`. Число аргументов
в образце конструктора должно совпадать с числом его полей (`FLICK-T018`).
Образцы в `let` и параметрах функций должны соответствовать всем значениям.
В образце записи можно указать только часть её полей.

Образец списка `[a, b]` подходит только спискам этой длины, а `[a, b, ...rest]`
— спискам не короче, поэтому `[] | [x, ...rest]` охватывает любой список.
Длина списка заранее не известна, поэтому образец списка в `let` — ошибка,
если это не `[...all]`: используйте `match` или кортеж, если длина фиксирована.
Ошибка локального `let` предлагает оба варианта как исправления: `match`
переносит остаток блока в ветвь образца и добавляет ветви `-> todo` для
непокрытых значений.

`let assert p = e` связывает `p`, если значение подходит, а иначе завершается
с ошибкой, как `todo`, указав место, сообщение из `as "…"` и значение:
`let assert [x, ..._] = xs as "no items"`. Он пишется в блоке, а не на верхнем
уровне модуля (`FLICK-T026`); с образцом, подходящим всем значениям, это
предупреждение `FLICK-T025`. `[lint] no-let-assert` в `flick.toml` делает
каждый `let assert` ошибкой (`FLICK-T027`).

## GADT

Конструктор может назвать после `:` тип, который он строит. Его переменные
типов — собственные, а те переменные полей, которых нет в результате,
экзистенциальные: значение скрывает их типы. Конструктор без `: R` строит
`T a…`, как обычно, и в одном типе можно смешивать оба вида. На странице
[GADT](../gadts/) всё это разобрано на примерах.

```flick
type Expr a =
  | IntLit Int : Expr Int
  | BoolLit Bool : Expr Bool
  | Add (Expr Int) (Expr Int) : Expr Int
  | If (Expr Bool) (Expr a) (Expr a) : Expr a
  | Apply (Expr (b -> a)) (Expr b) : Expr a
  | Lit a

eval : forall a. Expr a -> a
let rec eval e =
  match e with
  | IntLit n -> n
  | BoolLit b -> b
  | Add x y -> eval x + eval y
  | If c t f -> if eval c then eval t else eval f
  | Apply f x -> (eval f) (eval x)
  | Lit x -> x
```

Ветвь узнаёт, какого типа сопоставляемое значение: в ветви `IntLit` `a` — это
`Int`, поэтому `n` годится как результат типа `a`, а редактор показывает там
значение типа `a` как `Int (= a)`. Результат конструктора — его собственный
тип, применённый ко всем параметрам типа (`FLICK-T056`). Аргумент — тип, член
`kind` или `Symbol`; параметры регионов, строк и захватов передаются как
переменные.

`match` не требует ветви для конструктора, который не строит значений
сопоставляемого типа, а ветвь для него — предупреждение `FLICK-T010`:

```flick
# type Expr a =
#   | IntLit Int : Expr Int
#   | BoolLit Bool : Expr Bool
#   | Add (Expr Int) (Expr Int) : Expr Int
size : Expr Int -> Int
let rec size e =
  match e with
  | IntLit _ -> 1
  | Add x y -> size x + size y
```

То, что сообщает один конструктор, верно для всего сопоставляемого значения: для
`(x, y)` типа `(Ty a, Ty a)` пара разных конструкторов `Ty` не требует ветви. Тип,
который конструктор скрывает, не прослеживается.

Проверка учитывает то, что узнала ветвь, только там, где типы известны
(`FLICK-T057`): у функции полная сигнатура, тип сопоставляемого значения
известен в месте сопоставления, и ничто снаружи ветви не получает свой тип из
того, что она узнала; такому типу нужна аннотация. `let` внутри ветви не
обобщается. Экзистенциальный тип не может покинуть свою ветвь (`FLICK-T007`).
То, что держит поле, держит и значение, поэтому ресурс области, спрятанный в
значении, тоже не выйдет из неё. Уточняет и скрывает типы только ветвь
`match`: образец `let`, параметра или альтернатива or-образца этого не
делают, и ни одна ветвь не узнаёт, что два региона или два ряда совпадают
(`FLICK-T058`).

`TypeEq a b` из core-модуля `TypeEq` — свидетельство того, что два типа
совпадают: `Refl : TypeEq a a` и `TypeEq.cast : TypeEq a b -> a -> b`.

```flick
import TypeEq exposing (TypeEq(..))

type Ty a =
  | TInt : Ty Int
  | TStr : Ty String

equal_types : forall a b. Ty a -> Ty b -> Option (TypeEq a b)
let equal_types a b =
  match (a, b) with
  | (TInt, TInt) -> Some Refl
  | (TStr, TStr) -> Some Refl
  | _ -> None

coerce : forall a b. Ty a -> Ty b -> a -> Option b
let coerce a b x =
  match equal_types a b with
  | Some eq -> Some (TypeEq.cast eq x)
  | None -> None
```

В TypeScript уточнения нет: в `.d.ts` каждый конструктор GADT — вариант любого
экземпляра своего типа, а скрытый им тип — `unknown`.

## Числа и операторы

Неявных преобразований нет (см. [Schema и стандартные типы данных](../../spec/07-schema/)).

| Операторы | Операнды | Результат |
| - | - | - |
| `+ - * / % **`, префиксный `-` | оба `Int`, оба `Float` или оба `BigInt` | тот же тип |
| `++` | оба `String` или оба `List a` | тот же тип |
| `< <= > >=` | оба `Int`, `Float`, `BigInt` или `String` | `Bool` |
| `== !=` | одного типа | `Bool` |
| `&& \|\|`, `not` | `Bool` | `Bool` |
| `x \|> f` | `f x` | результат `f` |

`1.5 + 1n` и `"a" ++ 1` вызывают `FLICK-T003`. Если тип операнда не следует
из других условий, выбирается `Int`, а для `++` — `String`. Диапазоны `a..b`,
`a..<b` и `a..` считают в `Int`.

Числовых типов три, неявных преобразований между ними нет:

| Тип | Значения | Арифметика |
| - | - | - |
| `Int` | 32-битные целые со знаком | по модулю 2³²: `2147483647 + 1 == -2147483648`; `/` отбрасывает дробную часть (`7 / 2 == 3`, `-7 / 2 == -3`); `/` и `%` на ноль дают `0` |
| `Float` | IEEE 754 binary64, число JS | `0.0 / 0.0` — NaN, `1.0 / 0.0` — `Infinity`; `==` — SameValueZero |
| `BigInt` | целые любого размера | `/` отбрасывает дробную часть; `/` и `%` на ноль дают `0n` |

Правила одинаковы на любом бэкенде. `Int.checked_add`, `Int.checked_div` и
остальные проверяемые операции возвращают `Result Int.ArithmeticError Int`
вместо переполнения или нуля; `Int.unsafe_div` и `Int.unsafe_rem` при нулевом
делителе дают дефект. Преобразования: `Int.to_float`, `Int.from_float`
(`None`, если число не целое или вне диапазона) и `Int.truncate`.

Целочисленный литерал (`3`, `0xFF`, `1_000`) получает тот числовой тип,
которого требует его использование, а если ничто не требует — `Int`:
`let ratio : Float = 3` и `3 + 0.5` дают `Float`, `3 + 4n` — `BigInt`.
Литерал с дробной частью или экспонентой (`3.0`, `1e3`) — `Float`. Литерал
вне диапазона своего типа вызывает `FLICK-T003`. Если тип литерала решает
только ограничение класса, берётся первый из `Int`, `Float`, `BigInt`, для
которого есть подходящий инстанс.

Одна функция для всех числовых типов пишется через закрытые классы модуля
`Numeric`: `Numeric a` (`Int`, `Float`, `BigInt`), `Integer a` (`Int`,
`BigInt`) и `Floating a` (`Float`). На переменной типа с таким ограничением
операторы и целочисленные литералы используют его методы (`add`, `div`,
`from_int`, …); литералу с дробной частью нужен `Floating`. Все инстансы
объявлены в самом модуле, программа не может объявить свой (`FLICK-C012`).

```flick
import Numeric exposing (Floating, Numeric)

square : Numeric a => a -> a
let square x = x * x

mean : Floating a => List a -> a
let mean xs = List.sum xs / Numeric.from_int (List.length xs)
```

`List.sum` и `List.product` принимают любой `Numeric`. Без ограничения
`x + 1` на переменной типа вызывает `FLICK-C001`. `< <= > >=` на переменной
типа с числовым классом используют его `lt`, `le`, `gt`, `ge` и значат то же,
что эти операторы на её типе (NaN не упорядочен); если есть только `Ord a`,
сравнение идёт через `compare`.

Счётчики, размеры, индексы, хэши и части даты во всей стандартной
библиотеке — `Int` (`List.length`, `HashMap.size`, `Hash.hash`,
`Queue.size`, `Schedule.recurs`, части `DateTime`); миллисекунды, эпохи,
размеры в байтах и измерения остаются `Float`: в 32 бита они не помещаются.

## Блоки

Все инструкции блока, кроме последней, должны иметь тип `Unit`.
Отбросить другое значение можно только с помощью `ignore`; иначе
возникает `FLICK-T011` с предложением этого исправления. Последняя инструкция
должна быть выражением: её значение становится значением блока (`FLICK-T019`).

## Переменные

`let mut name = value` объявляет переменную функции, в блоке которой стоит, а
`name = value` — инструкция типа `Unit` — присваивает ей значение. Чтение видит
последнее значение, присвоенное до него; значение, прочитанное раньше, остаётся
прежним.

```flick
clamp : Int -> Int -> Int -> Int
let clamp low high n =
  let mut value = n
  if value < low then value = low
  if value > high then value = high
  value
```

У переменной один тип, заданный там, где она объявлена, — сигнатурой или
значением; он не обобщается, и присваиваемое значение проверяется по нему
(`FLICK-T003`). Присваивание — не вызов среды выполнения: чистая функция может
присваивать своим переменным. Переменной бывает только имя одного `let mut` в
блоке: не определение модуля, не функция, не образец, не `let assert` и не
привязка `do` или `for` (`FLICK-S016`). Параметру, обычному `let` и определению
модуля присвоить нельзя (`FLICK-T060`; для обычного `let` исправление добавляет
`mut`); `mut`, которому ничего не присваивается, — предупреждение `FLICK-R017`,
исправление его убирает.

Переменная принадлежит своей функции. `fun`, локальная функция, `task`, ленивый
`for`, продолжение блока `do` или ветвь обработчика операций внутри неё могут
выполниться позже, повторно или одновременно, поэтому ни одна из них не читает
переменную и не присваивает ей (`FLICK-G005`): снаружи функция остаётся чистой.
Свяжите значение через `let` и используйте это имя. `scope`, `provide`, ветвь и
вариант `match` или `try` выполняются на месте и присваивать могут. Тело
`try … with`, `for … do` и `[for …]` пока не присваивает переменной, объявленной
снаружи (`FLICK-T061`); присвойте значение всего `try` или присваивайте в одной
из его ветвей. Внутри `scope` переменная снаружи не может получить то, чем владеет
область, как и `Ref` (см. [Регионы](../regions/)).

## Рекурсия

Объявления верхнего уровня могут ссылаться друг на друга в любом порядке,
но рекурсию нужно указывать явно. Функция, которая вызывает себя, объявляется
через `let rec`, а взаимно рекурсивные функции — в одной группе `rec { … }`
(`FLICK-T017`). Рекурсивными могут быть только функции. Если для определения
значения нужно сначала вычислить его само, возникает `FLICK-T012`.

Рекурсивная функция может вызывать себя с другим типом, только если её
сигнатура начинается с `forall`, связывающего все её переменные типа.
Иначе такой вызов вызывает `FLICK-T015`. Члены группы `rec` вызывают друг
друга со своими типами и без `forall`, как бы ни назывались их переменные:
`odd_len` типа `List b -> Bool`, вызванная из `even_len` типа
`List a -> Bool` на `List a`, — это тот же тип.

```flick
type Nested a = Flat a | Nest (Nested (List a))

depth : forall a. Nested a -> Float
let rec depth value =
  match value with
  | Flat _ -> 0
  | Nest inner -> 1 + depth inner
```

## Обобщение

Тип значения можно обобщить только при чистом определении: во время
определения не должен выполняться ни один эффектный вызов
(см. [Обобщение при наличии Ref](../../spec/03-types-and-classes/#обобщение-при-наличии-ref)).
Создание лямбды или `task` чистое: их тела выполняются позже.
Полиморфная сигнатура, аннотация или аргумент высшего ранга для результата
эффектного вызова вызывают `FLICK-T013`.
Та же ошибка возникает для значения верхнего уровня, тип которого остаётся
неизвестным. Переменные типа из внешней сигнатуры или уже доступного значения
не обобщаются. Изменяемые контейнеры инвариантны. Строка вызовов, ещё
неизвестная при обобщении привязки, становится `none`, как в конце объявления
([эффекты](../effects/)), и не квантифицируется.

```flick
make_empty : forall a. Unit ->{} Ref (Option a)
let make_empty () =
  Ref.make None

fresh_cell : forall a. Eff none none (Ref (Option a))
let fresh_cell =
  task { Ref.make None }
```

Подробнее о классах и их экземплярах — в разделе [классы](../classes/).
