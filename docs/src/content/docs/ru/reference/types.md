Проверка типов выполняется после разрешения имён для каждого модуля без
синтаксических ошибок (см. [Значения вычислений и их выполнение](../../spec/04-computations/), [Типовое ядро HKT и классы типов](../../spec/05-types-and-classes/), [Schema и стандартные типы данных](../../spec/09-schema/)). О других модулях она знает только через их
интерфейсы ([интерфейсы модулей](../iface/)).

## Встроенные типы

Их объявляет модуль `Prelude`; каждый модуль видит его имена без импорта,
а локальное определение с тем же именем скрывает их.

| Тип | Кинд |
| - | - |
| `Unit`, `Never`, `Bool`, `Number`, `BigInt`, `String`, `Unknown`, `Ordering` | `Type` |
| `List`, `Option`, `Ref`, `Redacted`, `Schema` | `Type -> Type` |
| `Result`, `PureCodec` | `Type -> Type -> Type` |
| `ServiceTag`, `ServiceImpl` | `ServiceRow -> Type` |
| `Scope` (сервис) | `Region -> Service` |
| `Eff` | `ServiceRow -> ErrorRow -> Type -> Type` |
| `Layer` | `ServiceRow -> ErrorRow -> ServiceRow -> Type` |
| `Codec` | `ServiceRow -> ServiceRow -> Type -> Type -> Type` |
| `Errors` | `ErrorRow -> Type` |

`Option a = None | Some a`, `Result e a = Err e | Ok a` и
`type error AppError = AppError { message : String; details : Option String }` —
обычные объявления; `identity : a -> a` — функция. `from_result` превращает
`Result` в ожидаемую ошибку ([эффекты](../effects/)). Встроенные модули
используются с квалифицированными именами без импорта: `Ref.make`, `Ref.get`, `Ref.set`,
`Ref.modify`, `String.trim`, `Platform.stdout_line`, `Platform.stderr_line`,
`App.fail`, `Layer.succeed`, `Layer.merge`, `Layer.override`, примитивы строк
модуля `Record` и `Fiber.spawn` с типами `Fiber.Owner`,
`Fiber.Fiber` и `Failure` ([регионы](../regions/)). Классы `Eq`, `Ord`, `Hash` и `Show`
тоже находятся в `Prelude` ([классы](../classes/)).

## Кинды

`Type`, `ServiceRow`, `ErrorRow`, `CaptureRow`, `Row k` (`Row Type` —
кинд полей записи), `Symbol`, `Region`, `Constraint`, конечные кинды из
объявлений `kind` и стрелки между ними. Параметр типа может явно указывать
свой кинд; иначе кинд выводится из мест использования параметра, а если его
ничто не определяет, это `Type`. Кинды параметров объявлений модуля
выводятся совместно, поэтому объявления могут использовать друг друга в любом порядке.

```flick
type alias Box (f : Type -> Type) a = { value : f a }

kind Nullability = NonNull | Nullable

type Js (n : Nullability) a
```

Три кинда строк эффектов не смешиваются: строка сервисов содержит сервисы,
строка ошибок — типы, объявленные с `error`, строка захватов — регионы. `none` —
пустая строка любого строчного кинда, а не тип. `Eff Unit Unit a`, `Option`
без аргумента и `Number String` приводят к `FLICK-T002`.

## Сигнатуры

У каждой именованной функции полная сигнатура находится непосредственно над её
`let` (см. [Прямые эффектные вызовы](../../spec/03-direct-calls/)): на верхнем уровне, локально, в экземплярах классов и у функции,
созданной частичным применением. Функция без сигнатуры — `FLICK-T004` с
предложением выведенного типа; типы, записанные в заголовке `let`, —
`FLICK-T005`; сигнатура без определения непосредственно под ней — `FLICK-T006`.
Значениям, которые не являются функциями, сигнатура не нужна, а локальное
`let x : T = …` служит подсказкой.

Новые переменные типа в сигнатуре квантифицируются по всей сигнатуре,
а их кинды выводятся. Внутри её тела то же имя во вложенной сигнатуре
обозначает тот же тип:

```flick
compose : (b -> c) -> (a -> b) -> a -> c
let compose f g x =
  apply : (a -> b) -> b
  let apply h = h x
  f (apply g)
```

Сигнатура проверяется, а не принимается на веру: тело должно работать для любого
типа, который может выбрать вызывающий код (`FLICK-T008`, если телу нужен один конкретный тип).

`_` в сигнатуре или аннотации — дыра: чекер выводит эту часть типа и сообщает её
(`FLICK-T024`) с исправлением, которое вписывает выведенный тип. Дыра нужна для
черновика; в объявлении типа её быть не может.

```flick
swap : (Number, String) -> _
let swap (a, b) = (b, a)
```

## Функции и высшие ранги

`a -> b`, `a ->{r; e} b` и `a ->{} b` — три разных типа; пустая
строка никогда не делает стрелку среды выполнения чистой (см. [Значения вычислений и их выполнение](../../spec/04-computations/)). Лямбда принимает
каждую стрелку типа, на соответствие которому её проверяют. Какие строки нужны
вызовам в теле и где вообще допустим вызов среды выполнения, описано в разделе
[об эффектах](../effects/).

`forall` может появляться внутри типа в сигнатуре. Тогда проверка идёт от
сигнатуры к аргументу, так что один колбэк можно использовать с несколькими типами:

```flick
apply_twice :
  (forall a. a -> a) -> (Number, String)
let apply_twice transform =
  (transform 42, transform "hello")
```

Инстанцирование предикативно: переменная типа никогда не обозначает
полиморфный тип. Переменная, связанная `forall`, не должна выходить за его
пределы, например сохраняться в ячейке, созданной вне колбэка (`FLICK-T007`).

## Записи

Записи точные и структурные (см. [Типовое ядро HKT и классы типов](../../spec/05-types-and-classes/)). `type alias User = { … }` — прозрачный
псевдоним, а порядок полей не имеет значения. Запись с дополнительными полями
не подходит для закрытого типа записи; сигнатура принимает дополнительные поля
с помощью открытой строки:

```flick
name : forall fields. { name : String | fields } -> String
let name value = value.name
```

`{ r with f = v }` заменяет существующие поля значениями того же типа.
Метка, указанная дважды в типе записи, литерале, обновлении или образце, —
`FLICK-T014`.

## Образцы

`match` должен охватывать все значения; `FLICK-T009` показывает значение,
которому не соответствует ни одна ветвь. Ветви с условием `when` ничего не
добавляют к покрытию. Ветвь, которая никогда не выполнится, вызывает
предупреждение `FLICK-T010`. Образец конструктора принимает ровно аргументы
конструктора (`FLICK-T018`). Образцы в `let` и параметрах должны соответствовать
всем значениям. Образец записи перечисляет некоторые её поля.

## Числа и операторы

Неявных преобразований нет (см. [Schema и стандартные типы данных](../../spec/09-schema/)).

| Операторы | Операнды | Результат |
| - | - | - |
| `+ - * / % **`, префиксный `-` | оба `Number` или оба `BigInt` | тот же тип |
| `++` | оба `String` или оба `List a` | тот же тип |
| `< <= > >=` | оба `Number`, `BigInt` или `String` | `Bool` |
| `== !=` | одного типа | `Bool` |
| `&& \|\|`, `not` | `Bool` | `Bool` |
| `x \|> f` | `f x` | результат `f` |

`1 + 1n` и `"a" ++ 1` — `FLICK-T003`. Операнд, тип которого ничто другое
не определяет, получает тип `Number` (`String` для `++`).

## Блоки

Каждая инструкция до последней должна иметь тип `Unit`; отбросить другое
значение можно только с помощью `ignore` (`FLICK-T011` с предложением этого
исправления). Последняя инструкция — значение блока, и она должна быть
выражением (`FLICK-T019`).

## Рекурсия

Объявления верхнего уровня могут использовать друг друга в любом порядке,
но рекурсия явная: функция, использующая себя, объявляется как `let rec`,
а взаимно рекурсивные функции определяются в одной группе `rec { … }`
(`FLICK-T017`). Рекурсивными могут быть только функции; значение, которое пришлось бы
вычислять во время его определения, — `FLICK-T012`.

Рекурсивная функция может вызывать себя с другим типом, только если её
сигнатура начинается с `forall`, связывающего все её переменные; иначе
такой вызов — `FLICK-T015`.

```flick
type Nested a = Flat a | Nest (Nested (List a))

depth : forall a. Nested a -> Number
let rec depth value =
  match value with
  | Flat _ -> 0
  | Nest inner -> 1 + depth inner
```

## Обобщение

Связывание полиморфно только тогда, когда оно создаётся чисто: при его
определении не выполняется ни один вызов среды выполнения (см. [Generalization при наличии Ref](../../spec/05-types-and-classes/#generalization-при-наличии-ref)). Тела лямбд и `task` отложены и считаются чистыми. Полиморфная
сигнатура для результата среды выполнения — `FLICK-T013`, как и значение верхнего
уровня, тип которого остаётся неизвестным. Переменные типа из внешней сигнатуры
или уже доступного значения никогда не обобщаются, а изменяемые контейнеры
инвариантны.

```flick
make_empty : forall a. Unit ->{} Ref (Option a)
let make_empty () =
  Ref.make None

fresh_cell : forall a. Eff none none (Ref (Option a))
let fresh_cell =
  task { Ref.make None }
```

Классы и экземпляры классов: [классы](../classes/).
