---
title: "Схемы и кодеки"
---

Схема — свидетельство о значениях типа в среде выполнения; кодек добавляет
формат передачи и преобразует его в значения и обратно (см. [Schema и стандартные типы данных](../../spec/09-schema/)). И то и другое —
значения программы, создаваемые из объявлений, DSL и библиотечных комбинаторов.
Декодирование завершается ошибкой `SchemaError` — списком проблем
`{ message; path }`, который указывает пути и никогда не содержит входные данные.

## Уточнённые типы

```flick
refined type Port = Number where fun n -> n > 0 && n < 65536
  deriving Eq, Schema

refined type Email = String where Checks.email
  deriving Eq, Hash, Schema
```

Уточнённый тип номинален: его значения — те значения базового типа,
которые проходят предикат, чистую функцию с результатом `Bool`. У него нет
конструктора; его сопутствующие функции — `T.parse : U -> Result SchemaError T`
и `T.value : T -> U`, а с `deriving Schema` появляется также `T.json`,
его JSON-кодек. Значение представлено как значение базового типа.

`T.parse` от константы проверяется при компиляции программы, если компилятору
известна проверка: функция из `Checks` (`Checks.email`, `Checks.non_empty`,
`Checks.positive`) или `fun`, тело которой сворачивается в литерал при
подстановке константы вместо параметра. Константа, не прошедшая проверку, —
`FLICK-D006`.

## Автоматический вывод схем

`deriving Schema` определяет свидетельство `schema T`:

| Объявление | Свидетельство |
| - | - |
| `type Shape = …`, псевдоним записи или кортежа, `type error` | `Schema Shape` |
| `type Tree a = …` | `Schema a -> Schema (Tree a)` |
| `type alias PairOf f = { count : f Number }` | `(forall a. Schema a -> Schema (f a)) -> Schema (PairOf f)` |
| параметр, который представление не использует (фантомный) | свидетельство для него не требуется |

```flick
tree_schema : Schema a -> Schema (Tree a)
let tree_schema item_schema =
  schema Tree item_schema
```

Каждому полю нужно свидетельство: примитив, `List`, `Option`, `Result`,
`Redacted`, кортеж или закрытая запись из них, параметр типа либо тип,
который сам выводит `Schema`. Ссылка на тип того же модуля ленивая,
поэтому рекурсивные и взаимно рекурсивные типы работают. У функции, `Ref`,
ресурса с областью жизни или описания среды выполнения (`Eff`, `Layer`,
кодека) нет свидетельства: `FLICK-D001` указывает путь поля, например
`Session.handler`. `schema T` для типа без `deriving Schema` — тоже `FLICK-D001`.

## DSL кодеков

```flick
profile_json : PureCodec Json Profile
let profile_json =
  codec (schema Profile) {
    email = field "email_address" Email.json;
    nickname = field "nickname" (option_as_null String.json);
  }
```

Блок `codec` для схемы записи задаёт каждое поле ровно один раз:
пропущенное поле — `FLICK-D002`, указанное дважды — `FLICK-D003`,
отсутствующее в записи — `FLICK-D004`, а два поля с одинаковым именем
в формате передачи — `FLICK-D005`. Блок для схемы, не являющейся схемой
записи, — `FLICK-D007`. Ключи, не названные в блоке, отклоняются, если
кодек не проходит через `ignore_extra_fields`.

| Поле | Кодирование `None` | Декодирование |
| - | - | - |
| `field "x" codec` | по правилам кодека | ключ обязателен |
| `field "x" (option_as_null codec)` | `null` | `null` — это `None`; отсутствие ключа — ошибка |
| `optional_field "x" codec` | ключ опускается | отсутствие ключа — `None`; присутствующее значение обрабатывается кодеком |
| `field "x" (option_as_nullish codec)` | `null` | отсутствие ключа и `null` — это `None` |
| `field "x" (Codec.tagged_option codec)` | `{"_tag": "None"}` | `{"_tag": "None"}` или `{"_tag": "Some", "value": …}` |

`field … |> on_missing (fun () -> v)` задаёт отсутствующему ключу значение
по умолчанию `v`, вызывая фабрику один раз на декодирование; `null` или
неверное значение всё ещё являются ошибкой. `on_missing_effect` принимает
фабрику среды выполнения, сервисы которой затем требуются декодированию.
Блок имеет тип `PureCodec Json R`, когда ни одному полю не нужны сервисы
для декодирования, и `Codec rd none Json R` в противном случае:
эффектный кодек никогда не является `PureCodec`, и такое его использование — ошибка типов.

## Кодеки

| Функция | |
| - | - |
| `Codec.decode`, `Codec.encode` | выполняются в среде выполнения, могут завершиться ошибкой `SchemaError` |
| `Codec.decode_result`, `Codec.encode_result` | чистые, для `PureCodec` |
| `Codec.json schema` | каноническая форма JSON: записи как объекты, варианты как `{"_tag": "Name", "_0": …}`, `Option` как значение или `null`, `Unit` как `null`, `BigInt` как строка |
| `String.json`, `Number.json_finite`, `Number.json`, `BigInt.json`, `Codec.bool`, `Codec.list` | примитивы; `Number.json_finite` отклоняет `NaN` и бесконечности в обе стороны, `Number.json` записывает их как строки |
| `Codec.transform`, `Codec.transform_result`, `Codec.transform_effect` | чистые преобразования, преобразования с возможной ошибкой и преобразования среды выполнения |
| `Codec.check predicate message` | проверка всего декодированного значения |
| `Redacted.json_reveal codec`, `Redacted.json_masked` | явные политики для значения `Redacted`: его содержимое или `"<redacted>"` только в одну сторону |

У значения `Redacted` нет формы JSON без одной из этих политик:
`Codec.json` для схемы с полем `Redacted` отказывается кодировать и декодировать
его, а не раскрывает содержимое. Декодирование читает только собственные
свойства данных входного значения; значение, повторно встреченное на
декодируемом пути, — цикл и ошибка, тогда как общее значение на двух путях
допустимо. `Json.parse` превращает текст JSON в `Unknown` для декодирования.

## Экспортёры и адаптеры

`Codec.json_schema root codec` точно описывает формат передачи в JSON Schema
2020-12 либо возвращает `ExportError`, указывающую путь узла, который не
может описать: `Profile.session -> JSON Schema: scoped resource has no wire
codec`. Отклоняются проверка без точного представления в JSON Schema,
проверка значения после преобразования, преобразование с возможной ошибкой
или в среде выполнения, резервный вариант декодирования, значение `Redacted`
без политики, непрозрачное свидетельство (`Schema.opaque`) и `Unknown`;
ничто не записывается как `{}` или `true`. Из проверок уточнённых типов
известны `Checks.email`, `Checks.non_empty` и `Checks.positive`; проверка
Effect из модуля `Check` записывается ключевыми словами, предоставляемыми
Effect, когда они точны (`Check.min_items 1` — это `minItems`,
`Check.lowercased` отклоняется, поскольку его шаблон менее строг, чем проверка).
Рекурсивный тип становится `$ref` в `$defs`; `Codec.annotate` добавляет
`title` и `description`.

`Codec.standard codec` — объект Standard Schema V1, выполняющий валидацию
синхронно. `Codec.standard_async codec` создаётся в среде выполнения:
его `validate` возвращает промис, выполняемый с сервисами и в области того
места, где объект был создан, а после закрытия этой области сообщает о проблеме.

`Schema.arbitrary schema` генерирует значения для тестов свойств;
уточнённому типу нужен `Schema.with_generator`.

## Проверки и кодеки Effect

`Check.apply check codec` ограничивает то, что кодек декодирует и кодирует,
одной из проверок Effect Schema: длины и кодовые точки, шаблоны, форматы
строк (`Check.uuid`, `Check.base64`), границы для чисел, `BigInt`,
`BigDecimal` и `Ord`, элементы списка и уникальность, размеры множеств
и ключи словаря `Codec.entries`. `Codec` добавляет готовые преобразования
Effect (`Codec.trim`, `Codec.number_from_string`, `Codec.base64_string`,
`Codec.json_string`, `Codec.split`), литералы, словари, резервные варианты
декодирования и кодирования, проверки среды выполнения и кодирование XML;
у `Duration`, `BigDecimal`, `Chunk`, `HashSet` и `HashMap` есть JSON-кодеки,
а `Arbitrary`, `JsonSchema` и `Differ` оборачивают генераторы Effect,
преобразования диалектов и патчи JSON.

## Выполнение декодеров

Схемы и кодеки — значения Effect Schema: `Schema a` — схема Effect Schema
для значений `a` в программе, а кодек — кодек Effect Schema из формата
передачи, поэтому код JS может использовать их напрямую с Effect,
а `--emit-dts` проецирует их как `Schema.Codec<A, I, RD, RE>`.
Интерпретатор Effect — базовый вариант. `flick build --schema-aot`
(или `schema-aot = true`) один раз загружает модули приложения в Node,
передаёт кодеки, созданные ими при загрузке, в `SchemaAOTCompiler` из Effect
и записывает статический модуль `schemas.aot.js`; средство запуска собирает
те же кодеки и устанавливает его до старта `main`. Кодек, созданный позднее,
или узел, который компилятор не обрабатывает, продолжает использовать
интерпретатор, а модуль, больше не соответствующий программе, пропускается
с предупреждением. Оба варианта дают одинаковый результат для любых входных
данных; тест сравнивает их на случайных входных данных.
