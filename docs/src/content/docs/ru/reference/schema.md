Схема описывает структуру значений типа и доступна во время выполнения.
Кодек задаёт формат передачи данных и преобразует представление в этом
формате в значения программы и обратно (см. [Schema и стандартные типы данных](../../spec/07-schema/)).
Схемы и кодеки — значения программы. Их можно создавать из объявлений типов,
с помощью DSL или библиотечных комбинаторов.

Если декодирование не удалось, ошибка `SchemaError` содержит список проблем
`{ message; path }`. В нём есть пути к проблемным значениям, но никогда нет
самих входных данных.

## Уточнённые типы

```flick
refined type Port = Float where fun n -> n > 0 && n < 65536
  deriving Eq, Schema

refined type Email = String where Checks.email
  deriving Eq, Hash, Schema
```

Уточнённый тип — отдельный номинальный тип. В него входят значения базового
типа, которые проходят предикат — чистую функцию с результатом `Bool`.
Конструктора, который программа могла бы назвать, у него нет. Вместо него
доступны функции `T.parse : U -> Result SchemaError T`, `T.value : T -> U` и
сам предикат `T.check : U -> Bool`.
С `deriving Schema` также появляется JSON-кодек `T.json`.
Во время выполнения значение представлено так же, как значение базового типа,
а другой модуль видит тип непрозрачным.

`refined type` — объявление плагина `std`: он пишет тип и его функции обычным
кодом языка, и `flick expand` его показывает. Слово `refined` не
зарезервировано.

Вызов `T.parse` с константой проверяется при компиляции, если компилятор
может выполнить предикат. Это возможно для известных функций из `Checks`
(`Checks.email`, `Checks.non_empty`, `Checks.positive`) и для `fun`,
тело которой сворачивается в литерал после подстановки константы вместо
параметра. Если константа не проходит проверку, возникает `FLICK-D006`.

## Автоматический вывод схем

`deriving Schema` создаёт схему, доступную через `T.schema`. Её пишет на Flick
плагин `std` комбинаторами `Schema` из таблицы ниже; `flick expand` её
показывает:

| Объявление | Схема |
| - | - |
| `type Shape = …`, псевдоним записи или кортежа, `type error` | `Schema Shape` |
| `type Tree a = …` | `Schema a -> Schema (Tree a)` |
| `type alias PairOf f = { count : f Float }` | `(forall a. Schema a -> Schema (f a)) -> Schema (PairOf f)` |
| фантомный параметр, который не используется в представлении типа | схема параметра всё равно нужна |
| перечисление, `untagged type Method = Get = "GET" \| …` | `Schema Method`, в формате передачи — его литералы |

```flick
# type Tree a = Leaf | Node (Tree a) a (Tree a)
#   deriving Schema
#
tree_schema : Schema a -> Schema (Tree a)
let tree_schema item_schema =
  Tree.schema item_schema
```

Для каждого поля должна быть схема. Поддерживаются примитивы, `List`,
`Option`, `Result`, `Redacted`, кортежи и закрытые записи из таких типов,
параметры типа и типы, у которых тоже есть `deriving Schema`. Псевдоним
модуля раскрывается; тип другого модуля, в том числе псевдоним, называет
свою схему, поэтому тоже выводит `Schema`. Ссылки на типы того же модуля
раскрываются лениво, поэтому поддерживаются рекурсивные и взаимно
рекурсивные типы.

Для функции, `Ref`, ресурса с областью владения или описания для среды
выполнения (`Eff`, `Layer`, кодека) схемы нет. В таком случае `std/D001`
указывает путь к полю, например `Session.handler`. Выражение `T.schema`
для типа без `deriving Schema` приводит к `FLICK-D001`.

Внешняя форма перечисления — его литерал, `"GET"`; JSON Schema перечисляет
их как `{ "enum": ["GET", …] }`. `deriving Schema { wire = "tag" }`
сохраняет форму вариантного типа, `{ "_tag": "Get" }`. Литерал, которого
перечисление не знает, не декодируется. `Open t b` из модуля `Open` его
сохраняет: `Open.parse` даёт `Known` со значением перечисления или
`Unknown` с литералом, `Open.value` — литерал любого из них, а
`Open.schema Schema.string` декодирует любой литерал.

```flick
# import Open exposing (Open)
# untagged type Method = Get = "GET" | Post = "POST"
#   deriving Show, Schema
#
methods : Schema (Open Method String)
let methods = Open.schema Schema.string
```

Комбинаторы, которые используются при автоматическом выводе схем, — значения `Schema`; ими может
пользоваться и программа:

| Комбинатор | Схема |
| - | - |
| `Schema.int`, `Schema.number`, `Schema.string`, … | примитив |
| `Schema.unsafe_record [Schema.field "x" s, …]` | запись, поля в порядке меток |
| `Schema.unsafe_tuple [Schema.item s, …]` | кортеж |
| `Schema.unsafe_adt "Shape" [Schema.unsafe_case Circle [Schema.item s], …]` | тип-сумма, конструкторы — значения |
| `Schema.lazy "T" (fun _ -> s)` | ссылка с именем `T` в JSON Schema, создаётся при первом использовании |
| `Schema.recursive "T" (fun self -> s)` | рекурсивный тип, `self` — ссылка на него |
| `Schema.unsafe_unboxed s`, `Schema.unsafe_refined "T" known s T.parse` | `unboxed type` и уточнённый тип |
| `Schema.enum Schema.string`, `Schema.unsafe_enum_tags Schema.string [("Get", Get), …]` | перечисление, в формате передачи — литералы или `{ "_tag" }` |

Что части `unsafe_`-комбинатора — части его типа, никто не проверяет: вывод
пишет их под сигнатурой схемы.

## DSL кодеков

Блок `codec` — плагин `codec` пакета `std`, который файл импортирует из
`Codec`. Свидетель типа — `T.schema`.

```flick
import Codec
# refined type Email = String where Checks.non_empty
#   deriving Schema
# type alias Profile = { email : Email; nickname : Option String }
#   deriving Schema

profile_json : PureCodec Json Profile
let profile_json =
  codec Profile.schema {
    email = field "email_address" Email.json;
    nickname = field "nickname" (option_as_null String.json);
  }
```

В блоке `codec` для схемы записи нужно указать каждое поле ровно один раз.
Пропущенное поле приводит к `std/D002`, повторное — к `std/D003`,
поле, которого нет в записи, — к `std/D004`. Если у двух полей совпадают
имена в формате передачи, возникает `std/D005`. Блок для схемы, которая
не описывает запись, приводит к `std/D007`, а поле, кодек которого
декодирует не тот тип, что у поля записи, — к `std/D012`. Блок — это
`PureCodec` или, если поле вызывает `field_effect` или `on_missing_effect`,
`Codec` нужных им сервисов.
При декодировании неизвестные ключи отклоняются, если к кодеку не применён
`ignore_extra_fields`.

| Поле | Кодирование `None` | Декодирование |
| - | - | - |
| `field "x" codec` | по правилам кодека | ключ обязателен |
| `field "x" (option_as_null codec)` | `null` | `null` — это `None`; отсутствие ключа — ошибка |
| `optional_field "x" codec` | ключ опускается | отсутствие ключа — `None`; присутствующее значение обрабатывается кодеком |
| `field "x" (option_as_nullish codec)` | `null` | отсутствие ключа и `null` — это `None` |
| `field "x" (Codec.tagged_option codec)` | `{"_tag": "None"}` | `{"_tag": "None"}` или `{"_tag": "Some", "value": …}` |

`field … |> on_missing (fun () -> v)` задаёт значение по умолчанию `v`
для отсутствующего ключа. Фабрика вызывается один раз на декодирование.
`null` и неверное значение по-прежнему приводят к ошибке.
`on_missing_effect` принимает эффектную фабрику; её сервисы потребуются
при декодировании.

Если ни одному полю не нужны сервисы для декодирования, блок имеет тип
`PureCodec Json R`. В противном случае его тип — `Codec rd none Json R`.
Эффектный кодек нельзя использовать как `PureCodec`: это ошибка типов.

## Кодеки

| Функция | Назначение |
| - | - |
| `Codec.decode`, `Codec.encode` | эффектные вызовы, которые могут завершиться ошибкой `SchemaError` |
| `Codec.decode_result`, `Codec.encode_result` | чистые функции для `PureCodec` |
| `Codec.json schema` | каноническая форма JSON: записи как объекты, варианты как `{"_tag": "Name", "_0": …}`, `Option` как значение или `null`, `Unit` как `null`, `BigInt` как строка |
| `String.json`, `Float.json_finite`, `Float.json`, `BigInt.json`, `Codec.bool`, `Codec.list` | кодеки примитивов; `Float.json_finite` отклоняет `NaN` и бесконечности при кодировании и декодировании, `Float.json` записывает их как строки |
| `Codec.transform`, `Codec.transform_result`, `Codec.transform_effect` | чистые преобразования, преобразования с возможной ошибкой и эффектные преобразования |
| `Codec.transform_as schema decode encode codec` | `transform`, значения которого — значения `schema`: объединение или ошибки эндпоинта `HttpApi` отличают их от других по конструкторам, а простой `transform` этого не может |
| `Codec.check predicate message` | проверка всего декодированного значения |
| `Redacted.json_reveal codec`, `Redacted.json_masked` | явные политики для `Redacted`: раскрыть содержимое или использовать одностороннее представление `"<redacted>"` |

Без одной из этих политик у `Redacted` нет представления в JSON.
Если в схеме есть поле `Redacted`, `Codec.json` отказывается кодировать
и декодировать его, а не раскрывает содержимое.

Декодер читает только собственные свойства входного значения, в которых
хранятся данные. Если одно значение повторно встречается на текущем пути
декодирования, это цикл и ошибка. Общее значение на двух разных путях
допустимо. `Json.parse` преобразует текст JSON в `Unknown`, который затем
можно декодировать.

## Экспортёры и адаптеры

`Codec.json_schema root codec` точно описывает формат передачи в JSON Schema
2020-12. Если узел нельзя описать точно, функция возвращает `ExportError`
с путём к нему: `Profile.session -> JSON Schema: scoped resource has no wire
codec`.

Экспортёр отклоняет проверки без точного представления в JSON Schema,
проверки значения после преобразования, преобразования с возможной ошибкой
и эффектные преобразования, резервные варианты декодирования, `Redacted`
без политики, непрозрачные схемы (`Schema.opaque`) и `Unknown`.
Вместо них не подставляются `{}` или `true`.

Из предикатов уточнённых типов экспортёр знает `Checks.email`,
`Checks.non_empty` и `Checks.positive`. Проверки из модуля `Check`
записываются своими ключевыми словами JSON Schema, но только
если они точно выражают проверку. Например, `Check.min_items 1`
превращается в `minItems`, а `Check.lowercased` отклоняется: его шаблон
менее строг, чем сама проверка.
Для рекурсивного типа создаётся `$ref` на определение в `$defs`;
`Codec.annotate` добавляет `title` и `description`.

`Codec.standard codec` создаёт объект Standard Schema V1 с синхронной
валидацией. `Codec.standard_async codec` — эффектный вызов.
У созданного объекта метод `validate` возвращает промис, который выполняется
с сервисами и в области создания объекта. После закрытия этой области
валидация сообщает о проблеме.

`Schema.arbitrary schema` генерирует значения для тестов свойств.
Для уточнённого типа нужно задать генератор через `Schema.with_generator`.

## Готовые проверки и кодеки

`Check.apply check codec` добавляет проверку при декодировании
и кодировании. Доступны проверки длины и кодовых точек, шаблонов и форматов
строк (`Check.uuid`, `Check.base64`), границ для чисел, `BigInt`, `BigDecimal`
и `Ord`, элементов и уникальности списка, размера множеств и ключей словаря
`Codec.entries`.

В `Codec` есть готовые преобразования (`Codec.trim`,
`Codec.number_from_string`, `Codec.base64_string`, `Codec.json_string`,
`Codec.split`), литералы, словари, резервные варианты декодирования
и кодирования, эффектные проверки и кодирование XML.
Для `Duration`, `BigDecimal`, `Chunk`, `HashSet` и `HashMap` есть JSON-кодеки.
Модули `Arbitrary`, `JsonSchema` и `Differ` предоставляют генераторы,
преобразования диалектов и патчи JSON.

## Выполнение декодеров

Схемы и кодеки представлены значениями Effect Schema. `Schema a` описывает
значения `a` в программе, а кодек преобразует данные из формата передачи
в значения программы и обратно. Поэтому код JS может использовать их
напрямую с Effect. При `--emit-dts` они получают тип
`Schema.Codec<A, I, RD, RE>`.

По умолчанию декодеры выполняет интерпретатор Effect.
При `flick build --schema-aot` (или `schema-aot = true`) сборка один раз
загружает модули приложения в Node.js и передаёт созданные при загрузке
кодеки в `SchemaAOTCompiler` из Effect. Результат записывается
в статический модуль `schemas.aot.js`. Средство запуска собирает те же
кодеки и подключает этот модуль до вызова `main`.

Кодеки, созданные позднее, и узлы, которые компилятор не поддерживает,
продолжают использовать интерпретатор. Если модуль больше не соответствует
программе, он пропускается с предупреждением.
Оба способа выполнения дают одинаковый результат для любых входных данных;
тест сравнивает их на случайных данных.
