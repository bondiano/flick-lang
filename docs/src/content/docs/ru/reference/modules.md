Один файл `.fl` — один модуль (§11). Заголовок модуля задаёт его имя
и перечисляет экспортируемые сущности; импорты вводят экспортируемые
сущности других модулей в область видимости.

```flick
module App.Users exposing (User, load_user)

import App.Domain exposing (User, UserId)
import Effect.Log as Log
```

## Имена модулей и файлы

Имя модуля — список имён с заглавной буквы, разделённых точками. В проекте
(см. [проекты](../project/)) путь относительно корня исходников задаёт имя
модуля: `App.Users` находится в `src/App/Users.fl`. Корень тестов — второй
набор модулей с тем же правилом.

| Ситуация | Диагностика |
| - | - |
| `src/App/Users.fl` объявляет `module App.User` | `FLICK-R001` с исправлением, переименовывающим модуль |
| имя каталога или файла начинается не с заглавной буквы (`src/app/users.fl`) | `FLICK-R001` |
| два файла объявляют одно имя модуля, например `src/App/Users.fl` и `test/App/Users.fl` | `FLICK-R002` для более позднего: сначала исходники, затем тесты, далее по пути |
| локальный модуль и установленный пакет предоставляют один модуль | `FLICK-R002` |

Файл без заголовка получает имя из своего пути. Файл вне корней проекта
или проверяемый без проекта задаёт собственный корень: `x/App/Main.fl`,
объявляющий `App.Main`, импортирует `App.Util` из `x/App/Util.fl`.

## Импорты

| Форма | Что вводит в область видимости |
| - | - |
| `import App.Domain` | квалифицированные имена `App.Domain.name` |
| `import App.Domain as D` | квалифицированные имена `D.name` |
| `import App.Domain exposing (User, load)` | `User`, `load` без квалификатора, а также квалифицированные имена |
| `import App.Domain exposing (Shape(..))` | тип `Shape` и его экспортируемые конструкторы |
| `import App.Domain exposing (..)` | всё экспортируемое из `App.Domain` |

Модуль исходников импортирует модули исходников; тестовый модуль импортирует
исходные и тестовые модули. В остальных случаях модуль берётся из
установленного пакета (см. [пакеты](../project/#пакеты)).

| Ситуация | Диагностика |
| - | - |
| ни файл, ни пакет не предоставляют модуль | `FLICK-R003` с указанием места для локального модуля и команды `flick add` |
| зависимость из `package.json` не установлена | `FLICK-P009` с командой `flick install` (код завершения `2`) |
| `exposing (name)` или `M.name` для имени, которое модуль не экспортирует | `FLICK-R004` |
| `exposing (Type(..))` для типа, экспортируемого без конструкторов, `exposing (Ctor)` или `M.Ctor` для неэкспортируемого конструктора | `FLICK-R005` |
| модули импортируют друг друга по циклу | `FLICK-R006` с перечислением цепочки, один раз на цикл |

Каждая ошибка указывает на вызвавший её импорт (или квалифицированное имя).

## Экспорт

Список `exposing` в заголовке — весь интерфейс модуля. Модуль без
`exposing` ничего не экспортирует.

| Элемент | Что экспортирует |
| - | - |
| `name` | значение: `let`, `foreign`, метод класса |
| `Type` | тип, `error`, `kind`, сервис или класс без конструкторов или членов |
| `Ctor` | один конструктор, если ни у одного типа нет такого имени |
| `Type(..)` | тип и его конструкторы; методы класса; члены `kind` |
| `..` | все определения модуля; конструкторы непрозрачных типов остаются закрытыми |

Экспорт типа не экспортирует его конструкторы. `opaque type` никогда не
экспортирует своё представление: `Id(..)` для непрозрачного `Id` —
`FLICK-R011`, как и `Alias(..)` для типа без конструкторов или имя, которое
модуль не определяет и не импортирует.

Модуль может реэкспортировать импортированное имя. Реэкспорт — та же
сущность, а не копия: импорт `User` одновременно из `App.Domain` и модуля,
который его реэкспортирует, не создаёт неоднозначности.

```flick
module App.Users exposing (User, load_user)

import App.Domain exposing (User)
```

## Определения верхнего уровня

В модуле имя определяется один раз в каждом пространстве имён: значений,
типов (типы, ошибки, кинды и их члены, сервисы, классы) и конструкторов.
Сигнатура и её `let` — одно определение; второе определение — `FLICK-R008`.

Прозрачные псевдонимы должны быть ацикличными: `type alias A = List A`
или цикл через несколько псевдонимов — `FLICK-R007`. Рекурсия проходит
через номинальный тип, который может ссылаться на себя и другие типы файла:

```flick
type Tree a = Leaf | Node a (Forest a)
type alias Forest a = List (Tree a)
```

## Затенение и неоднозначность

Каждое правило сравнивает имена и имена модулей, а не порядок импортов,
поэтому перестановка импортов не меняет диагностику.

1. Локальное связывание (параметр, образец, `let`, `scope`) затеняет любое
   имя верхнего уровня и импортированное имя; это разрешено.
2. Определение верхнего уровня без предупреждения затеняет имена из импортов
   `exposing (..)`, но совпадение с именем, импортированным явно через
   `exposing (name)`, — `FLICK-R009`: переименуйте определение или удалите импорт.
3. Два импорта, явно вводящие одно имя как разные сущности, — `FLICK-R010`;
   ошибка сообщается на импорте модуля, имя которого идёт последним при сортировке.
4. Имя, введённое двумя импортами `exposing (..)` как разные сущности, —
   `FLICK-R010` в месте использования без квалификатора; если оно не
   используется, ошибки нет.
5. Два импорта с одним квалификатором (`import A as M`, `import B as M`) —
   `FLICK-R010`.

```flick
import App.Users as Users exposing (..)
import App.Orders as Orders exposing (..)

let first = Users.find
```

Имена внутри `sql { }` принадлежат запросу и разрешаются при элаборации SQL.
Об именах, которые нигде не определены, сообщает проверка типов, знающая
прелюдию.
