Объявление `foreign` связывает функцию JS с сигнатурой Flick
(см. [Генерация TypeScript и граница FFI](../../spec/06-typescript-and-ffi/)).
Сигнатура задаёт типы аргументов, результата, сервисов и ошибок.
Режим определяет, когда и как вызывается функция, а строки метаданных
описывают передачу аргументов и обработку результата.

```flick
# import File exposing (Path)
# import JsError as FsError
# type alias FsError = JsError.JsError
#
hypot : Float -> Float -> Float
foreign pure hypot from global "Math.hypot"
  arity 2

now_millis : Unit ->{} Float
foreign now_millis from global "Date.now"
  arity 0

read_text : Path ->{Async; FsError} String
foreign read_text from "./fs.js" "readText"
  arity 1
  catch FsError.from_js
  cancel signal
```

## Режимы

| Режим | Вызов |
| - | - |
| `pure` | прямой вызов JS; чистота принимается на доверии, вызов возможен в том числе при загрузке модуля |
| нет, строка без `Async` | JS вызывается на эффектной стадии функции; исключение считается дефектом |
| нет, строка с `Async` | результат JS — промис, который создаётся при выполнении вызова, а не при построении `task`; отклонение промиса считается дефектом; ближайший владелец ждёт завершения промиса даже после прерывания |
| `effect` | фабрика JS вызывается при выполнении вызова (`Effect.suspend`), а возвращённый ею `Effect` выполняется в текущем файбере |

`foreign sync` и `foreign async` — прежние слова: `FLICK-F001`, исправление
убирает слово и даёт строке промиса её `Async`.

## Встроенный внешний код

Небольшие адаптеры хоста можно писать прямо внутри модуля `.fl` без отдельного
соседнего файла. Для одной привязки используйте `from inline` с любым строковым
литералом без интерполяции (`"..."`, многострочным `"""..."""` или сырым
`r#"..."#`), а для общих объявлений уровня модуля, используемых несколькими
встроенными привязками, — `foreign module inline`:

```flick
foreign module inline """
  const SCALE = 2;
  function scaled(x) {
    return x * SCALE;
  }
  """

cos : Float -> Float
foreign pure cos from inline "(d) => Math.cos(d)"

double_it : Float -> Float
foreign pure double_it from inline """
  (d) => scaled(d)
  """
```

Ядро компилятора считает встроенный текст непрозрачным и передаёт его вместе с
точным исходным спаном в IR и `BuildRequest.inline-foreign`. Форматтер
`flick fmt` сохраняет встроенные строковые литералы побайтово. Каждый бэкенд
сам проверяет и размещает встроенный код по правилам своего целевого языка:

- **`flick/js`**: помещает каждую преамбулу `foreign module inline` на верхний
  уровень модуля, а каждую привязку `from inline` — в константу уровня модуля
  под обычными адаптерами и копированием данных на границе.
- **`flick/go`**: поднимает и дедуплицирует объявления `import` из преамбул
  `foreign module inline`, помещает остальные объявления преамбулы на уровень
  пакета и вызывает выражения `from inline` по соглашению вызовов Go FFI
  (`func(fb *flickrt.Fiber, a0 flickrt.Value) flickrt.Value`, а для `Async` —
  `func(ctx flickrt.Context, ...)`).

Синтаксические ошибки, обнаруженные бэкендом во встроенной привязке или
преамбуле модуля, сообщаются как `FLICK-F011` и отображаются обратно на точную
строку и спан внутри строкового литерала файла `.fl`.

## Метаданные

Строки метаданных под объявлением `foreign` делятся на **слова ядра контракта**,
принадлежащие компилятору на каждом бэкенде, и **слова адаптеров бэкенда**,
которые объявляет дескриптор активного бэкенда пакета.

### Слова ядра контракта

| Метаданные | Значение |
| - | - |
| `arity n` | адаптирует `n` стадий функции Flick к `n` позиционным аргументам хоста; при `arity 0` первый аргумент `()` типа `Unit` вычисляется, но хост вызывается без аргументов |
| `catch f` | превращает исключение, панику, отклонение промиса или завершающий `error` в Go в типизированную ошибку `f value`, где `f` принимает тип хоста для `catch` активного бэкенда (`JsValue -> E` на `flick/js`, `String -> E` на `flick/go`), а `E` входит в строку ошибок; `E` не может содержать значения, привязанные к области владения (`FLICK-F003`) |
| `retention call` / `retention owner` | задаёт, как долго хост может хранить аргумент со значениями из области владения: до конца вызова или до закрытия владельца региона |
| `nullable` | результат имеет тип `Option a`: `null` и `undefined` (или отсутствие значения на хосте) превращаются в `None` |
| `optional i` | аргумент `i` (нумерация с 0) имеет тип `Option a`: `None` передаётся как отсутствующий (`undefined` в JS) |
| `reviewed "<pkg>@<ver> sha256:…"` | указывает объявление экспорта пакета, по которому проверена привязка; `flick ffi check` сравнивает его с установленным объявлением |
| `owned i` | аргумент `i` (нумерация с 0) передаёт владение внешнему вызову |

### Объявленные бэкендом слова адаптеров и атрибуты формы типа

Специфичные для цели слова адаптеров и атрибуты формы типа объявляются каждым
бэкендом в его WIT-дескрипторе (`descriptor.foreign-adapters` и
`descriptor.type-form-attributes`), а не зашиваются в ядро компилятора.
Неизвестные для активного бэкенда слова метаданных сообщают `FLICK-S011`,
неизвестные атрибуты формы типа или атрибуты другого бэкенда — `FLICK-S014`, а
автодополнение и подсказки при наведении в редакторе предлагают только слова
ядра контракта и слова адаптеров активного бэкенда пакета. Каждый бэкенд сам
проверяет свои слова адаптеров в `check-target` (как при `flick check` и в
редакторе, так и при `flick build`) и указывает ошибки точно по спану строки
метаданных.

| Бэкенд | Объявленные слова адаптеров | Атрибут формы типа |
| - | - | - |
| `flick/js` | `this` (первый аргумент — получатель вызова `target.call(a0, a1, …)`), `cancel signal` (для `Async`: последним аргументом передаётся `AbortSignal`, отменяемый при прерывании, пока владелец ждёт завершения), `variadic` (последний аргумент `List a` разворачивается в аргументы вызова) | [`@ts`](../codegen/#форма-типа) |
| `flick/go` | `this` (получатель для `flickrt.CallMethod`), `cancel context` (и `cancel signal` для переносимых привязок; отмена через `flickrt.Context` для `Async`), `variadic` (разворачивает последний аргумент `List a`) | `@go` |
| Пользовательские бэкенды | Любые не конфликтующие слова из `descriptor.foreign-adapters` (флаги, ключевые слова, индексы параметров, целые числа, строки или слова; повторяемые или однократные) | Любые не конфликтующие атрибуты из `descriptor.type-form-attributes` |

Если метаданные не соответствуют сигнатуре, режиму или правилам адаптеров
активного бэкенда, возникает `FLICK-F001`.
Результат типа `Unit` всегда равен `()`, что бы ни вернул JS.

Если тип параметра может содержать значения из области владения, нужна строка
`retention`; без неё возникает `FLICK-F002`. Это относится и к региону,
как в `File s`, и к квалификатору захватов `^c`. Без `retention` компилятор
не знает, как долго JS сохраняет аргумент.
Тип функции обратного вызова без квалификатора не держит живым ни один
регион. Поэтому замыкание, которое использует значение из области владения,
отклоняется в месте передачи (`FLICK-G002`).

`retention call` обещает, что JS не хранит ничего сверх того, что показывает
результат. Внешний тип, значения которого хранят функцию обратного вызова
после вызова (как кодек хранит значение поля по умолчанию), показывает это
атрибутом `@stores` перед объявлением. Тогда он становится
[данными со скрытым хранением](../regions/), и результат этого типа держит
то, до чего дотягиваются аргументы перед ним.

`catch JsError.from_js` преобразует исключение JS или отклонение промиса
в типизированную ошибку `JsError`. Она хранит только строковое описание
выброшенного значения в поле `message`, например `name: message` для `Error` в JS.

## Функции обратного вызова

Функция Flick, передаваемая в JS, адаптируется к арности, указанной её типом:
`(a -> b -> c)` передаётся как `(a, b) => c`. Это происходит только тогда,
когда функция — непосредственный аргумент внешней привязки.
Внутри записи, списка или `Option` функция остаётся каррированной,
как во Flick. Есть четыре семейства функций обратного вызова:

| Семейство | Что получает JS | Выполнение |
| - | - | - |
| чистые | `(a, b) => c` | напрямую при каждом вызове |
| Effect | `(a) => Effect<b, E, R>` для эффектной функции обратного вызова | принимающий код Effect запускает её в своём файбере со своими сервисами |
| Promise | `Js.promise_callback f`: `(a) => Promise<b>` | каждый вызов выполняется как дочерняя задача области создания с сервисами этой области; после начала закрытия области новые вызовы отклоняются, а область ждёт уже выполняющиеся |
| события области | `Events.listen owner policy supervisor handler` | каждый вызов ставит событие в очередь; события последовательно обрабатывает одна дочерняя задача `owner` |

`Events.attach listener add remove` регистрирует слушателя.
Когда владелец его региона начинает закрываться, слушатель сразу перестаёт
принимать события, а `remove` получает ту же функцию, которая была передана
в `add`. Затем завершается обработчик очереди и освобождаются ресурсы.
Если очередь `Events.queue capacity` заполнена, новое событие отбрасывается,
а супервизор получает сообщение об этом. Ему также передаётся каждый сбой
обработчика. Сам обработчик никогда не выполняется внутри вызова источника
событий.

### Функции без захвата и трамплины

Хост без замыканий, например C или core WebAssembly, принимает указатель на
функцию, обычно вместе с аргументом `void*` для её данных. Бэкенд такого
хоста адаптирует функцию обратного вызова Flick трамплином. Его слова
адаптера `callback i data j` помечают аргумент `i` как указатель на функцию,
а аргумент `j` — как её окружение, и бэкенд генерирует трамплин
`(void* env, args…)`, который вызывает замыкание. Строка `retention` задаёт
срок жизни окружения: `retention call` держит его на время вызова, а
`retention owner` — до закрытия владельца региона, после чего освобождает.
Слова, арность хоста для каждой функции обратного вызова и срок удержания
бэкенд получает через IR (`Adapter.words`, `Adapter.callbacks`,
`Adapter.retention`).

Некоторые функции не принимают аргумента данных: `qsort`, результат `dlsym`,
точка входа JIT. Для них есть `FuncRef (a -> b)` — функция без захвата. Там,
где ожидается `FuncRef`, значение проверяется против `a -> b` и должно быть
именем функции верхнего уровня, которой при её типе не нужны словари
классов, или лямбдой, которая не использует ни локальных переменных, ни
словарей классов окружающего кода. Захваченная локальная переменная,
частичное применение, локальная функция, метод класса или функция с
ограничениями — это `FLICK-F015` в их диапазоне. Значение, которое уже
является `FuncRef`, передаётся как есть, а `FuncRef.fun r` вызывает его:

```flick
compare_ints : Int -> Int -> Int
let compare_ints a b = a - b

sort_with : FuncRef (Int -> Int -> Int) -> List Int ->{} List Int
foreign sort_with from "./sort.mjs" "sortWith"

ascending : List Int ->{} List Int
let ascending xs = sort_with compare_ints xs

descending : List Int ->{} List Int
let descending xs = sort_with (fun a b -> b - a) xs
```

На JS и Go `FuncRef` — сама функция, адаптированная к арности хоста, как
любая функция обратного вызова: `sortWith` получает `(a, b) => …`. Бэкенд C
или wasm отображает его в обычный указатель на функцию или в `funcref` wasm.

## ABI значений

Каждый компонент бэкенда может публиковать версионированную таблицу ABI
значений в своём WIT-дескрипторе (`descriptor.value-abi`) с ключами по
встроенным lang item и структурным конструкторам типов (`tuple`, `function`).
Каждая запись указывает тип Flick, тип хоста, преобразование (`none`, `copy`
или `view`) и допустимое направление (`in`, `out` или `both`), а также
непрозрачный тип по умолчанию и тип ошибки хоста для `catch`.

Во время проверки типов каждое прямое объявление `foreign` и выбранное
переопределение `@native` сверяется с таблицей активного бэкенда:

- Непрозрачные номинальные типы (`type Handle`) и непрозрачные псевдонимы
  проходят через непрозрачный вариант бэкенда без отдельной записи в таблице.
- Параметр, аргумент функции обратного вызова или возвращаемый тип вне таблицы
  (или в неподдерживаемом направлении) отклоняется с кодом `FLICK-F013` и
  выводит причину отказа бэкенда на спане привязки.
- Записи и пользовательские ADT не имеют стабильной раскладки между бэкендами
  и не входят в таблицу ABI значений.
- Пакет может объявить `[package.abi]` в `flick.toml`, а `BuildRequest.foreign`
  передаёт идентификатор и версию активного ABI; любое несовпадение между
  пакетом, запросом и бэкендом сообщает `FLICK-F014` вместо молчаливого вызова.

Построено напрямую из дескриптора бэкенда `flick/go`:

## Значения JS

`JsValue` представляет любое значение JS в том виде, в котором его передал
внешний код. `Js.snapshot` копирует поддерживаемые данные — примитивы,
простые объекты и плотные массивы — в замороженное значение `Unknown`.
Глубина ограничена 64 уровнями, количество значений — 100000.
`Js.snapshot_with` позволяет задать оба ограничения.

Свойства читаются через дескрипторы, поэтому геттеры не выполняются.
Геттер, функция, цикл, объект с другим прототипом, пропуск в массиве,
прокси, выбрасывающий исключение, или превышение ограничения приводят
к `SnapshotError` с указанием пути.
Поддерево, используемое в двух местах, копируется один раз.

При передаче через внешнюю привязку вне `@flick-lang/effect-ts` и `@flick-lang/runtime` данные Flick копируются:
`List`, кортеж, запись или значение конструктора в аргументе, результат,
значение `Promise` или `Effect`, а также то, что получает и возвращает
функция обратного вызова. JS может отсортировать полученный массив на месте
или изменить объект, который вернул раньше, а значение Flick останется
прежним. Примитивы, `JsValue`, непрозрачные типы и функции передаются как
есть, а функция обратного вызова без данных сохраняет свою идентичность.

`Js.Array` даёт доступ к изменяемым массивам JS через эффектные операции.
`Js.Array.from_list` копирует список Flick в массив JS, а `Js.Array.to_list`
копирует массив обратно в список Flick.

Структурные записи всегда пересекают границу FFI на JS и Go в каноническом
отсортированном порядке меток (ключи-индексы массива JS по возрастанию, затем
порядок UTF-16 — чистый порядок `Record.labels` для идентификаторов Flick),
независимо от способа построения (`{ ... }`, `{ r with ... }`, `Record.extend`,
`Record.merge_disjoint`, `Record.project`, `Record.remove`, конструкторы над
закрытыми записями, декодирование `Codec.json` и блоков `codec`, а также
`Combiner.struct` и `Reducer.struct`). Внешний код, читающий `Object.keys` в JS
или `flickrt.RecordToEntries` в Go, получает `["a", "z"]` и для
`{ z = 1; a = 2 }`, и для `{ a = 2; z = 1 }` (это меняет прежнее поведение, при
котором порядок записи в литерале мог просачиваться на сторону хоста). Значения
данных, записей и кортежей не имеют идентичности хранения на границе: внешний
код не должен полагаться на ссылочное равенство (`===`) между копиями одного
значения данных Flick, тогда как явные изменяемые ячейки и внешние значения
сохраняют идентичность.

Для `Json` и словарей `Record.ReadonlyRecord` действуют отдельные правила
порядка: они сохраняют порядок вставки/провода по правилам ECMAScript (индексы
массива по возрастанию, затем порядок вставки) через `Json.parse`,
`Record.from_entries` и `Record.set`. Преобразование структурной записи в
`Json` через `Codec.json` записывает ключи в каноническом порядке, а
декодирование JSON с любым порядком ключей даёт каноническую структурную
запись; блоки `codec` сохраняют объявленный порядок полей на проводе при
кодировании и канонизируют декодированную структурную запись.

## Нативные переопределения

Функция верхнего уровня с телом на Flick и парной сигнатурой может содержать
одну или несколько строк `@native` с отступом, задающих нативные реализации
для конкретных окружений:

```flick
# import Float
#
hypot : Float -> Float -> Float
let hypot a b = Float.sqrt (a * a + b * b)
  @native "Math.hypot" when js
  @native "math.Hypot" when go
```

Цель привязки использует те же формы, что и `foreign … from`: краткую форму
глобального имени (`"Math.hypot"` или `global "Math.hypot"`), экспорт модуля
(`"./math.mjs" "hypot"`) или встроенный код хоста
(`inline "(a, b) => Math.hypot(a, b)"`). Контракт (типы, стадии, чистый или
эффектный/`Async` режим и арность по умолчанию) берётся из сигнатуры функции, а
объявленные бэкендом слова адаптеров и строки метаданных (`this`,
`cancel signal`, `variadic`, `arity`, `nullable`, `optional`, `catch`,
`retention`, `owned`) могут идти с дополнительным отступом под строкой `@native`
по тем же правилам.

Тело на Flick всегда проходит проверку типов и задаёт семантику функции. Если
ни одна строка `@native` не подходит к активному окружению (например, на цели
без переопределения), компилятор понижает резервное тело на Flick.

Когда под активное окружение подходят несколько строк `@native`, Flick вычисляет
импликацию на конечном словаре тегов окружения (бэкенды, оси и хосты): побеждает
та строка, чьё условие `when` влечёт каждое другое подходящее условие (например,
`bun` влечёт `js`, `js && rt` влечёт `js`, а `cgo` влечёт `go`). Если две
наиболее конкретные подходящие строки не влекут друг друга (или логически
эквивалентны), компиляция завершается ошибкой `FLICK-F012` с указанием обеих
строк. Неизвестные теги окружения в условии `when` сообщают `FLICK-P066`.

**Граница доверия и проверка соответствия.** Привязка `@native` — обещание
наблюдаемой эквивалентности телу на Flick (результаты, ошибки и эффекты);
компилятор не доказывает эквивалентность статически. В release-сборках
оптимизатор считает переопределённую функцию непрозрачной и не встраивает и не
сворачивает её. Флаг `--no-native-overrides` для `flick build`, `flick run`,
`flick test` и `flick inspect` понижает резервные тела на Flick вместо
переопределений, продолжая проверять все условия и метаданные `@native` — это
позволяет наборам тестов проверять соответствие переопределений и резервных тел
в профилях debug и release.

## Go-target

На Go-target не относительная привязка пакета Go, например `foreign hypot from "math" "Hypot"`
(или квалифицированное глобальное имя пакета Go вроде `"math.Hypot"` и `"strings.HasPrefix"`),
автоматически добавляет импорт пакета Go в сгенерированный модуль и порождает типизированные
преобразования по [таблице ABI значений `flick/go`](#abi-значений-flickgo):

```flick
hypot : Float -> Float -> Float
foreign pure hypot from "math" "Hypot"

to_upper : String -> String
foreign pure to_upper from "strings" "ToUpper"

cut_prefix : String -> String -> Option String
foreign pure cut_prefix from "strings" "CutPrefix"
```

- **Скаляры и копии:** `Int` (`int32`), `Float` (`float64`), `Bool` (`bool`) и `String` (`string`)
  передаются напрямую в своих типах Go; `Bytes` (`[]byte`) и `List a` (`[]T`) копируются на
  границе, чтобы изменения со стороны хоста не затрагивали значения Flick.
- **`Option a`:** передаётся как указатель Go `*T` там, где `nil` однозначно означает `None`
  (параметры, элементы срезов и возвращаемые значения с `nullable`), и использует флаг присутствия
  `(T, bool)` (для возвратов Go с проверкой `ok` вроде `os.LookupEnv` и `strings.CutPrefix`) либо
  `struct{ Val T; Ok bool }` при вложенном `Option` или непрозрачном дескрипторе, сохраняя
  различие между `None`, `Some None` и `Some (Some x)`.
- **Ошибки и отмена:** `catch f` (где `f : String -> E`) преобразует завершающий возврат `error`
  в Go — `(T, error)` или одиночный `error` при возврате `Unit` — в типизированный сбой Flick;
  привязка `Async` передаёт первым аргументом `context.Context`, который отменяется при прерывании
  файбера Flick, пока ближайший владелец ждёт возврата вызова.
- **Сторонние модули Go:** пакеты объявляют внешние модули Go в `[target.go.dependencies]` файла
  `flick.toml` (например `"github.com/google/uuid" = "v1.6.0"`), а `flick/go` автоматически
  генерирует `go.mod` и `go.sum` программы (см.
  [Целевые пакеты библиотеки](../project/#целевые-пакеты-библиотеки)).
- **Типы вне таблицы:** прямые привязки пакетов Go отклоняют типы вне таблицы `flick.go-ffi`
  (`BigInt`, записи, ADT, кортежи, функции обратного вызова, `Result`, `JsValue` и др.) на спане
  привязки с кодом `FLICK-F013` и причиной отказа из таблицы.

Привязка к модулю самой программы — по относительному пути,
`./timers.mjs` — или привязка `from inline` сохраняет запасной путь через `flickrt.Value` для
типов вне таблицы. Относительный путь вызывает Go-функцию с тем же именем из `timers.go` рядом с
ним; сборка копирует этот файл в Go-модуль, а без него привязка —
`FLICK-P012` с именем файла, который нужно добавить. Файл объявляет
`package main` и импортирует `flick.app/flickrt`. Его функции принимают и
возвращают `flickrt.Value` в представлении Go-target (см.
[Генерацию кода](../codegen/#go-target)) и получают все аргументы привязки
сразу; `()` у `arity 0` не добавляет аргумента Flick:

| Режим | Go-функция |
| - | - |
| `pure`, `sync` | `f(fb *flickrt.Fiber, a0, a1, …)` |
| `effect` | `f(fb *flickrt.Fiber, a0, …)`: выполняется в вызывающем волокне и захватывает ресурсы в scope вокруг вызова через `flickrt.AcquireRelease` |
| `async` | `f(ctx flickrt.Context, a0, …)` в собственной goroutine: прерывание отменяет `ctx`, а ближайший owner ждёт возврата вызова, прежде чем освобождать ресурсы, — как ждёт promise |

Чистые вызовы тоже получают исполняющее волокно: зависящее от контекста
отображение не должно сохранять волокно, в котором создали функцию.
`flickrt.Fn` принимает `(*flickrt.Fiber, flickrt.Value)`, а `flickrt.Poly` —
`(*flickrt.Fiber, ...flickrt.Value)`; оба возвращают `flickrt.Value`.
В `flickrt.Apply(fb, f, arg)` и `flickrt.Inst(fb, f, dictionaries...)`
передаётся волокно текущего вызова. `nil` допустим только при инициализации
модуля или в неизменяемых метаданных схем вне исполнения программы. Этот
скрытый контекст не делает чистую стадию Flick эффектной.

Panic — дефект, если не перехвачен через `catch`. Метаданные привязок
(`catch`, `this`, `optional`, `variadic` и `callbacks`) транслируются во
вспомогательные функции рантайма `flickrt` (`OptVal`, `CatchForeign`, `CallMethod`, `WrapCallback`).
Представление значений в Go — ещё не стабильный интерфейс: Go-файл должен соответствовать версии компилятора,
которым его собирают.

## Условия окружения и хост-пакеты

Внешние модули, привязывающие API конкретного бэкенда, среды выполнения или
хоста, помечают заголовок модуля атрибутом `@when "<cond>"` (или ограничивают
всю библиотеку полем `[package] when = "<cond>"` в `flick.toml`):

```flick
@when "js && node"
module App.NodeFs exposing (exists)

exists : String ->{} Bool
foreign exists from "node:fs" "existsSync"
  arity 1
```

Условие объединяет теги бэкенда, осей и хоста операторами `&&`, `||`, `!` и
скобками (см. [Окружения, хост-пакеты и условия `when`](../project/#окружения-хост-пакеты-и-условия-when)).
Неизвестные теги сразу дают `FLICK-P066` в условии, а достижимые из входа или
публичного экспорта библиотеки обращения в неподходящем окружении —
`FLICK-P064` на месте использования с путём от входа. Неиспользуемые импорты и
недостижимые функции не считаются ошибкой, поэтому общие модули могут
передавать типы или разделять привязки по хостам, не ломая переносимые сборки.

Пакеты FFI для конкретного хоста могут также публиковать раздел `[host]`
(`name`, `backend`, необязательный `requires` и `tags`), чтобы проекты выбирали
их через `[build] environment = "<backend>/<host>"` и ограничивали модули по
тегам этого хоста.

## Импорт `.d.ts` пакета

`flick ffi import <package> --out <dir>` читает объявления установленного
пакета с помощью TypeScript и записывает `<dir>/<Pkg>/Generated.fl` с модулем
`<Dir>.<Pkg>.Generated` (`date-fns` → `DateFns`) и отчётом по каждому
выбранному экспорту. `ffi` — команда JavaScript-бэкенда (полное имя —
`flick js:ffi import`, см. [Добавленные команды](../commands/)). Она
запускает импортёр, который установлен в проекте
(`pnpm add -D @flick-lang/dts-importer`), закреплённым `node`. Проект
должен разрешить его бэкенду:

```toml
[tools]
"flick/js" = ["node"]
```

Подпути пакетов и npm-псевдонимы сохраняют точную строку импорта из команды.
Настоящее имя пакета используется для определения версии, а не для замены пути.
`--select a,b` ограничивает импорт перечисленными экспортами.
Каждому экспорту присваивается один из статусов:

| Статус | Что генерируется |
| - | - |
| поддерживается | привязка `foreign` с `/// <pkg>@<ver> sha256:…` над ней |
| нужна политика | `foreign blocked name "needs policy: …"`: нужны сведения, которых нет в `.d.ts` |
| не поддерживается | `foreign blocked name "unsupported: …"`: экспорт вне поддерживаемого подмножества |

Использование `foreign blocked` приводит к `FLICK-F005`.
Остальные экспорты пакета остаются доступными. Если заблокированный экспорт
явно запрошен через `--select`, импорт тоже завершается ошибкой.

Импортёр не выводит свойства, которых нет в объявлении.
Обычный вызов получает режим `sync` (`Unit ->{} Float` для
`nextId(): number`); чистота `pure` не выводится.

| TypeScript | Flick |
| - | - |
| `string`, `number`, `boolean`, `bigint` | `String`, `Float`, `Bool`, `BigInt` |
| результат `void`, `undefined` | `Unit` |
| `any`, `unknown` | `JsValue`; отклоняется при `strict = true` |
| `T[]`, `[A, B]` | `List T`, `(A, B)` |
| `x?: T`, `x: T \| undefined` | `Option T` с `optional i` |
| `...xs: T[]` | `List T` с `variadic` |
| `<T>` без ограничений | `forall t.`, если `T` встречается в параметре |
| экземпляр класса, `Date`, именованный объектный тип | непрозрачный `type` сгенерированного модуля; если пакет экспортирует этот тип или он есть в глобальной области (`Date`, `Intl.DateTimeFormatOptions`), [форма `@ts`](../codegen/#форма-типа) говорит об этом, и сгенерированные объявления называют этот тип, а не метку |
| `type Method = "GET" \| "POST"` | перечисление `untagged type Method` сгенерированного модуля |
| функция обратного вызова `(a: A) => B` | чистая `(A -> B)`; требуется `retention` |
| результат `Promise<T>` | строка с `Async`; требуется `catch` |
| результат `T \| undefined` или `T \| null` | `Option T` с `nullable`; требуется `undefined = "none"` |
| перегрузки с разным количеством параметров | по одной привязке для каждой, `name_<n>` |

Не поддерживаются прочие объединения, литеральные типы, пересечения, параметры
типов с ограничениями и параметры типов, встречающиеся только в результате,
параметры `this`, аргументы `null`, объектные аргументы с неименованной
структурой, возвращаемые функции, сам класс (`typeof C`) и имя типа, которое
пакет объявляет дважды (два `Options` в разных файлах). Для каждого случая
указывается причина.
Завершающий необязательный параметр такого типа опускается с примечанием.

Алиас `type`, все члены которого — строковые литералы или все — целые
числа, становится перечислением: `untagged type Method = Get = "GET" |
Post = "POST"`. JS видит его значения как сами литералы. Конструктор
строкового литерала — его слова в PascalCase (`"content-type"` →
`ContentType`). Имена в политике нужны литералу, из которого такое имя не
получается, каждому целому числу, а также двум литералам или двум
перечислениям с одинаковым конструктором. Объединение литералов без алиаса
или со смесью строк, чисел и булевых значений не поддерживается. Если
объединение получает имя в `.d.ts`, отпечаток не меняется.

Политики задаются в `<dir>/<Pkg>/policy.toml`.
Команда импорта читает этот файл, но никогда не записывает его:

```toml
strict = false             # true: `any` and `unknown` are refused

[exports.lookup]
undefined = "none"         # an undefined or null result is None
catch = "JsError"          # a throw or rejection becomes JsError
cancel = "signal"          # an async call gets an AbortSignal
# mode = "pure"            # trust the call to be pure
# retention = "call"       # or "owner": how long JS keeps a callback

[enums.Status]             # constructor names of an enum, by literal
200 = "Ok"
404 = "Missing"
```

Для объявления `export declare function lookup(id: string): Promise<string | undefined>`
эта политика создаёт привязку:

```flick
# import JsError exposing (JsError)
#
lookup : String ->{Async; JsError} Option String
foreign lookup from "lookup-lib" "lookup"
  arity 1
  catch JsError.from_js
  nullable
```

В редакторе на строке заголовка `// flick ffi import <pkg> [--select a,b]`
доступно действие «Regenerate from `<pkg>@<version>`». Оно заменяет файл тем,
что сейчас записала бы `flick ffi import` с учётом `policy.toml` рядом
с файлом; имя модуля берётся из пути файла. Файл из одной строки заголовка —
заготовка: действие записывает в него весь модуль. Объявления читает тот же
вспомогательный инструмент; если его не удаётся запустить, действие
показывается недоступным с указанием причины.

### Проверенные привязки и `ffi check`

Команда импорта записывает только `Generated.fl`.
Проверенную вручную привязку нужно поместить в собственный модуль,
обычно `<dir>/<Pkg>.fl`, и реэкспортировать из него остальные имена.
В `reviewed` указывается объявление, по которому проверена привязка.
Нужная строка приведена над экспортом в сгенерированном модуле:

```flick
# import JsError exposing (JsError)
#
lookup : String ->{Async; JsError} Option String
foreign lookup from "lookup-lib" "lookup"
  arity 1
  catch JsError.from_js
  nullable
  reviewed "lookup-lib@1.0.0 sha256:6fa1…"
```

`flick ffi check` проверяет корень исходного кода проекта или указанные пути.
Команда заново импортирует каждый пакет и сообщает об ошибках:

- Сгенерированный модуль отличается от нового импорта — `FLICK-F006`.
- У проверенной привязки изменилось или исчезло исходное объявление
  либо не хватает обязательных метаданных: `catch` для Promise,
  `nullable` для пустого результата, `retention` для функции обратного вызова —
  `FLICK-F007`.
- Политика ссылается на экспорт, которого нет в пакете, — `FLICK-F008`.
