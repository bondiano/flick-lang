Во Flick три числовых типа: `Int`, `Float` и `BigInt`, и неявных
преобразований между ними нет (см. [Schema и стандартные типы данных](../../spec/07-schema/)).
Их правила одинаковы в debug и release на JS и Go. Пользовательских
операторов нет; приоритеты встроенных приведены в
[таблице операторов](../syntax/#таблица-операторов).

## Числовые типы

| Тип | Значения | Арифметика |
| - | - | - |
| `Int` | 32-битные целые со знаком | по модулю 2³²: `2147483647 + 1 == -2147483648`; `/` отбрасывает дробную часть (`7 / 2 == 3`, `-7 / 2 == -3`); `/` и `%` на ноль дают `0` |
| `Float` | IEEE 754 binary64, число JS | `0.0 / 0.0` — NaN, `1.0 / 0.0` — `Infinity`; `==` — SameValueZero |
| `BigInt` | целые любого размера | `/` отбрасывает дробную часть; `/` и `%` на ноль дают `0n` |

Целочисленный литерал (`3`, `0xFF`, `1_000`) получает тот числовой тип,
которого требует его использование, а если ничто не требует — `Int`:
`let ratio : Float = 3` и `3 + 0.5` дают `Float`, `3 + 4n` — `BigInt`.
Литерал с дробной частью или экспонентой (`3.0`, `1e3`) — `Float`. Литерал
вне диапазона своего типа вызывает `FLICK-T003`. Если тип литерала решает
только ограничение класса, берётся первый из `Int`, `Float`, `BigInt`, для
которого есть подходящий инстанс.

Счётчики, размеры, индексы, хэши и части даты во всей стандартной
библиотеке — `Int` (`List.length`, `HashMap.size`, `Hash.hash`,
`Queue.size`, `Schedule.recurs`, части `DateTime`); миллисекунды, эпохи,
размеры в байтах и измерения остаются `Float`: в 32 бита они не помещаются.

## Переполнение и деление

Выбирайте поведение при ошибке в месте вызова:

| Форма | Переполнение | Нулевой делитель |
| --- | --- | --- |
| Обычные операторы `Int` | Циклическое переполнение в знаковых 32 битах | `/` и `%` дают `0` |
| `Int.checked_add`, `checked_sub`, `checked_mul`, `checked_div`, `checked_rem` | Возвращают `Err Int.ArithmeticError`, если результат не помещается | Деление и остаток возвращают `Err` |
| `Int.unsafe_div`, `unsafe_rem` | Сохраняют обычное поведение целых | Вызывают дефект |
| Обычные операторы `BigInt` | Произвольная точность в пределах доступной памяти | `/` и `%` дают `0n` |
| `BigInt.divide`, `BigInt.remainder` | Произвольная точность | Возвращают `Err Int.ArithmeticError` |

Арифметический дефект подчиняется обычным правилам завершения и cleanup.
Это не типизированная арифметическая ошибка. Для ненадёжного ввода используйте
checked-форму, если вызывающему коду нужно обработать неверную арифметику как
данные.

```flick
wrapped : Int
let wrapped = 2147483647 + 1

checked : Result Int.ArithmeticError Int
let checked = Int.checked_div (-2147483648) (-1)

ordinary : BigInt
let ordinary = 5n / 0n
```

`wrapped` равен `-2147483648`; `checked` содержит ошибку, поскольку
положительное `2147483648` не помещается в `Int`; `ordinary` равен `0n`.
`Int.checked_rem (-2147483648) (-1)` успешно возвращает `Ok 0`.

Целочисленное деление усекается к нулю, а остаток сохраняет знак делимого:
`-7 / 2` равно `-3`, `-7 % 2` равно `-1`. Степени `Int` переполняются
циклически; отрицательные степени усекаются, поэтому `2 ** -1` равно `0`.
Отрицательная степень `BigInt` вызывает дефект.

Преобразования: `Int.to_float`, `Int.from_float` и `Int.truncate`.
`Int.from_float` принимает только конечные целые значения в знаковом
32-битном диапазоне, а для остальных даёт `None`. `Int.truncate` отбрасывает
дробную часть и циклически переполняется, а для NaN и бесконечностей даёт
ноль. `BigInt.from_number` отвергает дроби и неконечные значения;
`BigInt.to_number` округляет до binary64 и может терять точность целого.

`Int.parse` отбрасывает начальные и конечные пробельные символы и переводы
строк ECMAScript (`\t`, `\n`, `\v`, `\f`, `\r`, пробел, U+00A0, U+1680,
U+2000–U+200A, U+2028, U+2029, U+202F, U+205F, U+3000 и U+FEFF; но не U+0085),
затем требует необязательный ASCII-знак `+` или `-` и одну или более
десятичных ASCII-цифр в диапазоне `-2147483648..2147483647`. Отрицательный
ноль нормализуется к `0`. Пустая строка, строка только со знаком, внутренние
пробелы, недесятичный текст и значения вне диапазона возвращают `None`.

## Числа с плавающей точкой

`Float` — IEEE 754 binary64 со знаковым нулём, NaN и бесконечностями.
Структурное `==` использует SameValueZero: NaN равен себе, а оба нуля равны.
Числовые `<`, `<=`, `>` и `>=` оставляют NaN неупорядоченным; `compare`
задаёт полный порядок с NaN в конце. `Float.same_value` отличает
отрицательный ноль от положительного. `show` сохраняет `-0`;
`Float.round` округляет половины к положительной бесконечности, поэтому
`Float.round (-2.5)` равно `-2`.

Эти правила обязательны и для оптимизаций, и для будущих бэкендов. Другое
представление или машинная инструкция должны сохранять результаты,
дефекты и cleanup.

## Операторы

| Операторы | Операнды | Результат |
| - | - | - |
| `+ - * / % **`, префиксный `-` | оба `Int`, оба `Float` или оба `BigInt` | тот же тип |
| `++` | оба `String` или оба `List a` | тот же тип |
| `< <= > >=` | оба `Int`, `Float`, `BigInt` или `String` либо оба другого типа с `Ord` | `Bool` |
| `== !=` | одного типа | `Bool` |
| `&& \|\|`, `not` | `Bool` | `Bool` |
| `option orelse fallback` | `Option a` и `a` | `a` (вычисляет `fallback` только при `None`) |
| `x \|> f`, `f <\| x` | `f x` | результат `f` |
| `f >> g`, `g << f` | функции | функция, которая применяет `f`, затем `g` |

`x |> f` вычисляет сначала `x`, `f <| x` — сначала `f`, как и `f x`;
`f a <| x` — вызов `f a x`. Композиция — это замыкание `let f' = f;
let g' = g; fun x -> g' (f' x)`: она вычисляет операнды один раз, слева
направо, там, где записана, и получает тип этого замыкания. В её стрелке
ряды вызовов, которые она делает: композиция двух чистых функций чиста,
а `show >> Platform.stdout_line` — функция времени выполнения. Композиция
удерживает то же, что её операнды ([регионы](../regions/)). В release-сборке
замыкания там, где композицию применяют, нет: `(f >> g) x` — это `g (f x)`.

`1.5 + 1n` и `"a" ++ 1` вызывают `FLICK-T003`. Если тип операнда не следует
из других условий, выбирается `Int`, а для `++` — `String`. Диапазоны `a..b`,
`a..<b` и `a..` считают в `Int`.

`left orelse right` — ленивый fallback для `Option`, эквивалентный
`match left with | Some value -> value | None -> right`. Левая часть
вычисляется один раз, а правая — не более одного раза и только если слева
оказалось `None`. Если левая часть завершилась типизированной ошибкой или
дефектом, правая часть не выполняется. Оператор снимает ровно один слой
`Option` (`Some None orelse Some 1` даёт `None : Option Int`), не запускает
холодные значения `Eff` и `Lazy` и позволяет правой части завершаться ошибкой
в строку ошибок функции (например, `opt orelse Fail.fail Missing`). В отличие
от `Option.with_default`, который энергично вычисляет значение по умолчанию
до вызова, `orelse` не вычисляет дорогой или эффектный fallback при `Some`.

```flick
fallback : Option String -> String
let fallback host = host orelse "localhost"

first_valid : Option Int -> Option Int -> Int
let first_valid a b = a orelse b orelse 8080

nested_layer : Option (Option Int) -> Option Int
let nested_layer value = value orelse Some 1
```

## Числовые классы

Одна функция для всех числовых типов пишется через закрытые классы модуля
`Numeric`: `Numeric a` (`Int`, `Float`, `BigInt`), `Integer a` (`Int`,
`BigInt`) и `Floating a` (`Float`). На переменной типа с таким ограничением
операторы и целочисленные литералы используют его методы (`add`, `div`,
`from_int`, …); литералу с дробной частью нужен `Floating`. Все инстансы
объявлены в самом модуле, программа не может объявить свой (`FLICK-C012`).

```flick
import Numeric exposing (Floating, Numeric)

square : Numeric a => a -> a
let square x = x * x

mean : Floating a => List a -> a
let mean xs = List.sum xs / Numeric.from_int (List.length xs)
```

`List.sum` и `List.product` принимают любой `Numeric`. Без ограничения
`x + 1` на переменной типа вызывает `FLICK-C001`. `< <= > >=` на переменной
типа с числовым классом используют его `lt`, `le`, `gt`, `ge` и значат то же,
что эти операторы на её типе (NaN не упорядочен); если есть только `Ord a`,
сравнение идёт через `compare`. На любом другом типе, например `Bool`,
выведенном типе, записи или списке, они сравнивают через `compare` его
экземпляра `Ord`; тип без него вызывает `FLICK-C001`.
