Во Flick три числовых типа: `Int`, `Float` и `BigInt`. Их правила одинаковы
в debug и release на JS и Go. Литералы, преобразования и числовые классы
описаны в [типах и операторах](../types/#числа-и-операторы).

Выбирайте поведение при ошибке в месте вызова:

| Форма | Переполнение | Нулевой делитель |
| --- | --- | --- |
| Обычные операторы `Int` | Циклическое переполнение в знаковых 32 битах | `/` и `%` дают `0` |
| `Int.checked_add`, `checked_sub`, `checked_mul`, `checked_div`, `checked_rem` | Возвращают `Err Int.ArithmeticError`, если результат не помещается | Деление и остаток возвращают `Err` |
| `Int.unsafe_div`, `unsafe_rem` | Сохраняют обычное поведение целых | Вызывают дефект |
| Обычные операторы `BigInt` | Произвольная точность в пределах доступной памяти | `/` и `%` дают `0n` |
| `BigInt.divide`, `BigInt.remainder` | Произвольная точность | Возвращают `Err Int.ArithmeticError` |

Арифметический дефект подчиняется обычным правилам завершения и cleanup.
Это не типизированная арифметическая ошибка. Для ненадёжного ввода используйте
checked-форму, если вызывающему коду нужно обработать неверную арифметику как
данные.

```flick
wrapped : Int
let wrapped = 2147483647 + 1

checked : Result Int.ArithmeticError Int
let checked = Int.checked_div (-2147483648) (-1)

ordinary : BigInt
let ordinary = 5n / 0n
```

`wrapped` равен `-2147483648`; `checked` содержит ошибку, поскольку
положительное `2147483648` не помещается в `Int`; `ordinary` равен `0n`.
`Int.checked_rem (-2147483648) (-1)` успешно возвращает `Ok 0`.

Целочисленное деление усекается к нулю, а остаток сохраняет знак делимого:
`-7 / 2` равно `-3`, `-7 % 2` равно `-1`. Степени `Int` переполняются
циклически; отрицательные степени усекаются, поэтому `2 ** -1` равно `0`.
Отрицательная степень `BigInt` вызывает дефект.

`Int.from_float` принимает только конечные целые значения в знаковом
32-битном диапазоне. `Int.truncate` отбрасывает дробную часть и циклически
переполняется, а для NaN и бесконечностей даёт ноль. `BigInt.from_number`
отвергает дроби и неконечные значения; `BigInt.to_number` округляет до
binary64 и может терять точность целого.

`Float` — IEEE 754 binary64 со знаковым нулём, NaN и бесконечностями.
Структурное `==` использует SameValueZero: NaN равен себе, а оба нуля равны.
Числовые `<`, `<=`, `>` и `>=` оставляют NaN неупорядоченным; `compare`
задаёт полный порядок с NaN в конце. `Float.same_value` отличает
отрицательный ноль от положительного. `show` сохраняет `-0`;
`Float.round` округляет половины к положительной бесконечности, поэтому
`Float.round (-2.5)` равно `-2`.

Эти правила обязательны и для оптимизаций, и для будущих бэкендов. Другое
представление или машинная инструкция должны сохранять результаты,
дефекты и cleanup.
