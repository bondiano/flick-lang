---
title: "`.iface` — нативный интерфейс модуля"
---

Файл `.iface` описывает то, что предоставляет модуль, в форме, необходимой
проверяющему модулю, чтобы импортирующий модуль никогда не читал, не разбирал
и не проверял исходник этого модуля повторно (см. [Компилятор Flick и интеграция с Content Mapper](../../spec/11-compiler/)). Это версионированный JSON.
`.d.ts` — лишь проекция для TypeScript; `.iface` — источник истины для
импортирующих модулей Flick.

До версии 0.1.0 схема развивается вместе с компилятором: каждое изменение
повышает `iface-version`, а компилятор отклоняет любую версию, кроме своей,
с `FLICK-P010`. Релиз 0.1.0 фиксирует версию, с которой он поставляется.

## Версия 5

```json
{
  "iface-version": 1,
  "language": "0.7",
  "module": "App.Shapes",
  "exports": [
    { "module": "App.Shapes", "namespace": "type", "name": "Shape", "decl": "adt" },
    { "module": "App.Shapes", "namespace": "constructor", "name": "Circle", "decl": "constructor", "parent": "Shape" },
    { "module": "App.Shapes", "namespace": "type", "name": "Id", "decl": "opaque" },
    { "module": "App.Domain", "namespace": "type", "name": "User", "decl": "alias" },
    { "module": "App.Shapes", "namespace": "value", "name": "area", "decl": "let" }
  ],
  "hidden": [
    { "name": "Square", "parent": "Shape" }
  ]
}
```

| Поле | Значение |
| - | - |
| `iface-version` | версия схемы; должна совпадать с версией компилятора |
| `language` | версия языка Flick у компилятора, записавшего файл; должна совпадать с версией читающего компилятора |
| `module` | полное имя описываемого модуля |
| `exports` | интерфейс модуля в порядке его списка `exposing` |
| `hidden` | неэкспортируемые конструкторы экспортируемых типов, чтобы при попытке их импорта выдавалась точная диагностика `FLICK-R005`; опускается, если пусто |
| `instances` | экземпляры классов этого модуля и всех модулей, от которых он зависит, кроме встроенных; опускается, если пусто |
| `abi` | то, как скомпилированный код представляет определения модуля, см. [ABI](#abi); записывается командой `flick build`, отсутствует при `flick check` |
| `dependencies` | отпечаток интерфейса каждого импортируемого модуля, с которым был собран модуль; опускается, если пусто |
| `source` | исходник модуля относительно корня его пакета, чтобы редакторы находили объявления в опубликованном пакете; записывается командой `flick build` |

Каждый экспорт обозначает **сущность** через `module`, `namespace` и `name`.
`module` — место, где сущность *определена*: реэкспорт сохраняет определяющий
модуль, благодаря чему импортирующие модули распознают, что два имени обозначают
одну сущность (выше `User` реэкспортирован из `App.Domain`).

| `namespace` | Сущности |
| - | - |
| `value` | `let`, `foreign`, методы классов |
| `type` | типы, `error`, `kind` и его члены, сервисы, классы |
| `constructor` | конструкторы ADT, конструктор `error` |

| `decl` | Объявление | `parent` |
| - | - | - |
| `let` | `let` или сигнатура, определение которой проверяется позже | — |
| `foreign` | `foreign` | — |
| `method` | сигнатура метода класса | класс |
| `adt` | `type T = A \| B` | — |
| `alias` | `type alias T = …` | — |
| `opaque` | `opaque type` | — |
| `refined` | `refined type` | — |
| `abstract` | `type T` без определения | — |
| `error` | `type error E …` | — |
| `kind` | `kind K = …` | — |
| `kind-member` | член `kind` | кинд |
| `service` | `service` | — |
| `class` | `class` | — |
| `constructor` | конструктор | его тип |

`T(..)` в импорте открывает экспорты, у которых `parent` равен `T`.

Экспортируемый тип также экспортирует свои сопутствующие значения как сущности
`value` с именами `T$member`, которые невозможно записать как имя в исходнике
(`T$table` у `sql table`): `T$schema` у типа с выведенным `Schema`, `T$parse` и
`T$value` у уточнённого типа и `T$json` у уточнённого типа со схемой. `schema T`
и `T.parse` обращаются к ним. Экспорт объявления этого модуля имеет `at` —
диапазон байтов UTF-8 его имени в `source`. В `definition` класса список
`defaults` перечисляет методы с определением по умолчанию.

### Типы и кинды

Проверяющий модуль импортирующей стороны получает типы зависимости только из
её интерфейса, никогда из исходника. Модуль с синтаксическими ошибками не
проходит проверку типов; его экспорты не содержат типов, и импортирующие
модули допускают любое их использование.

| Поле | Где используется | Содержимое |
| - | - | - |
| `type` | значения, конструкторы | полный тип: `forall` с киндами переменных, ограничениями, стрелками эффектов и строками |
| `definition` | типы, ошибки, сервисы, классы, кинды | `kind` и `form`, см. ниже |

```json
{ "module": "App.Shapes", "namespace": "value", "name": "wrap", "decl": "let",
  "type": { "forall": {
    "vars": [ { "name": "f", "kind": { "arrow": ["type", "type"] } }, { "name": "a", "kind": "type" } ],
    "body": { "fun": {
      "param": { "app": { "head": { "var": "f" }, "arg": { "var": "a" } } },
      "result": { "record": { "entries": [ ["value", { "app": { "head": { "var": "f" }, "arg": { "var": "a" } } }] ] } }
    } }
  } } }
```

Типы — объекты с тегами; строка содержит `entries`, отсортированные по метке,
и необязательный `tail`. Элементы строки записи помечаются именами полей,
элементы строки сервисов или ошибок — именем `Module.Name` элемента,
элементы строки захватов — `^` и переменной региона.

| Тип | JSON |
| - | - |
| `Number` | `{ "con": { "module": "Prelude", "name": "Number" } }` |
| переменная типа `a` | `{ "var": "a" }` |
| `F a` | `{ "app": { "head": F, "arg": a } }` |
| `a -> b` | `{ "fun": { "param": a, "result": b } }` |
| `a ->{r; e} b` | `{ "fun": { "param": a, "effects": { "services": r, "errors": e }, "result": b } }` |
| `(a, b)` | `{ "tuple": [a, b] }` |
| `{ x : T \| r }` | `{ "record": { "entries": [["x", T]], "tail": r } }` |
| `{Users \| r}`, `none` | `{ "row": { "entries": [["App.Users.Users", …]], "tail": r } }`, `{ "row": { "entries": [] } }` |
| `r1 + r2` | `{ "union": [r1, r2] }` |
| `T^{s}` | `{ "captured": { "ty": T, "captures": { "row": { "entries": [["^s", { "var": "s" }]] } } } }` |
| `forall a. C a => T` | `{ "forall": { "vars": [{ "name": "a", "kind": K }], "constraints": [C a], "body": T } }` |

Кинды представлены как `"type"`, `"service-row"`, `"error-row"`, `"capture-row"`,
`"symbol"`, `"region"`, `"constraint"`, `"service"` (элемент строки сервисов),
`{ "row": K }`, `{ "named": { "module": …, "name": … } }` для объявления `kind`
и `{ "arrow": [K1, K2] }`.

| `form` | Поля | Объявление |
| - | - | - |
| `nominal` | — | встроенный тип, `type T`, `opaque type`, `refined type`; также непрозрачный ADT, конструкторы которого остаются скрытыми |
| `adt` | `constructors` | варианты, все конструкторы, включая неэкспортируемые (для проверки полноты сопоставления) |
| `error` | — | `type error E …`; его конструктор — `E` |
| `alias` | `params`, `body` | прозрачный псевдоним |
| `service` | `params`, `operations` (`name`, `type`) | `service`; `operations` содержит типы в том виде, в котором они объявлены, без самого сервиса, а импортирующий модуль выводит из них `S.Impl` |
| `class` | `params`, `supers`, `fundeps` (`from`, `to`: позиции параметров), `methods` | `class`; методы — экспорты `value`, тип которых начинается с ограничения класса |
| `kind` | — | `kind K = …`; `kind` — обозначаемый им кинд |
| `kind-member` | — | член `kind` |

Прозрачные псевдонимы разворачиваются в каждом экспортируемом типе, поэтому
импортирующему модулю никогда не нужен псевдоним из модуля, который он не
импортирует. Непрозрачный тип за пределами своего модуля имеет форму `nominal`:
импортирующие модули не видят его представления.

### Экземпляры классов

```json
{ "module": "App.Shapes", "name": "Show (List a)",
  "vars": [ { "name": "a", "kind": "type" } ],
  "context": [ { "app": { "head": { "con": { "module": "App.Shapes", "name": "Show" } }, "arg": { "var": "a" } } } ],
  "head": { "app": { "head": { "con": { "module": "App.Shapes", "name": "Show" } },
                     "arg": { "app": { "head": { "con": { "module": "Prelude", "name": "List" } }, "arg": { "var": "a" } } } } } }
```

`module` указывает модуль, объявляющий экземпляр класса, а `name` — его
заголовок в исходном написании; `head` и `context` используют переменные из
`vars`, с развёрнутыми прозрачными псевдонимами. Импортирующий модуль проверяет
свои экземпляры классов на пересечение и соблюдение функциональных зависимостей
с учётом этих экземпляров и использует их для разрешения ограничений.

### ABI

```json
"abi": {
  "data": [ { "type": "Shape", "constructors": [
    { "name": "Circle", "tag": "@acme/shapes/App.Shapes.Shape.Circle", "arity": 1 } ] } ],
  "dictionaries": [ { "instance": "Show (List a)", "export": "$i_Show_List_a_19082212",
    "context": 1, "methods": ["show"], "supers": [] } ],
  "values": [ { "name": "area", "stages": ".", "dicts": 0, "partial": false } ]
}
```

| Поле | Содержимое |
| - | - |
| `data` | каждый тип и ошибка, объявленные модулем, с их конструкторами: `id` — полное имя (пакет, модуль, тип, конструктор), `tag` — `_tag` их значений, состоящий из имени и хеша `id` (отсутствует у типов `unboxed` или `untagged`, значения которых представлены их полем), `arity` — поля `_0` … |
| `dictionaries` | каждый экземпляр класса, объявленный модулем: JS-экспорт `export` его словаря, количество принимаемых им словарей контекста, его `methods` и суперклассы, для которых у него есть геттер `$Class` |
| `values` | каждое экспортируемое значение: `stages` содержит по одному символу на параметр его определения, `.` для чистой стрелки и `!` для стрелки среды выполнения; `dicts` — число словарей, которые оно принимает первыми; `partial` равно `false`, только если применение ко всем его параметрам гарантированно не выбрасывает исключений и не расходится |

Представление, обозначаемое этими полями, описано в разделе [генерации кода](../codegen/).

### Отпечатки

Отпечаток интерфейса — 64-битный хеш FNV-1a в виде 16 шестнадцатеричных цифр,
вычисленный по его JSON без `dependencies`, `source` и `at` экспортов:
перемещение объявления ничего не меняет для импортирующих модулей. Равные
отпечатки означают, что код, скомпилированный с одним интерфейсом, корректен и
с другим. `dependencies` записывает отпечаток интерфейса каждого импортируемого
модуля на момент сборки; если модуль установленного пакета был собран с иным
интерфейсом зависимости, чем установленный, импортирующий модуль сообщает
`FLICK-P014`.

## Расположение в пакете

Пакет указывает каталог своих интерфейсов в `package.json`, а модуль `A.B`
описывается файлом `<iface-dir>/A/B.iface`:

```json
{ "name": "@acme/text", "flick": { "iface-dir": "iface" } }
```

Скомпилированный модуль находится рядом со своим интерфейсом, а импортирующий
его код импортирует `<package>/<iface-dir>/A/B.js`: с указанным выше полем
модуль `Text.Shout` из `@acme/text` — это `@acme/text/iface/Text/Shout.js`.
Пакет, объявляющий `exports`, должен экспортировать этот путь. `flick build`
записывает `A/B.iface` рядом с `A/B.js` в выходном каталоге, поэтому выходной
каталог служит `iface-dir`; `flick pack` записывает поле в `package.json`.
Вручную их никто не редактирует.
