title: "Проект"
---

Проект — это каталог с `flick.toml` (§12). Команды ищут ближайший
`flick.toml`, начиная с рабочего каталога и поднимаясь вверх; `--project <path>`
позволяет явно выбрать каталог проекта или файл конфигурации.

## `flick.toml`

```toml
schema-version = 1

[project]
kind = "app"
source-dir = "src"
test-dir = "test"
entry = "App.Main"

[build]
out-dir = "dist"
profile = "debug"
emit = "js"
emit-dts = false
promise-facade = false
schema-aot = false
```

| Ключ | Значения | По умолчанию |
| - | - | - |
| `schema-version` | `1`; обязателен, проверяется раньше всего остального | — |
| `project.kind` | `"app"` или `"lib"`; обязателен | — |
| `project.source-dir` | каталог исходных модулей | `"src"` |
| `project.test-dir` | каталог тестовых модулей | `"test"` |
| `project.entry` | модуль, экспортирующий `main`; обязателен для `app` | — |
| `build.out-dir` | базовый каталог артефактов | `"dist"` |
| `build.profile` | `"debug"` или `"release"` (см. [генерацию кода](../codegen/)); `--profile` у `build` и `test` переопределяет это значение | `"debug"` |
| `build.emit` | `"js"` или `"ts"` | `"js"` |
| `build.emit-dts` | логическое значение | `false` |
| `build.promise-facade` | логическое значение | `false` |
| `build.schema-aot` | логическое значение | `false` |
| `build.solver-steps` | число шагов разрешения экземпляров классов на определение | `100000` |
| `build.solver-depth` | глубина вложенных ограничений классов | `256` |

Ошибки конфигурации приводят к завершению с кодом `2`:

| Проблема | Диагностика |
| - | - |
| синтаксис TOML, неизвестный ключ, значение неверного типа или вне допустимого набора | `FLICK-P005` |
| `schema-version` отличается от `1` или отсутствует | `FLICK-P006` |
| `kind = "app"` без `entry` | `FLICK-P007` |
| проект не найден или `--project` не указывает на проект | `FLICK-P008` |
| `entry` не является исходным модулем, экспортирующим `main` | `FLICK-P011` |

## `flick check`

Без путей `flick check` проверяет каждый модуль в корневых каталогах исходников
и тестов. При указании путей проверяются эти файлы и каталоги вместе со всеми
модулями, которые они прямо или транзитивно импортируют. Вне проекта пути обязательны.

## Пакеты

Имена пакетов, версии и зависимости хранятся в `package.json`; устанавливает
их pnpm. Flick только читает установленное дерево: для каждой зависимости из
`package.json` он читает `node_modules/<name>/package.json`. Пакет с модулями
Flick указывает каталог их интерфейсов:

```json
{ "name": "@acme/text", "flick": { "iface-dir": "iface" } }
```

Модуль `Acme.Text` этого пакета описан в `iface/Acme/Text.iface`;
формат приведён в [описании `.iface`](../iface/).

| Проблема | Диагностика |
| - | - |
| импортируемый модуль нигде не найден, при этом одна из зависимостей не установлена | `FLICK-P009`: выполните `flick install` (код выхода `2`) |
| импортируемый модуль нигде не найден | `FLICK-R003`: добавьте пакет с помощью `flick add <package>` |
| файл `.iface` некорректен, имеет другую `iface-version` или версию языка либо описывает другой модуль | `FLICK-P010` (код выхода `2`) |
| модуль пакета был собран с другим интерфейсом зависимости, а не с установленным | `FLICK-P014` |
