Модуль тестового корня записывает свои тесты блоками: `suite "name" { … }`
объединяет блоки `test "name" { … }` и вложенные наборы, а блок `test`
может стоять и сам по себе. `flick test` находит модуль, собирает его и
запускает каждый тест в собственной области.

```flick
module App.UsersTest

import Test exposing (expect, to)

suite "names" {
  test "trims the name" {
    let name = String.trim "  Ada  "
    expect name |> to.equal "Ada"
  }

  suite "empty" {
    test "stays empty" { expect (String.trim "  ") |> to.equal "" }
  }
}

test "counts" { expect (List.length [1, 2, 3]) |> to.equal 3 }
```

Блоки принадлежат плагину пакета `std` (см. [плагины](../plugins/)),
который есть в каждом модуле без импорта. Они раскрываются в вызовы `Test`:
набор становится `Test.group`, тест — `Test.effect_test name (task { body })`,
как его пишут вручную, поэтому `flick expand` показывает код, за которым
стоит каждый блок.

## Блоки

Блок начинает объявление верхнего уровня: `suite` и `test` — головы только
там, а в остальных местах это обычные имена, и `Test.test "x" (fun () -> …)`
остаётся вызовом. Объявление верхнего уровня не может начинаться со значения
с именем `suite` или `test`, но сигнатура `test : T` по-прежнему его
объявляет.

| Блок | Что в нём |
| - | - |
| `suite "name" { … }` | блоки `test` и `suite`, по одному на строку, в порядке запуска |
| `test "name" { body }` | тело теста: строки, как после `=` в `let`, или одно выражение; `{}` — для теста, которому пока нечего проверять |

Тело теста — эффектный тест, как у `Test.effect_test`: он выполняется в
собственной области, которая владеет тем, что захватило тело, с живыми
сервисами хоста (`Host.Live`), которые переживают эту область. Тест
проходит, когда тело завершилось и его область закрылась без ошибок;
сопоставитель (см. [утверждения](#утверждения)) проваливает его на неверном
утверждении, а типизированная ошибка, дефект или сбой очистки тоже
проваливают тест.

Случаи модуля — его `tests : List Test.Test`, случай каждого блока
верхнего уровня в порядке записи. Модуль экспортирует `tests`, не называя
его в `exposing`, поэтому модулю с блоками `exposing` вообще не нужен.
Модуль, в котором есть блоки и объявленный вручную `tests`, — это
`FLICK-R008`: перенесите написанные вручную тесты в блок или уберите блоки.

```flick fail R008
module App.MixedTest

tests : List Test.Test
let tests = [Test.test "by hand" (fun () -> Test.Pass)]

test "a block" {}
```

Модуль без блоков по-прежнему собирает `tests` вручную через `Test` (см.
[стандартную библиотеку](../stdlib/#тесты)): оба вида модулей запускаются
одним `flick test`.

## Утверждения

`expect actual` называет значение, которое проверяет утверждение, а
сопоставитель из `to` проверяет его: `expect total |> to.equal 3`.
Сопоставитель, которому значение не подходит, проваливает тест с
`Test.AssertionFailed`, чьё сообщение становится ошибкой `assertion` теста.

| Сопоставитель | Проходит, когда |
| - | - |
| `to.equal expected` | значение равно `expected` (`Eq`, `Show`) |
| `to.be_true` | `Bool` равен `true` |
| `to.be_greater_than bound` | значение больше `bound` (`Ord`, `Show`) |
| `to.contain item` | `List` содержит `item` |
| `to.fail_with error` | задача, которую он запускает, падает с `error` |

Упавший `to.equal` говорит, что он ожидал и что получил: `expected 3, got
4`. Если какое-то из значений в записи `show` длинное или занимает
несколько строк, он показывает их строки как diff: строки, которыми оба
начинаются и заканчиваются, — как есть, а между ними каждую ожидаемую
строку после `- ` и каждую полученную после `+ `.

```flick
module App.LookupTest

import Test exposing (expect, to)

type error NotFound = NotFound String
  deriving Eq, Show

find : String ->{; NotFound} Int
let find name = if name == "ada" then 1 else Fail.fail (NotFound name)

test "finds ada" { expect (find "ada") |> to.equal 1 }

test "misses bob" { expect (task { find "bob" }) |> to.fail_with (NotFound "bob") }
```

`Test.check assertion` проваливает тест, если `Assertion`, собранное
вручную, например `Test.equal expected actual`, не выполнено. Раньше это
был `Test.expect`, пока `expect` не стал принимать значение; `assert` —
ключевое слово.

## Тестовые компаньоны

Модуль тестового корня видит только то, что экспортируют импортированные
им модули. Чтобы протестировать то, что модуль держит при себе, напишите
его тесты в компаньоне рядом с ним: `src/App/Users.test.fl` рядом с
`src/App/Users.fl`. Компаньон начинается с заголовка самого модуля, без
`exposing`, и видит каждое объявление верхнего уровня модуля, включая
приватные значения, типы и конструкторы, без импорта:

```flick
module App.Users

# trim : String -> String
# let trim name = String.trim name
#
test "trims a name" { Test.check (Test.equal "Ada" (trim "  Ada ")) }
```

Модуль никогда не видит своего компаньона, и никакой другой модуль не может
его импортировать. Случаи компаньона называются по модулю,
`App.Users > trims a name`, и запускаются тем же `flick test`, что и случаи
тестового корня. Компаньоны читают только `flick test` и `flick fmt`, а
`flick check` — тот, который назван путём: `flick build`, любой другой
`flick check`, публикуемые `.iface` и `.d.ts`, документация API и
`flick pack` их пропускают, поэтому вывод сборки одинаков с ними и
без них. Под `flick test` код модуля с компаньоном экспортирует ему всё,
что объявляет, а то, что компаньон видит в модуле, кэшируется отдельно от
публичного интерфейса модуля. Компаньон файла, который не является модулем
корня исходников, или компаньон с заголовком другого модуля — ошибка.

## Полные имена, skip и only

Полное имя случая — имя его модуля, имена его наборов и его собственное:
`App.UsersTest > names > trims the name`. `--filter` оставляет случаи,
полное имя которых содержит текст, а два случая одного набора или два
блока одного модуля с одинаковым именем — это `std/T002`.

Модификатор после слова помечает случай и каждый случай внутри него:

| Модификатор | Значение |
| - | - |
| `test.skip`, `suite.skip` | отмечается как пропущенный и никогда не запускается |
| `test.only`, `suite.only` | пока какой-либо случай выбранных файлов помечен `only`, запуск оставляет только такие случаи, а остальные отмечает пропущенными |

```flick
module App.WipTest

suite.skip "storage" {
  test "keeps a user" {}
}

test.only "being written" { Test.check (Test.equal 2 (1 + 1)) }
```

Пропущенный случай внутри набора с `only` остаётся пропущенным. `Test.skip`
и `Test.only` так же помечают тест, собранный вручную.

## Хуки

Хуки набора выполняются вокруг тех его случаев, которые выбрал запуск,
включая случаи вложенных наборов:

| Хук | Когда выполняется |
| - | - |
| `before_all { … }` | один раз, в области набора, перед его первым выбранным случаем |
| `before_each { … }` | в области каждого выбранного случая, перед телом |
| `after_each { … }` | после каждого выбранного случая, как финализатор области случая |
| `after_all { … }` | один раз, после последнего выбранного случая набора, как финализатор области набора |

```flick
module App.StoreTest

suite "store" {
  before_all { Platform.stdout_line "open the store" }
  before_each { Platform.stdout_line "begin" }
  after_each { Platform.stdout_line "roll back" }
  after_all { Platform.stdout_line "close the store" }

  test "keeps a user" {}

  suite "names" {
    before_each { Platform.stdout_line "load the names" }
    test "trims" {}
  }
}
```

Подготовка идёт снаружи внутрь, а очистка — изнутри наружу: для `store >
names > trims` выполняются `open the store`, затем `begin`, `load the
names`, тело и `roll back`; `close the store` — после последнего случая
набора. Набор без выбранных случаев, пропущенный и отфильтрованный случаи
хуков не запускают. Хуки одного вида выполняются в порядке записи, а их
очистка — в обратном.

Упавший `before_all` сообщает о каждом выбранном случае своего набора как
об ошибке `setup` и не запускает ни один из них; упавший `before_each`
проваливает `setup` своего случая и пропускает тело. Очистка всё равно
выполняется: хуки `after_*` набора и наборов вокруг него, как и
финализаторы области случая, в том числе после таймаута или прерывания.
Упавший хук `after_*` — это ошибка `cleanup` случая рядом с его
собственной. Тело хука — задача, как и тело теста, а `Test.before_all` и
остальные добавляют хук в группу, собранную вручную.

## Таймауты

`timeout <millis>` после имени случая даёт ему столько миллисекунд на хуки
`before_each` и тело, а после имени набора — каждому случаю внутри без
собственного таймаута. Случай, у которого вышло время, прерывается, его
область закрывается, его хуки `after_*` выполняются, и о нём сообщается
как о `timeout`. `--timeout` задаёт время случаям без собственного; по
умолчанию у случая нет ограничения времени.

То же время есть и у хуков набора — его собственный `timeout` или
внешний, включая `--timeout` запуска: у каждого хука `before_all`,
`after_each` и `after_all`, который не входит во время ни одного случая.
`before_all`, у которого вышло время, сообщает о каждом выбранном случае
набора как о `setup` (`before_all timed out after 50 ms`), а хуки
`after_*` набора всё равно выполняются; хук `after_*`, у которого вышло
время, — это ошибка `cleanup` его случая или последнего случая набора, и
запуск продолжается. Поэтому зависший хук не может повесить запуск, у
которого есть таймаут.

```flick
module App.SlowTest

suite "network" timeout 5000 {
  test "answers" timeout 500 {}
  test "retries" {}
}
```

`Test.timeout` делает то же для теста, собранного вручную.

## Фикстуры

`fixture name = expression` в наборе — это значение, которое его случаи и
хуки читают через `await name`. Каждый случай, который его использует,
получает своё, созданное, когда его код впервые ждёт его; `fixture shared
name = expression` создаётся один раз на запуск набора, когда его впервые
ждёт один из его случаев или хуков. Фикстура, которую не использует ни
один код, не создаётся никогда, а создаётся она не больше одного раза в
своей области: это `Lazy` (см. [эффекты](../effects/#lazy)).

```flick
module App.UsersTest

suite "users" {
  fixture shared names = SynchronizedRef.make ["Ada"]
  fixture count = List.length (SynchronizedRef.get (await names))

  before_all { SynchronizedRef.update (fun all -> all ++ ["Grace"]) (await names) }

  test "counts the names" { Test.check (Test.equal 2 (await count)) }
  test "reads them" { Test.check (Test.equal ["Ada", "Grace"] (SynchronizedRef.get (await names))) }
}
```

Выражение фикстуры — задача, как и тело теста, и оно может ждать фикстуры,
объявленные до неё, включая фикстуры наборов вокруг; использовать себя или
более позднюю фикстуру оно не может, поэтому фикстуры не могут зависеть
друг от друга по кругу (`std/T003`). Общая фикстура создаётся не для
какого-то одного случая, поэтому она может использовать только общие
фикстуры, как и хуки `before_all` и `after_all`.

Выражение выполняется в собственной области, которая владеет тем, что оно
захватывает. Фикстуры случая освобождаются, когда случай заканчивается,
после его хуков `after_each`, которые ещё могут их использовать; общие —
после последнего выбранного случая набора и его хуков `after_all`. Каждая
область освобождает свои фикстуры в порядке, обратном созданию, в том
числе после того, как более позднюю не удалось создать. `|>
Fixture.cleanup release` освобождает значение в этот момент, а
`Resource.own` закрывает значение `Close`, видя, чем закончился случай:
прошло ли его тело, упало, вышло за время или не запускалось после
упавшей подготовки. Так транзакция откатывается, когда её случай падает:

```flick
module App.AccountsTest

import Resource exposing (Close(..), own)

say : String ->{} Unit
let say line = Host.raw_stdout_line line

/// A transaction: it commits when its case passes and rolls back otherwise.
type Tx = Tx String

instance Close Tx =
  let close _ (Tx name) = say ("roll back " ++ name)
  let close_exit _ exit (Tx name) =
    say ((if Exit.is_success exit then "commit " else "roll back ") ++ name)

suite "accounts" {
  fixture tx = own (Tx "accounts")

  test "opens one" { ignore (await tx) }
}
```

Фикстура, выражение которой падает, проваливает каждый случай, который её
ждёт, с её ошибкой; общая фикстура для следующего случая заново не
создаётся.

Набор с общей фикстурой выполняет свои случаи по одному, в том числе при
`--jobs`, а другие наборы выполняются рядом с ним. `suite parallel "name"`
выполняет свои случаи одновременно и делит только фикстуры с пометкой
`fixture shared concurrent`: ею автор утверждает, что случаи могут
использовать фикстуру одновременно, как пул или данные только для чтения;
другая общая фикстура набора `parallel` — это `std/T004`. Набор
`parallel` внутри набора, который выполняет случаи по одному, тоже
выполняет их по одному. Собственные фикстуры случая не делятся никогда,
поэтому транзакция на случай поверх общей базы данных остаётся
изолированной.

Значение фикстуры не держит региона: типы не мешают случаю сохранить его
после своего конца, в общей фикстуре или в волокне, которое переживает
случай, а после этого оно может быть уже освобождено. Это гарантия
`Scope.add_finalizer`, а не `Resource.own`. Если бы значение уточнялось
регионом кода, который его ждёт, как `own` уточняет своё, большинство
применений было бы отвергнуто: функция, которая принимает значение без
`^c`, отвергает значение с регионом, так что даже `SynchronizedRef.get
(await names)` было бы `FLICK-G001`.

`Test.fixture`, `Test.shared` и `Test.share` — это то, во что
разворачиваются блоки: их показывает `flick expand`.

## Запуск

`flick test` собирает проект вместе с тестовым корнем в `.flick/test/` и
запускает выбранные случаи на Node, на собственной среде выполнения Flick
(`--rt`) или как исполняемый файл Go (`--emit go`), с одинаковыми именами
и отчётами на каждой.

| Флаг | Значение |
| - | - |
| `--filter <text>` | только случаи, полное имя которых содержит `text` |
| `--list` | вывести полное имя каждого случая, который запустил бы запуск, по строке на случай, и ничего не запускать |
| `--forbid-only` | завершиться с кодом `1`, не запуская ни одного случая, если какой-либо случай запуска помечен `only` |
| `--jobs <n>` | не больше `n` случаев одновременно, по умолчанию `1` |
| `--seed <n>` | зерно генераторов; проваленный запуск печатает использованное |
| `--timeout <duration>` | время каждого случая без собственного `timeout`: `500ms`, `5s`, `2m` или миллисекунды |
| `--reporter human\|json` | строки по случаям и итог или один объект JSON |
| `--watch` | запускать снова при изменении файла проекта |

CI передаёт `--forbid-only`, чтобы забытый в коммите `test.only` проваливал
сборку, а не пропускал остальные тесты:

```sh
flick test --forbid-only
```

Каждый результат — `passed`, `failed` с указанием того, что провалилось
(`assertion`, `failure`, `defect`, `setup`, `timeout`, `cleanup` или
`interrupted`), или
`skipped`. Итог считает пропущенные случаи, а отчёт JSON содержит счётчик
`skipped`, когда они есть. Код выхода — `0`, если прошёл каждый
запущенный случай, `1` в противном случае и `130` после SIGINT;
пропущенные случаи ничего не проваливают.

## Диагностика

| Проблема | Диагностика |
| - | - |
| блок без имени или фигурных скобок, неизвестный модификатор, `timeout` без миллисекунд, хук с именем, фикстура без имени или выражения или набор, в котором есть что-то кроме случаев, хуков и фикстур | `std/T001` |
| два случая одного набора, два блока одного модуля или две фикстуры одного набора с одинаковым именем | `std/T002` |
| фикстура, которая использует себя или объявленную после неё, общая фикстура или хук `before_all`/`after_all`, который использует фикстуру, создаваемую заново для каждого случая | `std/T003` |
| общая фикстура набора `parallel` без `concurrent` | `std/T004` |
| модуль с блоками, объявляющий `tests` вручную | `FLICK-R008` |
| ошибка в теле теста | обычная, в этом коде |

```flick fail std/T001
module App.BrokenTest

suite "users" {
  let ada = "Ada"
}
```
