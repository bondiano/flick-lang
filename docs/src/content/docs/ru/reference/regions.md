`scope` освобождает полученные ресурсы по завершении своего тела,
а проверка доказывает, что ничто пригодное к использованию не переживёт
эту область (см. [Ресурсы](../../spec/07-errors-and-concurrency/#ресурсы), [Статические regions и захваты](../../spec/07-errors-and-concurrency/#статические-regions-и-захваты)). Регионы
проверяются после типов и эффектов; нет ни досрочного закрытия, ни
линейности: ресурс можно использовать сколько угодно раз, пока его
область открыта.

## Области и владельцы

```flick
read_config : Path ->{FileSystem; OpenError, ReadError} String
let read_config path =
  scope {
    let file = File.open_scoped path
    File.read_all file
  }
```

Каждый `scope { … }` создаёт новый регион — жёсткий тип, который не может
упоминаться ни в одном типе вне этой области, — и владельца получаемых
внутри ресурсов. Операции, получающей ресурс региона `s`, нужен сервис
`Scope s` из `Prelude`, а каждый `scope` предоставляет `Scope` только
своего региона, подобно тому как `provide` предоставляет сервис. Вызов,
регион которого не известен из других условий, получает ресурс в самой
внутренней области `scope`. Функция может передать это требование области
вызывающего кода, указав его в своей сигнатуре:

```flick
open_two : forall s. Path ->{FileSystem, Scope s; OpenError} (File s, File s)
let open_two path =
  (File.open_scoped path, File.open_scoped path)
```

`scope s { … }` даёт региону имя `s` в типах своего тела и связывает
владельца `s : Fiber.Owner s` среди его значений. `scope` — конструкция
среды выполнения: чистая функция не может открыть такую область
(`FLICK-E001`). Вызов, которому нужен `Scope s`, вне всех областей
и без этого требования в сигнатуре — `FLICK-G004`.

Вызов, которому нужен `Scope s` внешнего региона, проходит через внутренние
области к той, которая владеет `s`, и ресурс освобождается при закрытии
этой области. Компилятор передаёт вызову владельца лексически: владелец
региона никогда не ищется по тому, какая область случайно оказалась самой
внутренней во время выполнения вызова.

```flick
keep : forall s. Path ->{FileSystem, Scope s; OpenError} File s
let keep path =
  acquire : Unit ->{FileSystem, Scope s; OpenError} File s
  let acquire () = File.open_scoped path
  scope {
    let local = File.open_scoped path
    acquire ()
  }
```

Здесь `local` освобождается по завершении внутреннего `scope`, а файл,
возвращаемый `keep`, — по завершении области вызывающего кода.

## Захваты

У ресурса регион присутствует в типе: `File s`, а также `List (File s)`
или номинальная обёртка `Wrapper s` вокруг него. Замыкание или `task`
удерживает используемые значения, а с ними и их регионы, которые его
собственный тип может не показывать. Такие скрытые захваты записываются
как квалификатор:

| Тип | Что удерживает |
| - | - |
| `T^{s, t}` | не более чем регионы `s` и `t` сверх того, что показывает `T` |
| `T^c` | не более чем строку захватов `c` (кинд `CaptureRow`) |
| `T^(c + d)` | не более чем обе строки |
| `T` | ничего сверх того, что показывает `T` |

```flick
read_later : forall s. File s -> (Eff none {ReadError} String)^{s}
let read_later file =
  task { File.read_all file }
```

Квалификатор задаёт верхнюю границу: более широкий принимается, а более
узкий, чем то, что удерживает значение, — `FLICK-G001`. Упоминание `s`
в типе параметра не заставляет функцию удерживать `s`; использование
значения этого региона — заставляет. То, что показывает тип,
удерживается явно и не требует квалификатора: `fun () -> file` имеет тип
`Unit -> File s`.

Каждая стадия каррированной функции удерживает предшествующие ей параметры,
как и её частичное применение, а сигнатура выражает это без квалификатора:
`File s -> String -> String` читается как `File s -> (String -> String)^{s}`,
в том числе в `.iface`. Так добавляются только регионы и строки захватов;
по сигнатуре неизвестно, что удерживает значение переменной типа,
поэтому стадии, которая скрывает такое значение, нужна запись `a^c -> (b -> b)^c`.

Для локальных значений всё выводится: замыкание без ожидаемого типа получает
квалификатор по тому, что использует, а локальная сигнатура не обязана
называть регионы, которые удерживает её функция. Сигнатура верхнего уровня
проверяется в записанном виде, а `.iface` сохраняет её квалификаторы для
импортирующих модулей.

| Конструкция | Что удерживает |
| - | - |
| `fun`, `task` | используемые локальные значения |
| стадия каррированной функции | регионы предшествующих ей параметров и используемые локальные значения |
| запись, кортеж, список, конструктор | то, что удерживают их части |
| `T^c` для переменной типа `a^c` | не более чем `c`, что бы ни обозначало `a` |
| переменная типа `a` без квалификатора | то, что обозначает `a`: обобщённому коду, скрывающему значение `a` в замыкании, нужно `a^c` |
| `Eff r e a`, функция | только свой квалификатор |

Функция, принимающая колбэк, объявляет его захваты и сохраняет их
в возвращаемом значении, как это делает `map_effect`:

```flick
map_effect : forall c a b r e. (a ->{r; e} b)^c -> (List a ->{r; e} List b)^c
foreign sync map_effect from "./list.js" "mapEffect"
```

Части значения, сопоставленного с образцом, имеют собственные типы:
поля конструктора проверяются на соответствие их типам при его создании.

## Что не может покинуть область

| Путь | Правило |
| - | - |
| значение области, напрямую или внутри данных | его тип не может упоминать регион (`FLICK-G002`) |
| возвращаемое или сохраняемое замыкание либо `task` | его квалификатор не может удерживать регион (`FLICK-G002` или `FLICK-G001` при проверке по записанному типу) |
| номинальная или непрозрачная обёртка | регион остаётся среди её аргументов типа |
| ячейка или связывание извне области | в его типе не должно появиться упоминание региона; изменяемое хранилище сохраняет свои захваты в точности (`T003`) |
| ошибка | её полезная нагрузка не удерживает регион, даже если её перехватывает обработчик внутри области (`FLICK-E005`); `type error E (s : Region) = E (File s)` отклоняется в месте объявления |
| внешняя функция | её сигнатура — контракт удержания: то, что она сохраняет, указано в квалификаторе результата |

## Дочерние файберы

```flick
spawn :
  forall s c r e a.
  Fiber.Outlives c s =>
  Fiber.Owner s ->
  (Failure e ->{r; none} Unit)^c ->
  (Eff r e a)^c ->{r; none} Fiber.Fiber e a
```

`Fiber.spawn owner supervisor task` регистрирует `task` у `owner`;
супервизор наблюдает за его сбоем. Дочерний файбер выполняется до закрытия
области владельца, поэтому задача и супервизор могут удерживать только
регионы, завершающиеся не раньше: регион владельца, регионы окружающих его
областей и то, что называет сигнатура, когда владелец — локальная область.
Это утверждает `Fiber.Outlives c s`; компилятор разрешает это ограничение,
а программа не объявляет его экземпляров класса. Дочерний файбер,
удерживающий более короткий регион, — `FLICK-G003`.

## Пока не проверяется

| Конструкция | Сейчас |
| - | - |
| полиморфные по захватам сигнатуры стандартной библиотеки | записываются вручную в каждом модуле, пока библиотека не существует |
| переменная региона, поздно унифицированная с другим регионом в строке захватов | они остаются раздельными, из-за чего программа может быть отклонена |
