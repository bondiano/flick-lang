`scope` освобождает полученные ресурсы, когда его тело завершается.
Проверка регионов доказывает, что после этого их никто не использует (см. [Ресурсы](../../spec/05-errors-and-concurrency/#ресурсы),
[Статические регионы и захваты](../../spec/05-errors-and-concurrency/#статические-регионы-и-захваты)).
Она выполняется после проверки типов и эффектов. Досрочного закрытия
и линейности нет: ресурс можно использовать сколько угодно раз,
пока его область владения открыта. Проверяется то, где значение
**использует** регион, а не то, что оно **держит**: значение может хранить
дескриптор после конца своей области, если там его никто не использует.

## Области и владельцы

```flick
# import File exposing (Path, FileSystem, OpenError, ReadError)
#
read_config : Path ->{Async, FileSystem; OpenError, ReadError} String
let read_config path =
  scope {
    let file = File.open_scoped path
    File.read_all file
  }
```

Каждый `scope { … }` создаёт новый регион с жёстким типом и владельца
получаемых внутри ресурсов. Тип региона нельзя упоминать в типах за
пределами этой области. Операции, которая получает ресурс региона `s`,
нужен сервис `Scope s` из `Prelude`. Каждый `scope` предоставляет `Scope`
только для своего региона, как `provide` предоставляет сервис.
Если регион вызова не определяется другими условиями, ресурс принадлежит
ближайшей области `scope`. Функция может возложить владение ресурсом
на вызывающий код: для этого требование указывается в сигнатуре:

```flick
# import File exposing (File, Path, FileSystem, OpenError)
#
open_two : forall s. Path ->{Async, FileSystem, Scope s; OpenError} (File s, File s)
let open_two path =
  (File.open_scoped path, File.open_scoped path)
```

`scope s { … }` вводит имя региона `s` для типов внутри тела и значение
владельца `s : Fiber.Owner s`. Конструкция `scope` эффектная:
чистая функция не может открыть такую область (`FLICK-E001`).
Если вызову нужен `Scope s`, но он находится вне всех областей владения
и этого требования нет в сигнатуре, возникает `FLICK-G004`.

Если вызову нужен `Scope s` внешнего региона, ресурс получает владелец
этого региона, несмотря на внутренние области. Ресурс освободится при
закрытии области владельца. Компилятор передаёт владельца лексически:
выбор не зависит от того, какая область оказалась самой внутренней
во время выполнения вызова.

```flick
# import File exposing (File, Path, FileSystem, OpenError)
#
keep : forall s. Path ->{Async, FileSystem, Scope s; OpenError} File s
let keep path =
  acquire : Unit ->{Async, FileSystem, Scope s; OpenError} File s
  let acquire () = File.open_scoped path
  scope {
    let local = File.open_scoped path
    acquire ()
  }
```

В этом примере `local` освобождается по завершении внутреннего `scope`,
а файл, который возвращает `keep`, — при закрытии области вызывающего кода.

`scope s { body }` означает `Scope.run (fun s -> body)`. `Scope.run` принимает
функцию, полиморфную по региону, поэтому тело можно передать как значение:

```flick
with_region : (forall s. Fiber.Owner s ->{Scope s; none} String) ->{} String
let with_region body = Scope.run body
```

## Держать — не значит использовать

Замыкание, `task` или конструктор могут держать дескриптор после конца
своего `scope`, если ничто из того, что они выполняют, его там не
использует:

```flick
# type File (s : Region)
#
# service Files =
#   open_scoped : forall s. String ->{Scope s} File s
#
held_task : String ->{Files} Eff none none Unit
let held_task path = scope {
  let file = Files.open_scoped path
  task { ignore file }
}
```

Использование, которое переживает свой регион, — это `FLICK-G002`:

```flick fail G002
# type File (s : Region)
#
# type error ReadError = ReadError String
#
# service Files =
#   open_scoped : forall s. String ->{Scope s} File s
#   read_all : forall s. File s ->{; ReadError} String
#
read_later : String ->{Files} (Unit ->{Files; ReadError} String)
let read_later path = scope {
  let file = Files.open_scoped path
  fun () -> Files.read_all file
}
```

```text
FLICK-G002: this uses region `s`, which the expected type `Unit ->{Files; ReadError} String` does not keep live: a function or a task uses a region only while the region is live
```

То, что стадия использует от региона, видно в её строке как `Live` —
элемент, который программа не пишет: проверка достраивает его в сигнатурах
(элизия) и не показывает в сообщениях, интерфейсах и сгенерированном коде.

- **Стадия сигнатуры использует то, до чего достают её параметры.**
  Каждой runtime-стрелке и `Eff` нужно живым то, до чего достают параметры
  перед ней: `read_all : File s ->{; ReadError} String` требует живого `s`
  там, где её вызывают, и того же требует стадия внутри функции,
  возвращающей замыкание над параметром.
- **Чистая операция не использует регион.** Чистая стадия не может
  добраться до ресурса, поэтому ленивая последовательность `for` над файлом
  области может её покинуть; строгий `[for …]` строит свой список внутри.
- **Внешняя функция над ресурсом имеет стадию выполнения.** Чистая
  внешняя стрелка, параметр которой дотягивается до региона,
  `peek : File s -> Int`, могла бы прочитать ресурс после его `scope`, когда
  ничто не живо, поэтому такая привязка записывается стрелкой выполнения,
  `File s ->{} Int`, и элизия требует живого `s` в каждом вызове
  (реализуется).
- **`scope` — это место, где его регион жив.** `Scope s` в строке держит
  `s` живым, а конец `scope s` снимает `Live s`. Строка, которая использует
  регион и не держит его живым, — это `FLICK-G002`. `Live s` не даёт
  `Scope s`: функция, которая приобретает в регион, называет `Scope s`
  (`FLICK-G004`).
- **Сервис, который индексирует регион, держит его живым.** `Setup s` в
  setup компонента держит живым регион экземпляра, как `Scope s`, поэтому
  setup может вызывать `Ui.on_mount`, `Ui.watch` и `Atom.value` своего
  экземпляра. Среда выполнения предоставляет `Setup s` только пока регион
  экземпляра открыт, а обработчику такого сервиса, который ставит программа,
  нужен живой регион там, где его ставят (`FLICK-G002`).

## Квалификаторы

| Тип | Что нужно для использования |
| - | - |
| `T^{s, t}` | живые регионы `s` и `t` |
| `T^c` | живая строка захватов `c` (вид `CaptureRow`) |
| `T^(c + d)` | обе строки живыми |
| `T` | ничего сверх того, что показывает `T` |

Квалификатор говорит, что нужно для использования значения, а не что оно
держит: вызов функции `(τ₁ → τ₂)^C`, ожидание задачи `(Eff r e τ)^C` или
запуск `(Stream r e a)^C` требуют там живого `C`. Более узкий квалификатор
скрывает такую потребность и даёт `FLICK-G001`; более широкий допустим.
Части данных получают их квалификатор: функции, извлечённой из
`(Option (Unit -> Unit))^C`, при вызове нужен живой `C`.

```flick
# import File exposing (File, FileSystem, ReadError)
#
read_later : forall s. File s -> (Eff {Async, FileSystem} {ReadError} String)^{s}
let read_later file =
  task { File.read_all file }
```

Переменная типа — не использование того, что она обозначает: обобщённый
код не может разобрать значение `a`, а аргумент типа несёт собственный
квалификатор, поэтому `List a` держит `a`, не говоря об этом.
`Ref.make : forall c a. a^c ->{} Ref (a^c)` хранит ёмкость ячейки в
инвариантном типе содержимого: расширение псевдонима ячейки не впустит
замену с меньшим временем жизни. Это различие сохраняется в
[схеме 2 `.iface`](../iface/#типы-и-кинды).

Данные, которые хранят функцию, например `type G s a = G (s -> a)`, держат
то, что использует их поле, в скрытой строке захватов. Эта строка — такой же
аргумент типа, как остальные: регион, который показывает другой аргумент, её
не заменяет. Данные с меньшей строкой подходят туда, где ждут большую, но не
наоборот. Расширяется только строка, которую добавляет чтение: строка
захватов, названная в объявлении, `type K (c : CaptureRow)`, и данные внутри
аргумента другого типа, `List (G s a)`, сравниваются как записаны. Если такой тип в сигнатуре записан без квалификатора, строку
даёт элизия, как и `Live`:

- в параметре — любая строка: функция по ней обобщена;
- в результате — то, до чего дотягиваются предыдущие параметры;
- записанный квалификатор задаёт строку явно, и тело проверяется по нему.

Это относится к данным, которые хранят функцию или `task` — напрямую или
через поля других данных и непрозрачных типов стандартной библиотеки, — на
внешнем уровне параметра или результата. Значение без стрелок (`x : G s a`)
и данные внутри аргумента типа (`List (G s a)`) держат не больше того, что
показывает их тип. Как и `Live`, строка не показывается в сообщениях и при
наведении; `FLICK-G001` называет регион, который она держит, когда из-за
этого значение не может покинуть свой `scope`, а строку данных параметра
называет скрытой строкой данных параметра.

```flick
type Handle (r : Region)
type G s a = G (s -> a)

make : Handle r -> G Unit Int
let make _ = G (fun _ -> 1)

make_free : Handle r -> (G Unit Int)^{}
let make_free _ = G (fun _ -> 1)
```

`make h` держит `{r}` — то, до чего дотягивается её параметр, — и поэтому
не может покинуть `scope` региона `r` (`FLICK-G001`); `make_free h` ничего
не держит и может. Композиция через помощника, обобщённого по аргументу
данных, сохраняет строки своих частей, поэтому композиция, которая читает
файл области, не может её покинуть:

```flick fail G001
# import File exposing (Path, FileSystem, OpenError, ReadError)
#
type G s a = G (s ->{Async, FileSystem; ReadError} a)

run : G s a -> s ->{Async, FileSystem; ReadError} a
let run (G f) x = f x

compose : G a b -> G s a ->{Async, FileSystem; ReadError} G s b
let compose inner outer = G (fun x -> run inner (run outer x))

leaked : Path ->{Async, FileSystem; OpenError, ReadError} G Unit String
let leaked path = scope {
  let file = File.open_scoped path
  compose (G (fun f -> File.read_all f)) (G (fun _ -> file))
}
```

```text
FLICK-G001: this value holds region `s`, but the expected type `G Unit String` holds no captures
```

Значение области держит строку `G (fun f -> File.read_all f)`, а она
использует файл, результат же `leaked` читается как ничего не держащий.

Функция, принимающая обратный вызов, говорит, что нужно для использования
её результата, как `map_effect`:

```flick
map_effect : forall c a b r e. (a ->{r; e} b)^c -> (List a ->{r; e} List b)^c
foreign map_effect from "./list.js" "mapEffect"
  retention call
```

Обратные вызовы `map`, `map2` и `flat_map` из Prelude квантифицируют
границу входа **для каждого вызова** независимо от границы контейнера `d`:
`(forall v. a^v -> b)^c` у `map`,
`(forall u v. a^u -> (b^v -> x)^(c + u))^c` у `map2` и
`(forall v. a^v -> (m b)^(c + v))^c` у `flat_map`. То, что возвращает такой
обратный вызов, ничего не держит от его входа, поэтому `Option.map` даёт
`(Option b)^c`; ленивый `Seq.map`, `Eff` и `Result.map`, который передаёт
дальше свою ошибку, сохраняют источник и дают `^(c + d)`.
`pure : forall c a. a^c -> (f a)^c` сохраняет границу входного значения.
См. [пользовательские экземпляры трансформеров](../../contributing/implementation-decisions/#экземпляры-пользовательских-типов).

## Что не может покинуть область

| Как регион может выйти из области | Правило |
| - | - |
| результат области, напрямую или внутри данных | его тип не может упоминать регион (`FLICK-G002`) |
| возвращаемое или сохраняемое замыкание либо `task` | ни одной его строке не может быть нужен живой регион (`FLICK-G002`) |
| значение, полученное приобретением | `Resource.acquire_release` даёт `a^{s}`, значение региона `s` (`FLICK-G002`); функция, которой его передают, принимает `Conn^c` с некоторым `c` |
| ячейка или связывание вне области | в его типе не должно появиться упоминание региона; изменяемое хранилище и квалифицированные типы его элементов инвариантны (`FLICK-T003`), даже если границу значения иначе можно было бы расширить |
| переменная `let mut` вне области | её тип задан там, где она объявлена; присвоенное вызываемое значение сохраняет квалификатор использования и не может использовать регион после его закрытия |
| ошибка | данные ошибки не удерживают регион, даже если её перехватывает обработчик внутри области (`FLICK-E005`); `type error E (s : Region) = E (File s)` отклоняется при объявлении |
| внешняя функция | её сигнатура задаёт условия удержания: то, что нужно для использования результата, указано в его квалификаторе; при `retention owner` и одном регионе в сигнатуре она получает `Fiber.Outlives` для удерживаемой строки захватов и `Fiber.Provided` с `Detached` для сервисов удерживаемой работы; при двух регионах сигнатура пишет их сама (`FLICK-F002`) |

## Аренда

`ScopedRef`, `Resource` и `ScopedCache` владеют собственными ресурсами:
замена (`set`, `refresh`) или вытеснение освобождает ресурс, пока их регион
ещё открыт. Поэтому их значение доступно только в аренде: `use` вызывает
функцию с ним, а прежний ресурс освобождается, когда его больше не держит
ни один `use`.

```flick
# import ScopedRef exposing (ScopedRef)
#
use : forall c s r e a b. ScopedRef s a -> (forall t. a^{t} ->{r; e} b)^c ->{r; e} b
# let use = ScopedRef.use

from_acquire :
  forall c s r e a. (forall t. Eff {Scope t | r} e a^{t})^c ->{Scope s | r; e} ScopedRef s a
# let from_acquire = ScopedRef.from_acquire
```

У значения регион аренды `t`, поэтому функция не может ни вернуть его, ни
продолжать использовать (`FLICK-T007`, `FLICK-G002`). Приобретение идёт в
собственный регион `t`, который заканчивается с освобождением ресурса:
значение типа, называющего свой регион, например `File t`, в них хранить
нельзя. `RcRef`, `RcMap` и `Pool` одалживают значение области вызова
(`Scope t`) до её закрытия, поэтому их `get` даёт `a^{t}`.

## Дочерние файберы

```flick
spawn :
  forall s c r e a.
  (Fiber.Outlives c s, Fiber.Provided r s, Detached r) =>
  Fiber.Owner s ->
  (Failure e ->{Scope s | r; none} Unit)^c ->
  (Eff {Scope s | r} e a)^c ->{r; none} Fiber.Fiber e a
# let spawn owner supervisor child = Fiber.spawn owner supervisor child
```

`Fiber.spawn owner supervisor task` регистрирует `task` у `owner`;
супервизор наблюдает за сбоем задачи. Дочерний файбер работает до закрытия
области владельца, поэтому каждый регион, который используют задача и
супервизор, должен кончаться не раньше: регион владельца, регионы
окружающих областей и регионы, указанные в сигнатуре, если владелец —
локальная область. Это условие выражает `Fiber.Outlives c s`. Компилятор
разрешает ограничение; программа не может объявлять экземпляры этого
класса. Если дочерний файбер использует регион с меньшим временем жизни,
возникает `FLICK-G003`. Дочерний файбер исполняется с сервисами того места,
где его запустили, поэтому и они должны пережить владельца:
`Fiber.Provided r s` (см. [Эффекты](../effects/), «Сервисы»).

Ресурсы дочернего файбера принадлежат региону владельца: задача, получающая
ресурсы, должна указывать `Scope s` этого владельца. Указание другого региона
вызывает `FLICK-T008`. Так же `Fiber.Outlives` требует работа, удерживаемая до
закрытия владельца: финализатор (`Scope.add_finalizer`), освобождение у
`Resource.acquire_release`, обработчик событий (`Events.listen`), источник
фонового `Stream` или `Channel`, а также работа, которую компонент запускает
через `Ui.on_mount` и `Ui.watch`: она идёт до размонтирования экземпляра.

## Сравнение с Rust

| Rust | Flick |
| - | - |
| время жизни `'a` | регион: тот, что открывает `scope`, или параметр `forall s` |
| `T: 'a` | `Fiber.Outlives c s` для строки захватов `c` работы, которую держит владелец; решает проверка, а программа не объявляет экземпляров |
| `fn(&'lt ())` | `File inner -> Unit` |
| `for<'r> fn(&'r ())` | `forall r. File r -> Unit` |

Rust решает `T: 'a` синтаксически, как это сделал RFC 1214: каждое время
жизни, которое тип упоминает или скрывает, должно переживать `'a`, включая
аргумент указателя на функцию, который значение никогда не вызывает.
Комментарий в собственных тестах rustc на `outlives` называет это правило
строже необходимого: сам указатель на функцию всегда `'static`, поэтому он
мог бы быть бивариантным по своему аргументу. Flick читает его так, как
предпочитает этот комментарий: держать `File inner -> Unit` не значит
ничего использовать, поэтому такая функция может покинуть область `inner`.
Корректность здесь обеспечивает не вариантность, а доказательство
суждения о типизации: `T4'` в `formal/Formal/Live/T4Live.lean` показывает,
что программа, типизированная так, не доходит до шага, которому нужен
регион после закрытия его `scope`, и до операции, которую обслуживает
обработчик закрытого региона. Компилятор сравнивается с моделью тестами, а
не доказывается равным ей.

Rust принимает `outlives::<'static, _>((|_| ()) as fn(&'lt ()))`, потому что
аргумент типа `&'static ()` подходит для параметра `&'lt ()`
(контравариантность), и `T` выводится как `fn(&'static ())`. В Flick между
регионами нет подтипирования: `File inner` — не `File outer` (`FLICK-T008`).
Вместо этого есть параметр-регион, `forall r. File r -> Unit`.

## Пока не проверяется

| Конструкция | Сейчас |
| - | - |
| условия удержания внешних функций | сигнатуры пишутся и проверяются вручную; модуль проверки требует `retention`, а для удерживаемого при `retention owner` выводит или требует `Fiber.Outlives`, но не анализирует реализации внешних функций |
| переменная региона, поздно унифицированная с другим регионом в строке захватов | регионы остаются раздельными, из-за чего допустимая программа может быть отклонена |
| чистая внешняя функция над ресурсом | принимается и может прочитать ресурс после его `scope`. Меняется: такой привязке нужна стадия выполнения |
