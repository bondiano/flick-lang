`Ui r e` описывает пользовательский интерфейс. Его обработчикам событий
нужны сервисы `r`; они могут завершиться с ошибками `e`
(см. [Программирование на уровне типов и eDSL](../../spec/10-type-programming-and-edsl/)).
Построение `Ui` — чистая операция: оно не запускает обработчики, не читает
состояние и не обращается к DOM. `Ui.Dom.run` отображает интерфейс
через React 19 (`react-dom/client`) и выполняет каждый обработчик события
как задачу.

```flick
type alias SaveButtonProps c =
  {
    label : String;
    disabled : Bool;
    on_save : (Unit ->{Users; SaveError} Unit)^c;
  }

save_button : SaveButtonProps c -> (Ui {Users} {SaveError})^c
let save_button props =
  ui {
    button
      {
        disabled = props.disabled;
        on_click = Ui.Event.exhaust (fun _ ->
          task { props.on_save () }
        );
      }
      [text props.label]
  }
```

`c` — строка захватов (см. [регионы](../regions/#захваты)).
Как и любая новая переменная типа в сигнатуре, она неявно квантифицируется
по всей сигнатуре, поэтому `forall c.` можно опустить ([типы](../types/)).

Два квалификатора `^c` связывают захваты `on_save` с захватами
результирующего `Ui`. Без квалификатора тип функции не допускает регионов.
Поэтому при `on_save : Unit ->{Users;
SaveError} Unit` нельзя передать функцию обратного вызова, которая
использует `File s` из окружающей `scope`: возникает `FLICK-G001`,
даже если `Ui` никогда не покидает эту область.

Квалификатор `^c` у поля разрешает функции обратного вызова любые захваты,
а `^c` у результата сохраняет их в `Ui`. Если среди захватов есть регион,
такой `Ui` по-прежнему не может покинуть свою область. Одного квалификатора
у результата недостаточно: поле без `^c` всё равно не допустит захватов.
Компилятор проверяет сигнатуру верхнего уровня в записанном виде
и не добавляет эти квалификаторы сам. Если функции обратного вызова
компонента никогда не захватывают ресурсы области, оба квалификатора
можно опустить.

В блоке `ui { … }` имена из `Ui` доступны без префикса `Ui.`.
При поиске имени сначала учитывается локальная привязка, затем экспорт
из `Ui`, затем имена текущего модуля. Другой семантики у блока нет:
`ui { button … [text …] }` и `Ui.button … [Ui.text
…]` компилируются в одно и то же промежуточное представление.

## Элементы и свойства

Свойства задаются точными записями. Пропущенное или неизвестное поле,
как и неверный тип поля, приводит к ошибке.
Ключ задаётся через `Ui.keyed`: это метаданные, а не свойство.

| Функция | Элемент | Дочерние элементы |
| - | - | - |
| `text s` | текстовый узел React; разметка не интерпретируется | нет |
| `fragment`, `optional`, `empty` | без элемента | `List`, `Option`, нет |
| `div`, `span` `{ class_name }` | `div`, `span` | `List (Ui r e)` |
| `paragraph`, `heading`, `list`, `item` | `p`, `h1`, `ul`, `li` | `List (Ui r e)` |
| `button { disabled; on_click }` | `button type="button"` | `List (Ui r e)` |
| `input { value; placeholder; on_input }` | `input`; `value` — начальный текст | нет |
| `textarea { value; placeholder; on_input }` | многострочный вариант `input` | нет |
| `pre { class_name }` | `pre`: пробелы и переводы строк сохраняются | `List (Ui r e)` |
| `link { href : SafeUrl }` | `a` | `List (Ui r e)` |
| `html (s : SanitizedHtml)` | `div` с HTML | нет |
| `select (SelectProps a r e c)` | `ul role="listbox"`; выбор элемента запускает `on_change` с этим элементом | элементы через `render_item` |
| `panel { header; body; footer }` | `section` с `header`, `main`, `footer` | задаются именованными полями |
| `tabs { selected } (NonEmpty (Tab r e))` | список вкладок и выбранная панель | значения `Tab` из `tab label ui` |
| `component c props` | внешний компонент React | его свойства |

`text` имеет тип `forall r e. String -> Ui r e`, поэтому его можно
включить в список дочерних элементов любого элемента.
`SafeUrl` можно получить только через `Ui.safe_url`: функция принимает
относительные URL и схемы `http`, `https`, `mailto`, но отклоняет
управляющие символы. `SanitizedHtml` создаётся только через `Ui.trusted_html`;
за безопасность такого HTML отвечает программа. Обычная `String`
не заменяет ни один из этих типов.

Внешний компонент имеет тип `Ui.Component p` и привязывается через
`foreign pure`. Его отображает React; Flick никогда не вызывает его сам.

## Мемоизация представлений

`Ui.lazy_view view model` откладывает построение чистого поддерева до
рендера React и пропускает повторный рендер для моделей, равных согласно
экземпляру `Eq`. Вариант `Ui.lazy_view_with equal view model` принимает
собственную чистую каррированную функцию сравнения:

```flick
count_label : Number -> Ui none none
let count_label n = Ui.text ("count " ++ show n)

label : Number -> Ui none none
let label n = Ui.lazy_view count_label n
```

Передавайте стабильную функцию представления — обычно функцию верхнего
уровня. Новое замыкание считается новым представлением и вызывает повторный
рендер даже при равных моделях. Так обработчики не сохраняют старое замыкание.
Функция сравнения должна учитывать всё, что используют представление
и его обработчики, а не только видимый текст.

Модели должны быть неизменяемыми снимками. Заменяйте модель новым значением,
а не изменяйте внешние JS-объекты на месте. Несколько входных значений
можно передать записью или кортежем; отдельные lazy-функции для двух
и трёх аргументов не нужны.

`Ui.keyed id (Ui.lazy_view view model)` позволяет распознавать один и тот же
динамический дочерний узел при перестановках. Ключи действуют только
в списке соседних узлов и должны быть уникальны в нём.
При перестановке сохраняются поддерево React и состояние политики событий
этого ключа. Например, если `exhaust` уже выполняет задачу, ещё одна
не запускается.


## Обработчики и политики

Поле обработчика имеет непрозрачный тип `Ui.Handler snapshot r e`.
Создать его можно только через политику из `Ui.Event`, поэтому обработчик
нельзя запустить без отслеживания его задачи:

| Политика | Что происходит с событием, если предыдущие задачи ещё выполняются |
| - | - |
| `exhaust f` | событие игнорируется |
| `latest f` | текущая задача прерывается, новая запускается только после её остановки; из ожидающих событий сохраняется последнее |
| `queue capacity f` | событие встаёт в очередь, в которой могут ждать не более `capacity` событий; при переполнении отклоняется |
| `concurrent limit f` | обработчик запускается, если одновременно выполняется меньше `limit` задач; иначе событие отклоняется |

`capacity` и `limit` должны быть положительными целыми числами.
Неверная константа приводит к `FLICK-U001`, а вычисляемое значение
проверяется при создании обработчика. Отклонённое событие передаётся
супервизору как инфраструктурный дефект, но никогда не как ошибка из `e`.

Функция `f` получает инертный снимок, созданный внутри функции обратного
вызова DOM: `ClickSnapshot` (`button`, `alt`, `ctrl`, `shift`, `meta`),
`InputSnapshot` (`value`) или элемент `select`.
`Ui.Event.prevent_default decide h` вызывает чистую функцию `decide`
со снимком до возврата из функции обратного вызова. По её результату
действие по умолчанию либо предотвращается, либо выполняется.

Обработчики сохраняют захваты. Если обработчик кнопки удерживает файл
из области владения, кнопка не может покинуть эту область (`FLICK-G001`).
Представление должно быть чистым, поэтому вызов `Ref.get` в нём запрещён
как эффектный вызов (`FLICK-E001`).

Между завершёнными рендерами свойство события сохраняет того же слушателя,
но передаёт ему актуальный обработчик. Удаление свойства или размонтирование
элемента отсоединяет слушателя и отбрасывает события, ожидающие в очереди
его политики. Уже запущенные задачи остаются задачами корня и могут
завершиться. Закрытие корня по-прежнему прерывает их и ждёт остановки.

## Запуск корневого интерфейса

```flick
run :
  forall c r e m.
  Ui.Dom.Container -> (Failure e ->{r; none} Unit)^c -> Ref m -> (m -> (Ui r e)^c)^c ->{r; none} Never
```

`Ui.Dom.run container supervisor model view` строит интерфейс через `view`
по содержимому `model`. Обработчики заменяют модель с помощью `Ref.set`.
Первое монтирование DOM выполняется синхронно. Завершение последующих задач
запрашивает рендер React. React 19 может объединять ожидающие обновления,
а если идентичность модели не изменилась, корневое представление
может быть пропущено.

Не рассчитывайте на фиксацию изменений в DOM после каждой задачи
или на отображение всех промежуточных моделей. Расписание определяет React;
один рендер на кадр анимации тоже не гарантируется.
Каждая задача получает сервисы вызова `run`. Сбой задачи и каждое
отклонённое событие передаются в `supervisor`. Прерывание политикой
или при закрытии туда не передаётся.
Если сбой происходит в самом супервизоре, `run` завершается с дефектом.

`run` выполняется до прерывания его файбера — обычно при закрытии области,
которая его породила. Завершение проходит в две фазы. Сначала очистка React
немедленно прекращает приём событий, размонтирует дерево и удаляет слушателей.
Затем прерываются задачи обработчиков, включая супервизоры, и ожидается
их остановка. Только после этого завершается `run`, поэтому область
освобождает ресурсы уже после остановки задач.
`Ui.Dom.container id` находит элемент для отображения интерфейса.

Адаптер находится в `@flick-lang/runtime/ui`. Пакеты `react` и `react-dom`
версии 19 — peer-зависимости среды выполнения; их устанавливает приложение.

Работа с корнями DOM вынесена в модуль `Ui.Dom`. Сам `Ui` импортирует
только React-адаптер, поэтому скомпилированным программам с `Ui.run_with`
не нужен `react-dom`. Для DOM используются `Ui.Dom.run` и `Ui.Dom.container`;
алиасов этих функций в `Ui` нет.

## Серверный рендеринг и гидратация

Экспортируйте из Flick функцию начального представления и выполните
её холодный эффект на сервере. Передайте полученный `Ui` в `uiRenderStatic`
из `@flick-lang/runtime/ui/react`, затем сериализуйте React-узел через
`renderToString` из `react-dom/server`. На сервере обработчики
не запускаются. Отдельная HTML-реализация виджета не нужна.

Пометьте контейнер атрибутом `data-flick-ssr`. Тогда `Ui.Dom.run`
использует `hydrateRoot` вместо очистки готового HTML.
Начальная модель, ключи и разметка на сервере и клиенте должны совпадать.
Введённый до запуска текст textarea, фокус и выделение сохраняются.
Перед проверкой или отправкой перенесите этот текст в модель Flick.
Сначала монтируйте корень, затем запускайте фоновые задачи,
которые уведомляют его обработчики.

Так устроены шапка документации и Play/Transpile.
Без атрибута обычное клиентское монтирование работает как прежде.

## Другие рендереры React

`@flick-lang/runtime/ui` — адаптер React DOM.
`@flick-lang/runtime/ui/react` содержит только преобразование узлов React,
мемоизацию и управление жизненным циклом задач. Импорт этого подпути
не загружает `react-dom` и не читает `document` или `window`.

Из него экспортируются `uiRunWith` и тип фабрики рендерера:

```typescript
type Renderer = () => {
  render(node: React.ReactNode): void;
  unmount(): void;
};
```

Фабрика вызывается при запуске корневого Effect, а не при построении
его описания. Метод `render` передаёт узел React выбранному рендереру,
а `unmount` синхронно отсоединяет корень.
Общий код запуска прекращает приём событий, размонтирует дерево,
прерывает задачи и ждёт их завершения. Рендерер должен размонтировать
все свои компоненты React. Просто скрыть результат рендеринга недостаточно.

В Flick фабрика привязывается через `foreign pure` как непрозрачный
`Ui.Renderer` и запускается вызовом
`Ui.run_with renderer supervisor model view`. Сервисы, ошибки, захваты
и порядок завершения такие же, как у `Ui.Dom.run`.
Так можно подключить React Native, Ink и React Three Fiber,
но готовых адаптеров для них нет.

Существующие `div`, `input` и другие HTML-функции предназначены только для DOM.
Для других рендереров нужны собственные типизированные примитивы и снимки
событий либо внешние компоненты через `Ui.component`.
Адаптер рендерера, не использующего DOM, не должен импортировать DOM-подпуть.

## Сходство с архитектурой Elm

Сейчас есть чистое представление, модель в `Ref` и обработчики Effect
под управлением супервизора. Последовательного цикла `Msg → update`,
команд из `init`/`update` и запуска или остановки подписок по модели
пока нет. Приоритеты перечислены [ниже](#приоритеты-развития).
Effect, файберы, области и политики конкурентного выполнения событий
уже есть. Будущий MVU API должен использовать их, а не вводить вторую
среду выполнения асинхронных операций.

### Сравнение с Elmish

Сравнение относится к [`elmish/react` v6.x](https://github.com/elmish/react/tree/v6.x),
а не к полноценному MVU-фреймворку.
В [`common.fs`](https://github.com/elmish/react/blob/v6.x/react/common.fs)
реализованы `lazyViewWith` на основе `React.memo` и ключи соседних узлов.
В [`react.fs`](https://github.com/elmish/react/blob/v6.x/react/react.fs) —
проверка идентичности корневой модели, объединение обновлений через
`requestAnimationFrame`, гидратация и `valueOrDefault`.
Цикл обработки сообщений и подписки относятся к отдельному ядру
[`elmish/elmish`](https://github.com/elmish/elmish).
В Flick обновления объединяет React 19, но он не гарантирует расписания
по кадрам анимации, как у Elmish.

### Реализованные оптимизации и тесты

- Корневое представление не вычисляется заново, если идентичность модели
  не изменилась. React 19 объединяет ожидающие рендеры, а не фиксирует
  изменения синхронно после каждой задачи. Только первое монтирование DOM
  остаётся синхронным.
- `Ui.lazy_view` использует существующий экземпляр `Eq`,
  а `Ui.lazy_view_with` — чистую функцию сравнения. Захваты модели,
  представления и обеих каррированных стадий функции сравнения сохраняются
  в полученном `Ui`. Новое замыкание представления сбрасывает мемоизацию
  даже при равных моделях.
- При перестановке ключи сохраняют поддерево и состояние занятой политики
  событий. Стабильные слушатели принадлежат компонентам и получают
  актуальный обработчик после фиксации изменений, не удерживая
  устаревшее представление.
- `Ui.Renderer`/`Ui.run_with` используют общий жизненный цикл React
  без импорта `react-dom`. За монтирование DOM отвечает `Ui.Dom`;
  задачи принадлежат корню, а не DOM.

Реализация находится в
[коде запуска для React](https://github.com/bondiano/flick-lang/blob/main/runtime/src/ui/react/index.ts),
[DOM-адаптере](https://github.com/bondiano/flick-lang/blob/main/runtime/src/ui/index.ts)
и встроенных модулях
[`Ui`](https://github.com/bondiano/flick-lang/blob/main/flick-core/src/types/builtins/Ui.fl)
и [`Ui.Dom`](https://github.com/bondiano/flick-lang/blob/main/flick-core/src/types/builtins/Ui/Dom.fl).
Для этих возможностей есть регрессионные тесты:

- [`runtime/test/ui.test.ts`](https://github.com/bondiano/flick-lang/blob/main/runtime/test/ui.test.ts):
  мемоизация, объединение обновлений, ключи, стабильные слушатели, StrictMode,
  работа супервизора, размонтирование с ожиданием задач и импорт подпути
  для React без DOM.
- Примеры проверки lazy-представлений
  ([проходит проверку](https://github.com/bondiano/flick-lang/blob/main/tests/check/pass/ui/lazy.fl),
  [ошибка проверки](https://github.com/bondiano/flick-lang/blob/main/tests/check/fail/ui/lazy.fl)):
  чистота, `Eq`, захваты, сервисы и требования к супервизору.
- [`tests/run/ui/counter.fl`](https://github.com/bondiano/flick-lang/blob/main/tests/run/ui/counter.fl):
  пользовательский экземпляр `Eq` и рендерер.
- [`tests/run/ffi/foreign.fl`](https://github.com/bondiano/flick-lang/blob/main/tests/run/ffi/foreign.fl):
  сохранение идентичности функции обратного вызова с одним аргументом при FFI.
  [Генератор внешних вызовов](https://github.com/bondiano/flick-lang/blob/main/flick-core/src/codegen/js/items.rs)
  передаёт такую функцию без изменений и без выделения памяти под обёртку.
  Функции с несколькими аргументами по-прежнему адаптируются
  из каррированного ABI.
- `compiled_ui_core_imports_without_a_dom_renderer` в
  [`flick/tests/e2e.rs`](https://github.com/bondiano/flick-lang/blob/main/flick/tests/e2e.rs):
  импорт скомпилированного Flick-модуля с запретом загрузки `react-dom`.
  Так разделение проверяется не только через TypeScript-код среды выполнения.

### Приоритеты развития

Перечисленные возможности **ещё не реализованы**. Приоритеты учитывают
будущую поддержку React Native, Ink и React Three Fiber:
одного переноса DOM-тегов для нового рендерера недостаточно.

| Приоритет | Возможность | Что требуется и зачем |
| - | - | - |
| P1 | MVU, не зависящий от рендерера | `init`, чистый `update`, стабильный `dispatch` и последовательная очередь сообщений, включая повторный вход в `dispatch`. Представление не меняет `Ref` напрямую. Один цикл для DOM, Native, Ink и R3F. |
| P1 | Команды из `init`/`update` | Запуск существующих задач Effect и преобразование результата в сообщение. Использовать существующий супервизор, прерывание и ожидание завершения, а не создавать вторую среду выполнения `Cmd` поверх Effect. |
| P1 | Подписки по модели с устойчивыми ключами | Сопоставление, запуск и остановка подписок по устойчивой идентичности, защита от запоздавших событий и освобождение ресурсов при закрытии области. Таймеры, сокеты, терминал и источники анимации обновляют модель, не дожидаясь завершения обработчика UI. |
| P1 | Типизированные примитивы и события рендереров | Разделить HTML-конструкторы и специфичные для рендереров `View`/`Text`, узлы Ink и узлы сцены R3F. Свойства со стилями и числовыми значениями, а также снимки событий не должны зависеть от DOM `target.value` или `preventDefault`. |
| P1 | Адаптеры Native / Ink / R3F | Регистрация и монтирование, обновления, синхронное отсоединение и освобождение ресурсов на основе `Renderer` и примитивов рендерера. Для R3F отдельно определить связь MVU с циклом отрисовки кадров и запросами перерисовки; не отправлять 60 сообщений/с без необходимости. |
| P1 | Управляемые поля и синхронизация значения | Сейчас `input`/`textarea` получают только начальный `defaultValue`. Нужны сброс и внешнее обновление значения, сохранение положения курсора и ввода через IME, а также определённое поведение при асинхронных обработчиках. Вариант Elmish `valueOrDefault` — ориентир, но не готовая модель управляемого поля. |
| P2 | Типизированное взаимодействие с React | Дочерние элементы и именованные области внешних компонентов, ссылки с областью владения, Context и провайдеры, жизненный цикл с явно заданным освобождением ресурсов. Сейчас есть только непрозрачный `Ui.component` со свойствами. |
| P2 | Инструменты разработки и диагностики MVU | Запись сообщений и состояний модели, воспроизведение чистого update, HMR с сохранением состояния. Строить на API MVU, а не на единственном глобальном изменяемом объекте. |

Отдельные `lazyView2`/`lazyView3` не нужны: несколько входных значений
уже передаются записью или кортежем. Effect, файберы и области, политики
событий с ограниченной очередью или параллельностью, супервизор, проверки
выхода значений из области и безопасный вывод текста уже есть.
Для них не нужны дублирующие API.
