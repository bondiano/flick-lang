Скомпилированный код работает через `@flick-lang/runtime` (см. [Ошибки, сервисы, ресурсы и конкурентность](../../spec/07-errors-and-concurrency/), [Компилятор Flick и интеграция с Content Mapper](../../spec/11-compiler/)).
Это адаптер для Effect `4.0.5`. Сгенерированные модули импортируют только
этот пакет. Адаптер обеспечивает соблюдение описанных ниже правил
независимо от поведения Effect по умолчанию.

## Версия Effect

Адаптер проверен именно с Effect `4.0.5`. Перед запуском `main` средство
запуска точки входа проверяет установленную версию и матрицу возможностей
используемых операций Effect. Если версия отличается или нужной операции
нет, выполнение завершается с кодом `2`:

```text
error: the Flick runtime requires effect 4.0.5, found 4.1.0
```

## Владельцы и области

У каждой `scope` есть лексический владелец, а у средства запуска точки входа —
корневой владелец. Владелец учитывает дочерние задачи, начатую ими внешнюю работу
и финализаторы ресурсов, полученных в этой области. После завершения тела —
успешного, с типизированной ошибкой, дефектом или прерыванием — владелец
закрывается в две фазы: сначала завершает дочернюю работу, затем освобождает
ресурсы. Порядок действий:

1. владелец перестаёт принимать новые дочерние задачи;
2. прерывает все дочерние задачи и ждёт завершения каждой, включая супервизоры;
   непрерываемая дочерняя задача задерживает закрытие;
3. ждёт завершения всех незавершённых внешних промисов `async`, даже
   если они игнорируют прерывание;
4. запускает финализаторы ресурсов в порядке, обратном порядку получения;
5. область завершается с исходом тела, к которому добавляются все сбои очистки.

Дочерние задачи и ресурсы — отдельные группы: ресурс, полученный после
запуска дочерней задачи, всё равно освобождается после её завершения.

`acquireRelease` регистрирует финализатор без типизированных ошибок у владельца,
в котором выполняется вызов. Это либо самый внутренний владелец, либо владелец
внешней `scope`, если вызов получает ресурс в регион этой области.
Во втором случае компилятор передаёт владельца через `within`.
В отличие от `acquireRelease`, `bracket` освобождает ресурс сразу после
использования и может завершиться с собственной типизированной ошибкой.

## Дочерние задачи

`Fiber.spawn owner supervisor task` запускает `task` как дочернюю задачу `owner`.
Если дочерняя задача завершилась со сбоем, в том числе из-за прерывания при
закрытии владельца, она передаёт свой `Failure` супервизору. Поле
`failure.shutdown` позволяет распознать прерывание при закрытии владельца.
Дефект супервизора передаётся корневому механизму отчётности
и делает весь запуск неудачным. `Fiber.join` ждёт завершения дочерней задачи
и при её сбое сам завершается сбоем с исходной причиной. Закрывающийся владелец
не принимает новых дочерних задач: попытка запустить в нём задачу приводит к дефекту.

## Конкурентность

| Операция | Контракт |
| - | - |
| `parallel a b` | оба результата в порядке входных аргументов |
| `parallel_all limit effects` | не более `limit` ветвей одновременно; `limit` должен быть положительным конечным целым числом, иначе дефект |
| `parallel_results effects` | типизированная ошибка каждой ветви в виде `Err`; дефект или прерывание останавливает группу |
| `parallel_exits effects` | непрозрачный `Exit` каждой ветви |

Эти операции доступны через Prelude. Для работы с исходами служат модули
`Exit`, `Failure` и `RawCause`:

```text
parallel : (Eff r e a)^c -> ((Eff r e b)^c ->{r; e} (a, b))^c
parallel_all : Number -> List ((Eff r e a)^c) ->{r; e} List a
parallel_results : List ((Eff r e a)^c) ->{r; none} List (Result (Errors e) a)
parallel_exits : List ((Eff r e a)^c) ->{r; none} List (Exit e a)
race_success : (Eff r e a)^c -> ((Eff r e a)^c ->{r; e} a)^c
race_first : (Eff r e a)^c -> ((Eff r e a)^c ->{r; e} a)^c
timeout : Number -> (Eff r e a)^c ->{r; TimeoutError | e} a
timeout_option : Number -> (Eff r e a)^c ->{r; e} Option a

Exit.value : Exit e a -> Option a
Exit.failure : Exit e a -> Option (Failure e)
Failure.primary : Failure e -> Option (Errors e)
Failure.raw_cause : Failure e -> RawCause
Failure.inspect : Failure e ->{} CauseReport
Failure.rethrow : Failure e ->{; e} a
RawCause.inspect : RawCause ->{} CauseReport
```

Задача может захватывать значения, принадлежащие областям вызывающего кода
(`^c`): комбинаторы завершают её выполнение до возврата результата.

При сбое новые ветви не запускаются. Уже выполняемые ветви прерываются,
а комбинатор ждёт их завершения и сохраняет в результате сбои,
наблюдавшиеся к этому моменту.

| Гонка | Контракт |
| - | - |
| `race_success a b` | первый успех; сбои проигравшей ветви не добавляются |
| `race_first a b` | первая завершившаяся ветвь независимо от её исхода |
| `timeout millis e` | завершается с `TimeoutError`, если время истекло раньше |
| `timeout_option millis e` | `None`, если время истекло раньше; остальные сбои сохраняются |

До возврата результата комбинатор прерывает проигравшие ветви и ждёт их
завершения. Если ветвь готова сразу, она может выиграть ещё до запуска другой.

## Исходы

`try … with` обрабатывает первую типизированную ошибку в причине сбоя.
Если причина содержит ещё и дефект, обработчик не запускается, а типизированные
ошибки становятся дефектами. Причина, состоящая только из прерывания,
не содержит ошибки. Если подходящей ветви нет, исходная причина
распространяется без изменений:

| Причина | Восстановление |
| - | - |
| `Fail(A)` | `A` |
| `Fail(A), Fail(B)` | `A`, первая |
| `Fail(A), Interrupt` | `A` |
| `Fail(A), Die(D)` | нет: ошибки становятся дефектами |
| `Interrupt` | нет |
| `Fail(B), Fail(A)`, ветви только для `A` | нет: причина распространяется дальше |

`Exit e a`, `Failure e` и `RawCause` непрозрачны. `Failure.primary` возвращает
ошибку, которую выбрал бы обработчик; `Failure.rethrow` завершается сбоем
с исходной причиной. `Failure.inspect` и `RawCause.inspect` возвращают
`CauseReport` — замороженные данные без прототипа. Для каждой причины
в отчёте указан её вид (`fail`, `die`, `interrupt`), а также `_tag` или
сообщение об ошибке, прочитанные из собственных свойств данных.
Если прочитать их таким способом нельзя, используется заполнитель.
Построение отчёта никогда не выполняет код, связанный с данными ошибки:
геттеры, `toString`, `toJSON` или ловушки Proxy.

## Слои

`provide layer { body }` также создаёт лексического владельца. Слой строится
до выполнения тела; если построение завершается со сбоем, тело не выполняется.
В пределах одного построения повторные обращения к слою используют общий
результат, а два `provide` строят его дважды. Сервисы слоя доступны только
в теле, вместе с сервисами окружающего контекста. Финализаторы слоя выполняются
после завершения тела, с теми сервисами, с которыми они были зарегистрированы.

## Средство запуска точки входа

`flick-main.js` выполняет `main` под корневым владельцем. Сигналы SIGINT и SIGTERM
прерывают `main` и закрывают корневого владельца по тому же протоколу.
Процесс продолжает работать до завершения очистки. Если она занимает больше
двух секунд, процесс сообщает об этом в stderr; задержку задаёт
`FLICK_SHUTDOWN_NOTICE_MS`:

```text
shutting down: waiting for cleanup to finish
```

| Код завершения | Условие |
| - | - |
| `0` | `main` и очистка завершились успешно |
| `1` | типизированная ошибка (`error: <message>` для `AppError`), дефект (выводится его причина), сбой очистки, дефект супервизора или прерывание не из-за сигнала |
| `2` | установленная версия Effect не поддерживается средой выполнения |
| `130` / `143` | `main` остановлен только сигналом SIGINT / SIGTERM, очистка прошла успешно |

Сбой приложения или очистки сохраняет код `1`, даже если одновременно
пришёл сигнал.
