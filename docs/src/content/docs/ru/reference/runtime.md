`@flick-lang/runtime` — основа, на которой работает скомпилированный код (§7, §11).
Это тонкий адаптер поверх Effect `4.0.5`: сгенерированные модули импортируют только
этот пакет, а адаптер закрепляет приведённые ниже контракты так, чтобы они
соблюдались независимо от поведения Effect по умолчанию.

## Версия Effect

Адаптер проверен именно с Effect `4.0.5`. Средство запуска точки входа
проверяет установленную версию и матрицу возможностей операций Effect,
на которые опирается, до запуска `main`; другая версия или отсутствующая
операция завершают выполнение с кодом `2`:

```text
error: the Flick runtime requires effect 4.0.5, found 4.1.0
```

## Владельцы и области

У каждой `scope` есть лексический владелец, а у средства запуска точки входа —
корневой владелец. Владелец хранит группу дочерних задач, начатую ими внешнюю работу
и финализаторы ресурсов, полученных в нём. Когда тело завершается —
успешно, с типизированной ошибкой, дефектом или прерыванием, — владелец
закрывается в две фазы:

1. больше не принимает новые дочерние задачи;
2. прерывает все дочерние задачи и ждёт завершения каждой, включая супервизоры;
   непрерываемая дочерняя задача задерживает закрытие;
3. ждёт завершения каждого незавершённого внешнего промиса `async`, даже
   игнорирующего прерывание;
4. запускает финализаторы ресурсов в порядке, обратном порядку получения;
5. область завершается с исходом тела, объединённым с любым сбоем очистки.

Дочерние задачи и ресурсы — отдельные группы: ресурс, полученный после
запуска дочерней задачи, всё равно освобождается после её завершения.

`acquireRelease` регистрирует финализатор без типизированных ошибок у владельца,
в котором выполняется вызов: самого внутреннего либо владельца внешней `scope`,
которого компилятор передаёт через `within`, когда вызов получает ресурс
в регион этой области; `bracket` освобождает ресурс сразу после его
использования и может завершиться с собственной типизированной ошибкой.

## Дочерние задачи

`Fiber.spawn owner supervisor task` запускает `task` как дочернюю задачу `owner`.
Дочерняя задача, завершившаяся сбоем, в том числе прерванная закрывающимся владельцем,
передаёт свой `Failure` супервизору; `failure.shutdown` позволяет отличить прерывание
при закрытии владельца. Дефект супервизора передаётся корневому средству отчётности
и делает весь запуск неудачным. `Fiber.join` ждёт дочернюю задачу и завершается
сбоем с её исходной причиной. Закрывающийся владелец не принимает новых дочерних
задач: порождение задачи в нём — дефект.

## Конкурентность

| Операция | Контракт |
| - | - |
| `parallel a b` | оба результата в порядке входных аргументов |
| `parallel_all limit effects` | не более `limit` ветвей одновременно; `limit` должен быть положительным конечным целым числом, иначе дефект |
| `parallel_results effects` | типизированная ошибка каждой ветви в виде `Err`; дефект или прерывание останавливает группу |
| `parallel_exits effects` | непрозрачный `Exit` каждой ветви |

Программы получают доступ к ним через Prelude, а к исходам — через модули
`Exit`, `Failure` и `RawCause`:

```text
parallel : (Eff r e a)^c -> ((Eff r e b)^c ->{r; e} (a, b))^c
parallel_all : Number -> List ((Eff r e a)^c) ->{r; e} List a
parallel_results : List ((Eff r e a)^c) ->{r; none} List (Result (Errors e) a)
parallel_exits : List ((Eff r e a)^c) ->{r; none} List (Exit e a)
race_success : (Eff r e a)^c -> ((Eff r e a)^c ->{r; e} a)^c
race_first : (Eff r e a)^c -> ((Eff r e a)^c ->{r; e} a)^c
timeout : Number -> (Eff r e a)^c ->{r; TimeoutError | e} a
timeout_option : Number -> (Eff r e a)^c ->{r; e} Option a

Exit.value : Exit e a -> Option a
Exit.failure : Exit e a -> Option (Failure e)
Failure.primary : Failure e -> Option (Errors e)
Failure.raw_cause : Failure e -> RawCause
Failure.inspect : Failure e ->{} CauseReport
Failure.rethrow : Failure e ->{; e} a
RawCause.inspect : RawCause ->{} CauseReport
```

Задача может содержать то, чем владеют области вызывающего кода (`^c`):
комбинаторы выполняют её до возврата.

При сбое новые ветви не запускаются, выполняемые ветви прерываются
и ожидаются, а результат сохраняет сбои, наблюдавшиеся к этому моменту.

| Гонка | Контракт |
| - | - |
| `race_success a b` | первый успех; сбои проигравшей ветви не добавляются |
| `race_first a b` | первая завершившаяся ветвь независимо от её исхода |
| `timeout millis e` | завершается с `TimeoutError`, если время истекло раньше |
| `timeout_option millis e` | `None`, если время истекло раньше; остальные сбои сохраняются |

Проигравшие ветви прерываются и ожидаются до возврата результата. Ветвь,
готовая сразу, может выиграть ещё до того, как другая вообще запустится.

## Исходы

`try … with` обрабатывает первую типизированную ошибку причины; причина,
содержащая также дефект, не восстанавливается, а её ошибки становятся дефектами;
причина, состоящая только из прерывания, не содержит ошибки. Если подходящей
ветви нет, исходная причина распространяется без изменений:

| Причина | Восстановление |
| - | - |
| `Fail(A)` | `A` |
| `Fail(A), Fail(B)` | `A`, первая |
| `Fail(A), Interrupt` | `A` |
| `Fail(A), Die(D)` | нет: ошибки становятся дефектами |
| `Interrupt` | нет |
| `Fail(B), Fail(A)`, ветви только для `A` | нет: причина распространяется дальше |

`Exit e a`, `Failure e` и `RawCause` непрозрачны. `Failure.primary` — ошибка,
которую выбрало бы восстановление; `Failure.rethrow` завершается сбоем с исходной причиной;
`Failure.inspect` и `RawCause.inspect` возвращают `CauseReport`: замороженные данные
без прототипа с перечислением вида каждой причины (`fail`, `die`,
`interrupt`), `_tag` или сообщения об ошибке, прочитанных из собственных свойств данных,
а в остальных случаях — с заполнителем. Построение отчёта никогда не выполняет код
полезной нагрузки: геттеры, `toString`, `toJSON` или ловушки Proxy.

## Слои

`provide layer { body }` — тоже лексический владелец. Слой строится до
тела; если построение завершается сбоем, тело не выполняется. В рамках одного
построения каждый слой используется совместно, а два `provide` строят его дважды.
Тело видит сервисы окружающего контекста наряду с сервисами слоя, которые
после него больше недоступны. Финализаторы слоя выполняются после завершения
тела, с теми сервисами, с которыми они были зарегистрированы.

## Средство запуска точки входа

`main.js` выполняет `main` под корневым владельцем. SIGINT и SIGTERM прерывают
`main` и закрывают корневого владельца по тому же протоколу; процесс продолжает
работать до завершения очистки и сообщает в stderr, если она занимает
больше двух секунд (`FLICK_SHUTDOWN_NOTICE_MS` задаёт задержку):

```text
shutting down: waiting for cleanup to finish
```

| Код завершения | Условие |
| - | - |
| `0` | `main` и очистка завершились успешно |
| `1` | типизированная ошибка (`error: <message>` для `AppError`), дефект (выводится его причина), сбой очистки, дефект супервизора или прерывание не из-за сигнала |
| `2` | установленная версия Effect не поддерживается средой выполнения |
| `130` / `143` | только SIGINT / SIGTERM остановил `main`, а очистка прошла успешно |

Сбой приложения или очистки сохраняет код `1`, даже если одновременно
пришёл сигнал.
