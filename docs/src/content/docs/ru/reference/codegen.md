`flick build` компилирует каждый модуль в ES-модуль (см. [Генерация TypeScript и граница FFI](../../spec/06-typescript-and-ffi/), [Архитектура компилятора](../../contributing/implementation-decisions/#архитектура-компилятора)).
Ниже описан отладочный профиль. Его преобразования кода служат эталоном:
во всех остальных профилях программа должна вести себя так же.

Код в отладочном профиле форматируется для удобства чтения: если группа в скобках не
помещается в 100 столбцов или содержит многострочные элементы,
каждый элемент выводится на отдельной строке, а единственная функция обратного
вызова размещается непосредственно рядом с вызовом. Оба профиля опускают скобки, которые не нужны по
приоритету. Отладочный вывод импортирует модуль под его собственным именем,
`Ui.div`, `Ui_Event.exhaust`, если оно не занято конструктором модуля или
глобальным объектом JS, а неиспользуемый параметр называется `_`; в release —
`$m_Ui` и `$_`. Вывод release остаётся компактным; читать его стоит через
карты исходного кода.

Фабрике, захватывающей предшествующие локальные значения, могут потребоваться
дополнительные файлы вида `App/Factory$lexical$123.js`. В них находятся исходные
связывания префикса; обычный модуль их реэкспортирует. Результаты импортируют
префикс напрямую, поэтому внешний модуль может сам использовать результат
без цикла инициализации. Теги конструкторов, ключи сервисов и тождества типов
по-прежнему используют путь Flick-модуля. Go упорядочивает отдельные
инициализаторы по зависимостям значений.

## Выходные файлы

| Путь в выходном каталоге | Содержимое |
| - | - |
| `A/B.js`, `A/B.js.map` | модуль `A.B` и его карта исходного кода |
| `_flick/<Name>.js` | встроенные модули, до которых доходит программа (`Prelude`, `Platform`, …); с `--emit-dts` — все |
| `flick-main.js`, `flick-<name>.js` | раннер каждого входа приложения: импортирует `main` из определяющего модуля и запускает через среду выполнения либо вызывает чистый `main` напрямую; без schema AOT раннер чистого входа не импортирует среду выполнения |
| `package.json` | `{ "type": "module", "sideEffects": ["./flick-main.js"] }` со всеми раннерами; `"sideEffects": false` без них |

Модуль `Main` сохраняет имя `Main.js`/`Main.ts`. Дефис в имени файла запуска
`flick-main.js`/`flick-main.ts` предотвращает коллизии на файловых системах,
которые не различают регистр. Старое имя файла запуска при генерации
больше не используется.

Вне проекта команда `flick build <files> --out-dir <dir>` записывает ту же
структуру. Для корневого файла, модуль которого экспортирует `main`,
создаётся файл запуска. Импорт модуля ничего не выполняет:
модули только определяют значения. Значение верхнего уровня, которое является
вызовом, выведенным экземпляром или сразу вызываемой стрелкой, помечено
`/*#__PURE__*/`, поэтому бандлер отбрасывает то, что программа не использует.

По умолчанию код импортирует `@flick-lang/runtime/rt`, как и при `--rt`.
При явном `effect = "effect"` он импортирует `@flick-lang/effect-ts`; адаптер предоставляет `Effect`. Модуль без эффектных стадий вообще не импортирует `Effect`.

## Значения

| Значение в исходном коде | JS |
| - | - |
| `Unit`, `()` | `undefined` |
| `Int`, `Float`, `BigInt`, `String`, `Bool` | примитив JS; числовой литерал печатается по значению (`0xff` и `1_000` становятся `255` и `1000`, отрицательный берётся в скобки), литерал `BigInt` сохраняет основание и получает `n` |

Арифметика `Int` держит значение в 32 битах: `a + b` — это `(a + b \| 0)`,
`a * b` — `Math.imul(a, b)`, а `/`, `%` и `**` — вызовы рантайма, которые
отбрасывают дробную часть и на нулевом делителе дают `0`. `/` и `%` на
`BigInt` — тоже вызовы рантайма, ради нулевого делителя.
| кортеж, `List` | плотный массив |
| запись | простой объект с теми же полями и в том же порядке, что в записи |
| значение алгебраического типа данных | `{ _tag, _0, _1, … }`, поля расположены в порядке объявления |
| `unboxed type T = C f` | само поле |
| `untagged type T = A f \| B g …` | поле соответствующего конструктора; конструкторы различаются по типу поля в JS |
| `untagged type T = A = "a" \| B = "b"` | литерал конструктора, строка или число |
| `type error E = E …` | та же структура: ошибки — значения их единственного конструктора |
| `Option`, `Result` | собственные типы Effect `Option` (`Some`/`None`, `value`) и `Result` (`Success`/`Failure`, `success`/`failure`) |
| `Ref` | ячейка среды выполнения, равная только самой себе |

Полный идентификатор конструктора включает пакет, модуль, тип и конструктор:
`@acme/shapes/App.Shapes.Shape.Circle`. Если пакета нет — например, у файла
вне проекта или встроенного модуля, — идентификатор имеет вид
`App.Shapes.Shape.Circle`. Поле `_tag` содержит имя конструктора и старшие
48 бит хеша FNV-1a 64 от полного идентификатора: `Circle#7c57f5571734`.
Так тег сохраняет идентичность конструктора, но получается примерно вдвое
короче. В `.iface` записываются оба значения. Пользовательский тип
с конструктором `Some` никогда не принимается за `Option`.

`unboxed type` и `untagged type` задают представление вариантного типа при
взаимодействии через FFI. Это представление сохраняется во всех профилях.
Тип без упаковки имеет один конструктор с одним полем и представлен самим
полем. Тип без тега представлен единственным полем каждого конструктора.
Типы этих полей в JS должны различаться: `Float`, `String`, `Bool`, `BigInt`
или один список либо кортеж. Иначе выдаётся `FLICK-T020`.

При сопоставлении с образцом проверяется `typeof` или `Array.isArray` вместо
`_tag`. Выведенные экземпляры `Eq`, `Ord`, `Hash` и `Show` используют это
представление. Для типа без упаковки `deriving Schema` даёт формат передачи
его поля; для типа без тега свидетельство схемы не выводится.
В TypeScript такой тип представлен типом поля или объединением типов полей.

```flick
unboxed type UserId = UserId String
  deriving Eq, Show, Schema

untagged type Key = ByNumber Float | ByName String | ByPath (List String)
```

`opaque unboxed type Token = Token String` скрывает конструктор от импортирующих
модулей, как и `opaque type`, и сохраняет саму строку во время выполнения.

Перечисление — `untagged type`, конструкторы которого — литералы: каждое
значение во время выполнения и есть его литерал. Литералы — все строки или
все `Int`, попарно различные (`FLICK-T020`; `Int` вне диапазона —
`FLICK-T003`). У конструктора нет полей, у типа — параметров, а запись
`Get "GET"` без `=` получает подсказку. `match` сравнивает значение, как и
`==`; выведенный `Ord` идёт в порядке объявления, `Show` даёт имя
конструктора. Компилятор даёт каждому перечислению экземпляр
`Enum.Enum t b`, программа своих не объявляет (`FLICK-C012`), а его методы —
компаньоны `T.value`, `T.parse` (`Err` для неизвестного литерала; от
константы проверяется при компиляции, `FLICK-D006`) и `T.all` в порядке
объявления. `opaque untagged type` скрывает конструкторы, но не компаньоны.

```flick
untagged type Method = Get = "GET" | Post = "POST" | Delete = "DELETE"
  deriving Eq, Ord, Show

untagged type Priority = Low = 1 | High = 2

literals : Enum.Enum t String => List t -> List String
// `literals Method.all` — `["GET", "POST", "DELETE"]`
let literals values = List.map Enum.value values
```

`==` — каноническое структурное равенство: SameValueZero для чисел, поэтому
`NaN == NaN` и `0 == -0`; `Float.strict_equal` — это `===`, а
`Float.same_value` — `Object.is`. `<`, `<=`, `>`, `>=` — операторы JS;
`Ord Float` (`compare`) задаёт полный порядок с NaN в конце. Если операнды —
`String`, `Bool` или `BigInt`, `==` компилируется в `===`; для типа,
у конструкторов которого нет полей, — в `a._tag === b._tag`.

## Функции и стадии

Каждой стрелке каррированной функции соответствует отдельная стрелочная
функция JS: `(a) => (b) => …`. Чистая стадия выполняется как обычный JS.
Эффектная стадия возвращает `Effect.gen`: внутри него эффектные вызовы
используют `yield*`, а чистые остаются обычными вызовами:

```flick
# type UserId = UserId String
# type alias User = { name : String }
# type error NotFound = NotFound UserId
# service Users =
#   get : UserId ->{; NotFound} User
# service Log =
#   info : String ->{} Unit
# normalize_name : String -> String
# let normalize_name name = String.trim name
#
load_name : UserId ->{Users, Log; NotFound} String
let load_name id =
  let user = Users.get id
  let name = normalize_name user.name
  Log.info name
  name
```

```js
export const load_name = (id) => Effect.gen(function* () {
  const user = yield* $rt.operation($s_Users, "get", 1)(id);
  const name = normalize_name(user.name);
  yield* $rt.operation($s_Log, "info", 1)(name);
  return name;
});
```

Вычисление идёт слева направо, стадия за стадией. Первая эффектная стадия
завершается до вычисления следующего аргумента. Если для вычисления операнда
нужны инструкции (`match`, блок, ветвь с инструкциями), значения
предшествующих операндов сначала сохраняются в константах.

| Конструкция | JS |
| - | - |
| `task { body }` | `Effect.gen(function* () { … })`, строится без выполнения; каждый `yield*` выполняет тело заново |
| `await e` | `yield* e` |
| чистая функция там, где ожидается эффектная | оборачивается: каждая стадия, преобразованная в эффектную, выполняется в `Effect.sync` |
| `try body with arms` | `$rt.tryWith(body, handler)`: ветви видят первую типизированную ошибку причины |
| `provide layer { body }` | `$rt.provide(layer, body)`: слой строится до тела |
| `scope [s] { body }` | `$rt.scope((s) => body)`: лексический владелец с двухфазным закрытием, см. [среду выполнения](../runtime/) |
| вызов, получающий ресурс в регион внешней `scope` | `$rt.within(owner, call)`, где `owner` — владелец региона этой области |
| поддерживаемый чистый хвостовой вызов | цикл по параметрам, в том числе для взаимно рекурсивных функций верхнего уровня; см. ниже |
| подходящий хвостовой обход списка | массив и смещение вместо копии остатка списка на каждом шаге |
| эффектная рекурсия | через `yield*`, без роста стека JS |

## Рекурсия: дело не только в стеке

Вызов находится в хвостовой позиции, если его результат возвращается
без дальнейших вычислений. `sum (acc + x) rest` ниже — хвостовой вызов,
а `x + sum 0 rest` — нет: сложение ещё должно выполниться после возврата.

```flick
sum : Float -> List Float -> Float
let rec sum acc xs =
  match xs with
  | [] -> acc
  | [x, ...rest] -> sum (acc + x) rest
```

В debug и release рекурсивный вызов превращается в цикл. Следующие
аргументы вычисляются из привязок текущей итерации и присваиваются
напрямую; неизменившийся аргумент не требует присваивания.
Поэтому даже перестановка аргументов сохраняет смысл без дополнительного
набора временных переменных на каждом шаге. Правый операнд `&&` или `||`
тоже находится в хвостовой позиции, если возвращается всё выражение:
сокращённое вычисление сохраняется.

Список Flick — массив JS, поэтому одного предотвращения переполнения стека для
эффективного `sum` недостаточно. Если каждый шаг копирует `rest` через `slice`,
общее число скопированных элементов растёт квадратично.
В таком обходе компилятор сохраняет исходный массив и сдвигает смещение:
сопоставление читает оставшуюся длину и индексирует относительно него.
Обход становится линейным, без нового массива хвоста на каждой итерации.

Преобразование намеренно ограничено: параметр списка должен использоваться
только для сопоставления в хвостовой позиции, а `rest` — только как
аргумент той же позиции списка при следующем переходе цикла.
Другой список сбрасывает смещение в ноль. Хвост, возвращаемый вызывающему
коду или иначе покидающий цикл, по-прежнему получает собственный массив:
представление `List` не меняется.

### Взаимная рекурсия и словари

Чистые функции верхнего уровня, чьи хвостовые вызовы образуют цикл,
исполняются в общем цикле с выбором текущей функции. Каждая публичная
функция входит в него со своего состояния:

```flick
rec {
  is_even : Float -> Bool
  let is_even n = if n == 0 then true else is_odd (n - 1)

  is_odd : Float -> Bool
  let is_odd n = if n == 0 then false else is_even (n - 1)
}
```

Эти функции проверки чётности рассчитаны на неотрицательное целое число:
преобразование в цикл не добавляет валидацию и не гарантирует
завершение для других входов.

Переходы между функциями становятся сменой состояния в цикле
`for (;;) switch`, а не новым кадром стека JS на каждом шаге.
Хвостовой вызов функции с ограничениями классов также может быть преобразован
в цикл, если она передаёт ровно собственные словари. Вызов с другими
словарями остаётся вызовом; это не обещание устранить любую рекурсию.

Чистый цикл синхронен: отсутствие роста стека не делает длительное вычисление
кооперативным или отменяемым. Эффектная рекурсия выполняется шагами Effect
и сохраняет работу планировщика и прерывание.


## Сервисы

Объявление `service S` в модуле `M` задаёт ключ сервиса `M.S` в среде
выполнения. Вызов `S.op` ищет сервис на первой эффектной стадии операции,
затем вызывает метод записи реализации. Метод значения `S.Impl` вызывается
напрямую. Вызов `Layer.succeed S impl` создаёт слой.

## Словари

Определение с ограничениями классов сначала принимает словари этих классов.
Например, `render : Show a => a -> String` превращается в
`(dShow) => (value) => …`, а вызов — в `render(<Show Int>)(1)`.
Словарь — объект с методами класса и геттером для каждого суперкласса
(`$Eq` у словаря `Ord`). Экземпляр класса с контекстом — функция,
принимающая словари этого контекста. Выведенные экземпляры классов,
а также экземпляры для записей и кортежей, которые предоставляет компилятор,
среда выполнения строит из словарей полей. Аргумент высшего ранга
с ограничением — функция, принимающая его словари. Словарь
`instance Show Float` называется `$i_Show_Float`; к заголовку, который
не состоит из имён через пробел (`Show (List a)`), добавляется хэш:
`$i_Show_List_a_19082212`.

## Внешние функции

`foreign mode name from "module" "export"` импортирует указанное экспортируемое
значение. Каррированная функция Flick вызывает его, передавая аргументы
всех стадий до первой эффектной включительно (или `arity n`).
Словари передаются первыми. Режим `pure` означает прямой вызов,
`sync` — выполнение в `Effect.sync`, `async` — ожидание возвращённого `Promise`,
а `effect` — возврат `Effect`. В режиме `async` самый внутренний владелец
ждёт завершения промиса даже после прерывания (см. [среду выполнения](../runtime/)).
Относительный путь модуля разрешается относительно исходного файла.
Режим `global` указывает глобальное значение, как в `foreign now from global "Date.now"`.

## Карты исходного кода

У каждого модуля есть карта исходного кода версии 3. Она сопоставляет
определения, инструкции, вызовы, операторы и возвраты с началом соответствующего
узла Flick. Поэтому при `node --enable-source-maps` трассировка стека указывает
на строки `.fl`. Пути к исходникам в карте указаны относительно неё самой
(`../../src/App/Main.fl`), поэтому пути машины сборки в неё не попадают.

## TypeScript

`flick build --emit ts` (или `emit = "ts"` в `flick.toml`) записывает те же
модули в файлы `.ts`, которые импортируют друг друга с расширением `.ts`.
Каждый модуль содержит представления экспортируемых типов в TypeScript
и аннотации экспортируемых значений с соответствующими типами
(см. [Публичные интерфейсы TypeScript](../../spec/06-typescript-and-ffi/#публичные-интерфейсы-typescript)):

| Flick | TypeScript |
| - | - |
| `Int`, `Float`, `String`, `Bool`, `BigInt`, `Unit`, `Never`, `Unknown` | `number`, `number`, `string`, `boolean`, `bigint`, `undefined`, `never`, `unknown` |
| `List a`, `(a, b)`, `{ x : a }` | `ReadonlyArray<A>`, `readonly [A, B]`, `{ readonly x: A }` |
| `Option a`, `Result e a` | `Option.Option<A>`, `Result.Result<A, E>` из Effect |
| `a -> b` | `(arg: A) => B`, одна стрелка на стадию |
| `a ->{r; e} b`, `Eff r e a` | `(arg: A) => Effect.Effect<B, E, R>`, `Effect.Effect<A, E, R>`; пустая строка — `never` |
| экспортируемая функция с последней Sync-стадией, `a ->{Atom.Read} b` | `(arg: A) => Effect.Effect<B, never, Atom.Read>`: вызывающий код на Flick по-прежнему сразу получает значение, а TypeScript — Effect, читающий сервисы файбера, так что прямой вызов больше не падает |
| `Stream r e a` | `Stream.Stream<A, E, R>` Effect, само значение |
| вариантный тип, ошибка | объединение `{ readonly _tag: "<constructor id>"; readonly _0: … }` |
| перечисление; непрозрачное перечисление | объединение его литералов, `"GET" \| "POST"`; `string` или `number` с меткой его полного имени |
| непрозрачный, абстрактный или встроенный номинальный тип, сервис | интерфейс с меткой его полного имени |
| `service S` | интерфейс с меткой его имени, а в `.d.ts` — `$s_S: Context.Service<S, { op: … }>`, ключ, по которому TypeScript предоставляет реализацию (`Effect.provideService(program, $s_S, impl)`) |
| класс типов | интерфейс его словаря; значение с ограничением принимает словарь первым |
| `forall a.` | обобщённый параметр `<A>`; полиморфная константа использует `never` |
| `forall a b. a -> b -> …` | каждый параметр типа — на первой стадии, которая его принимает: `<A>(arg: A) => <B>(arg: B) => …`, так что поздний аргумент выводит свой |

`--emit-dts` (или `emit-dts = true`) записывает `A/B.d.ts` рядом с каждым
модулем. Файл содержит те же объявления, `export declare const` для каждого
экспортируемого значения и конструктора, а также словарь каждого экземпляра
класса без контекста. Если экспортируемый тип нельзя представить в TypeScript,
выдаётся `FLICK-F004`. Объявления никогда не содержат `any`.

В `.d.ts` комментарий `///` экспортируемого типа, конструктора или значения
становится его JSDoc, а Markdown остаётся как написан; так же и у библиотеки
из кэша пакетов. Синоним записи (`type alias`) объявляется как
`export interface`, и TypeScript показывает при наведении его имя. В отличие
от объектного типа у интерфейса нет неявной индексной сигнатуры, поэтому он
не присваивается `Record<string, unknown>`. Остальные синонимы остаются
`export type`.

`--promise-facade` (или `promise-facade = true`) записывает `A/B.promise.js`
и его `.d.ts` для каждой экспортируемой эффектной функции, которой не нужны
сервисы и чьи предыдущие стадии только создают замыкания. Вызов
`f(a, b, options?)` выполняет `f a b` под собственным владельцем и возвращает
`Promise<Result<A, E>>`. При ожидаемой ошибке промис успешно завершается
с `Result.fail`, а при дефекте или прерывании отклоняется с `RuntimeFailure`.
Его сообщение содержит отчёт о причине, построенный без выполнения кода
из данных ошибки. Параметр `options.signal` прерывает выполнение,
а промис завершается после очистки. Уже отменённый сигнал отклоняет вызов
до выполнения функции и её эффектов; завершённые вызовы снимают обработчики
отмены. Импорт любого из этих файлов ничего не выполняет.

Некоторые типы TypeScript не может выразить точно: переменную типа высшего
порядка, регион или значение, которое его содержит, открытую запись.
Для них нет проекции: при `--emit ts` экспорт остаётся `any`,
а `--emit-dts` сообщает об этом.

Код внутри модуля аннотируется как `any`: исходные типы известны модулю
проверки типов Flick и записаны в `.iface`. Сгенерированный код выполняется
на Node как есть (с удалением типов) и проходит `tsc --noEmit` с `strict`,
`allowImportingTsExtensions` и `module: nodenext`. Для этого
`@flick-lang/effect-ts` поставляет `index.d.ts`.

## Профиль выпуска

`--profile release` (или `build.profile = "release"`; `flick test` принимает
тот же флаг) запускает оптимизатор над типизированным промежуточным
представлением до генерации кода. Этот профиль использует ту же среду
выполнения и сохраняет всё наблюдаемое поведение программы: вывод,
порядок эффектных вызовов, сбои, `Exit` и коды завершения.
Файл `.iface` модуля также сохраняется таким, каким он получен при эталонном
преобразовании кода. Корпус сквозных тестов запускается в обоих профилях
с одинаковыми ожиданиями.

| Проход | Действие |
| - | - |
| свёртка констант | вычисляет выражения из литералов с побитово точной семантикой JS (`60 * 60 * 24` → `86400`) и `show` литерала `Bool`, `String`, `BigInt` или `Float` в записи JS `String` (`"n" ++ show (10.0 + 10.01)` → `"n20.009999999999998"`); неконечный результат — глобальное значение JS `Infinity`, `-Infinity` или `NaN`, а `Float.infinity` и `Float.nan` сворачиваются как константы; выбирает ветвь, если условие — константа; выражения, для которых JS может дать другой результат (`2 ** 0.5`) или выбросить исключение (`2n ** -1n`), остаются вычислениями; арифметика `Int` сворачивается с переполнением по модулю 2³² |
| девиртуализация | реализация по умолчанию, которую берёт экземпляр, становится его собственным методом, если при известных экземпляре и словарях её сигнатуры по умолчанию её код — функция или данные, так что `deriving Default` через `Generic` компилируется в экземпляр, написанный вручную; метод известного экземпляра заменяется его кодом, если это небольшие данные или функция, разбирающая известный конструктор; `match` известного конструктора — выбранная ветка |
| специализация | функция с ограничениями числовых классов из своего или другого модуля сборки (в том числе встроенного, как `List.sum`) получает приватную копию для числовых инстансов, с которыми её вызывают, и методы в копии становятся операторами типа; функция другого модуля копируется, только если её тело ссылается на экспортируемые имена своего модуля |
| встраивание | встраивает известное полное применение небольшой чистой функции модуля или встроенного модуля (core, std), тело которой называет только экспортированное этим модулем (`Int.min 3 5` — это `3`), или приватной функции, используемой один раз; сначала связывает аргументы по порядку; выполняет бета-редукцию `(fun x -> …) a` |
| распространение | заменяет обращение к локальной привязке её литералом или именем, и так же значение верхнего уровня модуля, привязанное к литералу; переносит чистое значение, которое не может выбросить исключение, в единственное место использования, если оно гарантированно выполняется |
| слияние (fusion) | `Seq.map`, `Seq.filter`, `Seq.flat_map` и `Seq.take` от ленивого `for` и `List.map`, `List.filter` от строгого выполняются в его цикле; `Seq.to_list` от ленивого `for` — строгий `for`, цикл с `push` в массив; `for` над `for` вкладывает клаузы внутреннего. Их функции чистые, поэтому выполнение между клаузами незаметно; известная лямбда применяется на месте, другая функция связывается один раз перед циклом. `for`, тело которого делает Sync-вызовы, остаётся как есть. Конвейер из `for`, фильтра и отображения в список — один цикл: в 17 раз быстрее генераторов debug (`tools/fusion-bench`) |
| скалярная замена | заменяет локальную запись, используемую только для чтения полей, или локальный кортеж, используемый только для деструктуризации, отдельными локальными привязками для каждой части; объект не создаётся |
| удаление мёртвого кода | удаляет неиспользуемые чистые привязки (включая неиспользуемый `task { … }`) и недостижимые приватные значения верхнего уровня; эффектный вызов сохраняется независимо от того, нужен ли результат |
| вспомогательные функции | создаёт для функции верхнего уровня с чистыми стадиями до последней функцию `f$n`, принимающую все `n` аргументов; известное полное применение вызывает её, частичное сохраняет каррированную `f`; у приватной функции, применяемой только полностью, каррированная форма не создаётся. Экспортируемая функция от двух и более параметров без словарей, включая `foreign`, экспортирует `f$n` рядом с `f`, и полное применение в другом модуле вызывает её: `n` берётся из `stages` её сводки в `.iface` |
| словари | выделяет метод экземпляра класса без контекста в экспортируемую константу `<экземпляр>$<метод>`, которая вызывается напрямую в местах канонического использования — в модуле и у импортёра; словарь, переданный как значение (свидетельство `EqHash`), никогда не заменяется |
| foreign | заменяет чистый `foreign`, который передаёт аргументы и результат без изменений, самим импортом: `export const div$2 = $f_div`; полное применение в модуле вызывает `$f_div` |
| одиночные эффекты | заменяет тело эффектной стадии, которое только возвращает один эффект, `Effect.gen(function* () { return yield* x; })`, на `Effect.suspend(() => x)`: эффект строится так же поздно, но без генератора |
| match и конструкторы | не проверяет последнюю ветку `match` без охранного условия, поскольку match исчерпывающий; превращает три и более ветки-конструктора, поля которых только связываются (последняя может быть любым связыванием), в `switch (x._tag)` с `default` в конце; строит помеченный конструктор, применённый ко всем полям, как литерал объекта `{ _tag: "Rect#…", _0: 3, _1: 4 }` |

Если первая стадия функции что-либо вычисляет или выполняет, вспомогательная
функция для неё не создаётся: объединение стадий перенесло бы эту работу
за вычисление следующего аргумента.

Описанные преобразования в циклы доступны в обоих профилях;
эффектная рекурсия остаётся цепочкой шагов `Effect.gen` или
`Effect.suspend`. Оптимизатор не меняет группировку арифметических
операций (`(a + b) + c`), не сворачивает `x * 0`, не выполняет
и не мемоизирует задачу, не объединяет два построения `Layer`,
не переносит поиск сервиса через `provide` и не убирает проверку схемы.
Автоматическое расписание файберов, а значит и победитель гонки между
одновременно готовыми ветками, может различаться между профилями;
точки отмены, явные уступки управления и финализаторы программы — нет.

## Go-target

`emit = "go"` (или `--emit go`) собирает приложение в один исполняемый файл
без Node: для каждого входа — Go-модуль в `go/<entry>/` вывода, `package
main` с файлом на каждый модуль Flick и пакетом runtime `flickrt` рядом,
который `flick build` собирает `go build` в `flick-<entry>`. `go build`
компилирует все файлы пакета, поэтому модуль перечисляет записанное сборкой в
`go/<entry>/.flick-files`, и следующая сборка в тот же вывод удаляет те
перечисленные файлы, которые больше не пишет; файлы, которые она не писала,
остаются. Компилируется
только то, до чего доходит `main`; конструкция, которую target ещё не
компилирует, — `FLICK-P012` с её названием, а не заглушка во время
выполнения. Пока это ленивый `for`, который читает сервисы,
схемы с `deriving Form`, а также привязка `foreign` без
Go-реализации: в runtime для стандартной библиотеки — у её части
за пределами ядра такой реализации пока нет (большая часть `Stream`, очереди, расписания
сверх `recurs`, часть `Codec`) — или рядом с программой для её собственных
привязок (см. [FFI](../ffi/#go-target)). Модули только для js-target дают
`FLICK-P030` уже в `flick check`.

Представление значений — как у JS-target, в терминах Go:

| Flick | Go |
| - | - |
| `Int` | `int32` |
| `Float` | `float64` |
| `BigInt` | `*big.Int`, не изменяется |
| `String` | `string` с WTF-8 |
| `Bool`, `Unit` | `bool`, `flickrt.Unit` |
| кортеж, `List` | `[]flickrt.Value`; `[x, ...rest]` использует общую память с исходным списком |
| запись | `*flickrt.Record`, метки в порядке ключей JS, `{ r with … }` копирует |
| конструктор | `*flickrt.Data` с тегом JS-target и полями |
| функция | `func(*flickrt.Fiber, flickrt.Value) flickrt.Value` на каждую стадию; функция от двух или трёх аргументов, у которой стадии до последней чистые, — `flickrt.Fn2` или `flickrt.Fn3`, принимающая их сразу |
| словарь | `*flickrt.Dict`; суперклассы и методы по умолчанию создаются при первом обращении |

Числа и строки сохраняют семантику JS-target: `Int` переполняется по
модулю 2³², а деление на ноль даёт `0`, `**` усекает отрицательную степень;
`Float` — IEEE double с JS `%` и `Math.pow`; `==` — SameValueZero; `show`
пишет `Float` как JS `String` (`0.30000000000000004`, `1e+21`, `-0`), теми
же цифрами, что и свёртка констант. `String` считает code units UTF-16 в
`length`, индексах и срезах; срез может разрезать суррогатную пару, `++`
склеивает половины обратно, строки упорядочены по code units, а вывод в
stdout заменяет одиночную половину на U+FFFD, как Node. Нормализация и
регистр (`ß` в `SS`, конечная сигма, турецкая и азербайджанская i,
литовские точки, греческие заглавные без ударений) следуют таблицам,
которые `tools/go-unicode/gen.mjs` пишет из ICU Node, а тег локали
проверяется и канонизируется как в V8, с его `RangeError` для неверного
тега; `RegExp` работает на
движке RE2 из Go, с позициями в code units и шаблонами замены `$` из JS, а
синтаксис, которого нет в RE2 (lookaround, обратные ссылки), — `RegExpError`.
`String.locale_compare` упорядочивает строки как `Intl.Collator`: Unicode
Collation Algorithm на корневой коллации CLDR 48 и её tailoring для языков 52
распространённых локалей, которые `tools/go-collate/gen.mjs` строит так же, как
ICU; тег другого языка сравнивается как локаль по умолчанию, расширения
`-u-co-…` не учитываются.
`DateTime` форматирует по таблицам, которые `tools/go-intl/gen.mjs` берёт из
Node: языки 52 распространённых локалей со всеми региональными вариантами
ICU, тег разрешается как в V8, имена зон по metazone (`CET`, `Central European
Standard Time`) при смещениях зоны в 2024 году, а смещение (`+01:00`, `+0100`)
принимается как имя зоны.
Дату в тексте (`DateTime.make`, `Config.date`, даты HTTP) читает порт
`Date.parse` из V8, вместе с устаревшими формами; дата-время без смещения —
местное время, `time.Local` из Go. `Cli.file_parse` читает INI, TOML и
YAML портами парсеров JS-target, вместе с их ошибками.

Шаблон, который RE2 читает, кое-где всё же значит другое: у RE2 нет
JS-режима, а Flick передаёт исходник как есть.

- `\s` — пробельные символы ASCII без `\v`; `.` совпадает с `\r`, U+2028 и
  U+2029; `^` и `$` с `m` делят строки только по `\n`.
- Режима без `u` нет: `.` и класс берут целую кодовую точку, а не половину
  суррогатной пары, а `\p{…}` — класс Unicode по таблицам Unicode 15 из Go,
  а не литерал `p{…}`.
- `i` сравнивает регистр по simple folding Unicode, так что `ſ` совпадает с
  `s`, а знак кельвина — с `k`; в JS они различны.
- `replace_all` пропускает пустое совпадение сразу после непустого: `a*` на
  `"baaac"` даёт `-b-c-`, а JS — `-b--c-`.
- Замена понимает `$$`, `$&`, `` $` ``, `$'` и `$n`, но не `$<name>`.
- Флаги кроме `g`, `i`, `m`, `s` и `y` игнорируются, а не дают `SyntaxError`,
  так что `d`, `u` и `v` ничего не меняют.
- Текст `RegExpError` — от RE2, а не от V8. Ту же ошибку дают lookaround,
  обратные ссылки, `\u…`, `\c…`, `[\b]`, `[^]` и повтор больше 1000, хотя
  JS их принимает.

`Seq` начинается заново на каждой итерации, как на JS-target; ленивый
`for` — это `Seq`. `HashMap` и `HashSet` перечисляют элементы в порядке
обхода HAMT — по `Hash.hash`, по пять бит начиная с
младших, — так что неотсортированный `to_list` печатает одно и то же на
обоих target.

Функция верхнего уровня представлена Go-функцией, которая принимает текущий файбер, свои словари
и все параметры; полное применение вызывает её, а частичное или
использование как значения создаёт вокруг неё функцию от значений. Параметр
типа `Int`, `Float`, `Bool` или `String` и результат такого типа имеют там
свой тип Go (`func F(fb *flickrt.Fiber, n int32) int32`), так что число,
переданное известной функции или возвращённое ею, не становится
`flickrt.Value` ради вызова. Хвостовые вызовы, которые на
JS-target становятся циклами (см. [Рекурсия](#рекурсия-дело-не-только-в-стеке)),
в Go тоже циклы: вызов самой себя — `for`, который присваивает следующие
аргументы и продолжает, а группа функций, вызывающих друг друга, — одна
Go-функция с циклом по `switch` на члене, который выполняется. В Go циклом
становится и хвостовой вызов, последняя стадия которого выполняет эффекты:
JS-target держит каждый его шаг в куче. Прочая рекурсия использует стек Go,
который растёт до 1 ГБ. Дефект печатает сообщение и строки Flick из стека
по директивам `//line` в сгенерированном коде. Значения верхнего уровня
присваивает одна функция на модуль, и они выполняются в порядке зависимостей
модулей. Случаи `tests/run` из `tests/run/portable.txt` выполняются на обоих
target и дают одинаковый вывод.

Каждая сгенерированная функция Flick принимает исполняющее волокно
`*flickrt.Fiber` первым, включая чистые функции и функции обратного вызова.
Сохранённая функция использует волокно текущего вызова, а не создания:
при отображении URL используются текущие имена параметров, подлежащих маскированию, без глобального состояния.
Чистые стадии остаются чистыми. `task` — замыкание Go над волокном, которое
выполняется заново при каждом `await`. Типизированная ошибка, дефект или
прерывание — panic в Go с деревом причин; `try` перехватывает
его по правилам JS-target, а упавший `main` сообщается так же, как его
сообщает JS-runner. Сервис — это его ключ `M.S`, который ищется в сервисах
волокна в момент выполнения операции, так что задача, созданная вне
`provide` и выполненная внутри, видит предоставленный сервис. Каждое
волокно `Fiber.spawn`, `parallel`, гонки или `timeout` — goroutine.
Прерывание кооперативное: оно проверяется при runtime-вызовах эффектов,
в блокирующих ожиданиях и в голове эффектных хвостовых циклов; чистые циклы
не получают точек прерывания. `Effect.uninterruptible` его откладывает. `scope`
закрывается как на JS-target: приём работы прекращается, дочерние задачи прерываются, после чего
среда выполнения ждёт завершения этих задач и их супервизоров, затем финализаторы выполняются в
обратном порядке, а их ошибки присоединяются к ошибке тела без дублирования.
Финализаторы Layer возвращают только cleanup-причины и видят исходный exit; перед
финализаторами завершаются foreign-вызовы, которые дети оставили
работать. `Ref`, `Deferred`, `Latch`, семафоры и синхронизированные ref
безопасны между goroutine. SIGINT и SIGTERM прерывают `main` и закрывают
его scope, а код выхода — как у JS-runner: 130 или 143, если программу
остановил только сигнал. Напечатанное программой выводится, прежде чем
волокно заблокируется, и построчно, как только рядом с `main` работают
другие волокна.

Свидетель схемы — значение схем runtime, а `Codec.json` читает и пишет
канонический JSON JS-target с теми же issues, путями и текстами;
`Json.parse` падает с сообщениями V8. `Http.Server.serve` слушает через
`net/http` из Go: каждый запрос выполняет обработчик в собственном волокне
с сервисами вызова, при ошибке сервер возвращает тот же статус, что и JS-бэкенд, а закрытие scope
прекращает приём соединений и ждёт выполняющиеся запросы. Каждый запрос
владеет своими ресурсами до окончания передачи тела ответа. После grace period
(по умолчанию 20 секунд) оставшиеся запросы прерываются; сервер ждёт их
финализаторы до освобождения ресурсов своего владельца. Этот таймаут
не ограничивает очистку и непрерываемую работу. Остальные `Http`
и `HttpApi` следуют JS-target: заголовки, cookies, URL, настройки
роутера по умолчанию, middleware, multipart-формы, статика, потоковые тела,
клиент на `net/http` (прерывание волокна отменяет его запрос), типизированные
клиенты `HttpApi` и тот же документ OpenAPI. Отличается то, что решает
`net/http`: status text ответа всегда стандартный, а клиент отправляет
заголовки запроса отсортированными по имени. Сервер видит заголовки запроса
в том порядке, в каком они пришли, как Node, по HTTP/1.x; где он не может
проследить разметку соединения, первым идёт host, остальные по имени.
Сжатие brotli и zstd идёт через Go-модули
`andybalholm/brotli` и `klauspost/compress`, которые программа требует,
только если доходит до `Http.Middleware.compression`; первая её сборка
скачивает их, если их нет в кэше модулей.

Отображение URL и детали HTTP-ошибок учитывают текущий
`Http.UrlParams.with_redacted_names`, в том числе во вложенных и конкурентных
scope; после выхода из scope ошибка хранит уже замаскированный URL. Роутер
проверяет ограничения и составные параметры до выбора обработчика.
Ограничения используют RE2: неподдержанный синтаксис JS-regexp, в том числе
смешанные regex/составные сегменты с многосимвольным разделителем, которым
нужен lookaround, отвергается при создании маршрута, а не становится
параметром без ограничения.

`FileSystem.node` реализует `access`, `copy`, `copy_file`, `chmod`, `chown`,
`glob`, `link`, `open`, `read_link`, `real_path`, `symlink`, `truncate` и
`utimes`; `open` принадлежит окружающему scope. `noFollow` атомарен на POSIX,
а на Windows возвращает типизированный `BadArgument`, как Node. Windows
`chown` сообщает ошибку неподдержанной операции Go вместо успешного no-op
из Node. Непортированные foreign-операции файловых дескрипторов остаются
`FLICK-P012`; метаданные `stat` пока частичны.
POSIX-классы glob проверяются на минимуме Go 1.23, включая неназначенные
кодовые точки. `Stream.watch` использует inotify на Linux, kqueue на macOS
и `ReadDirectoryChangesW` на Windows. В отличие от FSEvents у Node, kqueue
не сливает события, а уведомление о файле, созданном во время чтения нового каталога,
может прийти дважды. Где у системы нет уведомлений или кончились watch'и
или дескрипторы, путь опрашивается каждые 50 мс; Node в этом случае
падает.
`Path.node` и пути флагов `Cli` на Windows — это пути win32 из Node
(`tools/go-path/gen.mjs` сверяет их с `path.win32`), на остальных ОС — POSIX.

`flick run` и `flick dev` в проекте с `emit = "go"` собирают его
исполняемый файл в поколение запуска и запускают его, а `dev` пересобирает
и перезапускает его при каждом изменении; `flick test` собирает один
исполняемый файл `flick-test`, который выполняет `tests` каждого тестового
модуля с опциями, seed и выводом node-раннера. Для сборки нужен Go 1.23 или
новее в `PATH`, как Gleam нужен Erlang или Node: `flick` не поставляет
toolchain Go, а собранному файлу ничего устанавливать не нужно. Сборка идёт
без cgo, так что компилятор C тоже не нужен, если не задан `CGO_ENABLED`.
