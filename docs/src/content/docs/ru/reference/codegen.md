title: "Генерация кода"
---

`flick build` компилирует каждый модуль в ES-модуль (см. [Генерация TypeScript и граница FFI](../../spec/08-typescript-and-ffi/), [Компилятор Flick и интеграция с Content Mapper](../../spec/11-compiler/)). Эта страница
описывает отладочный профиль — эталонное понижение: любой другой
профиль должен вести себя так же.

## Выходные файлы

| Путь в выходном каталоге | Содержимое |
| - | - |
| `A/B.js`, `A/B.js.map` | модуль `A.B` и его карта исходного кода |
| `_flick/<Name>.js` | встроенные модули (`Prelude`, `Platform`, …) |
| `flick-main.js` | для приложения: выполняет `main` входного модуля через средство запуска точки входа среды выполнения |
| `package.json` | `{ "type": "module", "sideEffects": ["./flick-main.js"] }`; `"sideEffects": false` без средства запуска |

Модуль `Main` сохраняет имя `Main.js`/`Main.ts`; дефис в имени запускателя `flick-main.js`/`flick-main.ts` предотвращает коллизии на файловых системах без учёта регистра, а старое имя запускателя больше не используется при генерации.

Без проекта `flick build <files> --out-dir <dir>` записывает ту же структуру;
корневой файл, модуль которого экспортирует `main`, получает средство запуска.
Импорт модуля ничего не выполняет: модули только определяют значения.
Top-level значение, которое является вызовом, выведенным экземпляром или
сразу вызываемой стрелкой, помечено `/*#__PURE__*/`, поэтому бандлер
отбрасывает то, что программа не использует.

Сгенерированный код импортирует только `@flick-lang/runtime`: `Effect` поступает через него.
Модуль без стадий среды выполнения вообще не импортирует `Effect`.

## Значения

| Значение в исходном коде | JS |
| - | - |
| `Unit`, `()` | `undefined` |
| `Number`, `BigInt`, `String`, `Bool` | примитив JS; числовые литералы сохраняют своё написание в JS |
| кортеж, `List` | плотный массив |
| запись | простой объект ровно с её полями в порядке записи |
| значение алгебраического типа данных | `{ _tag, _0, _1, … }`, поля в порядке объявления |
| `unboxed type T = C f` | само поле |
| `untagged type T = A f \| B g …` | поле соответствующего конструктора, различаемое по его типу JS |
| `type error E = E …` | та же структура: ошибки — значения их единственного конструктора |
| `Option`, `Result` | собственные типы Effect `Option` (`Some`/`None`, `value`) и `Result` (`Success`/`Failure`, `success`/`failure`) |
| `Ref` | ячейка среды выполнения, равная только самой себе |

Идентификатор конструктора указывает пакет, модуль, тип и конструктор:
`@acme/shapes/App.Shapes.Shape.Circle`; без пакета (файл вне проекта,
встроенные модули) это `App.Shapes.Shape.Circle`. `_tag` содержит имя конструктора
и старшие 48 бит хеша FNV-1a 64 от его идентификатора, `Circle#7c57f5571734`:
идентичность сохраняется в теге примерно вдвое меньшей длины. `.iface` записывает
оба значения. Пользовательский тип с конструктором `Some` никогда не принимается
за `Option`.

`unboxed type` и `untagged type` задают представление вариантного типа
для кода, пересекающего границу FFI, во всех профилях. Тип без упаковки имеет один
конструктор с одним полем и представлен этим полем; тип без тега представлен
единственным полем каждого конструктора, причём типы JS этих полей должны
различаться — `Number`, `String`, `Bool`, `BigInt` или один список либо кортеж
(иначе `FLICK-T020`). Образец проверяет `typeof` или `Array.isArray` вместо `_tag`;
выведенные `Eq`, `Ord`, `Hash` и `Show` следуют представлению; `deriving Schema`
для типа без упаковки даёт формат передачи поля, а для типа без тега
свидетельство не выводится. Проекция в TypeScript — тип поля или объединение
типов полей.

```flick
unboxed type UserId = UserId String
  deriving Eq, Show, Schema

untagged type Key = ByNumber Number | ByName String | ByPath (List String)
```

`opaque unboxed type Token = Token String` скрывает конструктор от импортирующих
модулей, как и `opaque type`, и сохраняет саму строку во время выполнения.

`==` — каноническое структурное равенство: SameValueZero для чисел, поэтому
`NaN == NaN` и `0 == -0`; `Number.strict_equal` — это `===`, а
`Number.same_value` — `Object.is`. `<`, `<=`, `>`, `>=` — операторы JS;
`Ord Number` (`compare`) задаёт полный порядок с NaN в конце.

## Функции и стадии

Каждая стрелка каррированной функции — одна стрелочная функция JS, `(a) => (b) => …`.
Чистая стадия — обычный JS. Стадия среды выполнения возвращает `Effect.gen`,
в котором вызовы среды выполнения используют `yield*`; чистые вызовы в ней
остаются обычными вызовами:

```flick
load_name : UserId ->{Users, Log; NotFound} String
let load_name id =
  let user = Users.get id
  let name = normalize_name user.name
  Log.info name
  name
```

```js
export const load_name = (id) => Effect.gen(function* () {
  const user = (yield* $rt.operation($s_Users, "get", 1)(id));
  const name = normalize_name(user.name);
  (yield* $rt.operation($s_Log, "info", 1)(name));
  return name;
});
```

Вычисление идёт слева направо, стадия за стадией: первая стадия среды выполнения
завершается до вычисления следующего аргумента. Если операнду нужны инструкции
(`match`, блок, ветвь с инструкциями), предшествующие ему операнды сначала
становятся константами.

| Конструкция | JS |
| - | - |
| `task { body }` | `Effect.gen(function* () { … })`, строится без выполнения; каждый `yield*` выполняет тело заново |
| `await e` | `yield* e` |
| чистая функция там, где ожидается функция среды выполнения | оборачивается: каждая поднятая стадия выполняется в `Effect.sync` |
| `try body with arms` | `$rt.tryWith(body, handler)`: ветви видят первую типизированную ошибку причины |
| `provide layer { body }` | `$rt.provide(layer, body)`: слой строится до тела |
| `scope [s] { body }` | `$rt.scope((s) => body)`: лексический владелец с двухфазным закрытием, см. [среду выполнения](../runtime/) |
| вызов, получающий ресурс во внешнюю `scope` | `$rt.within(owner, call)`, владелец региона этой области |
| чистый хвостовой вызов самой функции | цикл по параметрам |
| рекурсия среды выполнения | через `yield*`, без роста стека JS |

## Сервисы

`service S` в модуле `M` — ключ сервиса среды выполнения `M.S`. `S.op` ищет
сервис на первой стадии среды выполнения операции и вызывает метод записи
реализации; метод значения `S.Impl` вызывается напрямую.
`Layer.succeed S impl` строит слой.

## Словари

Определение с ограничениями классов сначала принимает их словари:
`render : Show a => a -> String` — это `(dShow) => (value) => …`; при использовании
они передаются как `render(<Show Number>)(1)`. Словарь — объект методов класса
с геттером для каждого суперкласса (`$Eq` у словаря `Ord`). Экземпляр класса
с контекстом — функция от словарей этого контекста. Выведенные экземпляры классов
и принадлежащие компилятору экземпляры классов для записей и кортежей строятся
средой выполнения из словарей их полей. Аргумент высшего ранга с ограничением —
функция от его словарей.

## Внешние функции

`foreign mode name from "module" "export"` импортирует экспорт; каррированная
функция Flick вызывает его со всеми аргументами своих стадий до первой стадии
среды выполнения включительно (или `arity n`), словари идут первыми. `pure` —
прямой вызов, `sync` выполняется в `Effect.sync`, `async` ждёт возвращённый `Promise` —
самый внутренний владелец ждёт его завершения даже после прерывания
(см. [среду выполнения](../runtime/)), — а `effect` возвращает `Effect`.
Относительный путь модуля разрешается относительно исходного файла.
`global` указывает глобальное значение, как в `foreign sync now from global "Date.now"`.

## Карты исходного кода

У каждого модуля есть карта исходного кода версии 3. Определения, инструкции,
вызовы, операторы и возвраты отображаются на начало соответствующего узла Flick,
поэтому трассировка стека при `node --enable-source-maps` указывает на строки `.fl`.

## TypeScript

`flick build --emit ts` (или `emit = "ts"` в `flick.toml`) записывает те же
модули как файлы `.ts`, импортирующие друг друга с расширением `.ts`. Каждый
модуль объявляет представление экспортируемых типов в TypeScript и аннотирует
экспортируемые значения их проекциями типов (см. [Публичные TypeScript интерфейсы](../../spec/08-typescript-and-ffi/#публичные-typescript-интерфейсы)):

| Flick | TypeScript |
| - | - |
| `Number`, `String`, `Bool`, `BigInt`, `Unit`, `Never`, `Unknown` | `number`, `string`, `boolean`, `bigint`, `undefined`, `never`, `unknown` |
| `List a`, `(a, b)`, `{ x : a }` | `ReadonlyArray<A>`, `readonly [A, B]`, `{ readonly x: A }` |
| `Option a`, `Result e a` | `Option.Option<A>`, `Result.Result<A, E>` из Effect |
| `a -> b` | `(arg: A) => B`, одна стрелка на стадию |
| `a ->{r; e} b`, `Eff r e a` | `(arg: A) => Effect.Effect<B, E, R>`, `Effect.Effect<A, E, R>`; пустая строка — `never` |
| вариантный тип, ошибка | объединение `{ readonly _tag: "<constructor id>"; readonly _0: … }` |
| непрозрачный, абстрактный или встроенный номинальный тип, сервис | интерфейс с меткой его полного имени |
| класс над типами | интерфейс его словаря; значение с ограничением принимает его первым |
| `forall a.` | обобщённый параметр `<A>`; полиморфная константа использует `never` |

`--emit-dts` (или `emit-dts = true`) записывает `A/B.d.ts` рядом с каждым модулем:
те же объявления, `export declare const` для каждого экспортируемого значения
и конструктора, а также словарь каждого экземпляра класса без контекста. Экспорт,
тип которого не имеет представления в TypeScript, даёт `FLICK-F004`; объявления
никогда не содержат `any`.

`--promise-facade` (или `promise-facade = true`) записывает `A/B.promise.js` и
его `.d.ts` для каждой экспортируемой функции среды выполнения, которой не нужны
сервисы и чьи предыдущие стадии только создают замыкания: `f(a, b, options?)`
выполняет `f a b` под собственным владельцем и возвращает `Promise<Result<A, E>>`.
При ожидаемой ошибке промис успешно завершается с `Result.fail`; при дефекте
или прерывании отклоняется с `RuntimeFailure`, сообщение которого — инертный отчёт
о причине; `options.signal` прерывает выполнение, а промис завершается после очистки.
Импорт любого из этих файлов ничего не выполняет.

Тип, который TypeScript не может выразить точно, — переменная высшего кинда,
регион или содержащее его значение, открытая запись — не имеет проекции:
экспорт остаётся `any` при `--emit ts`, а `--emit-dts` сообщает об этом.
Код внутри модуля аннотируется как `any`: исходные типы находятся в проверяющем
модуле Flick и его `.iface`. Выходной код выполняется на Node как есть (с удалением
типов) и проходит `tsc --noEmit` с `strict`, `allowImportingTsExtensions` и
`module: nodenext`. Для этого `@flick-lang/runtime` поставляет `index.d.ts`.

## Профиль выпуска

`--profile release` (или `build.profile = "release"`; `flick test` принимает
тот же флаг) запускает оптимизатор над типизированным промежуточным представлением
до генерации кода. Он использует ту же среду выполнения и сохраняет всё, что программа
может наблюдать: вывод, порядок вызовов среды выполнения, сбои, `Exit` и коды завершения,
а также `.iface` модуля, полученный из эталонного понижения. Корпус сквозных тестов
запускается в обоих профилях с одинаковыми ожиданиями.

| Проход | Действие |
| - | - |
| свёртка констант | выражения из литералов с побитово точной семантикой JS (`60 * 60 * 24` → `86400`); ветвь константного условия; результат, который JS может вычислить иначе (`2 ** 0.5`) или при котором выбрасывает исключение (`1n / 0n`), остаётся вычислением |
| встраивание | известное полное применение небольшой чистой функции модуля или приватной функции, используемой один раз; сначала аргументы связываются по порядку; бета-редукция `(fun x -> …) a` |
| распространение | локальная привязка к литералу или имени заменяется им; чистое значение, которое не может выбросить исключение, переносится в единственное место использования, если оно гарантированно выполняется |
| скалярная замена | локальная запись, каждое использование которой читает поле, или локальный кортеж, который только деструктурируется, превращается в отдельную локальную привязку для каждой части: без объекта |
| мёртвый код | неиспользуемые чистые привязки (включая неиспользуемый `task { … }`) и недостижимые приватные значения верхнего уровня; вызов среды выполнения всегда сохраняется независимо от использования результата |
| рабочие функции | функция верхнего уровня с чистыми стадиями до последней получает `f$n`, принимающую все `n` аргументов; известное полное применение вызывает её, частичное сохраняет каррированную `f`; у приватной функции, применяемой только полностью, нет каррированной формы |
| словари | метод канонического экземпляра класса в модуле становится отдельной константой, вызываемой напрямую в местах использования; словарь, переданный как значение (свидетельство `EqHash`), никогда не заменяется |
| одиночные эффекты | тело стадии среды выполнения, которое только возвращает один эффект, `Effect.gen(function* () { return (yield* x); })`, становится `Effect.suspend(() => x)`: строится так же поздно, без генератора |

Функция, первая стадия которой что-либо вычисляет или выполняет, не получает
рабочую функцию: объединение стадий перенесло бы эту работу за следующий аргумент.
Чистая хвостовая рекурсия самой функции — цикл в обоих профилях; рекурсия среды
выполнения остаётся цепочкой шагов `Effect.gen` или `Effect.suspend`, поэтому уступает управление
планировщику и может быть прервана. Ничто не меняет группировку арифметических
операций (`(a + b) + c`), не сворачивает `x * 0`, не выполняет и не мемоизирует задачу,
не объединяет два построения `Layer`, не переносит поиск сервиса через `provide`
и не убирает проверку схемы.

## Пока не компилируется

Блоки `sql` и `cli` проверяются, но не компилируются: `flick build` сообщает
`FLICK-P012`.
