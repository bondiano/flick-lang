Классы разрешаются после вывода типов: каждое ограничение получает ровно
один словарь, выбранный по экземплярам классов, видимым модулю. Операции
сервисов — не методы классов ([эффекты](../effects/)).

## Классы

```flick
class Show a =
  show : a -> String

class Eq a => Hash a =
  hash : a -> Number

class Collection c a | c -> a =
  empty : c
  insert : a -> c -> c

class Functor (f : Type -> Type) =
  map : (a -> b) -> f a -> f b
```

У класса один или несколько параметров любого кинда, суперклассы перед `=>`
и функциональные зависимости после `|`: `c -> a` означает, что типы на
позиции `c` определяют типы на позиции `a`. Тип метода —
`forall params own. C params => …`. Цепочка суперклассов не должна вести
обратно к классу (`FLICK-C008`). Класс без методов лишь связывает свои
параметры и не содержит `=`.

`Prelude` объявляет `Eq`, `Ord` (`compare : a -> a -> Ordering` с
`type Ordering = LT | EQ | GT`), `Hash` и `Show`, с экземплярами классов для
встроенных типов, `List`, `Option` и `Result`; у `Ref` есть `Eq` (та же
ячейка), но нет `Hash`.

## Экземпляры классов

```flick
instance Show a => Show (List a) =
  let show items = "[" ++ show_items items ++ "]"
```

Каждый метод класса определяется один раз с сигнатурой класса, в которой
параметры класса заменены типами экземпляра класса. Собственная сигнатура
необязательна: без неё метод имеет в точности этот тип; явно записанная
сигнатура может быть более полиморфной, но не может требовать ограничения,
которого нет в сигнатуре класса (`FLICK-C010`). Отсутствующий или неизвестный
метод — `FLICK-C011`. Для типов экземпляра класса с учётом его контекста
должны выполняться ограничения суперклассов (`FLICK-C001`).

У метода может быть реализация по умолчанию: его сигнатура и `let`
непосредственно под ней в теле класса. Экземпляр класса, не определяющий
метод, получает реализацию по умолчанию; она видит словарь экземпляра класса,
как любая функция с ограничением этого класса. Собственное определение
в экземпляре класса заменяет её. Метод без реализации по умолчанию
абстрактный, и экземпляр класса без него — `FLICK-C011`, как и `let`
в теле класса, имя которого не является методом класса.

```flick
class Pretty a =
  pretty : a -> String
  verbose : a -> String
  let verbose x = "<" ++ pretty x ++ ">"

instance Pretty Number =
  pretty : Number -> String
  let pretty n = show n
```

Экземпляры классов каноничны. Проверка отклоняет экземпляр класса, когда:

| Правило | Код |
| - | - |
| его голова унифицируется с головой другого экземпляра класса после раскрытия псевдонимов; контекст не используется для выбора | `FLICK-C003` |
| две головы совпадают по определяющим типам зависимости, но не по определяемым | `FLICK-C004` |
| переменная определяемой части не встречается в определяющей части (строгое покрытие) | `FLICK-C005` |
| ни класс, ни номинальный тип в голове его первого типа не принадлежат этому пакету | `FLICK-C006` |
| переменной контекста нет в голове, либо ограничение контекста не меньше головы или повторяет переменную чаще | `FLICK-C007` |
| он определён для примитива строк либо для `Eq`, `Ord`, `Hash`, `Show` записи или кортежа | `FLICK-C012` |

Принадлежность определяется по пакету: исходные и тестовые модули проекта —
один пакет, каждая зависимость — отдельный, встроенные модули — ещё один.
Прозрачный псевдоним или запись не дают права владения; номинальная обёртка даёт:

```flick
unboxed type LocalExternalId = LocalExternalId ExternalId

instance Hash LocalExternalId =
  let hash id =
    match id with
    | LocalExternalId raw -> hash_external raw
```

`unboxed` сохраняет само значение `ExternalId` в среде выполнения:
обёртка ничего не стоит и передаётся SDK как есть, а экземпляры классов
принадлежат номинальному типу.

Модуль видит экземпляры классов каждого модуля, от которого зависит прямо
или косвенно, независимо от способа его импорта; порядок и форма `import`
ничего не меняют.

## Разрешение

Ограничение разрешается по порядку: предположением внешней сигнатуры,
экземпляра класса или `forall` высшего ранга (либо одним из их суперклассов),
примитивом строк, структурным экземпляром класса записи или кортежа либо
единственным экземпляром класса, голова которого ему соответствует.
Функциональная зависимость определяет неизвестные типы: при
`Collection UserSet User` для `empty : UserSet` не нужна аннотация элемента.
Ограничения разрешаются при проверке определения; у обобщаемого значения
переменные неразрешённых ограничений остаются мономорфными.

| Причина отказа | Код |
| - | - |
| ни один экземпляр класса не подходит или сигнатура не предполагает это ограничение; сообщение перечисляет экземпляры класса | `FLICK-C001` |
| тип в ограничении неизвестен, поэтому выбрать экземпляр класса невозможно | `FLICK-C002` |
| разрешение превышает свой лимит; сообщение показывает цепочку ограничений | `FLICK-C009` |

Лимит задаётся для каждого определения: `solver-steps` (100 000) и
`solver-depth` (256 вложенных ограничений) в `[build]` файла `flick.toml`.
Исчерпание лимита никогда не считается успехом.

## Записи и кортежи

У записей и кортежей есть принадлежащие компилятору экземпляры `Eq`, `Ord`,
`Hash` и `Show`, когда соответствующий экземпляр класса есть у каждого поля;
два прозрачных псевдонима одной формы разделяют их и не могут иметь собственные.
Открытая запись требует предположения об ограничении на всю запись.

## Примитивы строк

Модуль `Record` объявляет классы, которые компилятор разрешает по полям
известных записей; программа не может объявлять их экземпляры. Метка на
уровне типов — строка: `"name"` с киндом `Symbol`.

| Примитив | Выполняется, когда |
| - | - |
| `HasField l r a` | у `r` есть поле `l` типа `a` (`l r -> a`) |
| `Lacks l r` | у `r` нет поля `l` |
| `Remove l r out` | `out` — это `r` без поля `l` (`l r -> out`) |
| `Project r out` | каждое поле `out` является полем `r` того же типа |
| `UnionDisjoint a b out` | ни одна метка не встречается в обеих записях, а `out` содержит поля обеих (`a b -> out`) |
| `Map f r out` | у `out` метки из `r`, а тип `t` каждого поля становится `f t` (`f r -> out`) |
| `Labels r` | метки `r` известны |

`Record.Field "x" T` — это `{ x : T }`. Функции: `Record.label : Label l`
(используется как `(Record.label : Record.Label "x")`), `Record.get`,
`Record.extend` (требует `Lacks`), `Record.remove`, `Record.project`,
`Record.merge_disjoint` (требует `UnionDisjoint`) и `Record.labels`
(в каноническом, отсортированном порядке). Расширение открытой записи
требует `Lacks` для её строки в сигнатуре:

```flick
tag : Record.Lacks "tag" { id : Number | r } => { id : Number | r } -> { id : Number; tag : String | r }
let tag value = Record.extend (Record.label : Record.Label "tag") "t" value
```

## Автоматический вывод экземпляров классов

```flick
type Tree a = Leaf | Node (Tree a) a (Tree a)
  deriving Eq, Show
```

`deriving` создаёт экземпляры `Eq`, `Ord`, `Hash` и `Show` для
алгебраического типа данных (ADT), ошибки, уточнённого типа или непрозрачного
псевдонима, требуя соответствующий класс для каждого параметра типа с киндом
`Type`. Каждому полю нужен экземпляр класса; `Hash` и `Ord` выводятся только
вместе с `Eq`, чтобы все они использовали одни и те же поля. У прозрачного
псевдонима уже есть экземпляры классов его формы. Ошибки — `FLICK-C013`.

## Словари

Каждое разрешённое ограничение сохраняет свой словарь в месте, где оно
потребовалось: экземпляр класса, применённый к словарям его контекста,
предположение, суперкласс другого словаря, структурный экземпляр класса по
полям или примитив. Генерация кода передаёт их как аргументы.
