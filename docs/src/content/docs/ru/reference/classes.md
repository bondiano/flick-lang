---
title: "Классы и экземпляры классов"
---

После вывода типов компилятор разрешает ограничения классов: для каждого
выбирает ровно один словарь по экземплярам классов, видимым модулю.
Операции сервисов не относятся к методам классов ([эффекты](../effects/)).

## Классы

```flick
class Show a =
  show : a -> String

class Eq a => Hash a =
  hash : a -> Number

class Collection c a | c -> a =
  empty : c
  insert : a -> c -> c

class Functor (f : Type -> Type) =
  map : (a -> b) -> f a -> f b
```

У класса один или несколько параметров, каждый из которых может иметь любой
кинд. Суперклассы указываются перед `=>`, функциональные зависимости —
после `|`. Зависимость `c -> a` означает, что типы на позиции `c`
однозначно определяют типы на позиции `a`. Тип метода записывается как
`forall params own. C params => …`. Цепочка суперклассов не должна
возвращаться к исходному классу (`FLICK-C008`). Класс без методов только
связывает свои параметры; в его объявлении нет `=`.

В `Prelude` объявлены классы `Eq`, `Ord` (`compare : a -> a -> Ordering` с
`type Ordering = LT | EQ | GT`), `Hash` и `Show`, а также их экземпляры для
встроенных типов, `List`, `Option` и `Result`. У `Ref` есть экземпляр `Eq`,
который проверяет, что это одна и та же ячейка, но нет экземпляра `Hash`.

## Экземпляры классов

```flick
instance Show a => Show (List a) =
  let show items = "[" ++ show_items items ++ "]"
```

В экземпляре класса каждый метод определяется один раз. Его тип берётся
из сигнатуры метода в классе, где параметры класса заменяются типами
экземпляра. Указывать собственную сигнатуру необязательно: без неё метод
имеет в точности этот тип. Явная сигнатура может быть более полиморфной,
но не может требовать ограничения, которого нет в сигнатуре класса
(`FLICK-C010`). Отсутствующий или неизвестный метод вызывает `FLICK-C011`.
Типы экземпляра с учётом его контекста должны удовлетворять ограничениям
суперклассов (`FLICK-C001`).

У метода может быть реализация по умолчанию: в теле класса сразу под
сигнатурой записывается `let`. Если экземпляр класса не определяет этот
метод, он получает реализацию по умолчанию. Ей доступен словарь экземпляра,
как и любой функции с ограничением этого класса. Собственное определение
метода в экземпляре заменяет реализацию по умолчанию. Метод без такой
реализации считается абстрактным: если экземпляр его не определяет,
возникает `FLICK-C011`. Та же ошибка возникает, если имя `let` в теле
класса не совпадает ни с одним из его методов.

```flick
class Pretty a =
  pretty : a -> String
  verbose : a -> String
  let verbose x = "<" ++ pretty x ++ ">"

instance Pretty Number =
  pretty : Number -> String
  let pretty n = show n
```

Для каждого ограничения должен существовать единственный подходящий
экземпляр класса. Компилятор отклоняет объявление экземпляра в следующих случаях:

| Причина отказа | Код |
| - | - |
| после раскрытия псевдонимов его голова унифицируется с головой другого экземпляра; контекст не учитывается при выборе | `FLICK-C003` |
| головы двух экземпляров совпадают по определяющим типам функциональной зависимости, но различаются по определяемым | `FLICK-C004` |
| переменная из определяемой части зависимости не встречается в определяющей части: нарушено строгое покрытие | `FLICK-C005` |
| ни класс, ни головной номинальный тип первого аргумента экземпляра не принадлежат этому пакету | `FLICK-C006` |
| переменная контекста не встречается в голове экземпляра либо ограничение контекста не меньше головы или содержит больше повторений переменной | `FLICK-C007` |
| экземпляр объявлен для примитива строк либо для `Eq`, `Ord`, `Hash`, `Show` записи или кортежа | `FLICK-C012` |

Владение определяется на уровне пакета: исходные и тестовые модули проекта
относятся к одному пакету, каждая зависимость — к отдельному, а встроенные
модули — ещё к одному. Прозрачный псевдоним или запись не дают права объявлять
экземпляр по правилу владения; номинальная обёртка даёт:

```flick
unboxed type LocalExternalId = LocalExternalId ExternalId

instance Hash LocalExternalId =
  let hash id =
    match id with
    | LocalExternalId raw -> hash_external raw
```

С `unboxed` в среде выполнения остаётся само значение `ExternalId`:
обёртка не добавляет затрат и передаётся SDK без преобразования.
При этом экземпляры классов принадлежат номинальному типу.

Модулю видны экземпляры классов из всех модулей, от которых он зависит
прямо или косвенно. Порядок и форма `import` на это не влияют.

## Разрешение

Компилятор ищет способ разрешить ограничение в следующем порядке:

1. Предположение из внешней сигнатуры, контекста экземпляра класса или
   `forall` высшего ранга, в том числе один из их суперклассов.
2. Примитив строк.
3. Структурный экземпляр класса для записи или кортежа.
4. Единственный экземпляр класса с подходящей головой.

Функциональная зависимость позволяет определить неизвестные типы:
при `Collection UserSet User` для `empty : UserSet` не нужна аннотация
типа элемента. Ограничения разрешаются при проверке определения.
При обобщении значения переменные неразрешённых ограничений остаются
мономорфными.

| Причина отказа | Код |
| - | - |
| нет подходящего экземпляра класса или предположения в сигнатуре; сообщение перечисляет экземпляры класса | `FLICK-C001` |
| тип в ограничении неизвестен, поэтому выбрать экземпляр класса невозможно | `FLICK-C002` |
| превышен лимит разрешения; сообщение показывает цепочку ограничений | `FLICK-C009` |

Лимиты задаются в разделе `[build]` файла `flick.toml` и действуют для
каждого определения отдельно: `solver-steps` (100 000) и `solver-depth`
(256 вложенных ограничений). Исчерпание лимита не считается успешным разрешением.

## Записи и кортежи

Компилятор предоставляет записям и кортежам структурные экземпляры `Eq`,
`Ord`, `Hash` и `Show`, если соответствующий экземпляр есть у каждого поля.
Два прозрачных псевдонима одной формы используют одни и те же экземпляры
и не могут объявить собственные. Для открытой записи нужно предположение
об ограничении на запись целиком.

## Примитивы строк

Модуль `Record` объявляет классы, ограничения которых компилятор разрешает
по полям известных записей. Программа не может объявлять экземпляры этих
классов. Метка на уровне типов — строковый литерал, например `"name"`,
с киндом `Symbol`.

| Примитив | Выполняется, когда |
| - | - |
| `HasField l r a` | у `r` есть поле `l` типа `a` (`l r -> a`) |
| `Lacks l r` | у `r` нет поля `l` |
| `Remove l r out` | `out` — это `r` без поля `l` (`l r -> out`) |
| `Project r out` | каждое поле `out` есть в `r` и имеет тот же тип |
| `UnionDisjoint a b out` | у записей нет общих меток, а `out` содержит поля обеих (`a b -> out`) |
| `Map f r out` | метки `out` совпадают с метками `r`, а тип `t` каждого поля заменён на `f t` (`f r -> out`) |
| `Labels r` | метки `r` известны |

`Record.Field "x" T` обозначает `{ x : T }`. Модуль предоставляет функции
`Record.label : Label l` (пример использования:
`(Record.label : Record.Label "x")`), `Record.get`, `Record.extend`
(требует `Lacks`), `Record.remove`, `Record.project`,
`Record.merge_disjoint` (требует `UnionDisjoint`) и `Record.labels`
(возвращает метки в каноническом, отсортированном порядке).
Чтобы расширить открытую запись, в сигнатуре нужно ограничение `Lacks`
для её строки:

```flick
tag : Record.Lacks "tag" { id : Number | r } => { id : Number | r } -> { id : Number; tag : String | r }
let tag value = Record.extend (Record.label : Record.Label "tag") "t" value
```

## Автоматический вывод экземпляров классов

```flick
type Tree a = Leaf | Node (Tree a) a (Tree a)
  deriving Eq, Show
```

`deriving` создаёт экземпляры `Eq`, `Ord`, `Hash` и `Show` для
алгебраического типа данных (ADT), ошибки, уточнённого типа или непрозрачного
псевдонима. Для каждого параметра типа с киндом `Type` требуется
соответствующее ограничение класса, а для каждого поля — экземпляр класса.
`Hash` и `Ord` выводятся только вместе с `Eq`, чтобы все они использовали
одни и те же поля. Прозрачный псевдоним уже использует экземпляры классов
своей формы. Нарушения этих правил вызывают `FLICK-C013`.

## Словари

Для каждого разрешённого ограничения компилятор сохраняет словарь в том
месте, где он потребовался. Источником словаря может быть экземпляр класса,
применённый к словарям своего контекста, предположение, суперкласс другого
словаря, структурный экземпляр по полям или примитив. При генерации кода
эти словари передаются как аргументы.
