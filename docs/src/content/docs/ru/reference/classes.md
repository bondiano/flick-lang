После вывода типов компилятор разрешает ограничения классов: для каждого
выбирает ровно один словарь по экземплярам классов, видимым модулю.
Операции сервисов не относятся к методам классов ([эффекты](../effects/)).

## Классы

```flick
class Show a =
  show : a -> String

class Eq a => Hash a =
  hash : a -> Int

class Collection c a | c -> a =
  empty : c
  insert : a -> c -> c

class Functor (f : Type -> Type) =
  map : (a -> b) -> f a -> f b
```

У класса один или несколько параметров, каждый из которых может иметь любой
кинд. Суперклассы указываются перед `=>`, функциональные зависимости —
после `|`. Зависимость `c -> a` означает, что типы на позиции `c`
однозначно определяют типы на позиции `a`. Тип метода записывается как
`forall params own. C params => …`. Цепочка суперклассов не должна
возвращаться к исходному классу (`FLICK-C008`). Класс без методов только
связывает свои параметры; в его объявлении нет `=`.

В `Prelude` объявлены классы `Eq`, `Ord` (`compare : a -> a -> Ordering` с
`type Ordering = LT | EQ | GT`), `Hash` и `Show`, а также их экземпляры для
встроенных типов, `List`, `Option` и `Result`. У `Ref` есть экземпляр `Eq`,
который проверяет, что это одна и та же ячейка, но нет экземпляра `Hash`.
`Display` (`display : a -> String`) подставляется в дырку `\{e}` строки;
его экземпляры есть для `String`, `Int`, `Float` и `Bool`.

## Экземпляры классов

```flick
# class Show a =
#   show : a -> String
# show_items : Show a => List a -> String
# let show_items items = String.join ", " (List.map show items)
#
instance Show a => Show (List a) =
  let show items = "[" ++ show_items items ++ "]"
```

В экземпляре класса каждый метод определяется один раз. Его тип берётся
из сигнатуры метода в классе, где параметры класса заменяются типами
экземпляра. Указывать собственную сигнатуру необязательно: без неё метод
имеет в точности этот тип. Явная сигнатура может быть более полиморфной,
но не может требовать ограничения, которого нет в сигнатуре класса
(`FLICK-C010`). Отсутствующий или неизвестный метод вызывает `FLICK-C011`.
Типы экземпляра с учётом его контекста должны удовлетворять ограничениям
суперклассов (`FLICK-C001`).

У метода может быть реализация по умолчанию: в теле класса сразу под
сигнатурой записывается `let`. Если экземпляр класса не определяет этот
метод, он получает реализацию по умолчанию. Ей доступен словарь экземпляра,
как и любой функции с ограничением этого класса. Собственное определение
метода в экземпляре заменяет реализацию по умолчанию. Метод без такой
реализации считается абстрактным: если экземпляр его не определяет,
возникает `FLICK-C011`. Та же ошибка возникает, если имя `let` в теле
класса не совпадает ни с одним из его методов.

```flick
class Pretty a =
  pretty : a -> String
  verbose : a -> String
  let verbose x = "<" ++ pretty x ++ ">"

instance Pretty Float =
  pretty : Float -> String
  let pretty n = show n
```

Для реализации по умолчанию могут потребоваться дополнительные ограничения, которых нет у класса. Тогда
в теле класса сигнатура метода повторяется с этими ограничениями перед
ней — это сигнатура по умолчанию, и реализация проверяется по ней.
Экземпляр, который берёт реализацию по умолчанию, должен выполнять эти
ограничения для своих типов (`FLICK-C001` на экземпляре называет то, чего
не хватает); экземпляру со своим определением метода они не нужны.
Сигнатура по умолчанию имеет в точности тип метода и ограничивает только
параметры класса и собственные переменные, как `rep` в
`(Generic a rep, GDefault rep) => a`: у самого метода не должно быть своих
ограничений, а сигнатура по умолчанию у метода одна (`FLICK-C010`).
Сигнатура по умолчанию без `let` — `FLICK-C011`.

```flick
class Describe a =
  describe : a -> String
  describe : Show a => a -> String
  let describe x = "<" ++ show x ++ ">"

instance Describe Float   // берёт реализацию по умолчанию: `Show Float` есть
```

Для каждого ограничения должен существовать единственный подходящий
экземпляр класса. Компилятор отклоняет объявление экземпляра в следующих случаях:

| Причина отказа | Код |
| - | - |
| после раскрытия псевдонимов его голова унифицируется с головой другого экземпляра; контекст не учитывается при выборе | `FLICK-C003` |
| определяющие аргументы унифицируются, но определяемые несовместимы либо у неперекрывающихся голов для их равенства нужны дополнительные подстановки | `FLICK-C004` |
| определяемая переменная не покрыта определяющими аргументами головы и зависимостями контекста | `FLICK-C005` |
| ни класс, ни головной номинальный тип первого аргумента экземпляра не принадлежат этому пакету | `FLICK-C006` |
| переменная контекста не встречается в голове экземпляра либо ограничение контекста не меньше головы или содержит больше повторений переменной | `FLICK-C007` |
| экземпляр объявлен для примитива строк, для `Eq`, `Ord`, `Hash`, `Show` записи или кортежа либо для закрытого `Numeric` или `Iterable` | `FLICK-C012` |

Проверка покрытия начинается с переменных определяющих аргументов головы.
Затем компилятор до неподвижной точки добавляет переменные, определяемые
зависимостями контекста и его подставленных суперклассов. Правило применяется,
только когда покрыты все его входы. Каждая зависимость головы проверяется
отдельно; несвязанные ограничения и циклы без исходных переменных ничего
не добавляют. Псевдонимы раскрываются до проверки. Так допускается обычный
перенос возможности через трансформер:

```flick
# class MonadState (m : Type -> Type) s | m -> s
# type ReaderT r (m : Type -> Type) a = ReaderT (r -> m a)
#
instance MonadState m s => MonadState (ReaderT r m) s
```

Голова определяет `m`, а зависимость `m -> s` контекста — `s`.
Контекст помогает покрытию, но не выбирает экземпляр. Согласованность
по-прежнему определяется только головами: если определяющие аргументы
неперекрывающихся голов унифицируются, определяемые должны быть равны
при одной лишь этой подстановке.

Владение определяется на уровне пакета: исходные и тестовые модули проекта
относятся к одному пакету, каждая зависимость — к отдельному, а встроенные
модули — ещё к одному. Прозрачный псевдоним или запись не дают права объявлять
экземпляр по правилу владения; номинальная обёртка даёт:

```flick
# import Sdk exposing (ExternalId, hash_external)
#
unboxed type LocalExternalId = LocalExternalId ExternalId

instance Hash LocalExternalId =
  let hash id =
    match id with
    | LocalExternalId raw -> hash_external raw
#
# instance Eq LocalExternalId =
#   let eq (LocalExternalId a) (LocalExternalId b) = hash_external a == hash_external b
```

С `unboxed` в среде выполнения остаётся само значение `ExternalId`:
обёртка не добавляет затрат и передаётся SDK без преобразования.
При этом экземпляры классов принадлежат номинальному типу.

Модулю видны экземпляры классов из всех модулей, от которых он зависит
прямо или косвенно. Порядок и форма `import` на это не влияют.
Два модуля, которые не зависят друг от друга, не видят экземпляров друг
друга: о перекрытии между ними компилятор сообщает при проверке модуля, которому видны оба
набора экземпляров (`FLICK-C003`, `FLICK-C004`), на своей строке `module`.

## Разрешение

Компилятор ищет способ разрешить ограничение в следующем порядке:

1. Предположение из внешней сигнатуры, контекста экземпляра класса или
   `forall` высшего ранга, в том числе один из их суперклассов.
2. Примитив строк.
3. Структурный экземпляр класса для записи или кортежа.
4. Единственный экземпляр класса с подходящей головой.

Функциональная зависимость позволяет определить неизвестные типы:
при `Collection UserSet User` для `empty : UserSet` не нужна аннотация
типа элемента. Ограничения разрешаются при проверке определения.
При обобщении значения переменные неразрешённых ограничений остаются
мономорфными.

| Причина отказа | Код |
| - | - |
| нет подходящего экземпляра класса или предположения в сигнатуре; сообщение перечисляет экземпляры класса | `FLICK-C001` |
| тип в ограничении неизвестен, поэтому выбрать экземпляр класса невозможно | `FLICK-C002` |
| превышен лимит разрешения; сообщение показывает цепочку ограничений | `FLICK-C009` |

Лимиты задаются в разделе `[build]` файла `flick.toml` и действуют для
каждого определения отдельно: `solver-steps` (100 000) и `solver-depth`
(256 вложенных ограничений). Структурные ограничения контекста сохраняются,
но уточнение типов по функциональным зависимостям контекста не гарантирует, что разрешение ограничений всегда завершится.
Каждый шаг разрешения и повтор после уточнения расходует лимит.
Его исчерпание не считается успешным разрешением.

## Записи и кортежи

Компилятор предоставляет записям и кортежам структурные экземпляры `Eq`,
`Ord`, `Hash` и `Show`, если соответствующий экземпляр есть у каждого поля.
Два прозрачных псевдонима одной формы используют одни и те же экземпляры
и не могут объявить собственные. Для открытой записи нужно предположение
об ограничении на запись целиком.

## Примитивы строк

Модуль `Record` объявляет классы, ограничения которых компилятор разрешает
по полям известных записей. Программа не может объявлять экземпляры этих
классов. Метка на уровне типов — строковый литерал, например `"name"`,
с киндом `Symbol`.

| Примитив | Выполняется, когда |
| - | - |
| `HasField l r a` | у `r` есть поле `l` типа `a` (`l r -> a`) |
| `Lacks l r` | у `r` нет поля `l` |
| `Remove l r out` | `out` — это `r` без поля `l` (`l r -> out`) |
| `Project r out` | каждое поле `out` есть в `r` и имеет тот же тип |
| `UnionDisjoint a b out` | у записей нет общих меток, а `out` содержит поля обеих (`a b -> out`) |
| `Map f r out` | метки `out` совпадают с метками `r`, а тип `t` каждого поля заменён на `f t` (`f r -> out`) |
| `Labels r` | метки `r` известны |

`Record.Field "x" T` обозначает `{ x : T }`. Модуль предоставляет функции
`Record.label : Label l` (пример использования:
`(Record.label : Record.Label "x")`), `Record.get`, `Record.extend`
(требует `Lacks`), `Record.remove`, `Record.project`,
`Record.merge_disjoint` (требует `UnionDisjoint`) и `Record.labels`
(возвращает метки в каноническом, отсортированном порядке).
Чтобы расширить открытую запись, в сигнатуре нужно ограничение `Lacks`
для её строки:

```flick
tag : Record.Lacks "tag" { id : Float | r } => { id : Float | r } -> { id : Float; tag : String | r }
let tag value = Record.extend (Record.label : Record.Label "tag") "t" value
```

## Место вызова

Класс ядра `CallSite` из модуля `CallSite` — место использования:
`CallSite.place` — это `Module:line`, а `CallSite.definition` — `Module.name`
объемлющего определения верхнего уровня или `Module` вне его. Его даёт
чекер, а не экземпляр: функция с `CallSite =>` в сигнатуре передаёт дальше
место своего вызывающего, а любое другое использование получает своё.
`Atom.set` называет место записи в отладочном логе, serializable-атом берёт
ключ из определения, а `todo`, `echo` и `let assert` так называют своё
место.

```flick
# import CallSite exposing (CallSite)
#
/// Место того, кто вызвал `traced`.
traced : CallSite => String -> String
let traced label = label ++ " at " ++ CallSite.place
```

Программа не объявляет его экземпляров (`FLICK-C012`). В контексте
экземпляра и в сигнатуре метода по умолчанию он бывает только given.

## Автоматический вывод экземпляров классов

```flick
type Tree a = Leaf | Node (Tree a) a (Tree a)
  deriving Eq, Show
```

`deriving` создаёт экземпляры `Eq`, `Ord`, `Hash` и `Show` для
алгебраического типа данных (ADT), ошибки, уточнённого типа или непрозрачного
псевдонима. Для каждого параметра типа с киндом `Type` требуется
соответствующее ограничение класса, а для каждого поля — экземпляр класса.
`Hash` и `Ord` выводятся только вместе с `Eq`, чтобы все они использовали
одни и те же поля. Прозрачный псевдоним уже использует экземпляры классов
своей формы. Нарушения этих правил вызывают `FLICK-C013`.

Экземпляр класса с `@derive` выводит плагин из пакета этого класса или из пакета, указанного в
атрибуте, например `@derive std` (см. [плагины](../plugins/#derive)).
`deriving C { … }` передаёт derive аргументы, а `deriving instance C (M.T a)`
выводит экземпляр для типа другого модуля пакета. Таков `Cli.Value`. Любой
другой класс — `FLICK-C013`: у класса нет derive.

```flick
@derive
class Arbitrary a =
  arbitrary : a

type Point = Point Float Float
  deriving Arbitrary

deriving instance Arbitrary (Shapes.Shape)
```

`deriving Generic` (модуль `Generic`) даёт типу его представление, и класс
можно написать один раз для всех типов через него. Экземпляр —
`Generic T rep` с `to_rep : T -> rep` и `from_rep : rep -> T`:

| `T` | `rep` |
| - | - |
| `type Shape = Circle Float \| Dot` | `Sum (Con "Circle" (Field "_0" Float, Unit)) (Con "Dot" Unit)` |
| `type Named = Named { width : Float; label : String }` | `Con "Named" (Field "label" String, (Field "width" Float, Unit))` |

Каждый конструктор — `Con` с его именем, внутри поля парами с `Unit` в
конце: пронумерованные `_0`, `_1`, … или, если поле одно и это запись,
подписанные её метками в порядке сортировки, как у `Named`. Несколько конструкторов — вложенные `Sum` (`Inl`,
`Inr`) в порядке объявления. `Con` и `Field` — unboxed: представление
стоит одного `Sum` на каждый конструктор, кроме последнего, и пары на поле.
У типа без конструкторов представления нет (`FLICK-C013`).

```flick
# import Generic exposing (Generic(..), Field(..))
#
class GCount rep =
  gcount : rep -> Int

instance GCount Unit =
  let gcount _ = 0

instance GCount rest => GCount (Field l a, rest) =
  let gcount (_, rest) = 1 + gcount rest

count : (Generic a rep, GCount rep) => a -> Int
let count x = gcount (to_rep x)
```

Выводится и класс с одним параметром, у каждого метода которого есть
реализация по умолчанию: экземпляр берёт их все и требует соответствующего
ограничения класса для каждого параметра типа с киндом `Type`. Если сигнатуре по умолчанию нужен `Generic`,
тип получает и экземпляр `Generic`, так что класс, написанный один раз через
представление, выводится для любого типа:

```flick
# import Generic exposing (Generic(..), Sum(..), Con(..), Field(..))
#
# class GDefault rep =
#   gdefault : rep
#
# instance GDefault Unit =
#   let gdefault = ()
#
# instance (Default a, GDefault rest) => GDefault (Field l a, rest) =
#   let gdefault = (Field default, gdefault)
#
# instance GDefault fields => GDefault (Con n fields) =
#   let gdefault = Con gdefault
#
class Default a =
  default : a
  default : (Generic a rep, GDefault rep) => a
  let default = from_rep gdefault

type Pair a = Pair a a
  deriving Default    // instance Default a => Default (Pair a)
```

Если типу не хватает того, что нужно реализации по умолчанию, например
`GDefault` одного из полей, это `FLICK-C013`; так же и для класса с методом
без реализации по умолчанию или с несколькими параметрами.


Конструктор GADT, который не скрывает типов и не хранит словарей, выводится
как любой другой, и каждое поле берётся в том типе, который строит
конструктор: `IntLit Int : Expr Int` показывает свой `Int` через `Show Int`.
Для конструктора, скрывающего тип поля или хранящего словарь, вывода нет
(`FLICK-C013`), как нет у GADT и `Generic`; `Schema`, `Url` и `Form` отказывают
ему со своими кодами.
## Словари

Для каждого разрешённого ограничения компилятор сохраняет словарь в том
месте, где он потребовался. Источником словаря может быть экземпляр класса,
применённый к словарям своего контекста, предположение, суперкласс другого
словаря, структурный экземпляр по полям или примитив. При генерации кода
эти словари передаются как аргументы.

### Словари в значениях

Конструктор GADT может хранить словари: ограничения перед ним, `C =>`,
разрешаются там, где строится значение (там же `FLICK-C001`), и значение
хранит их словари после своих полей. Ветвь `match` по такому конструктору
получает их как предположения, в том числе для скрытых им типов:

```flick
type Showable =
  | Show b => Showable b : Showable

describe : Showable -> String
let describe s =
  match s with
  | Showable x -> show x

shown : List String
let shown = List.map describe [Showable 1, Showable "two", Showable [3.5]]
```

Достаёт словари только ветвь `match` (для образца `let` или параметра —
`FLICK-T058`). `==` сравнивает поля таких значений, а не словари; в `.d.ts`
хранимый словарь не становится полем.
