`suite` группирует случаи, `test` именует один, а `test.each` создаёт случай
для каждого сценария команд. `expect actual |> to.equal expected` проваливает
случай, если результат отличается. `left_after` даёт каждому случаю новый
`Ref` и фейковый слой `Shelf`: состояния тестов не смешиваются.

**Где запускается:** редактор выполняет `main`, короткую демонстрацию тех же
сценариев, а не `tests`. Локально поместите модуль в `test/Main.fl` проекта
Flick и запустите `flick test --forbid-only`. CI проверяет этот вход и результат
**3 passed, 0 failed**. Глава [«Тестирование»](../suites/) объясняет разделение;
см. также [справочник](../../reference/testing/).

**Попробуйте:** задайте `read = false` в `Books.finish`. Второй локальный случай
провалится, а демонстрация в браузере выведет `FAILED`.
