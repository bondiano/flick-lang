Flick — язык семейства ML, который компилируется в JavaScript и использует Effect. Он не заменяет среду выполнения JavaScript или сам Effect: компилятор проверяет программы Flick, сгенерированные ES-модули используют адаптер Flick, а адаптер построен поверх Effect.

Поэкспериментировать с языком можно в [Play](/ru/play/), а изучить сгенерированный JavaScript — в [Transpile](/ru/transpile/). Точные сигнатуры и контракты собраны в [указателе API и справочника](../api/).

## Что доступно и где?

В [репозитории исходного кода](https://github.com/bondiano/flick-lang) находятся перечисленные ниже инструменты. Имя пакета в манифесте **не доказывает**, что существует публичный релиз npm. В частности, интеграция Astro и импортёр объявлений — приватные пакеты рабочего пространства; примеры на этой странице не предлагают устанавливать их из публичного реестра.

| Компонент | Расположение и способ распространения |
| --- | --- |
| Нативный компилятор и CLI | Крейт Rust `flick`, использующий общее с браузерным компилятором ядро `flick-core`. Собирается из исходников; в репозитории также есть процесс выпуска нативных архивов по тегу. |
| Браузерный компилятор | Крейт Rust `flick-wasm`, собираемый в WebAssembly с помощью wasm-bindgen. Используется браузерными инструментами сайта; здесь он не представлен как публичный npm-пакет компилятора. |
| Адаптер времени выполнения | Пакет рабочего пространства `@flick-lang/runtime` в `runtime/`, содержащий JavaScript и объявления TypeScript. В манифесте закреплён Effect `4.0.5`; версии компилятора и адаптера должны соответствовать друг другу. |
| Интеграция Astro/Vite | Приватный пакет рабочего пространства `@flick-lang/astro` в `tools/astro-flick/`. Этот сайт подключает его через `workspace:*`. |
| Импортёр объявлений TypeScript | Приватный пакет рабочего пространства `@flick-lang/dts-importer` в `tools/dts-importer/`. Нужны его локальная сборка и установленный пакет с доступными для чтения объявлениями. |
| Поддержка редакторов | Исходники для VS Code, Zed и tree-sitter в `editors/`; языковой сервер входит в нативный исполняемый файл `flick`. |

Какие нативные архивы действительно доступны, проверяйте на [странице релизов GitHub](https://github.com/bondiano/flick-lang/releases). Процесс выпуска настроен для macOS, Linux и Windows на x86-64 и ARM64; наличие целевой платформы в настройках не гарантирует архив для каждой версии.

## Нативный компилятор и CLI

CLI создаёт проекты, проверяет типы, компилирует, запускает приложения и тесты, форматирует код и управляет зависимостями. Результат сборки — ES-модули; также поддерживаются вывод TypeScript и генерация `.d.ts`. Управление зависимостями делегируется pnpm, отдельного реестра пакетов Flick нет.

В клонированном репозитории с установленным закреплённым инструментарием Rust соберите нативный исполняемый файл:

```sh
cargo build -p flick
./target/debug/flick --version
```

Когда нужный исполняемый файл доступен через `PATH`, следующие команды проверяют окружение и работают с проектом Flick:

```sh
flick doctor
flick check
flick build
```

`check` и `build` не устанавливают зависимости и не запускают приложение. `doctor` показывает версии компилятора, Node.js, pnpm, адаптера и Effect — полезная отправная точка при диагностике интеграции. Процесс работы и требования описаны в разделах [«Первые шаги»](../start/getting-started/), [«CLI компилятора»](../reference/cli/) и [«Настройка проекта»](../reference/project/).

## Браузерный компилятор WebAssembly

`flick-wasm` предоставляет проверку, предварительный просмотр компиляции и результат сборки с модулями JavaScript и диагностикой. Он использует общее ядро компилятора со встроенными исходниками библиотек. Его браузерное окружение представляет один исходный модуль, а не файловую систему локального проекта или дерево установленных зависимостей npm.

В [Play](/ru/play/) можно попробовать поддерживаемые браузерные примеры, а в [Transpile](/ru/transpile/) — изучить сгенерированный JavaScript. Компиляция и выполнение — разные этапы: компиляция в JavaScript не делает доступными в браузере файловые API Node.js, соединение с PostgreSQL или произвольные внешние пакеты. Задача репозитория `just docs-wasm` собирает компилятор и его браузерные привязки для сайта документации.

## Адаптер и основа на Effect

`@flick-lang/runtime` — адаптер, используемый сгенерированными модулями. Поверх закреплённой версии Effect он определяет контракты Flick для владельцев областей, дочерних файберов, финализаторов, причин сбоев и запуска точки входа. Для необязательных адаптеров React и PostgreSQL предусмотрены необязательные peer-зависимости; импорт основного адаптера не означает, что эти возможности есть в любом окружении.

Effect уже предоставляет существенную основу для TypeScript: типизированные ошибки, внедрение зависимостей, структурированную конкурентность, безопасную работу с ресурсами, расписания и наблюдаемость. Об этих понятиях и базовой библиотеке читайте в [официальной документации Effect](https://effect.website/docs/). Flick добавляет другой исходный язык и правила времени компиляции; он не заменяет планировщик Effect и не утверждает, что приложениям на TypeScript нужно мигрировать.

[Справочник адаптера](../reference/runtime/) описывает гарантии выполнения, специфичные для Flick. [Стандартная библиотека](../reference/stdlib/) и [покрытие Effect](../reference/effect-surface/) объясняют доступный API и явные исключения. Не следует считать все API исходного Effect или другой его версии автоматически доступными встроенными возможностями Flick.

## Интеграция Astro и Vite

Локальный пакет `@flick-lang/astro` позволяет странице Astro или клиентскому скрипту импортировать экспортированное значение из файла `.fl`. Интеграция Astro регистрирует плагин Vite, который вызывает нативную команду `flick build` и реэкспортирует скомпилированный модуль. Это интеграция этапа сборки, а не браузерный компилятор WebAssembly.

В рабочем пространстве, где этот локальный пакет уже доступен, настройте Astro следующим образом:

```js
import flick from "@flick-lang/astro";
import { defineConfig } from "astro/config";

export default defineConfig({ integrations: [flick()] });
```

Этот же пакет экспортирует `flickVite` из `@flick-lang/astro/vite` для конфигурации Vite. Плагин выбирает компилятор сначала из опции `binary`, затем из `FLICK_BIN`, затем ищет `flick` в `PATH`; остальные опции — `profile` и `outDir`. Он отслеживает исходники Flick внутри каталога импортированного файла и компилирует выбранным нативным исполняемым файлом. Импорты адаптера и внешнего JavaScript в сгенерированном коде разрешает Vite, поэтому соответствующие зависимости должны быть доступны в проекте.

Этот сайт документации сам использует интеграцию рабочего пространства. Перед применением вне репозитория изучите [исходники интеграции](https://github.com/bondiano/flick-lang/tree/main/tools/astro-flick): это приватный инструмент рабочего пространства, а не документированная установка публичного пакета npm.

## Редакторы и синтаксические инструменты

Нативный языковой сервер запускается командой `flick lsp --stdio`. Он предоставляет диагностику с быстрыми исправлениями, подсказки с исходными типами, переход к определению и к объявлению типа, поиск ссылок, дополнение, подсказку сигнатуры, рефакторинги, структуру документа и символы рабочей области, семантическую подсветку, сворачивание, вложенные подсказки типов, форматирование и переименование поддерживаемых символов проекта. Определения встроенных библиотек открываются как настоящие файлы `.fl` только для чтения; просмотр не превращает их в редактируемые исходники проекта.

- **VS Code:** в `editors/vscode/` находятся грамматика TextMate и клиент языкового сервера. Настройка в репозитории использует локальное расширение; `flick.path` выбирает исполняемый файл.
- **Zed:** в `editors/zed/` находятся расширение и интеграция tree-sitter. Запускающий код сначала проверяет явно заданный `lsp.flick.binary.path`, затем `PATH` рабочего дерева, затем релиз, соответствующий версии расширения, с возможностью использовать офлайн-кэш. Локальный путь снимает зависимость от наличия подходящего релиза для скачивания.
- **tree-sitter:** `editors/tree-sitter-flick/` — грамматика уровня токенов с вложенными скобками, а не полный семантический анализ компилятора. Точную семантическую информацию предоставляет языковой сервер.

Возможности и локальная настройка Zed описаны в [справочнике редакторов](../reference/editor/), установка из репозитория — в [README поддержки редакторов](https://github.com/bondiano/flick-lang/blob/main/editors/README.md). Наличие этих интеграций в исходниках не означает доступность в маркетплейсах или равенство возможностей с другими языковыми экосистемами.

## JavaScript, TypeScript и импорт объявлений

У границы взаимодействия два направления:

1. **Вызов JavaScript из Flick.** Объявление `foreign` задаёт сигнатуру Flick и режим выполнения: `pure`, `sync`, `async` или `effect`. Метаданные описывают число аргументов, nullable-значения, преобразование в типизированные ошибки, отмену и удержание обратных вызовов. Это контракты, которые нужно проверять, а не гарантии, выведенные из JavaScript.
2. **Использование Flick из JavaScript или TypeScript.** Компилятор выводит ES-модули, умеет выводить TypeScript и создавать `.d.ts` для представимых публичных типов. Функции времени выполнения предоставляют значения Effect; сам экспорт не превращает их в Promise. Для необязательных Promise-фасадов действуют собственные ограничения применимости и контракты сбоев.

Для установленного пакета JavaScript команда `flick ffi import <package> --out <dir>` читает его `.d.ts` через вспомогательный инструмент Node `@flick-lang/dts-importer`. Это локальный инструмент рабочего пространства: компилятор ищет его в `node_modules` проекта либо использует скрипт, указанный в `FLICK_DTS_IMPORTER`. Импортёр поддерживает определённое подмножество TypeScript и помечает экспорты как поддерживаемые, требующие политики или неподдерживаемые. Заблокированные сгенерированные привязки нельзя незаметно вызвать.

Одних объявлений недостаточно, чтобы установить чистоту, преобразование ошибок или время удержания обратного вызова библиотекой. Задайте и проверьте нужную политику, затем используйте `flick ffi check` для сравнения проверенных привязок с установленными объявлениями. Импорт объявлений не переводит произвольную реализацию TypeScript во Flick и не доказывает совместимость любого API npm.

Режимы, политики и ограничения описаны в разделе [«Внешние функции»](../reference/ffi/), а форма сгенерированных модулей, объявления и Promise-фасады — в разделе [«Генерация кода»](../reference/codegen/).
