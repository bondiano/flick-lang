Flick компилируется в JavaScript. Компилятор проверяет исходный код,
а сгенерированные ES-модули используют адаптер Flick на основе Effect.
Ни JavaScript, ни Effect при этом не заменяются другой средой выполнения.

Попробовать язык можно в [Play](/ru/play/), а посмотреть сгенерированный
JavaScript — в [Transpile](/ru/transpile/). Правила языка и сигнатуры
библиотек собраны в [справочнике](../api/).

## Что доступно и где?

Перечисленные инструменты находятся в
[репозитории Flick](https://github.com/bondiano/flick-lang).
Не все пакеты предназначены для установки из npm: интеграция Astro
и импортёр объявлений — приватные пакеты рабочего пространства.
Примеры ниже предполагают, что они подключены локально.

| Компонент | Где находится и как получить |
| --- | --- |
| Нативный компилятор и CLI | Крейт Rust `flick`, использующий ядро `flick-core`, общее с браузерным компилятором. Собирается из исходников. В репозитории также настроен выпуск архивов по тегам. |
| Браузерный компилятор | Крейт `flick-wasm`, собираемый в WebAssembly через wasm-bindgen. Работает в инструментах этого сайта; установка отдельного npm-пакета компилятора здесь не описывается. |
| Адаптер среды выполнения | Пакет `@flick-lang/runtime` в `runtime/`: JavaScript и объявления TypeScript. Использует Effect `4.0.5`. Версии компилятора и адаптера должны быть согласованы. |
| Интеграция Astro/Vite | Приватный пакет `@flick-lang/astro` в `tools/astro-flick/`. Этот сайт подключает его через `workspace:*`. |
| Импортёр объявлений TypeScript | Приватный пакет `@flick-lang/dts-importer` в `tools/dts-importer/`. Нужно собрать его локально и установить пакет, чьи объявления будут импортироваться. |
| Поддержка редакторов | Исходники интеграций с VS Code, Zed и tree-sitter — в `editors/`. Языковой сервер входит в исполняемый файл `flick`. |

Готовые архивы проверяйте на
[странице релизов GitHub](https://github.com/bondiano/flick-lang/releases).
Сборки настроены для macOS, Linux и Windows на x86-64 и ARM64,
но для конкретной версии опубликованы не обязательно все варианты.

## Нативный компилятор и CLI

CLI создаёт проекты, проверяет типы, собирает и запускает программы
и тесты, форматирует код и управляет зависимостями. Компилятор выводит
ES-модули или TypeScript, при необходимости — декларации `.d.ts`.
Зависимости устанавливает pnpm; отдельного реестра пакетов Flick нет.

Чтобы собрать компилятор из исходников, клонируйте репозиторий
и установите закреплённый в нём инструментарий Rust:

```sh
cargo build -p flick
./target/debug/flick --version
```

Когда `flick` доступен в `PATH`, проверьте окружение и проект:

```sh
flick doctor
flick check
flick build
```

`check` и `build` не устанавливают зависимости и не запускают приложение.
Команда `doctor` показывает версии компилятора, Node.js, pnpm, адаптера
и Effect — начните с неё, если инструменты не работают вместе.
Подробности — в разделах [Начало работы](../start/getting-started/),
[CLI компилятора](../reference/cli/) и [Настройка проекта](../reference/project/).

## Браузерный компилятор WebAssembly

`flick-wasm` проверяет код и возвращает результат компиляции: модули
JavaScript и диагностические сообщения. Он использует общее ядро
компилятора со встроенными исходниками библиотек. В браузере доступен
один исходный модуль, а не файловая система проекта и дерево npm-зависимостей.

В [Play](/ru/play/) примеры можно редактировать и запускать,
в [Transpile](/ru/transpile/) — изучать сгенерированный JavaScript.
Успешная компиляция не делает доступными в браузере файловые API Node.js,
соединения с PostgreSQL или произвольные внешние пакеты.
Команда `just docs-wasm` собирает компилятор и браузерные привязки для сайта.

## Адаптер и основа на Effect

Сгенерированные модули используют `@flick-lang/runtime`. Этот адаптер
работает поверх закреплённой версии Effect и задаёт правила Flick
для владельцев областей, дочерних файберов, финализаторов, причин сбоев
и запуска точки входа. Для React и PostgreSQL нужны отдельные
необязательные peer-зависимости. Импорт основного адаптера их не подключает.

Effect предоставляет типизированные ошибки, внедрение зависимостей,
структурированную конкурентность, работу с ресурсами, расписания
и наблюдаемость. Эти возможности описаны в
[официальной документации Effect](https://effect.website/docs/).
Flick добавляет другой исходный язык и статические проверки,
но не заменяет планировщик Effect. Приложение на TypeScript с Effect
не обязано переходить на Flick.

Гарантии выполнения описаны в [справочнике адаптера](../reference/runtime/).
Доступные функции и исключения перечислены в
[стандартной библиотеке](../reference/stdlib/) и
[манифесте покрытия Effect](../reference/effect-surface/).
API другой версии Effect или API без привязки не становится доступным
во Flick автоматически.

## Интеграция Astro и Vite

Локальный пакет `@flick-lang/astro` позволяет импортировать значения
из `.fl` в страницы Astro и клиентские скрипты. Интеграция регистрирует
Vite-плагин: он вызывает нативный `flick build` и реэкспортирует собранный
модуль. Компиляция происходит при сборке сайта, а не через WebAssembly
в браузере.

Если пакет уже подключён в рабочем пространстве, добавьте его в настройки Astro:

```js
import flick from "@flick-lang/astro";
import { defineConfig } from "astro/config";

export default defineConfig({ integrations: [flick()] });
```

Для Vite без Astro пакет экспортирует `flickVite` из `@flick-lang/astro/vite`.
Путь к компилятору выбирается в таком порядке: опция `binary`,
переменная `FLICK_BIN`, команда `flick` в `PATH`. Ещё две опции —
`profile` и `outDir`. Плагин отслеживает исходники Flick в каталоге
импортированного файла и запускает выбранный компилятор.
Зависимости среды выполнения и внешнего JavaScript должен разрешить
Vite, поэтому установите их в проекте.

Этот сайт использует локальную интеграцию из того же рабочего пространства.
Перед подключением в другом проекте изучите
[её исходники](https://github.com/bondiano/flick-lang/tree/main/tools/astro-flick).
Примеры выше не предполагают установку пакета из публичного npm-реестра.

## Редакторы и синтаксические инструменты

Языковой сервер запускается командой `flick lsp --stdio`.
Он показывает диагностику с быстрыми исправлениями и исходные типы,
поддерживает переход к определению и к объявлению типа, поиск ссылок,
автодополнение, подсказки сигнатур, рефакторинги, структуру документа
и символы рабочей области, семантическую подсветку, сворачивание,
вложенные подсказки типов, форматирование и переименование
поддерживаемых символов проекта. Исходники встроенных библиотек
открываются как файлы `.fl` только для чтения и не становятся
редактируемой частью вашего проекта.

- **VS Code.** В `editors/vscode/` находятся грамматика TextMate и клиент
  языкового сервера. Настройка в репозитории использует локальное
  расширение; путь к компилятору задаётся через `flick.path`.
- **Zed.** В `editors/zed/` находятся расширение и интеграция tree-sitter.
  Сначала расширение проверяет `lsp.flick.binary.path`, затем `PATH`
  рабочего дерева, затем ищет релиз для своей версии. При отсутствии
  доступа к сети может использовать ранее скачанную копию.
  Явный локальный путь позволяет работать без скачивания релиза.
- **tree-sitter.** Грамматика в `editors/tree-sitter-flick/` распознаёт
  токены и вложенные скобки. Она не заменяет семантический анализ:
  сведения о типах и связях между именами предоставляет языковой сервер.

Настройка Zed описана в [справочнике редакторов](../reference/editor/),
установка из репозитория — в
[README интеграций](https://github.com/bondiano/flick-lang/blob/main/editors/README.md).
Наличие исходников расширения не означает, что оно опубликовано
в маркетплейсе или поддерживает те же возможности, что расширения других языков.

## JavaScript, TypeScript и импорт объявлений

Внешний код можно вызывать в обоих направлениях:

1. **Из Flick в JavaScript.** Объявление `foreign` задаёт сигнатуру
   и режим вызова: `pure`, `sync`, `async` или `effect`. Метаданные
   определяют число аргументов, представление отсутствующих значений,
   преобразование ошибок, отмену и срок хранения переданных функций.
   Автор привязки должен проверить эти свойства: компилятор не выводит
   их из реализации JavaScript.
2. **Из JavaScript или TypeScript во Flick.** Компилятор создаёт ES-модули,
   умеет выводить TypeScript и декларации `.d.ts` для представимых
   публичных типов. Эффектная функция возвращает Effect, не Promise.
   Для Promise-фасадов отдельно определены допустимые сигнатуры
   и правила передачи ошибок.

Команда `flick ffi import <package> --out <dir>` читает `.d.ts`
установленного пакета через инструмент Node `@flick-lang/dts-importer`.
Компилятор ищет этот локальный пакет в `node_modules` проекта
или запускает скрипт из `FLICK_DTS_IMPORTER`. Импортёр поддерживает
определённое подмножество TypeScript. В отчёте видно, какие экспорты
поддерживаются, каким не хватает политики, а какие не поддерживаются.
Заблокированную привязку вызвать нельзя.

Объявления TypeScript не доказывают чистоту функции, способ преобразования
ошибок и срок хранения переданной функции. Проверьте эти свойства
и задайте политики явно. После изменения зависимостей запускайте
`flick ffi check`, чтобы сравнить привязки с установленными объявлениями.
Импортёр не переводит реализацию TypeScript во Flick и не гарантирует
совместимость с любым npm-пакетом.

Режимы, политики и ограничения описаны в разделе
[Внешние функции](../reference/ffi/). Вид сгенерированных модулей,
декларации и Promise-фасады — в разделе [Генерация кода](../reference/codegen/).
