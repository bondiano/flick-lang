Flick — язык семейства ML, который компилируется в ES-модули JavaScript.
Для выполнения эффектов он использует Effect через пакет
`@flick-lang/runtime`. Эффекты, ошибки и сервисы описываются средствами
языка; JavaScript и Effect по-прежнему отвечают за выполнение программы.

Ниже — порядок изучения основных понятий с небольшими заданиями.
Подробные правила описаны в [справочнике](../reference/grammar/).
Если вы уже решаете конкретную задачу, перейдите к [руководствам](../guides/).

## Выберите отправную точку

- **Я пишу на TypeScript, но ещё не использовал Effect.** Начните с первых
  трёх шагов. Разберитесь, чем отличаются готовое значение, эффектный вызов
  и отложенное вычисление.
- **Я уже использую Effect.** Прочитайте [Flick и Effect](./flick-and-effect/),
  затем изучите стадии применения функций, строки ошибок и области
  владения ресурсами. Основа выполнения вам знакома; синтаксис и часть
  правил владения отличаются.
- **Я знаю язык семейства ML.** Просмотрите синтаксис и типы, затем
  переходите к эффектам и сервисам. Пустые строки сервисов и ошибок
  не означают, что функция чистая.

## 1. Запустите и исследуйте небольшую программу

Создайте приложение по разделу [Начало работы](../start/getting-started/),
установите зависимости и запустите `main`. Для этого нужны компилятор Flick,
Node.js 24.18 или новее и pnpm. Используйте версии среды выполнения и Effect,
закреплённые в шаблоне проекта: компилятор рассчитывает именно на них.

Основные команды описаны в
[справочнике командной строки](../reference/cli/):

- `flick check` проверяет исходные и тестовые модули, не запуская приложение.
- `flick build` записывает ES-модули, карты исходного кода и интерфейсы модулей.
- `flick run` собирает и запускает точку входа.
- `flick dev` пересобирает и заменяет работающее приложение после изменений.

**Попробуйте:** измените приветствие и снова запустите программу. Затем
посмотрите её JavaScript командой `flick inspect App.Main --emit js`.
В разделе [Генерация кода](../reference/codegen/) объясняется результат:
эффектные стадии превращаются в вычисления Effect, а чистые — в обычные функции.

## 2. Опишите данные и напишите чистые функции

Прочитайте [Кинды и типы](../reference/types/). Если синтаксис незнаком,
сверяйтесь с [грамматикой](../reference/grammar/). Начните с функций,
записей, `List`, `Option`, `Result` и вариантных типов. Полиморфизм высших
рангов и кинды можно изучить позже, когда они понадобятся для конкретного API.

Вот несколько важных отличий от TypeScript:

- Перед определением именованной функции, в том числе локальной, пишется
  полная сигнатура. Методы экземпляров могут наследовать сигнатуру класса.
  Тип значения, которое не является функцией, компилятор может вывести сам.
- Функции каррированы: `a -> b -> c` описывает две стадии применения.
- Запись содержит ровно те поля, которые указаны в типе. Чтобы принимать
  записи с дополнительными полями, укажите открытую строку полей. Не
  рассчитывайте на структурную подтипизацию по ширине, как в TypeScript.
- `match` должен обрабатывать все варианты. Если значение может отсутствовать,
  это обычно выражают через `Option`, а не доступ, способный вернуть `undefined`.

**Попробуйте:** объявите вариантный тип с двумя конструкторами: один без
полей, другой со строкой. Напишите чистую функцию, которая обрабатывает оба
варианта. Удалите одну ветку `match`, прочитайте сообщение о неполном
сопоставлении и верните ветку.

После этого прочитайте [Модули](../reference/modules/), чтобы разделить код
по файлам и выбрать экспортируемые имена. Встроенные модули доступны по
квалифицированным именам, например `String.trim` и `List.map`; для своих
модулей нужны явные импорты.

## 3. Разберитесь, где выполняются эффекты

Прочитайте [Эффекты, ошибки и сервисы](../reference/effects/), начиная со
стадий и `task` / `await`.

| Тип Flick | Как его читать |
| - | - |
| `a -> b` | Чистая функция |
| `a ->{Users; NotFound} b` | Эффектная функция: требует сервис `Users`, может завершиться ошибкой `NotFound` |
| `a ->{} b` | Эффектная функция без требований к сервисам и без ожидаемых ошибок; **не** чистая функция |
| `Eff r e a` | Отложенное вычисление с результатом `a`, строкой сервисов `r` и строкой ошибок `e` |

Внутри эффектной функции `let user = Users.get id` связывает результат
вызова — пользователя, а не `Eff`. Чтобы передать само вычисление, отложите
его через `task { ... }`. Чтобы выполнить сохранённое вычисление в текущем
файбере, используйте `await`. Создание `task` не выполняет его тело;
инициализация модулей остаётся чистой.

Для пользователей Effect: `Eff r e a` соответствует `Effect.Effect<A, E, R>`,
но **порядок параметров отличается**. `none` во Flick — пустая строка,
а не `Unit`, `Never` или конструктор `None`.

**Попробуйте:** вызовите эффектную функцию из чистой и прочитайте сообщение
компилятора. Затем отложите вызов через `task` и выполните полученное
вычисление из эффектной функции. Полные примеры есть в
[сравнении Flick и Effect](./flick-and-effect/).

## 4. Отделите зависимости от ожидаемых ошибок

Продолжите разделами об ошибках, сервисах и слоях в
[справочнике эффектов](../reference/effects/).

Объявите ошибку приложения через `type error` и укажите её в строке ошибок
функции. Вызывающий код увидит в сигнатуре, что нужно обработать.
Используйте `try ... with`: ошибка исчезает из строки, только если
образцы обработчика покрывают все её значения. Дефекты и прерывание
обрабатываются иначе — это не обычные ошибки приложения.

Опишите внешние операции через `service`, создайте реализацию с
`Layer.succeed` и предоставьте её через `provide`. Сервис — зависимость
вычисления, а не класс типов. В разделе
[Классы и экземпляры](../reference/classes/) описан другой механизм:
выбор единственной реализации операций над типом, например `Show` или `Eq`.

**Попробуйте:** замените реализацию сервиса в одном блоке `provide`, не
меняя вызывающую функцию. Затем обработайте одну из объявленных ошибок
и проверьте, что другая, необработанная, осталась в сигнатуре.

## 5. Назначьте владельца конкурентной работе и ресурсам

Прочитайте [Регионы и захваты](../reference/regions/), затем контракты
конкурентности и завершения в разделе
[Адаптер среды выполнения](../reference/runtime/).

Для конкурентного выполнения передавайте значения `task` в `parallel`,
`parallel_all` с явным ограничением, функции гонок и тайм-аутов.
Получайте ресурсы внутри `scope`. Для запуска через `Fiber.spawn` явно
укажите владельца задачи. Компилятор отслеживает ссылки на ресурсы даже
внутри замыканий и отложенных вычислений: вернуть функцию, которая
обращается к уже закрытому ресурсу, не получится.

**Попробуйте:** получите ресурс внутри области и используйте его там.
Затем попробуйте вернуть задачу, которая его захватывает. Прочитайте
сообщение компилятора и перенесите выполнение задачи внутрь области.
Проверка времени жизни действует для кода Flick; внешний JavaScript
по-прежнему должен соблюдать заявленные правила работы с ресурсами.

## 6. Подключитесь к миру JavaScript

Прежде чем вызывать JavaScript из Flick, прочитайте
[Внешние функции](../reference/ffi/). Для каждой привязки нужно определить
режим вызова, преобразование ошибок, отмену и срок хранения переданной
функции. Объявлений TypeScript для этого не всегда достаточно.

Чтобы вызывать Flick из TypeScript, изучите раздел
[Генерация кода](../reference/codegen/): вывод `.ts`, декларации `.d.ts` и
Promise-фасады. TypeScript не может точно выразить некоторые типы Flick,
включая регионы, переменные типов высших порядков и открытые записи.
Выберите представимый публичный интерфейс, а такие типы оставьте внутри
модуля.

Раздел [Редакторы](../reference/editor/) описывает языковой сервер и
проекцию TypeScript для редактора, а [Проект и пакеты](../reference/project/) —
расположение модулей, манифесты и зависимости.
