title: Изучение Flick
description: Путь от TypeScript и Effect к типам, эффектам, сервисам и областям владения Flick.
---

Flick — язык семейства ML, который компилируется в JavaScript ES-модули и
работает на Effect через `@flick-lang/runtime`. Он предоставляет языковой
синтаксис для эффектов, ошибок и сервисов, но не заменяет ни JavaScript-среду,
ни среду выполнения Effect.

Этот маршрут знакомит с понятиями в том порядке, в котором они понадобятся.
Подробные правила находятся в [справочнике](../reference/grammar/), а
[руководства](../guides/) помогут, если у вас уже есть конкретная задача.

## Выберите отправную точку

- **Я пишу на TypeScript, но ещё не использовал Effect.** Начните с первых
  трёх шагов ниже. Особое внимание уделите разнице между значением,
  runtime-вызовом и отложенным вычислением.
- **Я уже использую Effect.** Прочитайте [Flick и Effect](./flick-and-effect/),
  затем сосредоточьтесь на стадиях функций, строках ошибок и лексических
  областях владения. Основа среды выполнения знакома, но исходный язык и
  некоторые контракты владения отличаются.
- **Я знаю язык семейства ML.** Просмотрите синтаксис и типы, затем начните
  с эффектов и сервисов. Не считайте функцию чистой только потому, что её
  строки эффектов пусты.

## 1. Запустите и исследуйте небольшую программу

Следуйте разделу [Начало работы](../start/getting-started/): создайте
приложение, установите зависимости с закреплёнными версиями и запустите
`main`. Описанная настройка для Node использует Node.js 24.18 или новее и
pnpm; компилятор и среда выполнения ожидают согласованные версии пакета
среды выполнения и Effect.

Затем разберитесь с назначением команд по
[справочнику командной строки](../reference/cli/):

- `flick check` проверяет исходные и тестовые модули, не запуская приложение.
- `flick build` записывает ES-модули, карты исходного кода и интерфейсы модулей.
- `flick run` собирает и запускает точку входа.
- `flick dev` пересобирает и заменяет работающее приложение после изменений.

**Попробуйте:** измените приветствие, снова запустите программу и изучите
её JavaScript командой `flick inspect App.Main --emit js`. Сопоставьте
результат с разделом [Генерация кода](../reference/codegen/): runtime-стадии
становятся вычислениями Effect, а чистые стадии остаются обычными функциями.

## 2. Опишите данные и напишите чистые функции

Прочитайте [Роды и типы](../reference/types/), обращаясь к
[грамматике](../reference/grammar/), если синтаксис незнаком. Начните с
функций, записей, `List`, `Option`, `Result` и вариантных типов; полиморфизм
высших рангов и роды можно отложить до API, которому они понадобятся.

Вот несколько важных отличий от TypeScript:

- У именованных функций, в том числе локальных, есть полная сигнатура
  непосредственно перед `let`. Методы экземпляров могут наследовать
  сигнатуру класса; типы значений, не являющихся функциями, могут выводиться.
- Функции каррированы. У `a -> b -> c` две стадии применения.
- Записи точные. Для дополнительных полей нужна открытая строка записи,
  а не предположение о структурной подтипизации по ширине.
- `match` обязан быть исчерпывающим. Ожидаемое отсутствие значения обычно
  выражается через `Option`, а не через непроверенный доступ, который может
  вернуть `undefined`.

**Попробуйте:** определите вариантный тип с пустым случаем и случаем,
содержащим строку, затем напишите чистую функцию отображения обоих случаев.
Удалите одну ветку сопоставления, прочитайте диагностику полноты и верните
ветку на место.

После этого прочитайте [Модули](../reference/modules/), чтобы разделить код
по файлам и выбрать экспортируемые имена. Встроенные модули доступны по
квалифицированным именам, например `String.trim` и `List.map`; для своих
модулей нужны явные импорты.

## 3. Разберитесь, где выполняются эффекты

Прочитайте [Эффекты, ошибки и сервисы](../reference/effects/), начиная со
стадий и `task` / `await`.

| Тип Flick | Как его читать |
| - | - |
| `a -> b` | чистая функция |
| `a ->{Users; NotFound} b` | runtime-вызов, требующий `Users` и допускающий ошибку `NotFound` |
| `a ->{} b` | runtime-вызов без требований к сервисам и без ожидаемых ошибок; **не** чистая функция |
| `Eff r e a` | отложенное вычисление с результатом `a`, строкой сервисов `r` и строкой ошибок `e` |

Внутри runtime-функции `let user = Users.get id` связывает полученного
пользователя, а не `Eff`. Используйте `task { ... }`, если API нужно
вычисление как значение, и `await`, чтобы выполнить его в текущем fiber.
Создание `task` не выполняет его тело. Инициализация модулей чистая.

Для пользователей Effect: `Eff r e a` соответствует `Effect.Effect<A, E, R>`,
но **порядок параметров отличается**. `none` во Flick — пустая строка,
а не `Unit`, `Never` или конструктор `None`.

**Попробуйте:** перенесите runtime-вызов в чистую функцию и изучите
диагностику нарушения границы. Затем отложите его через `task` и используйте
из runtime-функции. В [сравнении](./flick-and-effect/) есть полные примеры
стиля с прямыми вызовами.

## 4. Отделите зависимости от ожидаемых ошибок

Продолжите разделами об ошибках, сервисах и слоях в
[справочнике эффектов](../reference/effects/).

Объявите предметную ошибку через `type error`: строка ошибок делает её
видимой вызывающему коду. Обработайте её через `try ... with`; ошибка
исчезает из строки только тогда, когда шаблоны покрывают все её значения.
Дефекты и прерывание не являются обычными предметными ошибками.

Объявите внешнюю возможность через `service`, создайте реализацию с
`Layer.succeed` и предоставьте её через `provide`. Сервис — runtime-зависимость,
а не класс; это важно для последующего чтения раздела
[Классы и экземпляры](../reference/classes/). Классы выбирают канонические
реализации для типов, например `Show` или `Eq`, а не ищут сервис приложения.

**Попробуйте:** замените реализацию сервиса в одном блоке `provide`, не
меняя вызывающую функцию. Затем обработайте одну объявленную ошибку и
убедитесь, что необработанная ошибка остаётся в сигнатуре вызывающего кода.

## 5. Назначьте владельца конкурентной работе и ресурсам

Прочитайте [Регионы и захваты](../reference/regions/), затем контракты
конкурентности и завершения в разделе
[Адаптер среды выполнения](../reference/runtime/).

Используйте значения `task` с `parallel`, ограниченным `parallel_all`,
гонками и тайм-аутами. Для приобретаемых ресурсов используйте `scope`, а
когда нужен `Fiber.spawn` — именованного владельца области. Проверка
регионов учитывает и ресурсы, скрытые в замыканиях и задачах, поэтому
возвращение callback не позволяет обойти время жизни ресурса.

**Попробуйте:** получите ресурс внутри области, используйте его там и
попытайтесь вернуть задачу, которая его захватывает. Прочитайте отказ,
затем оставьте работу в пределах времени жизни владельца. Это статическая
проверка времени жизни, а не утверждение, что внешний JavaScript
автоматически соблюдает все контракты.

## 6. Подключитесь к миру JavaScript

Перед привязкой JavaScript API прочитайте
[Внешние функции](../reference/ffi/). Режим вызова, преобразование ошибок,
отмена и удержание callback входят в контракт; декларация TypeScript не
всегда содержит всю необходимую информацию.

Затем прочитайте часть о TypeScript в разделе
[Генерация кода](../reference/codegen/): вывод `.ts`, декларации `.d.ts` и
Promise-фасады. Некоторые типы Flick, включая регионы, переменные высших
родов и открытые записи, нельзя точно спроецировать в публичный TypeScript
API. Проектируйте границу явно, не предполагая, что любая функция может
пересечь её без изменений.

Раздел [Редакторы](../reference/editor/) описывает language server и
межъязыковую проекцию, а [Проект и пакеты](../reference/project/) — корни
модулей, манифесты и зависимости.

## Перейдите к реальной задаче

Выберите рецепт в [Руководствах](../guides/) и находите готовые модули в
[обзоре стандартной библиотеки](../reference/stdlib/), вместо того чтобы
заново писать существующие функции. Изучайте предметные части по мере
необходимости:

- [Схемы и кодеки](../reference/schema/) для проверки внешних данных.
- [SQL](../reference/sql/) для типизированных запросов PostgreSQL.
- [HTTP API](../reference/http-api/) для описания конечных точек.
- [Приложения командной строки](../reference/cli-dsl/) для определений CLI.
- [Пользовательские интерфейсы](../reference/ui/) для представлений на React
  и задач событий с владельцем.

Если следующий вопрос — стоит ли вообще вводить новый язык, прочитайте
[Flick и Effect](./flick-and-effect/): сравнение не предполагает, что Flick
подходит каждому приложению на TypeScript.
