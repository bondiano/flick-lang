**Effect — библиотека TypeScript. Flick — отдельный язык семейства ML,
который компилируется в JavaScript и использует Effect через адаптер
среды выполнения.** Выбирая Flick, вы меняете исходный язык, проверки
компилятора и инструменты. Выполнение эффектов остаётся на Effect.

Если приложение уже написано на TypeScript с Effect, переход на Flick
не нужен ради типизированных ошибок, внедрения зависимостей или
структурированной конкурентности: всё это уже есть в Effect.

## Общая основа

Тип
[`Effect.Effect<A, E, R>`](https://effect.website/docs/v4/getting-started/the-effect-type/)
описывает вычисление: `A` — результат, `E` — ожидаемая ошибка,
`R` — требуемые сервисы. Создать такое значение — не значит выполнить
описанную в нём работу.

Во Flick вычисление как значение имеет тип `Eff r e a`.
**Порядок параметров другой: сервисы, ошибки, результат.**
Эффектная функция, например `String ->{Users; NotFound} User`,
компилируется в функцию, возвращающую Effect. Чистая
`String -> User` остаётся обычной JavaScript-функцией.

[Адаптер среды выполнения Flick](../../reference/runtime/) использует
закреплённую версию Effect **4.1.2**. Сгенерированные модули импортируют
`@flick-lang/runtime`. Этот адаптер также задаёт правила владения задачами
и ресурсами, обработки ошибок дочерних задач, ожидания внешних Promise
и завершения работы. Поэтому общая основа не означает, что все
низкоуровневые API можно заменять друг другом. Подробности —
в разделе [Генерация кода](../../reference/codegen/).

| Тема | TypeScript с Effect | Flick на Effect |
| - | - | - |
| Исходный язык | TypeScript и API Effect | Отдельный язык семейства ML и компилятор |
| Вычисление как значение | `Effect.Effect<A, E, R>` | `Eff r e a`, создаваемое через `task` |
| Последовательное выполнение эффектов | `Effect.gen` и `yield*` или библиотечные комбинаторы | Прямые вызовы в эффектных функциях; `await` для сохранённого `Eff` |
| Ожидаемые ошибки | Типизированный канал ошибок; данные с тегами и `catchTag` | `type error`, строки ошибок и `try ... with` |
| Сервисы | `Context.Service`, реализации и `Layer` | `service`, `S.Impl`, `Layer` и `provide` |
| Чистый код | Обычный TypeScript; построение и выполнение эффектов разделены API библиотеки | Разные стрелки для чистых и эффектных функций; различие проверяет компилятор |
| Время жизни ресурсов | Области Effect, получение ресурсов и финализаторы | Освобождение ресурсов при выполнении и статические проверки регионов и захватов |
| Работа с JavaScript/TS | Обычные импорты и типы TypeScript | Явные внешние привязки и сгенерированные публичные интерфейсы |
| Доступ к API Effect | TypeScript API установленной библиотеки | API закреплённой версии, доступный через Flick; исключения перечислены в манифесте |

В примерах ниже явно указаны публичные типы, чтобы их было легче сравнить.
В TypeScript часть этих типов можно вывести автоматически.
Каждый блок Flick — полный модуль для файла `src/Learn/Errors.fl` или
`src/Learn/Services.fl`. Модули экспортируют вычисления для вызова из
другого кода, а не точку входа `main`.

## Пример: типизированная ошибка и запасное значение

Обе версии возвращают `"Ada"` для идентификатора `1` и `"Guest"` для
остальных идентификаторов. Для наглядности поиск выполняется в памяти,
без подключения к базе данных.

### TypeScript с Effect

Объявление и обработка ошибки соответствуют
[руководству Effect по ожидаемым ошибкам](https://effect.website/docs/v4/error-management/expected-errors/).

```ts
import { Data, Effect } from "effect"

class NotFound extends Data.TaggedError("NotFound")<{
  readonly id: number
}> {}

const find = (id: number): Effect.Effect<string, NotFound> =>
  id === 1
    ? Effect.succeed("Ada")
    : Effect.fail(new NotFound({ id }))

export const lookup = (id: number): Effect.Effect<string> =>
  find(id).pipe(
    Effect.catchTag("NotFound", () => Effect.succeed("Guest")),
  )
```

### Flick

```flick
module Learn.Errors exposing (lookup)

type error NotFound = NotFound Float

find : Float ->{; NotFound} String
let find id =
  if id == 1 then "Ada"
  else from_result (Err (NotFound id))

lookup : Float ->{} String
let lookup id =
  try find id with
  | NotFound _ -> "Guest"
```

`find` может завершиться ошибкой `NotFound`. Функция `lookup`
обрабатывает все её значения, поэтому строка ошибок у неё пуста.
При этом стрелка `->{}` остаётся эффектной: пустая строка ошибок
не делает функцию чистой.

Во Flick используются обычное ветвление, прямой вызов и обработчик
с образцом. Компилятор сам связывает операции через Effect, поэтому
в исходном коде не нужны `yield*` или вызовы комбинаторов для каждого шага.
Полные правила описаны в разделе
[Эффекты, ошибки и сервисы](../../reference/effects/).

Ни одна из версий не превращает все возможные сбои в `NotFound`.
Effect различает
[ожидаемые ошибки и дефекты](https://effect.website/docs/v4/error-management/two-error-types/).
Flick сохраняет это различие: `try ... with` не перехватывает
произвольные исключения JavaScript.

## Пример: объявить, использовать и предоставить сервис

В обеих версиях вычисление получает сервис `Greeter` и возвращает
`"Hello, Ada"`. Слой предоставляет реализацию сервиса.
Создание `program` ничего не выполняет: не вызывает сервис,
не печатает результат и не запускает фоновую работу.

### TypeScript с Effect

Сервисы и слои описаны в руководствах Effect:
[Managing Services](https://effect.website/docs/v4/requirements-management/services/)
и [Managing Layers](https://effect.website/docs/v4/requirements-management/layers/).

```ts
import { Context, Effect, Layer } from "effect"

class Greeter extends Context.Service<
  Greeter,
  { readonly greet: (name: string) => Effect.Effect<string> }
>()("Learn.Services.Greeter") {}

const welcome = (name: string): Effect.Effect<string, never, Greeter> =>
  Effect.gen(function* () {
    const greeter = yield* Greeter
    return yield* greeter.greet(name)
  })

const greeterLayer = Layer.succeed(Greeter, {
  greet: (name: string) => Effect.succeed("Hello, " + name),
})

export const program: Effect.Effect<string> = Effect.provide(
  welcome("Ada"),
  greeterLayer,
)
```

### Flick

```flick
module Learn.Services exposing (program)

service Greeter =
  greet : String ->{} String

welcome : String ->{Greeter; none} String
let welcome name =
  Greeter.greet name

greeter_layer : Layer none none {Greeter}
let greeter_layer =
  Layer.succeed Greeter { greet = fun name -> "Hello, " ++ name }

program : Eff none none String
let program =
  task {
    provide greeter_layer {
      welcome "Ada"
    }
  }
```

`welcome` требует сервис `Greeter`. У `program` этого требования уже нет:
сервис предоставлен слоем. Объявление `service` создаёт ключ сервиса
и функции доступа к его операциям. Компилятор включает вызов из `welcome`
в последовательность выполнения Effect.

В реализации сервиса передана чистая функция. Компилятор адаптирует её
к объявленному эффектному типу. Внешний `task` откладывает всю работу:
значение `program` можно передать другому коду, не выполняя его.

В Effect генераторы тоже не обязательны:
[руководство по созданию эффектов](https://effect.website/docs/v4/getting-started/creating-effects/)
показывает конструкторы и комбинаторы. Во Flick для последовательного
эффектного кода предусмотрен синтаксис прямых вызовов.

## Что добавляет Flick

Flick использует Effect для выполнения программы и добавляет
собственные средства языка и проверки:

- **Различие чистого и эффектного кода.** Сигнатуры `a -> b` и
  `a ->{r; e} b` обозначают разные виды функций. Компилятор не разрешает
  эффектный вызов в чистом теле, даже если обе строки пусты.
  См. [Типы](../../reference/types/) и [Эффекты](../../reference/effects/).
  Для `foreign pure` чистоту гарантирует автор привязки: компилятор
  не доказывает свойства произвольного JavaScript.
- **Типы данных в стиле ML.** Вариантные типы, исчерпывающий `match`,
  точные записи и открытые строки полей входят в язык.
  Их проверяет компилятор, а не соглашения о форме объединений TypeScript.
  См. [Типы](../../reference/types/).
- **Классы типов и единственный выбор экземпляра.** Класс может описывать
  операции над конструкторами типов. Компилятор выбирает словари
  и отклоняет пересекающиеся экземпляры; `deriving` автоматически
  создаёт поддерживаемые стандартные экземпляры.
  Классы типов — не классы JavaScript и не сервисы среды выполнения.
  См. [Классы и экземпляры](../../reference/classes/).
- **Проверка времени жизни ресурсов.** Регионы и квалификаторы захватов
  отслеживают ссылки на ресурсы, в том числе в возвращаемых замыканиях
  и задачах. У дочерней задачи явно заданы владелец и супервизор.
  Ограничения этих проверок и требования к внешнему коду описаны
  в разделе [Регионы и захваты](../../reference/regions/).
- **Генерация интерфейса для JavaScript и TypeScript.** Компилятор
  создаёт ES-модули и карты исходного кода, умеет выводить TypeScript,
  декларации и Promise-фасады для подходящих функций.
  Не все типы Flick представимы в TypeScript; ограничения перечислены
  в разделе [Генерация кода](../../reference/codegen/).

У Effect уже есть
[безопасное получение ресурсов и финализаторы](https://effect.website/docs/v4/resource-management/introduction/).
Flick добавляет к ним статические проверки владения и захватов,
а его адаптер задаёт порядок завершения задач и освобождения ресурсов.

## В чём особенно хорош Effect

**Можно остаться в TypeScript.** Effect работает в обычных `.ts`-модулях.
Не нужны ещё один язык, компилятор и внешние привязки. Настройка описана
в [руководстве по установке](https://effect.website/docs/v4/getting-started/installation/).

**Весь API библиотеки доступен напрямую.**
[Экосистема Effect](https://effect.website/docs/v4/onboarding/)
включает потоки, наблюдаемость, схемы, HTTP, SQL, CLI и другие пакеты.
В TypeScript вы используете их API и документацию без дополнительных привязок.
Во Flick доступность каждого API зависит от
[манифеста покрытия](../../reference/effect-surface/): там отдельно отмечены
обёртки, конструкции языка, исключения и ещё не добавленные привязки.
Запись в манифесте сама по себе не означает, что API уже можно вызвать.

**Не нужно согласовывать типы двух языков.** SDK, типы фреймворков
и абстракции TypeScript остаются в своём языке.
[Импортёр FFI Flick](../../reference/ffi/) поддерживает только описанное
в справочнике подмножество TypeScript. Для сложных перегрузок, объединений
или правил хранения переданной функции может понадобиться ручная
привязка; часть форм не поддерживается. Не все публичные типы Flick
можно выразить в TypeScript. Если основная работа — соединять
TypeScript-библиотеки, использование одного языка сокращает эту работу.

Эти различия не означают, что код на Effect обязательно длиннее
или хуже типизирован. У языков разные средства для описания одних задач.

## Что выбрать?

**TypeScript с Effect подойдёт, если** вы хотите сохранить существующий
процесс разработки, много работаете с SDK и фреймворками TypeScript,
нуждаетесь в прямом доступе к API Effect или не хотите сопровождать
ещё один компилятор и набор инструментов. Типизированные ошибки,
сервисы, структурированная конкурентность и управление ресурсами
у вас уже есть.

**Flick подойдёт, если** вам нужны типы данных и классы типов в стиле ML,
проверяемое разделение чистого и эффектного кода, прямые вызовы эффектов
и статические правила регионов и захватов. Взамен придётся освоить
его синтаксис и компилятор, использовать закреплённую версию Effect
и описывать взаимодействие с внешним кодом. Начните с отдельного модуля
с небольшим публичным интерфейсом — переписывать всё приложение не нужно.

**Flick можно использовать внутри JavaScript-приложения.** Проверьте
сгенерированные декларации или Promise-фасад, оставьте непредставимые
типы внутри модуля и убедитесь, что ошибки и отмена работают ожидаемо.
Теги ошибок Flick создаёт компилятор. Совпадение имени с классом
`Data.TaggedError` из примера выше не означает совпадения представления.
Общая основа Effect не делает исходники и значения двух языков
автоматически совместимыми.

в [Руководствах](../../guides/).
