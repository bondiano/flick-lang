Flick и Effect — не конкурирующие среды выполнения. **Effect — библиотека
TypeScript; Flick — язык семейства ML, который компилируется в JavaScript
и использует Effect через адаптер среды выполнения.** Выбор прежде всего
касается исходного языка, проверок компилятора, инструментов и границы
интеграции, а не замены модели выполнения Effect.

Если ваше приложение на TypeScript уже успешно использует Effect,
внедрение Flick — отдельное решение о языке, а не условие получения
типизированных ошибок, внедрения зависимостей или структурированной
конкурентности.

## Общая основа

Effect описывает вычисление тремя параметрами:
[`Effect.Effect<A, E, R>`](https://effect.website/docs/v4/getting-started/the-effect-type/)
для результата, ожидаемой ошибки и требуемых сервисов. Значение описывает
работу; его создание само по себе эту работу не выполняет.

Тип вычисления как значения во Flick — `Eff r e a`: **сначала сервисы,
затем ошибки, затем результат**. Runtime-функция, например
`String ->{Users; NotFound} User`, компилируется в функцию, возвращающую
Effect. Чистая `String -> User` остаётся обычной JavaScript-функцией.

Текущий [адаптер среды выполнения](../../reference/runtime/) закрепляет
Effect **4.0.5**. Сгенерированные модули импортируют `@flick-lang/runtime`,
а не второй независимый движок эффектов. Адаптер также определяет
специфичные для Flick контракты лексических владельцев, супервизии,
внешних promise и завершения; общая основа Effect не делает все
низкоуровневые API взаимозаменяемыми. Фактическое преобразование описано
в разделе [Генерация кода](../../reference/codegen/).

| Тема | TypeScript с Effect | Flick на Effect |
| - | - | - |
| Исходный язык | TypeScript и API Effect | Отдельный язык семейства ML и компилятор |
| Вычисление как значение | `Effect.Effect<A, E, R>` | `Eff r e a`, создаваемое через `task` |
| Последовательный runtime-код | `Effect.gen` и `yield*` либо библиотечные комбинаторы | Прямые вызовы в runtime-функциях; `await` для значения `Eff` |
| Ожидаемые ошибки | Типизированный канал ошибок; данные с тегами и `catchTag` | `type error`, строки ошибок и `try ... with` |
| Сервисы | `Context.Service`, реализации и `Layer` | `service`, `S.Impl`, `Layer` и `provide` |
| Чистый код | Обычный TypeScript; построение и выполнение эффектов — библиотечные границы | Разные чистые и runtime-стрелки, проверяемые компилятором |
| Время жизни ресурсов | Области Effect и API получения и финализации | Runtime-освобождение плюс статические регионы и проверки захватов |
| Граница с JavaScript/TS | Нативные импорты и типы TypeScript | Явные внешние привязки и сгенерированные публичные проекции |
| Доступ к API Effect | TypeScript API установленной библиотеки | Закреплённый и проверенный API Flick с записанными исключениями |

В примерах ниже публичные типы видны с обеих сторон. TypeScript способен
вывести многие возвращаемые типы; это читаемые эквиваленты, а не конкурс
краткости или количества строк. Каждый блок Flick — полный модуль для
соответствующего пути `src/Learn/Errors.fl` или `src/Learn/Services.fl`.
Они экспортируют переиспользуемые вычисления, а не исполняемую `main`.

## Пример: типизированная ошибка и запасное значение

Обе версии возвращают `"Ada"` для идентификатора `1` и `"Guest"`, когда имя
отсутствует. Поиск намеренно представлен небольшим правилом в памяти, а
не имитацией интеграции с базой данных.

### TypeScript с Effect

Объявления и восстановление следуют официальному
[руководству по ожидаемым ошибкам](https://effect.website/docs/v4/error-management/expected-errors/).

```ts
import { Data, Effect } from "effect"

class NotFound extends Data.TaggedError("NotFound")<{
  readonly id: number
}> {}

const find = (id: number): Effect.Effect<string, NotFound> =>
  id === 1
    ? Effect.succeed("Ada")
    : Effect.fail(new NotFound({ id }))

export const lookup = (id: number): Effect.Effect<string> =>
  find(id).pipe(
    Effect.catchTag("NotFound", () => Effect.succeed("Guest")),
  )
```

### Flick

```flick
module Learn.Errors exposing (lookup)

type error NotFound = NotFound Number

find : Number ->{; NotFound} String
let find id =
  if id == 1 then "Ada"
  else from_result (Err (NotFound id))

lookup : Number ->{} String
let lookup id =
  try find id with
  | NotFound _ -> "Guest"
```

`find` допускает ошибку `NotFound`. `lookup` обрабатывает каждое значение
этой ошибки, поэтому её строка ошибок пуста. Пустая runtime-стрелка `->{}`
по-прежнему не означает чистую функцию. Её вызов — runtime-операция.

Тело Flick использует обычное ветвление, прямой вызов и обработчик с
шаблоном. Компилятор добавляет построение Effect и последовательность
выполнения. В этом и состоит сокращение служебного кода: операции
принадлежат языку, а не записываются библиотечной композицией в каждом
месте вызова. Полные правила находятся в разделе
[Эффекты, ошибки и сервисы](../../reference/effects/).

Ни одна версия не превращает любую возможную проблему в `NotFound`.
Effect разделяет
[ожидаемые ошибки и дефекты](https://effect.website/docs/v4/error-management/two-error-types/),
и Flick сохраняет это различие. `try ... with` не перехватывает все
исключения JavaScript без разбора.

## Пример: объявить, использовать и предоставить сервис

Обе версии описывают вычисление, которое получает сервис `Greeter` и
возвращает `"Hello, Ada"`. Слой предоставляет реализацию. Создание
`program` не выполняет его, ничего не печатает и не запускает фоновых
процессов.

### TypeScript с Effect

Использованы подходы из разделов
[Managing Services](https://effect.website/docs/v4/requirements-management/services/)
и [Managing Layers](https://effect.website/docs/v4/requirements-management/layers/).

```ts
import { Context, Effect, Layer } from "effect"

class Greeter extends Context.Service<
  Greeter,
  { readonly greet: (name: string) => Effect.Effect<string> }
>()("Learn.Services.Greeter") {}

const welcome = (name: string): Effect.Effect<string, never, Greeter> =>
  Effect.gen(function* () {
    const greeter = yield* Greeter
    return yield* greeter.greet(name)
  })

const greeterLayer = Layer.succeed(Greeter, {
  greet: (name: string) => Effect.succeed("Hello, " + name),
})

export const program: Effect.Effect<string> = Effect.provide(
  welcome("Ada"),
  greeterLayer,
)
```

### Flick

```flick
module Learn.Services exposing (program)

service Greeter =
  greet : String ->{} String

welcome : String ->{Greeter; none} String
let welcome name =
  Greeter.greet name

greeter_layer : Layer none none {Greeter}
let greeter_layer =
  Layer.succeed Greeter { greet = fun name -> "Hello, " ++ name }

program : Eff none none String
let program =
  task {
    provide greeter_layer {
      welcome "Ada"
    }
  }
```

`welcome` требует `Greeter`; у `program` требований к сервисам больше нет.
Во Flick `service` создаёт ключ сервиса и доступ к операциям, а вызов в
`welcome` встраивается компилятором в последовательность выполнения.
Чистый callback реализации поднимается до объявленного runtime-типа
callback. Внешний `task` делает всю операцию значением, которое можно
передавать, не выполняя.

Это не утверждение, что Effect везде требует генераторы. Его
[руководство по созданию эффектов](https://effect.website/docs/v4/getting-started/creating-effects/)
и руководство по сервисам также показывают конструкторы и комбинаторы.
Flick выбирает один проверяемый синтаксис прямых вызовов для runtime-тел,
вместо того чтобы оставлять такой выбор каждому месту использования.

## Что добавляет Flick

Flick добавляет язык и статические правила поверх этой основы среды
выполнения:

- **Проверяемое различие чистого и runtime-кода.** Сигнатуры различают
  `a -> b` и `a ->{r; e} b`; runtime-вызов отвергается в чистом теле,
  даже если обе строки пусты.
  Правила объясняют [типы](../../reference/types/) и
  [эффекты](../../reference/effects/). Привязка `foreign pure` остаётся
  контрактом доверия, а не доказательством свойств произвольного JavaScript.
- **Моделирование данных в стиле ML.** Вариантные типы, исчерпывающий
  `match`, точные записи и открытые строки записей — возможности языка,
  а не соглашения поверх объединения TypeScript. См.
  [Типы](../../reference/types/).
- **Классы, роды и канонические экземпляры.** Классы могут абстрагироваться
  над конструкторами типов; проверка разрешает словари и отвергает
  пересекающиеся экземпляры. `deriving` создаёт поддерживаемые стандартные
  экземпляры. Это не классы JavaScript и не runtime-сервисы; см.
  [Классы и экземпляры](../../reference/classes/).
- **Статические проверки выхода ресурсов за область.** Регионы и
  квалификаторы захватов отслеживают значения области даже внутри
  возвращаемых замыканий и задач. Владельцы и супервизоры делают время
  жизни порождённой работы явным. Гарантии и роль доверенных контрактов
  удержания внешнего кода описаны в разделе
  [Регионы и захваты](../../reference/regions/).
- **Границу вывода, управляемую компилятором.** ES-модули и карты
  исходного кода, вывод TypeScript, генерация деклараций и Promise-фасады
  для подходящих функций позволяют включать Flick в JavaScript-проект.
  Это не делает каждый тип Flick представимым в TypeScript; см.
  [Генерация кода](../../reference/codegen/).

Flick **не** добавляет финализацию ресурсов в среду выполнения, где её
раньше не было. У Effect уже есть
[безопасное получение ресурсов и финализация](https://effect.website/docs/v4/resource-management/introduction/).
Дополнительная возможность Flick — проверки владения и захватов в
исходном языке вместе с заданными контрактами завершения адаптера.

## В чём особенно хорош Effect

**Внедрение в существующий TypeScript.** Effect можно добавить в
TypeScript-проект и использовать в обычных `.ts`-модулях, не вводя ещё
один исходный язык, компилятор или слой внешних привязок. Официальное
[руководство по установке](https://effect.website/docs/v4/getting-started/installation/)
описывает настройку TypeScript и интеграции со средами выполнения.

**Прямой доступ к экосистеме.** В
[обзоре Effect](https://effect.website/docs/v4/onboarding/)
перечислены потоки, наблюдаемость, проверка схем, HTTP, SQL, CLI и другие
пакеты на общей основе. В TypeScript вы работаете с собственными API и
документацией установленных пакетов.
[Манифест покрытия Effect во Flick](../../reference/effect-surface/)
различает обёрнутые API, конструкции языка, исключения и ожидающие
привязки. Записанное решение не означает наличие вызываемой обёртки
Flick для каждого экспорта Effect.

**Нативная интеграция с TypeScript.** Существующие SDK, типы фреймворков
и специфичные для TypeScript абстракции остаются в родном языке.
[Импортёр FFI Flick](../../reference/ffi/) поддерживает явно описанное
подмножество; сложные перегрузки, объединения и политики callback могут
потребовать вручную проверенной границы или не поддерживаться.
У публичных типов Flick тоже есть ограничения проекции. Если задача
в основном сводится к соединению TypeScript-библиотек, сохранение
TypeScript избавляет от работы на этой границе.

Это практические преимущества, а не свидетельство меньшей
типизированности Effect или неизбежно большего объёма его кода. Языки
предлагают разные средства выражения контрактов.

## Что выбрать?

**Выбирайте TypeScript с Effect, если** главное — сохранить существующий
TypeScript-процесс, большая часть работы связана с SDK или фреймворками
TypeScript, нужен прямой доступ к текущему API пакета Effect либо команда
не хочет сопровождать ещё один набор языковых инструментов.
Типизированные ожидаемые ошибки, требования к сервисам,
структурированная конкурентность и управление ресурсами при этом
сохраняются.

**Выбирайте Flick, если** вам нужны именно данные и классовые абстракции
в стиле ML, проверяемые границы чистого и runtime-кода, синтаксис прямых
вызовов эффектов и статические правила регионов и захватов — и вы готовы
принять его компилятор, синтаксис, закреплённую версию Effect и явные
контракты интеграции. Начните с отдельного модуля с точно описанной
границей, а не с предположения, что всё приложение нужно переписать.

**Сочетайте их осознанно, если** небольшой компонент Flick полезен внутри
JavaScript-приложения. Изучите сгенерированные декларации или
Promise-фасад, оставьте непроецируемые типы внутри и проверьте
представления ошибок и поведение отмены. У ошибок Flick номинальные
теги, созданные компилятором; совпадение исходного имени не означает
совпадения формы с классом `Data.TaggedError` выше. Общая основа Effect
не обеспечивает автоматическую совместимость исходников или
представлений значений.
