Flick — функциональный язык для приложений, которые работают в браузере,
на сервере и в командной строке. Он компилируется в JavaScript для
браузера и Node и в Go для самостоятельного исполняемого файла. На этой
странице описано, что это даёт и чего пока не даёт.

## Один язык от браузера до командной строки

Одни и те же модули собираются для двух целевых платформ:

- **JavaScript.** ES-модули для браузера и Node. Представления `ui`
  отрисовываются через React, а эффекты выполняются на
  [Effect](https://effect.website/) через `@flick-lang/runtime`.
- **Go.** `flick build --emit go` собирает приложение в один исполняемый
  файл, которому не нужен Node.

Библиотечный пакет компилируется для платформы каждого пакета, который от
него зависит. Чистый код — типы, проверки данных, маршруты, кодеки —
пишется один раз и используется везде. В
[примере Conduit](https://github.com/bondiano/flick-lang/tree/main/examples/conduit)
контракт API — один пакет. От него зависят и сервер на Go, и клиент
в браузере, поэтому расхождение между ними — ошибка типов.

## Эффектный код читается как обычный

Чтобы писать на Flick, не нужно знать, что такое монада. В эффектной
функции вызов сервиса — прямой вызов, `let` связывает его результат,
а строки выполняются сверху вниз. Этот код взят из
[примера first slice](https://github.com/bondiano/flick-lang/tree/main/examples/first-slice):

```flick
# opaque type alias UserId = String
# type alias User = { id : UserId; name : String }
# type alias UserView = { id : UserId; title : String }
# to_view : User -> UserView
# let to_view user = { id = user.id; title = String.trim user.name }
#
type error NotFound = NotFound UserId

service Users =
  get : UserId ->{; NotFound} User

service Log =
  info : String ->{} Unit

load_view : UserId ->{Users, Log; NotFound} UserView
let load_view id =
  let user = Users.get id
  let view = to_view user
  Log.info ("Loaded " ++ view.title)
  view

load_two : UserId -> UserId ->{Users, Log; NotFound} (UserView, UserView)
let load_two first_id second_id =
  let first = task { load_view first_id }
  let second = task { load_view second_id }
  parallel first second
```

В `load_view` нет ни `yield`, ни `flatMap`, ни `pipe`: последовательность
вызовов выстраивает компилятор. `task { … }` превращает вызов в значение,
не выполняя его, а `parallel` выполняет оба значения параллельно
и возвращает оба результата. Локальные изменяемые переменные и
циклы общего вида запланированы; в языке их пока нет.

## Безопасность за счёт типов, а не дисциплины

Три вещи, которые иначе пришлось бы проверять на ревью вручную, записаны
в типах:

- **Эффекты.** `a -> b` — чистая функция. `a ->{Users, Log; NotFound} b` —
  эффектный вызов, которому нужны сервисы `Users` и `Log`. Эффектный вызов
  в чистой функции — ошибка компиляции (`FLICK-E001`), как и тело,
  которому нужен сервис или ошибка, не названные в сигнатуре (`FLICK-E002`).
- **Ошибки.** `NotFound` объявлена через `type error` и входит в строку
  ошибок. `try … with` убирает её, только если обработчики покрывают все её
  значения; необработанная ошибка остаётся в сигнатуре вызывающей функции.
- **Ресурсы.** `scope { … }` освобождает то, что захватил, когда
  заканчивается. Проверка регионов доказывает, что ничего пригодного для
  использования не переживает область, в том числе ресурс, спрятанный
  в замыкании или `task`.

Замыкание ниже прочитало бы файл после того, как его область закрыла этот
файл. Компилятор отвергает его с `FLICK-G001`: замыкание удерживает регион
области, а его тип не допускает ни одного.

```flick fail
# import File exposing (Path, FileSystem, OpenError, ReadError)
#
read_later : Path ->{FileSystem; OpenError} (Unit ->{FileSystem; ReadError} String)
let read_later path =
  scope {
    let file = File.open_scoped path
    fun () -> File.read_all file
  }
```

Полные правила — в разделах [Эффекты, ошибки и сервисы](../../reference/effects/)
и [Регионы и захваты](../../reference/regions/).

## Библиотеки платформы вместо переписывания

Flick не нужна собственная копия каждой библиотеки. Объявление `foreign`
связывает функцию JavaScript с сигнатурой Flick, а большую часть таких
объявлений пишут и проверяют инструменты:

- `flick ffi import <package> --out <dir>` читает `.d.ts` установленного
  npm-пакета и пишет привязки Flick с отчётом по каждому экспорту:
  поддержан, нужна политика или не поддержан — с причиной. Импорт
  не выводит ничего, чего не видно из объявления: вызов никогда не
  считается чистым, а для Promise нужно преобразование ошибки.
- В редакторе действие «Regenerate from `<pkg>@<version>`» на строке
  заголовка сгенерированного модуля пишет его заново по установленным
  объявлениям. `flick ffi check` сообщает о привязках, чьи объявления
  изменились.
- В обратную сторону `flick build --emit-dts` пишет объявления TypeScript
  для модулей Flick, и TypeScript вызывает Flick с его типами.
  `--promise-facade` добавляет эффектной функции точку входа с Promise.

Для `lookup(id: string): Promise<string | undefined>` с политикой, которая
говорит, как функция завершается ошибкой и что значит `undefined`, импорт
даёт такую привязку:

```flick
# import JsError exposing (JsError)
#
lookup : String ->{; JsError} Option String
foreign async lookup from "lookup-lib" "lookup"
  arity 1
  catch JsError.from_js
  nullable
```

На платформе Go привязка к модулю программы вызывает одноимённую функцию
Go из файла `.go` рядом с ним. Подробнее — в разделах
[Внешние функции](../../reference/ffi/) и TypeScript в
[Генерации кода](../../reference/codegen/#typescript).

## Код пишет модель, проверяет человек

Flick подходит для кода, который пишет языковая модель, а проверяет
человек:

- **Сигнатуры обязательны.** У каждой именованной функции полная сигнатура
  стоит прямо над её `let`. Функция без сигнатуры — `FLICK-T004`, и
  сообщение предлагает выведенный тип. Сигнатура говорит, что нужно
  функции, как она может завершиться ошибкой и чистая ли она, а компилятор
  проверяет тело по ней.
- **Ошибки в коде — ошибки компиляции с кодами.** Эффекты не на своём
  месте, необработанные ошибки, ресурсы, покидающие область, и неполные
  сопоставления обнаруживаются до запуска программы. `flick explain <code>`
  объясняет код, а `--diagnostics json` выдаёт инструментам по событию на
  строку.
- **Стандартная библиотека покрывает типичное приложение.** HTTP API, RPC,
  типизированные запросы к PostgreSQL, схемы и кодеки, командная строка,
  представления на React, трассировка и метрики, криптография и JWT входят
  в неё. Выбирать и изучать приходится меньше пакетов. См.
  [обзор](../../reference/stdlib/).

Исходный код примерно такой же длины, как у того же приложения на Go и
React. `just tokens` считает написанный вручную исходный код
`examples/conduit` (контракт, сервер на Go и клиент в браузере) и
эталонную реализацию того же приложения из RealWorld: бэкенд на Go (gin)
и клиент на React/Redux, каждый закреплён на коммите. Тесты, вендоренные
и сгенерированные файлы не учитываются.

| Токенизатор | Flick | Эталон | Отношение |
| - | -: | -: | -: |
| Claude (Opus 5.5) | 48 180 | 52 034 | 0,93 |
| o200k_base (GPT) | 30 018 | 29 778 | 1,01 |

По токенизатору Claude Flick короче примерно на 7% (0,98 для сервера,
0,87 для клиента). По токенизатору GPT длина примерно одинаковая. Метод
описан в
[`tools/tokens`](https://github.com/bondiano/flick-lang/blob/main/tools/tokens/index.mjs).

## Три примера

### Веб-приложение целиком

[`examples/conduit`](https://github.com/bondiano/flick-lang/tree/main/examples/conduit)
— Conduit из RealWorld, клон Medium: сервер на Go поверх PostgreSQL и
одностраничный клиент на React, которые разделяют один типизированный
контракт API. Конечные точки — записи с `deriving HttpApi`, поэтому
опечатка в пути — ошибка типов, а документ OpenAPI получается из того же
значения. Запросы — блоки `sql`, проверенные по миграциям. Примеру не
нужны внешние привязки, и против него запускаются официальные наборы
тестов RealWorld для API и для фронтенда.

### Утилита командной строки на двух платформах

[`examples/cli-tool`](https://github.com/bondiano/flick-lang/tree/main/examples/cli-tool)
— утилита для заметок, описанная одним блоком `cli`: подкоманды, мастер,
который спрашивает первую заметку, справка, версия и автодополнение для
оболочек. Логика — чистый модуль, поэтому тестам не нужен файл. Тот же
исходный код собирается в исполняемый файл Go без Node и выводит ту же
справку, те же ошибки и то же автодополнение.

### Сервисы, которые подменяются в тестах

[`examples/first-slice`](https://github.com/bondiano/flick-lang/tree/main/examples/first-slice)
— пример, из которого взят код выше. `App.Main` в одном месте
предоставляет настоящие `Users` и `Log` как слои. Тесты вместо них
предоставляют реализации поверх фиксированного списка и `Ref`, не меняя
проверяемый код.

Среди [примеров](https://github.com/bondiano/flick-lang/tree/main/examples)
есть ещё магазин, который отправляет данные в коллектор OpenTelemetry, и
планировщик на трансформерах монад, написанных на Flick.

## Кому Flick пока не подходит

- **Проектам, которым нужен стабильный язык.** Flick в версии 0.1, и язык
  ещё меняется. До 1.0 минорный релиз может сломать программы.
- **Командам, которые рассчитывают на большую экосистему.** Кроме
  стандартной библиотеки, пакетов на Flick мало. Библиотека JavaScript
  используется через привязки, которые вы генерируете и проверяете.
- **Страницам, которые должны отдавать мало JavaScript.** Бандл программы
  с интерфейсом несёт среду выполнения Effect и React: для интерактивных
  программ с интерфейсом, которые отслеживает этот репозиторий, бюджеты —
  117–126 KB в gzip. Программу можно собрать без Effect (`effect = "none"`), но тогда
  в ней нет эффектных вызовов и доступны лишь несколько базовых модулей,
  например `List` и `String`. Вынести Effect из ядра языка запланировано.
- **Другим платформам.** Целевых платформ для мобильных устройств,
  десктопа и WebAssembly нет; это направления развития, а не возможности.
  На Go часть стандартной библиотеки и некоторые метаданные `foreign` пока
  не компилируются; компилятор сообщает о них при сборке, а не во время
  выполнения.
- **Командам, которые уже продуктивно работают с TypeScript и Effect.**
  В JavaScript Flick работает на том же Effect, поэтому переход на него —
  выбор исходного языка, а не среды выполнения.
  [Flick и Effect](../../learn/flick-and-effect/) сравнивает оба варианта.
