## Граница между ядром языка и библиотекой

Ядро языка различает чистые и эффектные функции, задаёт номинальные типы, HKT, классы и захваты, а также поддерживает полное автоматическое построение Schema. `Schema`, `Ref`, `Option`, `Result`, `Redacted`, `BigDecimal`, `Duration` и `Chunk` — библиотечные типы с нативным ABI Effect. В первой версии специальные литералы есть только у чисел (`Int`, `Float`, `BigInt`); для Schema/SQL/UI предусмотрен синтаксис DSL, а остальные модули используют обычные функции.

| Исходный тип | Представление в Effect и TS |
| - | - |
| `Eff r e a` | `Effect.Effect<A, E, R>` |
| `Layer ri e ro` | `Layer.Layer<RO, E, RI>` |
| `Option a` | `Option.Option<A>` |
| `Result e a` | `Result.Result<A, E>` |
| `Ref a` | `Ref.Ref<A>` |
| `Redacted a` | `Redacted.Redacted<A>` |
| `Codec rd re i a` | `Schema.Codec<A, I, RD, RE>` |
| `PureCodec i a` | Тот же кодек Schema с гарантией чистоты, проверенной на уровне Flick |
| `Schema a` | Чистое свидетельство доменного типа на основе `Schema.Codec<A, A, never, never>` |
| `BigDecimal`, `Duration` | Нативные значения одноимённых модулей Effect |

Порядок параметров типов в API Flick может отличаться от TS; переупаковывать значения для этого не нужно. Метаданные Flick сохраняют кинды, строки и гарантии чистоты, которых нет в `.d.ts`.

| Возможность | Польза | Цена |
| - | - | - |
| Библиотечные комбинаторы | Простое ядро и явные значения | Больше служебного кода |
| Типы и структурное автоматическое построение схем | Одно описание структуры ADT и записей | Генерация должна учитывать рекурсию, параметры типов и неподдерживаемые поля |
| Уточняющие типы с проверкой при выполнении | Доменные ограничения видны в типах | Нужны безопасные конструкторы и правила доверенного FFI |
| DSL для внешнего формата | Переименования, значения по умолчанию и преобразования собраны рядом | Дополнительная грамматика и диагностика |
| Произвольные вычисления на уровне типов | Позволяют описывать сложные преобразования типов в библиотеках | Существенно усложняют проверку типов и увеличивают время компиляции |

Автоматическое построение схем охватывает все поддерживаемые формы данных. Комбинаторы Schema и DSL кодеков позволяют настраивать и расширять схемы. Произвольные семейства типов для этого не нужны.

## Тип значения и его внешний формат

Исходный тип описывает значения программы. Schema — значение, которое проверяет структуру и ограничения при выполнении. Codec дополнительно описывает преобразование между внешним и внутренним представлением. У одного доменного типа могут быть разные кодеки для HTTP, базы данных и конфигурации.

В [Effect v4](https://effect.website/docs/v4/schema/getting-started) общий тип кодека имеет четыре параметра: `Schema.Codec<T, Encoded, DecodingServices, EncodingServices>`. `Encoded` означает внешний формат, а не канал ошибок. Во Flick тоже полезно отдельно задавать требования к сервисам декодирования и кодирования.

В типах Flick декодированный результат стоит последним. Это не означает, что для Codec определён `Functor`: кодировщику нужно обратное преобразование, поэтому используются `imap` или отдельные декодировщик и кодировщик. `rd` и `re` обозначают сервисы декодирования и кодирования. Ожидаемая ошибка в обоих направлениях — `SchemaError`; доменную ошибку эффектного преобразования явно переводят в диагностику схемы, а дефекты и прерывания сохраняют.

```text
Schema a
PureCodec encoded decoded
Codec decoding_services encoding_services encoded decoded

Codec.decode :
  forall c ci rd re i a.
  (Codec rd re i a)^c ->
  (Unknown^ci ->{rd; SchemaError} a)^c

Codec.encode :
  forall c rd re i a.
  (Codec rd re i a)^c -> (a ->{re; SchemaError} i)^c

Codec.decode_result :
  forall c ci i a.
  (PureCodec i a)^c ->
  (Unknown^ci -> Result SchemaError a)^c

Codec.encode_result :
  forall c i a.
  (PureCodec i a)^c -> (a -> Result SchemaError i)^c
```

Захваты кодека сохраняются в частично применённой функции; происхождение возвращаемого `a`/`i` проверяется отдельно и не стирается при передаче обобщённого свидетельства. SchemaError содержит безопасную диагностику, а не исходное значение, которое могло бы вынести ресурс за пределы его области владения.

`PureCodec` — непрозрачное свидетельство чистого синхронного выполнения, а не псевдоним типа с пустыми строками сервисов. `Codec none none i a` может выполнять асинхронные и другие эффектные действия. Свидетельство создают проверенные чистые комбинаторы, автоматическое построение схем и FFI с явно доверенным контрактом. Внешняя Effect Schema без такого контракта получает общий Codec. Чистое декодирование принимает только Unknown языка Flick с инертным структурным представлением; произвольное JS-значение сначала проходит эффектный импорт из раздела 8.

`Schema a` в API Flick — тоже сертифицированное чистое свидетельство доменного типа; его контракт уже, чем у произвольной внешней Schema. `PureCodec` и `Schema` используют тот же объект Effect Schema в среде выполнения, а дополнительная гарантия хранится в интерфейсе Flick. Эффектные интерпретаторы Schema доступны через эффектные стрелки. [Schema Effect v4](https://effect.website/docs/v4/schema/getting-started).

## Типы и Schema из одного объявления

Для схем предусмотрены конструкции `refined type`, `deriving Schema`, `schema T` и `codec witness { ... }`. Уточняющий тип — номинальный тип с закрытым конструктором, чистым предикатом, безопасной функцией `parse` и доступом к исходному значению. Предикат возвращает Bool и не нормализует значение: false означает ошибку проверки, а неожиданный дефект остаётся дефектом. Обрезку пробелов, приведение к нижнему регистру и разбор значений выполняют при преобразовании в кодеке. `Checks.email` — конкретная библиотечная проверка, а не гарантия полной проверки всех адресов электронной почты.

```flick
refined type Email = String where Checks.email
  deriving Eq, Hash, Schema

type alias Profile = {
  email : Email
  nickname : Option String
} deriving Eq, Hash, Schema

profile_schema : Schema Profile
let profile_schema =
  schema Profile

profile_json : PureCodec Json Profile
let profile_json =
  codec profile_schema {
    email = field "email_address" Email.json
    nickname = field "nickname" (option_as_null String.json)
  }

parse_profile : Unknown -> Result SchemaError Profile
let parse_profile input =
  Codec.decode_result profile_json input
```

В DSL кодеков каждое поле декодируемой записи задаётся ровно один раз. Совпадение имён во внешнем формате, неизвестное поле или пропущенное обязательное поле — ошибка компиляции. По умолчанию лишние входные ключи отвергаются; `ignore_extra_fields` явно строит проверенную проекцию без них. Чтобы сохранять неизвестные поля, нужно объявить поле подходящего типа. В примере `None` кодируется как JSON null; отсутствующий ключ, null или Option с меткой варианта не выбираются неявно по одному `Option a`. [Представления Effect Schema](https://effect.website/docs/v4/schema/effect-data-types).

### Политики Option и значения по умолчанию

Политику поля задают в DSL кодеков; её нельзя вывести только из `Option a`.

| Политика | Кодирование None | Декодирование |
| - | - | - |
| `field "x" codec` | Как определено кодеком | Ключ обязателен |
| `field "x" (option_as_null codec)` | null | null означает None; отсутствие ключа — ошибка |
| `optional_field "x" codec` | Ключ отсутствует | Отсутствие ключа означает None; присутствующее значение проверяет кодек |
| `field "x" (option_as_nullish codec)` | Канонический null | Отсутствующий ключ и null преобразуются в None; undefined допустим только в явно выбранном JS-формате |
| Кодек Option с метками вариантов | Явная ветка None | Проверяемая метка варианта и его данные |

`undefined` не входит в `Json`.

Если приложение различает отсутствующий ключ и null, нужен отдельный ADT или другая модель, которая явно хранит это различие. Один `None` его не сохраняет.

```flick
type alias Preferences = {
  nickname : Option String
  quota : Float
} deriving Schema

preferences_json : PureCodec Json Preferences
let preferences_json =
  codec (schema Preferences) {
    nickname = optional_field "nickname" String.json
    quota =
      field "quota" Float.json_finite
      |> on_missing (fun () -> 0)
  }
```

`optional_field` и `on_missing` — принятые имена DSL. Если quota отсутствует, чистая функция-фабрика вызывается ровно один раз для этого декодирования и возвращает 0; null и неверное значение не заменяются значением по умолчанию. Float.json_finite отвергает значения, не являющиеся конечными числами, в том числе при кодировании. Чтобы исключить их в доменном типе, поле объявляют уточняющим типом.

Значение по умолчанию при создании, значение по умолчанию при декодировании и пропуск поля при кодировании — независимые политики. `on_missing` принимает чистую функцию-фабрику; отдельный `on_missing_effect` добавляет её сервисы в `rd`, а ожидаемые ошибки явно представляются как SchemaError. При кодировании поле не пропускается из-за равенства значению по умолчанию: для этого нужна отдельная политика. Эффектное значение по умолчанию не позволяет получить свидетельство PureCodec/Schema. [Значения по умолчанию в конструкторах Effect](https://effect.website/docs/v4/schema/default-constructors).

<div id="эффектные-преобразования-codec"></div>

### Эффектные преобразования кодеков

Кодек с поиском пользователя по ID может иметь тип `Codec {Directory} none UserId User`: декодирование требует `Directory`, а кодирование получает ID из уже имеющегося User. Значение кодека строится чисто, но декодирование выполняется эффектно. Такой поиск не гарантирует обратимость преобразования, если состояние Directory меняется.

Effect поддерживает [эффектные преобразования схем](https://effect.website/docs/v4/schema/transformations). Язык сохраняет независимые требования к сервисам декодирования и кодирования; пустые строки общего `Codec` не превращают его в `PureCodec`.

### Автоматическое построение Schema

`deriving Schema` — часть языка. Компилятор строит свидетельство по типизированному определению, явно передаёт параметры и генерирует схемы и комбинаторы Effect для использования при выполнении. Он не пытается восстановить стёртый тип из произвольного JS-значения.

| Форма данных | Что выводится |
| - | - |
| Примитивы, литералы, `Unit`, `Never` | Проверка выбранного множества значений; `Never` не принимает значений |
| Записи и точные кортежи | Свидетельства полей и элементов, представление данных и согласованная политика лишних ключей |
| Номинальные ADT | Проверки метки варианта и его данных для каждой ветки; согласование с ABI конструкторов |
| `Option`, `Result`, коллекции | Стандартные конструкторы схем с явными свидетельствами параметров |
| Обобщённые типы | Функция от схем используемых параметров к схеме результата |
| Параметры типов высших порядков | Явное полиморфное свидетельство построения схем для `f a` |
| Рекурсия и взаимная рекурсия | Ленивые ссылки внутри группы определений; без бесконечного разворачивания |
| Уточняющие типы | Чистый предикат и диагностика; нормализация вынесена в кодек |
| Непрозрачные типы | Свидетельство от владельца типа; закрытый конструктор не раскрывается |
| Фантомные параметры | Нет фиктивной проверки того, чего нет в представлении значения |

```flick
type Tree a =
  | Leaf a
  | Branch (List (Tree a))
  deriving Schema

tree_schema : Schema a -> Schema (Tree a)
let tree_schema item_schema =
  schema Tree item_schema

type alias PairOf f = {
  count : f Float
  label : f String
} deriving Schema

pair_of_schema :
  (forall a. Schema a -> Schema (f a)) -> Schema (PairOf f)
let pair_of_schema make_schema =
  schema PairOf make_schema
```

`List` здесь — API Flick для неизменяемой коллекции на основе JS-массива без пропусков. `make_schema` применяется к разным типам и проверяется с полиморфизмом высших рангов. `Schema a` — явно передаваемое значение-свидетельство, а не скрытое ограничение класса.

Обычные рекурсивные данные конечны; общие поддеревья разрешены, а цикл на текущем пути декодирования даёт SchemaError. Кодеки циклических графов не входят в первую версию. Рекурсивные и взаимно рекурсивные схемы используют ленивые ссылки; при нерегулярной рекурсии схемы лениво создаются для фактического параметра, без бесконечного немедленного разворачивания. Если такой контракт нельзя выразить конечной JSON Schema, строгий экспорт его отвергает.

Effect предоставляет [ленивые рекурсивные и взаимно рекурсивные схемы](https://effect.website/docs/v4/schema/advanced-usage). Вывод схем по определениям Flick и проверку параметров-свидетельств выполняет компилятор Flick.

### Полнота DSL и границы автоматизации

Полный DSL поддерживает переименование полей, метки вариантов ADT, композицию, чистые преобразования, преобразования с ожидаемыми ошибками и эффектные преобразования, уточнения типов, значения по умолчанию, проверки записи целиком и явные свидетельства. Компилятор переводит их в типизированные библиотечные конструкторы. При автоматическом построении схем неподдерживаемое поле не пропускается молча: нужно предоставить свидетельство, иначе компилятор выдаёт диагностику. Проверка метки типа у функции, Ref или непрозрачного обобщённого значения не доказывает параметричность или тип содержимого. Снимки изменяемых данных и ресурсов получают эффектными операциями; захваты непрозрачных значений на листьях структуры сохраняются.

Полнота автоматического построения означает, что оно не ограничивается простыми записями. Это не значит, что по типу функции можно проверить параметричность, по дескриптору ресурса — вывести сериализацию живого ресурса, а по `Redacted` — решить, можно ли раскрывать содержимое. Такие поля требуют явного проверенного свидетельства, предиката для непрозрачного типа или отдельного кодека. Для `Ref` и ресурсов получение снимка — эффектная операция; для секретов нужно объявить политику.

Схема данных и кодек внешнего формата остаются разными значениями. Импортируемая Effect Schema с неизвестными эффектами получает общий `Codec`; свидетельство чистоты автоматически не выдаётся. Arbitrary, JSON Schema и другие внешние интерпретаторы имеют собственные условия применимости: например, произвольный предикат не позволяет автоматически построить генератор значений. Неподдерживаемый экспорт должен требовать явной замены схемы или выдавать точную диагностику, а не заменять обещанный тип универсальной JSON-схемой.

<div id="schema-exporters-и-компиляция-выполнения"></div>

### Экспорт схем и оптимизация выполнения

Интеграции схем можно расширять; если контракт внешнего формата не поддерживается, требуется точная диагностика. Здесь нужно различать две задачи.

**Экспорт и интерпретация схем.** В первую версию входят:

| Формат или инструмент | Зафиксированный контракт | Ограничение |
| - | - | - |
| JSON Schema Draft 2020-12 | Строгий экспорт явно выбранного кодека формата JSON | Неподдерживаемое правило проверки даёт ExportError с путём |
| Standard Schema V1 | Синхронный адаптер или адаптер с Promise после предоставления сервисов декодирования | Владелец, отмена и импорт входных JS-значений остаются явными |
| Arbitrary | Генератор по структуре данных | Неподдерживаемое уточнение типа требует явного генератора |
| Форматирование диагностики | Структурированные ошибки, пути и маскирование | Не раскрывает Redacted и произвольные данные непрозрачного типа |
| OpenAPI 3.1 | Строгий экспорт значения `HttpApi`: пути, методы, параметры, тела, ответы, ошибки и безопасность; для схем действует тот же строгий контракт JSON Schema 2020-12 | Непредставимая схема эндпоинта даёт ExportError с путём `группа.endpoint -> поле` |
| Другие форматы и инструменты | Плагины после первой версии | Отдельные версии и таблица поддерживаемых возможностей |

Нативная [генерация JSON Schema](https://effect.website/docs/v4/schema/json-schema) допускает приближённое описание. Строгий экспорт Flick проверяет, можно ли точно выразить выбранный контракт внешнего формата: неподдерживаемый предикат, непрозрачный формат, эффектная проверка допустимости или невыразимая рекурсия дают ExportError с указанием узла и пути. Молчаливые `{}` и `any` запрещены. Явная замена схемы привязана к конкретному узлу. Можно отдельно экспортировать более простое свидетельство структуры внешнего формата, но его нельзя выдавать за полный контракт проверки эффектного кодека.

Например: `Profile.session -> JSON Schema: scoped resource has no wire codec`. Чтобы исправить ошибку, нужно предоставить кодек, явно спроецировать данные либо исключить поле из выбранного внешнего представления. Для статически известных схем это диагностика при сборке, для динамически построенных — типизированный результат операции экспорта.

[Адаптер Standard Schema для Effect](https://effect.website/docs/v4/schema/standard-schema) требует предоставить сервисы декодирования и допускает синхронную проверку или проверку через Promise. Адаптер Flick принадлежит владельцу предоставленных сервисов; вызов validate после закрытия владельца возвращает контролируемую ошибку. Вызов с произвольным входным JS-значением проходит эффектную границу с явно выбранным контрактом импорта. PureCodec допускает синхронное выполнение после безопасного импорта; общий Codec выполняется через Promise. Универсальный runSync не используется.

**Оптимизация выполнения Effect Schema.** В v4 есть [JIT- и AOT-компиляторы схем](https://effect.website/docs/v4/schema/compilers). Они генерируют JS для поддерживаемой части AST и оставляют остальные узлы интерпретатору. AOT создаёт статический модуль; API пока экспериментальный.

Интерпретатор обязателен; AOT в первой версии — явно включаемая оптимизация сборки. Неявная JIT-компиляция при выполнении не включается. Узел, не поддерживаемый AOT, остаётся интерпретируемым, если это сохраняет семантику; приближённый экспорт внешнего формата при этом по-прежнему запрещён. Реестр скомпилированных разборщиков устанавливается явной инициализацией в точке входа.

Ускоренный путь при построении подробной диагностики может повторно вызвать проверки или геттеры на неверном входе; чистые оптимизации схем требуют согласованного инертного ABI данных. Компилятор Effect пропускает ускоренные пути, которые могли бы повторно вычислить значения по умолчанию, преобразования или другие эффекты. Адаптер Flick сохраняет эти условия.

```text
Email.parse : String -> Result SchemaError Email
Email.value : Email -> String
```

Константу можно проверить во время компиляции, если конкретная проверка поддерживается компилятором. Произвольное значение требует проверки при выполнении. Типы стираются при генерации JS; само наличие имени `Email` не проверяет внешний объект.

## Чего не гарантируют уточняющие типы

Проверка неизменяемого значения может обосновывать его номинальный тип. Проверка «пользователь существует в БД» зависит от состояния внешнего мира и не гарантирует, что пользователь будет существовать после возврата результата. Такие операции остаются эффектными вызовами, при необходимости внутри транзакции.

Тип Codec не доказывает изоморфизм. Отдельный библиотечный контракт `lawful` фиксирует подмножество значений, для которых преобразование успешно, выбранный Eq и допустимую каноническую форму внешнего представления. Законы проверяются тестами компонента; проверка типов не доказывает их для произвольного кода.

Значения по умолчанию, нормализация, частичные преобразования и эффектный поиск сами по себе не обеспечивают обратимость. Односторонняя миграция, проекция или маскированный вывод могут предоставлять только декодировщик или кодировщик. Компилятор проверяет типы и требования, но не доказывает произвольные пользовательские законы.

## Ref и обобщение типов

`Ref` доступен через обычные библиотечные функции. Язык должен распознавать их эффектные стрелки и применять правило обобщения типов из раздела 5.

```text
Ref.make : forall c a. a^c ->{} Ref (a^c)
Ref.get : forall c a. (Ref a)^c ->{} a^c

Ref.set :
  forall c a.
  (Ref a)^c -> (a^c ->{} Unit)^c

Ref.modify :
  forall c d x a b.
  (Ref a)^c -> ((a^c -> (b^x, a^c))^d ->{} b^x)^c
```

`make` сохраняет `c` в инвариантном аргументе типа `a^c`: это постоянная
граница допустимых захватов ячейки, а не только граница её текущего значения.
У `get`, `set` и `modify` получатель по-прежнему имеет внешнюю границу `(Ref a)^c`.
Расширение этой внешней границы у псевдонима значения не расширяет тип хранимых
данных и не позволяет записать значение с более короткоживущими захватами.

`d` ограничивает захваты функции, а не записываемого значения; `x` независимо
ограничивает возвращаемый результат `b^x`. Функция может использовать scoped-значение
для вычисления копии, не сохраняя его в ячейке. Частичное применение `set` или
`modify` удерживает ячейку и её захваты; каждая запись сохраняет инвариантный тип данных.

```flick
increment : Ref Float ->{} Float
let increment counter =
  Ref.modify counter (fun current ->
    let next = current + 1
    (next, next)
  )
```

`modify` выполняет одну операцию изменения состояния; отдельные `get` и `set` не составляют одну атомарную операцию. Функция, переданная обычному `Ref.modify`, должна быть чистой. Чтобы передавать эффектную функцию, нужен другой контракт синхронизации. [Effect Ref](https://effect.website/docs/v4/state-management/ref).

Канонических Eq/Hash по содержимому Ref в первой версии нет: изменение ячейки могло бы изменить хеш ключа. Явная операция сравнения по идентичности или обёртка с однажды выделенным ключом идентичности — отдельный API; он не сравнивает сохранённое значение. `deriving Hash` для записи с Ref без такой обёртки или свидетельства выдаёт диагностику.

## Eq и Hash как классы языка

```flick
class Eq a => Hash a =
  hash : a -> Int
```

Закон: если `eq x y`, то хеши совпадают. Обратное неверно: коллизии допустимы. Автоматически построенные `Eq` и `Hash` должны одинаково трактовать поля. Проверка типов пользовательского экземпляра класса не доказывает этот закон. [Effect Hash](https://effect.website/docs/v4/trait/hash).

Канонические Eq/Hash отображаются в согласованные нативные протоколы Effect. Для альтернативных реализаций есть свидетельство `EqHash a` с обоими методами и конструкторы `HashSet.with witness` / `HashMap.with witness`. Коллекция хранит свидетельство, а адаптер упаковывает ключи в обёртки нативного протокола и разворачивает их при выдаче. Вставка и поиск всегда используют то же свидетельство; сменить его у заполненной коллекции нельзя. Объединение коллекций с разными свидетельствами требует явно пересчитать хеши по выбранному свидетельству. Так сохраняется реализация коллекций Effect, но добавляются расходы на обёртки. [Структурное равенство в Effect](https://effect.website/docs/v4/trait/equal).

## Option и совместимость представления

Стандартный `Option` имеет исходные конструкторы `None` и `Some`, а при выполнении использует `Option.none()` и `Option.some(value)` из Effect. Сопоставление с образцом проверяет фронтенд Flick; сгенерированный код читает нативное представление Effect. [Effect Option](https://effect.website/docs/v4/data-types/option).

Эту привязку определяет идентичность стандартного типа. Пользовательский `type Option ...` или объект с `_tag = "Some"` не получает ABI Effect автоматически. При импорте обычных JS-значений, допускающих null, преобразование выполняет явная привязка FFI.

Чистая функция над `Option` генерируется как обычная JS-функция. Импорт модуля данных Effect не запускает файбер. Генератор кода использует стандартные реализации Effect и может устранять неиспользуемые импорты.

## Основная коллекция и представление List

Основная коллекция — **`List a`**: **JS-массив без пропусков с неизменяемым API Flick**. Все `[a, b]` и `[]` создают List; скрытой перегрузки литерала по ожидаемому типу нет. Отдельный `Chunk a` использует нативный Effect Chunk. Изменяемые внешние массивы представлены как `Js.Array a` и доступны через эффектный API; второго равнозначного имени Array в прелюдии нет.

| Представление | Сильные стороны | Цена |
| - | - | - |
| JS-массив с неизменяемым API — выбранный List | Прямой JS ABI, индексный доступ и обычные циклы; простая генерация кода | Добавление в начало, обновление без изменения исходного массива и конкатенация обычно копируют O(n) элементов |
| Связный список `Nil / Cons` | Добавление в начало, получение головы и хвоста за O(1); общие хвосты; привычное сопоставление с образцом в стиле ML | Индексный доступ O(n); больше объектов и нагрузки на сборщик мусора; нужно преобразование в JS-массивы |
| Effect `Chunk` | Готовая неизменяемая коллекция для многократной конкатенации | Дополнительная структура и стоимость операций; для многих задач обычный массив проще |

Длину List и элемент по индексу получают за O(1), а для обхода используют обычный цикл. Добавление в начало, обновление без изменения исходного массива, получение хвоста и конкатенация обычно копируют O(n) элементов. Операции cons/tail за O(1) не гарантируются. Рекурсивный обход с повторным `slice(1)` может стать квадратичным; стандартные функции обхода используют циклы по индексам. Если появится связный список, это будет отдельный тип с другим представлением, а не изменение ABI List.

Основной литерал коллекции всегда означает List. Chunk, изменяемые JS-массивы и другие контейнеры создаются явными конструкторами или преобразованиями. JS-массив с пропусками нельзя принять как обычный List без адаптера.

`ReadonlyArray` в TS не гарантирует фактическую неизменяемость. FFI обязан копировать данные, передавать владение или работать с непрозрачным дескриптором изменяемого объекта. Поверхностной копии достаточно только для самой последовательности: для вложенных записей тоже нужно согласовать контракт. Небезопасные входные значения не должны попадать в доверенный чистый API.

[Документация Effect Chunk](https://effect.website/docs/v4/data-types/chunk) рекомендует Chunk прежде всего при частой конкатенации и отдельно предупреждает о дополнительных расходах в других сценариях. Все эти коллекции остаются библиотекой на основе той же среды выполнения Effect.

## Redacted и внешняя сериализация

`Redacted a` — непрозрачный тип с маскированным выводом и явным извлечением значения. Он не шифрует данные. Скрытие в логах не означает запрет сериализации.

В [Effect Schema v4](https://effect.website/docs/v4/schema/effect-data-types) каноническое кодирование Redacted в JSON может раскрывать внутреннее значение; доступна настройка `disallowJsonEncode: true`. Во Flick автоматическое построение схем не создаёт раскрывающий внешний кодек без явного разрешения. Запрет передачи секрета, намеренная передача и маскированная проекция задаются явно; маскированная проекция — односторонний кодировщик, который не гарантирует обратимость.

```text
Redacted.make : a ->{} Redacted a
Redacted.reveal : Redacted a ->{} a
```

Используется канонический `Redacted` Effect, чьё содержимое внешний код может стереть через `wipeUnsafe`. Поэтому создание и чтение в API Flick считаются эффектными: создание выделяет самостоятельный стираемый объект, а чтение зависит от его текущего состояния. Замораживание одной JS-оболочки не доказывает неизменяемость скрытого содержимого. Стирание через FFI тоже эффектно; чтение стёртого значения даёт дефект, если адаптер явно не переводит его в объявленную ошибку. Автоматические чистые Eq/Hash по содержимому не предоставляются. [Effect Redacted](https://effect.website/docs/v4/data-types/redacted).

## Числовая модель

Решение принято: числовых типов три, и смысл у них одинаков на любом бэкенде. `Int` — 32-битное целое со знаком, `Float` — IEEE 754 binary64 (JS `number`), `BigInt` — целое любого размера. `BigDecimal`, `Duration` и другие специальные типы остаются библиотечными типами со своими операциями. Операторы фиксированы и выбираются по типу операндов после вывода типов; иерархии классов за ними нет.

| Аспект | Контракт |
| - | - |
| `Int` | Дополнительный код, 32 бита; `+ - *` и `**` переполняются по модулю 2³²; `/` отбрасывает дробную часть; `/` и `%` на ноль дают 0; `min / -1` равно `min` |
| `Float` | IEEE 754 binary64, включая NaN, обе бесконечности и нули обоих знаков; округление, деление и остаток как в JS |
| `BigInt` | Целые любого размера; `/` отбрасывает дробную часть; `/` и `%` на ноль дают 0; отрицательная степень — дефект |
| Литералы | Целочисленный литерал получает тот числовой тип, которого требует использование, иначе `Int`, и должен помещаться в этот тип; литерал с дробной частью или экспонентой — `Float`; суффикс `n` выбирает `BigInt` |
| Проверяемые формы | `Int.checked_add`, `checked_div`, … возвращают `Result Int.ArithmeticError Int`; `Int.unsafe_div` и `unsafe_rem` на нуле дают дефект |
| Побитовые операции | Именованные функции `Int` над его 32 битами |
| Преобразования между типами | Неявных нет, в том числе через `==`; явно — `Int.to_float`, `Int.from_float`, `Int.truncate` |
| Представление в JS | `Int` и `Float` — JS `number`, `BigInt` — JS `bigint`; внешнему `Int` из FFI доверяют без проверки |
| JSON | `Int.json` принимает целые в диапазоне; Float допускает больше значений, чем JSON: кодек конечных чисел отвергает неподдерживаемое значение, кодек без потерь использует явную форму с меткой или строкой |

Бэкенд реализует `Int` своим 32-битным целым и проверяет нулевой делитель и `min / -1`, чтобы деление никогда не вызывало аппаратного исключения. Ещё один тип фиксированной ширины — это одна строка числовой таблицы компилятора и одна форма в каждом бэкенде. Ни обычное деление `Float` на ноль, ни NaN не превращаются молча в типизированную ошибку.

`Finite`, `SafeInteger`, `NonNegative` — возможные уточняющие типы для проверки входных и выходных данных. Арифметика над ними возвращает `Float`, пока отдельная операция не гарантирует сохранение ограничения. `Schema Float` отражает всё выбранное множество значений; ограничения JSON задаёт кодек. Нативный [JSON.stringify преобразует неконечные числа в null](https://tc39.es/ecma262/multipage/structured-data.html), поэтому его нельзя использовать как кодек Float без потерь.

### Eq, Hash и Ord для Float

| Равенство | NaN равен NaN | +0 равен -0 | Цена |
| - | - | - | - |
| Строгое равенство JS | Нет | Да | Нерефлексивность осложняет законы Eq и поведение ключей |
| `Object.is` | Да | Нет | Нужны согласованный хеш и адаптер для канонического равенства Effect |
| Каноническое равенство Effect — выбрано | Да | Да | Для точного JS `===` нужна отдельная функция |

Канонические `Eq Float` и оператор `==` используют SameValueZero: NaN равен NaN, +0 равен -0. Это совпадает с проверенным [Effect Equal](https://github.com/Effect-TS/effect/blob/81fc8d9c7855d0f31bf493f379ec7bc2a6150a6f/packages/effect/src/Equal.ts#L187-L205); [нативный Hash.number](https://github.com/Effect-TS/effect/blob/81fc8d9c7855d0f31bf493f379ec7bc2a6150a6f/packages/effect/src/Hash.ts#L311-L350) согласован с ним. `Float.strict_equal` предоставляет JS `===`, `Float.same_value` — Object.is. Хеш не служит стабильным внешним идентификатором между версиями среды выполнения.

`Ord Float.compare` задаёт полный порядок: −Infinity < конечные числа < +Infinity < NaN; нули обоих знаков сравниваются как EQ, все NaN — как EQ. `compare x y = EQ` эквивалентно каноническому Eq. Обобщённые функции сортировки и `Ord.less` используют этот порядок. Примитивные операторы Float/BigInt `<`, `<=`, `>`, `>=` сохраняют JS-семантику: например, любое такое сравнение Float с NaN ложно. Так явно различаются числовые операторы и Ord, соблюдающий свои законы; арифметика JS не меняется.

Даже если Eq считает +0 и -0 равными, компилятор не вправе повсеместно заменять одно другим: арифметика может их различать. Равенство для коллекций не разрешает произвольную подстановку одного значения вместо другого.

## BigDecimal и Duration

BigDecimal — отдельный нативный тип Effect с целочисленным коэффициентом и масштабом. Первая версия не вводит `dec`-литералы и не перегружает арифметику Float. Значения создаются из строки или пары BigInt и проверенного масштаба; преобразование из Float явно учитывает, что округление binary64 уже произошло. [Effect BigDecimal](https://effect.website/docs/v4/data-types/bigdecimal).

У десятичного API Flick нет скрытой глобальной точности. Точные сложение, вычитание и умножение сохраняют конечный десятичный результат; непредставимый масштаб даёт проверяемую ошибку DecimalError. `divide_to_scale` обязательно принимает конечный целый масштаб в диапазоне безопасных целых и политику округления: TowardZero, Floor, Ceiling, HalfEven, HalfAwayFromZero или Exact. Деление на ноль даёт DecimalError; Exact отвергает результат, требующий округления. Результат имеет тип `Result DecimalError BigDecimal`, нативное представление сохраняется. Адаптер вычисляет частное и остаток без промежуточного Float; нативное деление со своими значениями по умолчанию не подставляется вместо этого контракта. Небезопасные нативные операции доступны через явно названные привязки FFI.

Duration — нативная неотрицательная длительность, включая явно выбранное `Duration.infinity`; это не временная метка и не календарный период. В первой версии используются обычные проверяемые конструкторы nanos(BigInt), millis(Float), seconds(Float), без литералов `ms`/`s`. Отрицательное значение, NaN, бесконечность без явного выбора и переполнение при преобразовании единиц дают `Result DurationError Duration`. Точная наносекундная форма начинается с BigInt; формы на основе Float сохраняют выбранное округление JS и не гарантируют большей точности. Преобразование в Float с потерями называется явно; бесконечность не превращается молча в конечное число. [Effect Duration](https://effect.website/docs/v4/data-types/duration).

Для BigDecimal/Duration доступны согласованные нативные Schema, Eq, Hash, Ord и Show через проверенные адаптеры. Специальные литералы и перегрузка числовых операторов отложены до следующих версий. Проверяемые библиотечные конструкторы сохраняют единый числовой синтаксис Float/BigInt и не требуют новой среды выполнения.

В первый целевой релиз входят полное автоматическое построение Schema, явные кодеки, номинальные уточняющие типы с проверкой при выполнении, нативные типы Effect, библиотечный Ref, интеграция Eq/Hash и эффектный доступ к Redacted. Опытная реализация компилятора может добавлять эти механизмы поэтапно, но полнота автоматического построения схем остаётся требованием языка.
