## Вычисления и кинды

Тип вычисления записывается как `Eff requirements errors result`. Результат стоит последним, чтобы `Eff r e` был конструктором типов с киндом `Type -> Type`. Кинд — тип самого типа: он отличает обычный тип от конструктора, которому ещё нужны параметры.

```text
Unit, Never, Float, BigInt : Type
Option, List, Ref, Redacted, Schema : Type -> Type
Result, PureCodec : Type -> Type -> Type

Eff : ServiceRow -> ErrorRow -> Type -> Type
Layer : ServiceRow -> ErrorRow -> ServiceRow -> Type
Codec : ServiceRow -> ServiceRow -> Type -> Type -> Type
Errors : ErrorRow -> Type

FieldRow = Row Type
Region, CaptureRow, Symbol : Kind

Eff r e : Type -> Type
```

`FieldRow = Row Type` здесь обозначает равенство форм киндов, а не пользовательское объявление типа. `ServiceRow`, `ErrorRow` и `CaptureRow` — разные встроенные кинды. Метки полей имеют кинд `Symbol`; сервисы и ошибки имеют номинальную идентичность, которую нельзя заменить строковой меткой. Полная таблица встроенных типов и киндов — в [Кинды и типы](../../reference/types/).

На цели JS `Eff r e a` отображается в `Effect<A, ErrorUnion<E>, ServiceUnion<R>>`; строки Flick имеют собственные номинальные идентификаторы, нормализацию и правила ограничений, а пустая строка даёт `never`. Цель Go выполняет те же описания на `runtime-go/flickrt` ([генерация кода](../../reference/codegen/#go-target)).

## Запись и объединение строк

В позиции отдельной строки используются `none`, переменная `r`, закрытая строка `{Users, Log}` либо открытая `{Users, Log | r}`. В стрелке внешние скобки строк опускаются: `a ->{Users, Log; NotFound} b` и `a ->{Users | r; NotFound | e} b`. Здесь `| r` и `| e` обозначают хвост строки. Без хвоста список закрыт. Порядок элементов несущественен, повторы одного номинального элемента нормализуются.

`r1 + r2` и `e1 + e2` обозначают объединение строк одного кинда, например `Eff (r1 + r2) (e1 + e2) a`. Это встроенная операция решателя ограничений строк, а не пользовательское семейство типов. Сигнатура задаёт верхнюю границу: реализация может требовать меньше сервисов или допускать меньше ошибок. Расширение строки не превращает эффектную стрелку в чистую.

`Errors e` переводит строку ошибок в обычный тип значений: `Errors none = Never`, `Errors {NotFound} = NotFound`. При двух и более элементах или со строковой переменной `Errors e` — непрозрачный тип: его значение приходит только из ветви `x`/`_` у `try` и уходит в `from_result`, `Failure.rethrow` или обобщённый код; чтобы разобрать его по ошибкам, нужен `try` с ветвями по ошибкам над `from_result (Err e)`. Это встроенная проекция анализатора типов. Произвольный тип нельзя автоматически преобразовать обратно в строку: для обобщённого преобразования нужна сохранённая строка `e` либо аннотация, а для отдельной объявленной ошибки доступна строка из одного элемента.

## Пример HKT

```flick
class Functor (f : Type -> Type) =
  map :
    forall c d a b.
    (forall v. a^v -> b)^c -> ((f a)^d -> (f b)^(c + d))^c

instance Functor Option =
  map :
    forall c d a b.
    (forall v. a^v -> b)^c ->
    ((Option a)^d -> (Option b)^(c + d))^c
  let map f value =
    match value with
    | None -> None
    | Some x -> Some (f x)
```

Это `Functor` из прелюдии. Его `map` принимает чистую функцию. `c` ограничивает её захваты, `d` — захваты входного контейнера. Результат сохраняет верхнюю границу `c + d`, поскольку абстрактный `f` может отложить применение и удерживать входное значение и функцию. `v` независимо ограничивает аргумент каждого вызова: трансформер может получить состояние или окружение позже, при запуске. Частичное применение удерживает только функцию. `Option` применяет её сразу, а `Eff r e` создаёт холодное описание.

## Выбор экземпляров классов и словарей

Анализатор типов проверяет кинды, выводит типы и ограничения, выбирает экземпляры классов и вставляет явные аргументы-словари. Во время выполнения словарь — значение с реализациями методов; HKT не требуют отдельного исполнителя типов.

```flick
class Show a =
  show : a -> String

render : Show a => a -> String
let render value =
  show value
```

```ts
interface Show<A> {
  readonly show: (value: A) => string
}

const render =
  <A>(dictionary: Show<A>) =>
  (value: A): string =>
    dictionary.show(value)
```

Подробности разрешения, правила экземпляров и их диагностика — в [Классы и экземпляры](../../reference/classes/).

## Типовое ядро

- Функции обратного вызова с полиморфизмом высших рангов, вложенным `forall`, проверкой полных сигнатур и выводом типов внутри тела.
- Номинальные ADT, точные структурные записи с полиморфизмом строк и исчерпывающий `match`.
- GADT: конструктор называет тип, который строит (`| IntLit Int : Expr Int`), и может скрывать типы полей; ветвь `match` узнаёт тип сопоставляемого значения под полной сигнатурой функции, а исчерпываемость не требует ветвей для невозможных конструкторов во всех частях сопоставляемого значения. Индексы включают типы, конечные кинды, `Symbol`, строки сервисов, ошибок и захватов. Локальные уравнения ветви ограничивают все остаточные строки; идентичности регионов и строки полей не уточняются ([индексы-строки](../../reference/row-indices/)).
- HKT с конструкторами типов и частичным применением.
- Многопараметрические классы, суперклассы и функциональные зависимости; решатель ограничений строк использует фиксированные детерминированные операции.
- Уникальные канонические экземпляры классов без перекрытий, экземпляров-сирот и локального неявного поиска; владение определяется пакетом.
- Явные интерфейсы публичных модулей.
- Полиморфная рекурсия только по явно написанной полной `forall`-сигнатуре.
- Обобщаются только доказанно чистые построения; результаты эффектных выражений мономорфны.

SQL/UI используют встроенные операции над строками, обычные HKT, ограниченные отношения классов и типизированные AST.

### Чего нет во Flick

- Ассоциированных типов: связь между типами выражается функциональной зависимостью или явным свидетельством.
- Семейств типов, открытых и закрытых: для строк есть встроенные операции.
- Перекрывающихся экземпляров, цепочек экземпляров и приоритетов.
- Экземпляров-сирот: их место занимают номинальная обёртка или явный словарь.
- Локальных неявных экземпляров: альтернативное поведение — явное значение (функция сравнения, свидетельство `EqHash`).
- Подтипирования записей по ширине.
- Непредикативного инстанцирования и общего вывода типов высших рангов.
- Обобщения по вариантности (ослабленного ограничения значений).
- Индексированных и градуированных монад.

## Полиморфные функции обратного вызова

Вложенный `forall` в полной сигнатуре означает, что вызываемая функция вправе применять одну переданную функцию при разных типах. Для обычных выражений по-прежнему действует локальный вывод типов; на границе с полиморфным аргументом анализатор типов использует ожидаемую сигнатуру. HKT и ранг полиморфизма остаются разными свойствами.

| Правило | Следствие |
| - | - |
| Явный вложенный `forall` | Полиморфизм аргумента виден в полной сигнатуре; угадывать его по нескольким вызовам не нужно |
| Двунаправленная проверка типов | Анализатор выводит обычные типы и проверяет выражение по заданному полиморфному типу |
| Предикативное инстанцирование | Обычная переменная типа заменяется мономорфным типом; произвольный `List (forall a. ...)` не допускается |
| Ограничения внутри `forall` | При каждом применении переданной функции передаются словари для соответствующего типа |
| Строки во внешней области | Переданная функция может быть полиморфной по результату, сохраняя один и тот же набор сервисов и ошибок |
| Проверка захватов и выхода жёстких переменных типов из области | Полная сигнатура не разрешает скрыть дополнительную ссылку на изменяемый объект или выдать фиксированный тип за произвольный (`FLICK-T007`) |

Простой пример: одна переданная функция вызывается при типах `Float` и `String` в одном теле.

```flick
apply_twice :
  (forall a. a -> a) -> (Float, String)
let apply_twice transform =
  (transform 42, transform "hello")

render_twice :
  (forall a. Show a => a -> String) -> (String, String)
let render_twice render =
  (render 42, render "hello")
```

Эффектная функция обратного вызова тоже может быть полиморфной:

```flick
# type alias User = { name : String }
#   deriving Schema
# type alias Settings = { theme : String }
#   deriving Schema
#
decode_pair :
  (forall a. Schema a -> Unknown ->{r; SchemaError} a) ->
  Unknown -> Unknown ->{r; SchemaError} (User, Settings)
let decode_pair decode user_input settings_input =
  let user = decode User.schema user_input
  let settings = decode Settings.schema settings_input
  (user, settings)
```

Здесь `a` меняется при каждом вызове, а `r` принадлежит внешней сигнатуре. Для примера предполагаются объявленные `User`, `Settings` и их схемы Schema.
