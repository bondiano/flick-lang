## Вычисления и кинды

Тип вычисления записывается как `Eff requirements errors result`. Результат стоит последним, чтобы `Eff r e` был конструктором типов с киндом `Type -> Type`. Кинд — тип самого типа: он отличает обычный тип от конструктора, которому ещё нужны параметры.

```text
Unit, Never, Float, BigInt : Type
Option, List, Ref, Redacted, Schema : Type -> Type
Result, PureCodec : Type -> Type -> Type

Eff : ServiceRow -> ErrorRow -> Type -> Type
Layer : ServiceRow -> ErrorRow -> ServiceRow -> Type
Codec : ServiceRow -> ServiceRow -> Type -> Type -> Type
Errors : ErrorRow -> Type

FieldRow = Row Type
Region, CaptureRow, Symbol : Kind

Eff r e : Type -> Type
```

`FieldRow = Row Type` здесь обозначает равенство форм киндов, а не пользовательское объявление типа. `ServiceRow`, `ErrorRow` и `CaptureRow` — разные встроенные кинды. Метки полей имеют кинд `Symbol`; сервисы и ошибки имеют номинальную идентичность, которую нельзя заменить строковой меткой. Полная таблица встроенных типов и киндов — в [Кинды и типы](../../reference/types/).

На цели JS `Eff r e a` отображается в `Effect<A, ErrorUnion<E>, ServiceUnion<R>>`; строки Flick имеют собственные номинальные идентификаторы, нормализацию и правила ограничений, а пустая строка даёт `never`. Цель Go выполняет те же описания на `runtime-go/flickrt` ([генерация кода](../../reference/codegen/#go-target)).

## Запись и объединение строк

В позиции отдельной строки используются `none`, переменная `r`, закрытая строка `{Users, Log}` либо открытая `{Users, Log | r}`. В стрелке внешние скобки строк опускаются: `a ->{Users, Log; NotFound} b` и `a ->{Users | r; NotFound | e} b`. Здесь `| r` и `| e` обозначают хвост строки. Без хвоста список закрыт. Порядок элементов несущественен, повторы одного номинального элемента нормализуются.

`r1 + r2` и `e1 + e2` обозначают объединение строк одного кинда, например `Eff (r1 + r2) (e1 + e2) a`. Это встроенная операция решателя ограничений строк, а не пользовательское семейство типов. Сигнатура задаёт верхнюю границу: реализация может требовать меньше сервисов или допускать меньше ошибок. Расширение строки не превращает эффектную стрелку в чистую.

`Errors e` переводит строку ошибок в обычный тип значений: `Errors none = Never`, `Errors {NotFound} = NotFound`. При двух и более элементах или со строковой переменной `Errors e` — непрозрачный тип: его значение приходит только из ветви `x`/`_` у `try` и уходит в `from_result`, `Failure.rethrow` или обобщённый код; чтобы разобрать его по ошибкам, нужен `try` с ветвями по ошибкам над `from_result (Err e)`. Это встроенная проекция анализатора типов. Произвольный тип нельзя автоматически преобразовать обратно в строку: для обобщённого преобразования нужна сохранённая строка `e` либо аннотация, а для отдельной объявленной ошибки доступна строка из одного элемента.

## Пример HKT

```flick
class Functor (f : Type -> Type) =
  map :
    forall c d a b.
    (forall v. a^v -> b)^c -> ((f a)^d -> (f b)^(c + d))^c

instance Functor Option =
  map :
    forall c d a b.
    (forall v. a^v -> b)^c ->
    ((Option a)^d -> (Option b)^(c + d))^c
  let map f value =
    match value with
    | None -> None
    | Some x -> Some (f x)
```

Это `Functor` из прелюдии. Его `map` принимает чистую функцию. `c` ограничивает её захваты, `d` — захваты входного контейнера. Результат сохраняет верхнюю границу `c + d`, поскольку абстрактный `f` может отложить применение и удерживать входное значение и функцию. `v` независимо ограничивает аргумент каждого вызова: трансформер может получить состояние или окружение позже, при запуске. Частичное применение удерживает только функцию. `Option` применяет её сразу, а `Eff r e` создаёт холодное описание.

## Выбор экземпляров классов и словарей

Анализатор типов проверяет кинды, выводит типы и ограничения, выбирает экземпляры классов и вставляет явные аргументы-словари. Во время выполнения словарь — значение с реализациями методов; HKT не требуют отдельного исполнителя типов.

```flick
class Show a =
  show : a -> String

render : Show a => a -> String
let render value =
  show value
```

```ts
interface Show<A> {
  readonly show: (value: A) => string
}

const render =
  <A>(dictionary: Show<A>) =>
  (value: A): string =>
    dictionary.show(value)
```

Подробности разрешения, правила экземпляров и их диагностика — в [Классы и экземпляры](../../reference/classes/).

## Типовое ядро

- Функции обратного вызова с полиморфизмом высших рангов, вложенным `forall`, проверкой полных сигнатур и выводом типов внутри тела.
- Номинальные ADT, точные структурные записи с полиморфизмом строк и исчерпывающий `match`.
- GADT: конструктор называет тип, который строит (`| IntLit Int : Expr Int`), и может скрывать типы полей; ветвь `match` узнаёт тип сопоставляемого значения под полной сигнатурой функции, а исчерпываемость не требует ветвей для невозможных конструкторов во всех частях сопоставляемого значения. Индексы — типы, конечные кинды и `Symbol`; регионы, ряды и захваты не уточняются.
- HKT с конструкторами типов и частичным применением.
- Многопараметрические классы, суперклассы и функциональные зависимости; решатель ограничений строк использует фиксированные детерминированные операции.
- Уникальные канонические экземпляры классов без перекрытий, экземпляров-сирот и локального неявного поиска; владение определяется пакетом.
- Явные интерфейсы публичных модулей.
- Полиморфная рекурсия только по явно написанной полной `forall`-сигнатуре.
- Обобщаются только доказанно чистые построения; результаты эффектных выражений мономорфны.

SQL/UI используют встроенные операции над строками, обычные HKT, ограниченные отношения классов и типизированные AST.

### Чего нет во Flick

- Ассоциированных типов: связь между типами выражается функциональной зависимостью или явным свидетельством.
- Семейств типов, открытых и закрытых: для строк есть встроенные операции.
- Перекрывающихся экземпляров, цепочек экземпляров и приоритетов.
- Экземпляров-сирот: их место занимают номинальная обёртка или явный словарь.
- Локальных неявных экземпляров: альтернативное поведение — явное значение (функция сравнения, свидетельство `EqHash`).
- Подтипирования записей по ширине.
- Непредикативного инстанцирования и общего вывода типов высших рангов.
- Обобщения по вариантности (ослабленного ограничения значений).
- Индексированных и градуированных монад.

## Полиморфные функции обратного вызова

Вложенный `forall` в полной сигнатуре означает, что вызываемая функция вправе применять одну переданную функцию при разных типах. Для обычных выражений по-прежнему действует локальный вывод типов; на границе с полиморфным аргументом анализатор типов использует ожидаемую сигнатуру. HKT и ранг полиморфизма остаются разными свойствами.

| Правило | Следствие |
| - | - |
| Явный вложенный `forall` | Полиморфизм аргумента виден в полной сигнатуре; угадывать его по нескольким вызовам не нужно |
| Двунаправленная проверка типов | Анализатор выводит обычные типы и проверяет выражение по заданному полиморфному типу |
| Предикативное инстанцирование | Обычная переменная типа заменяется мономорфным типом; произвольный `List (forall a. ...)` не допускается |
| Ограничения внутри `forall` | При каждом применении переданной функции передаются словари для соответствующего типа |
| Строки во внешней области | Переданная функция может быть полиморфной по результату, сохраняя один и тот же набор сервисов и ошибок |
| Проверка захватов и выхода жёстких переменных типов из области | Полная сигнатура не разрешает скрыть дополнительную ссылку на изменяемый объект или выдать фиксированный тип за произвольный (`FLICK-T007`) |

Простой пример: одна переданная функция вызывается при типах `Float` и `String` в одном теле.

```flick
apply_twice :
  (forall a. a -> a) -> (Float, String)
let apply_twice transform =
  (transform 42, transform "hello")

render_twice :
  (forall a. Show a => a -> String) -> (String, String)
let render_twice render =
  (render 42, render "hello")
```

Эффектная функция обратного вызова тоже может быть полиморфной:

```flick
# type alias User = { name : String }
#   deriving Schema
# type alias Settings = { theme : String }
#   deriving Schema
#
decode_pair :
  (forall a. Schema a -> Unknown ->{r; SchemaError} a) ->
  Unknown -> Unknown ->{r; SchemaError} (User, Settings)
let decode_pair decode user_input settings_input =
  let user = decode User.schema user_input
  let settings = decode Settings.schema settings_input
  (user, settings)
```

Здесь `a` меняется при каждом вызове, а `r` принадлежит внешней сигнатуре. Для примера предполагаются объявленные `User`, `Settings` и их схемы Schema.

## Структурность записей

Записи во Flick — **точные закрытые структурные записи с полиморфизмом строк полей**. `type alias User = { ... }` — прозрачный псевдоним структуры; номинальность вводит номинальное объявление (ADT, `unboxed type`, `refined type`). ADT номинальны. Неявного подтипирования по ширине нет: дополнительные поля принимаются только через явно открытый хвост строки либо удаляются явной проекцией. Подтипирование по ширине оставляло бы скрытые поля во время выполнения и усложняло бы равенство и точные схемы.

Строка полей имеет кинд `FieldRow`, эквивалентный `Row Type`; это не строка сервисов или ошибок. Метки уникальны; их порядок не входит в тип. Модуль `Record` даёт встроенные `HasField`, `Lacks`, `Project`, `Remove`, `UnionDisjoint`, `Map` по конструктору с киндом `Type -> Type` и `Labels` — каноническое перечисление меток ([примитивы строк](../../reference/classes/#примитивы-строк)). Пользовательские экземпляры для этих операций запрещены (`FLICK-C012`). `UnionDisjoint` отвергает повтор метки; объединение строк сервисов и ошибок, наоборот, нормализует повтор одного номинального элемента.

```flick
name :
  forall fields. { name : String | fields } -> String
let name value =
  value.name

project_name :
  forall fields. { name : String | fields } -> { name : String }
let project_name value =
  { name = value.name }
```

`name` допускает дополнительные поля через `fields`. `project_name` создаёт объект только с полем `name`; это не приведение типа, которое лишь скрывает ключи. Обновление `{ record with field = value }` заменяет существующее поле значением того же типа. `Record.extend` требует `Lacks`; `Record.merge_disjoint` требует непересекающихся строк. Чтобы сменить тип поля, нужны явные remove/extend либо новая запись. При разворачивании полей нет скрытой перезаписи. Значения полей вычисляются в порядке исходного кода.

<div id="records-instances-и-ffi"></div>

### Записи, экземпляры классов и FFI

Два прозрачных псевдонима одной структуры — один тип и не получают разные глобальные `Eq` или `Hash`. Для закрытой записи действует канонический структурный экземпляр класса, если нужные экземпляры есть для каждого поля. Открытая строка требует ограничений на весь хвост. Структурные экземпляры, заданные компилятором, нельзя переопределить для отдельного псевдонима.

Для другой доменной семантики вводится номинальная обёртка. Альтернативное сравнение без нового типа — явное свидетельство `EqHash`, которое `HashSet` или `HashMap` хранит как часть своего типа ([хеш-коллекции](../../reference/stdlib/#хеш-коллекции)).

Запись представлена обычным объектом JS ровно с её полями (на цели Go — `*flickrt.Record`). При передаче через внешнюю привязку данные Flick копируются, поэтому JS не может изменить исходное значение Flick ([FFI](../../reference/ffi/#значения-js)). Недоверенный ввод становится записью только через декодирование схемой или кодеком, который отвергает неназванные ключи, если кодек не проходит через `ignore_extra_fields` ([схемы](../../reference/schema/)).

## Классы и зависимости между типами

У класса может быть несколько параметров любого кинда и суперклассы. `Show a` выбирает реализацию для одного типа; у `Functor f` один параметр с киндом `Type -> Type`. Отношению между независимыми типами нужны несколько параметров:

```flick
# type ConversionError = ConversionError String
#
class Convert input output =
  convert : input -> Result ConversionError output
```

Здесь полезны и `Convert String Email`, и `Convert String UserId`, поэтому у этого класса нет функциональной зависимости. Формат сериализации — явное значение кодека (`Codec rd re i a`), а не глобальный экземпляр.

### Функциональные зависимости

```flick
class Collection c a | c -> a =
  empty : c
  insert : forall captures. a^captures -> (c -> c)^captures
```

Квалификатор у insert сохраняет значение a в частично применённой функции; конкретный тип коллекции также сохраняет захваты своих элементов.

Зависимость `c -> a` читается: «конкретный тип коллекции определяет единственный тип элемента». Например, возможны заголовки экземпляров `Collection UserSet User` и `Collection NameSet String`.

```flick
# class Collection c a | c -> a =
#   empty : c
#   insert : forall captures. a^captures -> (c -> c)^captures
# type alias User = { name : String }
# type UserSet = UserSet (List User)
# instance Collection UserSet User =
#   let empty = UserSet []
#   let insert user set = set
#
empty_users : UserSet
let empty_users =
  empty
```

Ожидаемый `UserSet` определяет и `User`. Без зависимости у метода был бы тип `Collection c a => c`, где `a` не указан результатом; требуется отдельное основание для однозначного выбора словаря.

Пара `Collection UserSet User` и `Collection UserSet String` нарушает FD (`FLICK-C004`). Обратное направление не гарантируется: один `User` может храниться в разных коллекциях. После раскрытия псевдонимов и нормализации встроенных выражений строк покрытие начинается с переменных определяющих аргументов головы и замыкается по зависимостям контекста и его подставленных суперклассов. Зависимость добавляет выходы, только когда покрыты все её входы; каждая определяемая переменная головы должна входить в эту наименьшую неподвижную точку (`FLICK-C005`). Каждая зависимость головы проверяется отдельно, поэтому несвязанные ограничения и циклы без исходных переменных не помогают.

Контекст помогает покрытию и допускает перенос возможностей через трансформеры, но не выбирает экземпляр. Выбор идёт по полной голове до разрешения контекста. Несовместимые выходы FD и перекрывающиеся головы запрещены. Если определяющие позиции неперекрывающихся голов унифицируются, определяемые должны быть равны при одной лишь этой подстановке; контекст не оправдывает дополнительных подстановок выходов. Переменные контекста по-прежнему должны входить в голову, каждое ограничение должно быть структурно меньше головы, а число повторений переменных не должно расти. Эти ограничения не доказывают неограниченную завершаемость уточнения FD: каждый шаг разрешения и повтор после уточнения расходует заданный лимит шагов и глубины; его исчерпание — `FLICK-C009`, а не успех.

<div id="coherence-и-альтернативные-instances"></div>

## Согласованность и владение

Согласованность (coherence) означает, что одно ограничение получает одну реализацию. Для коллекций смена `Eq`, `Hash` или `Ord` между вставкой и поиском нарушила бы их поведение.

Заголовки экземпляров после раскрытия псевдонимов не должны унифицироваться (`FLICK-C003`); их контекст не используется для устранения перекрытий. Все переменные контекста должны присутствовать в заголовке. Рекурсивные ограничения классов должны структурно уменьшаться без роста числа вхождений переменной (`FLICK-C007`); граф суперклассов ацикличен (`FLICK-C008`). Это консервативное условие завершения, без аналога `UndecidableInstances`. Если решатель ограничений исчерпал выделенный ему бюджет, выдаётся диагностика; это никогда не считается успешным разрешением. `Eq a => Eq (List a)` допустим.

<div id="orphan-instance-и-внешняя-библиотека"></div>

### Внешний тип

Пусть `Hash` определён стандартной библиотекой, а `ExternalId` — SDK. Пакет адаптера, не владеющий ни классом, ни исходным типом, не может объявить `Hash ExternalId`: экземпляры-сироты запрещены.

```flick
# import Sdk exposing (ExternalId)
#
unboxed type LocalExternalId =
  | LocalExternalId ExternalId
```

Теперь адаптер владеет номинальным типом и может дать ему канонические экземпляры классов. `unboxed` оставляет во время выполнения сам `ExternalId`: обёртка не выделяет память и передаётся в SDK как есть, а идентичность и экземпляры классов остаются у номинального типа. Прозрачный псевдоним `type alias LocalExternalId = ExternalId` новой идентичности не создаёт. Другие варианты — экземпляр у владельца класса или типа либо переданный явно словарь.

Владение определяется **пакетом** (`FLICK-C006`): объявить экземпляр может пакет класса либо пакет внешнего номинального конструктора **первого параметра заголовка**. Прозрачный псевдоним и структурная запись владельца не создают. Для MPTC владения только более поздним параметром недостаточно: пакет `LocalEmail` не получает право объявить чужой `Convert String LocalEmail`. Для этого нужен явный кодек или словарь, обёртка первого параметра либо экземпляр у владельца класса. Привязка FFI не меняет идентичность внешнего типа.

Пакет — это проект или одна из библиотек, которые он компилирует из исходников (зависимость по пути, git или url либо npm-пакет с `source-dir`); модули core и `std` — один встроенный пакет. Экземпляр виден везде, где видны его класс и его тип в заголовке: экземпляры библиотеки приходят с ней в каждый зависимый проект, а две библиотеки, каждая из которых владеет одной стороной, не могут обе объявить экземпляр, потому что объявить его может только владелец класса или первого типа. Поэтому любая программа видит не больше одного экземпляра для каждого заголовка, какие бы библиотеки она ни сочетала.

Набор экземпляров, видимых модулю, определяется графом его зависимостей, а не порядком или формой `import`; конфликты диагностируются при проверке всего доступного графа.

## Обобщение при наличии Ref

Обобщение означает, что тип привязанного значения можно заново инстанцировать при каждом использовании. У `identity : forall a. a -> a` два вызова могут независимо выбрать `Float` и `String`. У одной изменяемой ячейки должен оставаться один тип содержимого. Явная сигнатура `forall` не может сделать небезопасное совместное использование состояния допустимым.

```flick fail T003
invalid : Unit ->{} String
let invalid () =
  let cell = Ref.make None
  Ref.set cell (Some 42)
  match Ref.get cell with
  | Some value -> String.trim value
  | None -> ""
```

Программа отвергается: запись `Some 42` фиксирует содержимое ячейки как `Option Int`, а `String.trim` требует `String`. Если бы `cell` получила `forall a. Ref (Option a)`, запись и чтение могли бы выбрать разные типы для одного объекта.

Обобщаются **доказанно чистые построения значений** и только по переменным, которые не свободны в окружении и не связаны с локальными жёсткими переменными типов, обязательствами по регионам и захватам или неоднозначными ограничениями. У привязки без сигнатуры нет ограничений классов: переменные её нерешённых ограничений и числовых литералов остаются мономорфными, а полиморфизм с ограничениями задаёт только сигнатура. Результат эффектного выражения не обобщается даже при `->{}` (`FLICK-T013`), в том числе в ковариантном неизменяемом типе вроде `Option a`. Полная сигнатура не отменяет эти проверки. Изменяемые контейнеры инвариантны. Доверенный чистый FFI обязан соблюдать тот же контракт чистоты.

```flick
make_empty : forall a. Unit ->{} Ref (Option a)
let make_empty () =
  Ref.make None

use_separate_cells : Unit ->{} Unit
let use_separate_cells () =
  let numbers = make_empty ()
  let names = make_empty ()
  Ref.set numbers (Some 42)
  Ref.set names (Some "Ada")
```

Значение функции `make_empty` полиморфно: создание замыкания чистое. Каждый эффектный вызов выделяет новую ячейку; сама `numbers` мономорфна и хранит только `Option Int`, а `names` — только `Option String`. Это различие сохраняет полезный полиморфизм фабрик, не разрешая менять тип уже созданного состояния.

Переменная `let mut` — состояние одной функции, а не ячейка: присваивание не является эффектным шагом, и чистая функция может присваивать своим переменным. Для неё действует то же правило, что для ячейки: её тип задаётся там, где она объявлена, никогда не обобщается, и каждое присваиваемое значение проверяется по нему, поэтому запись и чтение не могут выбрать разные типы, а `scope` не может отдать переменной свой регион. Ни функция, ни задача, ни ленивая последовательность, ни ветвь обработчика внутри функции не читают переменную и не присваивают ей, поэтому снаружи функция остаётся чистой ([Переменные](../../reference/types/#переменные)).

### Чистые вызовы и холодные описания

```flick
make_identity : Unit -> (a -> a)
let make_identity () =
  fun value -> value

identity_again : forall a. a -> a
let identity_again =
  make_identity ()
```

Правая часть `make_identity ()` — вызов, а не синтаксическое значение, но вызов чистый: состояние не выделяется, переменная `a` не захвачена из окружения. Поэтому `identity_again` обобщается.

```flick
fresh_cell : forall a. Eff none none (Ref (Option a))
let fresh_cell =
  task { Ref.make None }

use_tasks : Unit ->{} Unit
let use_tasks () =
  let numbers = await fresh_cell
  let names = await fresh_cell
  Ref.set numbers (Some 42)
  Ref.set names (Some "Ada")
```

`task` создаёт холодное описание. Поэтому `fresh_cell` можно обобщить: каждый `await` заново выполняет `Ref.make`. Полученные ячейки снова мономорфны. `await` не кеширует результат и не запускает отдельный файбер.

```flick
capture_cell : Ref (Option a) -> Eff none none (Ref (Option a))
let capture_cell cell =
  task { cell }
```

Здесь повторные запуски возвращают одну захваченную ячейку. Тип `a` связан с аргументом `cell`: локальное описание не может обобщить переменную, свободную в окружении. Холодность `Eff` сама по себе не доказывает отсутствия захватов.

## Deriving и законы классов

`deriving Eq, Ord, Hash, Show` создаёт экземпляры классов (`Hash` и `Ord` — только вместе с `Eq`); `deriving Generic` даёт типу его представление как сумму произведений, а `deriving C` для класса с одним параметром и реализацией по умолчанию у каждого метода — экземпляр, который их берёт, так что класс, написанный один раз через `Generic`, выводится для любого типа; `deriving Schema` создаёт свидетельство структуры данных, доступное во время выполнения. Deriving Schema охватывает записи, ADT, кортежи, обобщённые и рекурсивные типы и уточнения; он не объявляет одноимённый класс типов. Контракт — в [Schema и стандартные типы данных](../07-schema/).

Проверка экземпляра подтверждает его тип, но не доказывает законы класса. Выведенные `Eq`, `Ord` и `Hash` используют одни и те же поля. Для пользовательских реализаций нужны отдельные проверки законов; сериализация и формат хранения задаются явным кодеком, а не единственным глобальным экземпляром класса.

## Monad и объединение строк

Прелюдия объявляет `Functor`, `Applicative`, `Monad`, `Alternative`, `Foldable` и `Traversable` над `f : Type -> Type`; у `Functor`, `Applicative` и `Monad` есть экземпляры для `Eff r e`. Метод `Monad` — `flat_map : forall c d a b. (forall v. a^v -> (m b)^(c + v))^c -> ((m a)^d -> (m b)^(c + d))^c`; строки захватов задают верхние границы, а результат сохраняет захваты исходного описания и продолжения.

`Monad (Eff r e)` фиксирует `r` и `e`; допускается их явное или выведенное расширение до общей строки. Для прямых эффектных вызовов используется отдельный встроенный механизм последовательного выполнения, который объединяет строки (`Eff (r1 + r2) (e1 + e2) b`) без обращения к экземпляру `Monad`; анализатор типов вычисляет объединения строк требований и ошибок для прямых вызовов и сохраняет захваты описаний и переданных функций. Обобщённый `do` раскрывается прямо в методы `Monad` и `Alternative` из прелюдии, какие бы имена ни были в области видимости; с `Monad (Eff r e)` строки остаются фиксированными, поэтому для Eff основным стилем остаются прямые вызовы.
