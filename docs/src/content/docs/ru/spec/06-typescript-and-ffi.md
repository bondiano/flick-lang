## Чистые функции

```flick
identity : a -> a
let identity value = value

greet : String -> String -> String
let greet prefix name = "\{prefix}, \{name}"

hello : String -> String
let hello = greet "Hello"
```

```js
export const identity = (value) => value;

export const greet = (prefix) => (name) => prefix + ", " + name;

export const hello = /*#__PURE__*/ greet("Hello");
```

Чистая функция становится обычной функцией JavaScript. Каждая стрелка каррированной функции — одна стрелка JS; оптимизация полного применения не меняет порядок и момент вычисления аргументов.

## ADT и сопоставление с образцом

```flick keep
with_default : a -> Option a -> a
let with_default fallback value =
  match value with
  | None -> fallback
  | Some x -> x
```

```js
export const with_default = (fallback) => (value) => {
  if (value._tag === "None") {
    return fallback;
  }
  if (value._tag === "Some") {
    const x = value.value;
    return x;
  }
};
```

В этом примере `Option` — стандартный тип с нативным представлением Effect. Пользовательский ADT с похожим именем или тегами остаётся другим типом. Проверка типов гарантирует исчерпываемость сопоставления и номинальную идентичность типов. `readonly` в TypeScript описывает внешний интерфейс, а неизменяемость на границе FFI обеспечивается копированием данных (см. [Представление значений](#представление-значений-и-функции-обратного-вызова)).

### Варианты, условия веток и альтернативные образцы

Конструктор содержит ноль, одно или несколько полей. Они перечисляются после его имени так же, как аргументы при применении конструктора и в образце: `| Circle Point Float`. Поле задаётся атомарным типом, поэтому применение типа и стрелку берут в скобки: `| Branch (List (Tree a))`, `| Handler (a -> b)`. `Circle (Point, Float)` — одно поле-кортеж, а не два поля. В ABI поля занимают `_0`, `_1` и далее в порядке объявления.

Правая часть `type` всегда перечисляет варианты; ведущий `|` необязателен. Например, `type Wrapper = Wrap Float` — ADT с одним конструктором. Прозрачный псевдоним типа, в том числе типа записи, объявляется через `type alias`: `type alias UserId = Float`. `opaque type alias` скрывает представление за пределами модуля, а `opaque type` с вариантами скрывает конструкторы. `alias` — ключевое слово только сразу после `type`.

```flick
# type alias Point = { x : Float; y : Float }
#
type Shape = Circle Point Float | Rect Float Float | Empty

area : Shape -> Float
let area shape =
  match shape with
  | Circle _ radius -> Float.pi * radius ** 2
  | Rect width height when width == height -> width ** 2
  | Rect width height -> width * height
  | Empty -> 0

is_round : Shape -> Bool
let is_round shape =
  match shape with
  | Circle _ _ | Empty -> true
  | Rect _ _ -> false
```

Ветка `match` или `try` может иметь условие `when e`, а образец — альтернативы `p | q`. Ограничения следуют правилам Rust:

| Правило | Где проверяется |
| - | - |
| Все альтернативы `p \| q` связывают одинаковые имена одинаковых типов | Имена — парсер (`FLICK-S012`), типы — проверка типов |
| Одно имя связывается образцом или параметрами одной функции не более одного раза | Парсер (`FLICK-S012`) |
| Образец с альтернативами допустим в ветке `match`/`try` и вложенно: в скобках, полях записи и элементах List | Грамматика |
| Условие относится ко всей ветке, включая все её альтернативы, видит имена её образца и не связывает новых | Грамматика |
| Условие ветки — чистое выражение типа `Bool`; эффектный вызов в нём запрещён, иначе порядок проверки веток стал бы наблюдаемым | Проверка типов |
| Ветка с условием не учитывается при доказательстве исчерпываемости | Проверка типов |

Ветки проверяются сверху вниз, альтернативы — слева направо. Выполняется первая ветка с подходящим образцом и истинным условием.

## Эффектная функция

```flick
# type UserId = UserId String
# type alias User = { id : UserId; name : String }
# type error NotFound = NotFound UserId
# service Users =
#   get : UserId ->{; NotFound} User
# service Log =
#   info : String ->{} Unit
# normalize_name : String -> String
# let normalize_name name = String.trim name
#
load_name : UserId ->{Users, Log; NotFound} String
let load_name id =
  let user = Users.get id
  let name = normalize_name user.name

  Log.info name

  name
```

```js
export const load_name = (id) => Effect.gen(function* () {
  const user = yield* $rt.operation($s_Users, "get", 1)(id);
  const name = normalize_name(user.name);
  yield* $rt.operation($s_Log, "info", 1)(name);
  return name;
});
```

Эффектная стадия — тело `Effect.gen`: каждый эффектный вызов записывается через `yield*`, а чистые вызовы остаются обычными. Операция сервиса, например `Users.get`, находит сервис в момент выполнения своей эффектной стадии. Генераторы используются при генерации кода для построения вычислений Effect; исходный синтаксис Flick не требует их использования.

## HKT на границе TypeScript

Фронтенд компилятора проверяет HKT и кинды исходных типов. В сгенерированном JavaScript они стираются либо сохраняются в передаваемых словарях. Публичный API TypeScript экспортирует конкретные применения HKT и записи-словари. У экспорта, тип которого TypeScript не может выразить точно (переменная высшего кинда, регион, открытая запись), нет проекции: `--emit-dts` сообщает о нём (`FLICK-F004`), а объявления никогда не содержат `any`. Для такого экспорта нужен фасад с конкретными типами, написанный на Flick.

TypeScript не поддерживает запись `F<A>` для произвольного параметра типа `F`. Поэтому успешная проверка проекции в TypeScript не заменяет проверку исходной программы.

## FFI

Объявление `foreign` привязывает JS-значение к полной сигнатуре Flick, записанной над ним. Режим, а без слова режима — сигнатура, определяет, как выполняется вызов:

| Режим | Контракт |
| - | - |
| `foreign pure` | Прямой вызов JS, чистоту которого гарантирует автор привязки, в том числе при загрузке модуля |
| `foreign`, строка без `Async` | Откладывается до выполнения эффектной стадии; исключение — дефект, если `catch` его не преобразует |
| `foreign`, строка с `Async` | Promise, который создаётся при выполнении вызова, а не при построении `task`; ближайший владелец ждёт его завершения даже после прерывания |
| `foreign effect` | JS-фабрика вызывается при выполнении (`Effect.suspend`), а её `Effect` выполняется в текущем файбере |
| `foreign blocked name "причина"` | Привязки нет: использование `name` — ошибка компиляции (`FLICK-F005`); остальные экспорты модуля доступны |

Произвольный вход из JS имеет тип `JsValue`; запись или ADT языка получают только через снимок с проверкой или кодек. Если создать Promise заранее, `task` перестанет быть холодным. Если внешняя работа использует право доступа к ресурсу области, при отмене привязка ждёт подтверждённой остановки или завершения внешней операции: ни сам `AbortSignal`, ни завершение прерванного файбера этого не доказывают. Неотменяемая операция удерживает владельца до своего окончания.

Прямые хвостовые вызовы чистой функции самой себя и хвостовые вызовы между чистыми функциями верхнего уровня, образующие цикл, превращаются в циклы с сохранением порядка вычисления аргументов (см. [Рекурсия](../../reference/codegen/#рекурсия-дело-не-только-в-стеке)). Другая чистая рекурсия не получает общей гарантии работы без переполнения стека; для неё есть явный инструмент — модуль `Loop` (`Loop.loop`, `Loop.Trampoline`). Эффектная рекурсия выполняется через отложенные шаги Effect, без немедленного построения всей цепочки. У чистого цикла нет точек отмены, поэтому неограниченная последовательность эффектных шагов никогда не превращается в такой цикл.

## Импорт `.d.ts`

Привязки пишутся вручную или генерируются командой `flick ffi import <package>` из `.d.ts` пакета, которые разрешает TypeScript (см. [Импорт `.d.ts` пакета](../../reference/ffi/#импорт-dts-пакета)). Каждый выбранный экспорт получает один из трёх статусов: поддерживается — создаётся привязка `foreign`; нужна политика — `.d.ts` не может выразить контракт; не поддерживается — экспорт вне подмножества. Два последних генерируются как `foreign blocked name "причина"`; поддерживаемые экспорты пакета доступны, даже если другой экспорт заблокирован.

Средство импорта не выводит ничего, чего не показывает декларация. Вызов получает режим `sync`, а не `pure`; `any` и TS `unknown` становятся `JsValue` либо отвергаются политикой пакета `strict`. Результату Promise нужна политика `catch`, пустому результату — `nullable`, функции обратного вызова — `retention`. Непроверенный тип никогда не подменяется `any` или чистым типом языка, а форма объекта TypeScript не становится неизменяемой записью языка из-за `readonly`. HKT, классы типов и регионы не выражаются в `.d.ts`: библиотека на Flick передаёт их в своём `.iface`.

### Пример импортируемой функции

Гипотетическая библиотека объявляет:

```ts
export declare function lookup(
  id: string
): Promise<string | undefined>;
```

С политикой `undefined = "none"` и `catch = "JsError"` средство импорта создаёт:

```flick
# import JsError exposing (JsError)
#
lookup : String ->{Async; JsError} Option String
foreign lookup from "package" "lookup"
  arity 1
  catch JsError.from_js
  nullable
```

Правило `undefined -> None` задаётся строкой метаданных `nullable`, а не выводится из типа результата. Политики пакета средство импорта читает из `policy.toml` рядом со сгенерированным модулем (`undefined`, `catch`, `cancel`, `mode`, `retention`, `strict`) и никогда не изменяет этот файл. Promise создаётся при выполнении Effect, а не при построении task. Сигнатура не доказывает возможность отмены; `cancel signal` добавляется только для JS API, которое действительно её поддерживает.

Другой экспорт:

```ts
export declare function nextId(): number;
```

консервативно получает `Unit ->{} Float`. Функция может читать часы или менять счётчик. Чистая стрелка требует проверенного контракта; вывести её только по возвращаемому типу нельзя.

### Проверенные привязки и обновление пакетов

Импорт записывает только сгенерированный модуль. Проверенная вручную привязка находится в отдельном модуле и содержит `reviewed "<pkg>@<ver> sha256:…"` — отпечаток декларации, по которой её проверяли. `flick ffi check` заново импортирует каждый пакет и сообщает о сгенерированном модуле, который отличается от нового импорта (`FLICK-F006`), о проверенной привязке, декларация которой изменилась или исчезла либо которой не хватает того, что требует её форма (`FLICK-F007`), и о политике для экспорта, которого в пакете нет (`FLICK-F008`).

Функция обратного вызова с неизвестным сроком удержания не принимает дескриптор ресурса области или замыкание, которое его захватывает: `retention call` (только на время вызова) или `retention owner` (до закрытия владельца региона) задаёт, как долго JS её хранит. При `retention owner` и одном регионе в сигнатуре она получает `Fiber.Outlives` для удерживаемой строки захватов и `Fiber.Provided` с `Detached` для сервисов удерживаемой работы; при двух регионах эти ограничения нужно явно указать в сигнатуре. TS `readonly` не исключает изменения объекта через другую ссылку на него.

## Сигнатура и режим внешнего вызова

Режимы: `pure`, `sync`, `async`, `effect` и `blocked` (см. [FFI](#ffi)). Полная сигнатура Flick ставится над объявлением. Метаданные привязки задают `arity`, `this`, `catch`, преобразование допускающих null значений, удержание и отмену.

```flick
# import File exposing (Path)
# import JsError as FsError exposing (JsError)
# type alias FsError = JsError
# import App.Http exposing (Http, HttpError, UserId, User)
#
hypot : Float -> Float -> Float
foreign pure hypot from global "Math.hypot"
  arity 2

now_millis : Unit ->{} Float
foreign now_millis from global "Date.now"
  arity 0

read_text : Path ->{Async; FsError} String
foreign read_text from "./fs.js" "readText"
  arity 1
  catch FsError.from_js
  cancel signal

fetch_user : UserId ->{Http; HttpError} User
foreign effect fetch_user from "./users.js" "fetchUser"
  arity 1
```

`arity` задаёт число обычных позиционных аргументов JS-вызова. `arity 2` адаптирует две стадии каррирования; `arity 0` принимает исходный `()` и вызывает JS без аргументов. Пара `(Float, Float)` сама по себе не разворачивается в два аргумента. `cancel signal` (только для `foreign async`) передаёт `AbortSignal` последним аргументом и прерывает его при прерывании файбера; владелец всё равно ждёт Promise.

Источник задаётся как `from global "Math.hypot"` для глобального JS-значения или `from "./fs.js" "readText"` для экспорта ESM-модуля; относительный путь отсчитывается от исходного файла. Метаданные записываются с отступом под объявлением: по одному элементу на строку, имя и атомарные аргументы. Известные имена: `arity n`, `this`, `catch f`, `cancel signal`, `nullable`, `optional i`, `variadic`, `retention call` / `retention owner` и `reviewed "…"`. Неизвестное имя — ошибка `FLICK-S011`. Парсер проверяет только форму «имя и аргументы»; элемент, не подходящий сигнатуре или режиму, — ошибка `FLICK-F001`, а параметр, который может содержать права доступа области, без строки `retention` — ошибка `FLICK-F002`. Смысл каждого элемента описан в [справочнике FFI](../../reference/ffi/#метаданные).

Если аргумент `Unit` не передаётся в JS-вызов, вычисление, которое его произвело, всё равно сохраняется: `now_millis (Log.info message)` сначала выполняет логирование в исходном порядке.

`foreign effect` откладывает весь вызов JS-фабрики: тип TypeScript с результатом Effect не доказывает, что построение этого результата чистое.

```ts
const fetchUser = (id: UserId) =>
  Effect.suspend(() => fetchUserJs(id))
```

Вызов выполняется в текущем файбере. Исключение фабрики становится дефектом, если привязка не преобразует его в типизированную ошибку. `foreign pure`, который строит `Eff`, делает более сильное утверждение — что построение чистое; эти объявления различаются, даже если их типы TypeScript совпадают.

Исключение и отклонённый Promise становятся типизированной ошибкой только через `catch f`, где `f : JsValue -> E`, а `E` входит в строку ошибок; иначе они остаются дефектами. `E` не может содержать права доступа области (`FLICK-F003`). Ошибка импорта или инициализации внешнего модуля тоже возникает во время выполнения.

### Go-target

На Go-target (`[build] emit = "go"`) привязка к модулю программы, например `./timers.mjs`, вызывает одноимённую функцию Go из файла `timers.go` рядом с ним; сборка копирует этот файл в Go-модуль, а без него привязка — ошибка `FLICK-P012`. Функция Go принимает и возвращает `flickrt.Value` и получает все аргументы привязки сразу: функции режимов `pure`, `sync` и `effect` первым аргументом получают выполняющий файбер, а функция `async` — `flickrt.Context`, отменяемый при прерывании, и выполняется в собственной горутине, которую владелец ждёт так же, как Promise. Паника — дефект. `catch`, `this`, `optional`, `variadic` и адаптированные функции обратного вызова на этом target дают `FLICK-P012`. См. [FFI на Go-target](../../reference/ffi/#go-target).

## Представление значений и функции обратного вызова

| Значение Flick | ABI |
| - | - |
| Unit | JS `undefined`; успешный внешний результат типа `Unit` — `()`, что бы ни вернул JS |
| Int, Float, BigInt, Bool, String | Соответствующие примитивы JS; `Int` — число, хранимое в 32 битах |
| Кортеж | Плотный JS-массив фиксированной длины |
| List | Плотный JS-массив с неизменяемым API языка |
| Запись | Обычный JS-объект с точным набором собственных полей данных |
| Пользовательский ADT | Объект с `_tag` = `Имя#hash`, где hash — 48 старших бит FNV-1a 64 от квалифицированного идентификатора конструктора; данные находятся в `_0`, `_1` и далее |
| Номинальная обёртка | По умолчанию — объект с тегом; `unboxed type` задаёт представление полем, `untagged type` — полями, различимыми по JS-типу |
| Нативные типы Effect | `Option`, `Result` и другие типы Effect в нативном представлении закреплённой версии Effect |
| Неизвестные входные данные из JS | Непрозрачный `JsValue` до снимка с проверкой |
| Допускающие null и необязательные значения | `nullable` читает результат `null` или `undefined` как `None`; `optional i` передаёт `None` как `undefined` |
| Методы | Сохраняются this, число аргументов, порядок вычисления и идентичность обработчика |
| Функции обратного вызова | Четыре семейства: чистые, Effect, Promise и обработчики событий области |

FFI поддерживает некаррированные вызовы с фиксированным числом аргументов, `this`, необязательные аргументы и переменное число последних аргументов из `List`. Каррирование Flick сохраняется. Идентификатор конструктора включает пакет, модуль, тип и конструктор и фиксируется в `.iface` рядом с тегом; `_tag` содержит имя конструктора и хеш этого идентификатора, поэтому идентичность не сводится к одному имени. Неизменяемые данные копируются на границе: через каждую привязку вне `@flick-lang/effect-ts` и `@flick-lang/runtime` списки, кортежи, записи и значения конструкторов передаются в обе стороны с копированием; это правило действует и для её функций обратного вызова. Примитивы, `JsValue`, непрозрачные типы и функции передаются как есть.

Представление вариантного типа объявляется явно, потому что это ABI, а не решение оптимизатора:

```flick
unboxed type UserId = UserId String
  deriving Eq, Hash, Show, Schema

untagged type Key = ByNumber Float | ByName String | ByPath (List String)
```

Значение `unboxed type` представлено полем его единственного конструктора, у которого должно быть ровно одно поле. `opaque unboxed type` скрывает конструктор от импортирующих модулей так же, как `opaque type`. В `untagged type` каждый конструктор представлен своим полем. Поля различаются по JS-типу (`Float`, `String`, `Bool`, `BigInt`, один вариант со списком или кортежем); пересечения отвергаются при проверке типов (`FLICK-T020`). Сопоставление с образцом проверяет `typeof`/`Array.isArray` вместо `_tag`. Автоматически выведенные `Eq`, `Ord`, `Hash`, `Show` работают по представлению; внешняя форма `deriving Schema` у `unboxed type` совпадает с формой поля, а для `untagged type` свидетельство автоматически не выводится. Проекция в TypeScript — тип поля или объединение типов полей.

Перечисление — это `untagged type`, конструкторы которого — литералы (`Get = "GET"`). Каждое значение представлено своим литералом, строкой или целым числом, а `==` и `match` сравнивают сами литералы. Проекция в TypeScript — объединение литералов; у непрозрачного перечисления — `string` или `number` с меткой его квалифицированного имени. Импорт `.d.ts` делает перечисление из алиаса `type`, все члены которого — строковые литералы или все — целые числа.

Функция обратного вызова JavaScript относится к одному из **четырёх явных семейств**. Эффектная стрелка с пустыми строками не доказывает синхронность, а функция обратного вызова с результатом `void` никогда неявно не запускает Effect.

| Семейство | Что получает JS | Кто управляет выполнением | Где использовать |
| - | - | - | - |
| Чистая функция | `(a, b) => c` с числом аргументов JS по её типу | Прямой вызов | Функция сравнения, `map`, предикат, синхронное преобразование |
| Функция Effect | `(a) => Effect<b, E, R>` | Принимающий API Effect | Нативные операции композиции Effect; сохраняются текущий файбер и окружение |
| Функция Promise | `Js.promise_callback f`: `(a) => Promise<b>` | Дочерняя задача области, в которой она создана | API, которое действительно ожидает Promise |
| Обработчик событий области | Слушатель из `Events.listen`; каждый вызов ставит событие в очередь | Владелец региона и супервизор | События DOM, WebSocket, генератор событий, внешние уведомления |

Адаптируется только аргумент привязки: функция внутри записи, списка или `Option` приходит каррированной. Функция Promise, вызванная после начала закрытия её области, отклоняется, а область ждёт уже начатые вызовы.

### Подписки и обработчики событий

```flick
type Emitter

on : forall s. Emitter -> Events.Listener s Float ->{} Unit
foreign on from "./bindings.mjs" "on"
  retention owner

off : forall s. Emitter -> Events.Listener s Float ->{} Unit
foreign off from "./bindings.mjs" "off"
  retention call

report : Failure none ->{} Unit
let report failure =
  Platform.stdout_line "supervisor: \{RawCause.describe (Failure.inspect failure)}"

handle : Float -> Eff none none Unit
let handle n = task { Platform.stdout_line "handled \{n}" }

listen_while : Emitter -> (Unit ->{} Unit) ->{} Unit
let listen_while source work = scope s {
  let listener = Events.listen s (Events.queue 64) report handle
  Events.attach listener (on source) (off source)
  work ()
}
```

`Events.queue 64` задаёт ограниченную FIFO-очередь, `report` — супервизор, а `handle` создаёт холодную задачу для каждого события. Один исполнитель, дочерний для владельца, выполняет обработчик задача за задачей; он никогда не работает внутри вызова источника событий. Событие, заставшее очередь заполненной, отбрасывается, и супервизор получает уведомление — как и о каждом сбое обработчика. Когда владелец региона начинает закрываться, последующие события сразу игнорируются, `remove` получает ровно ту функцию, которую получил `add`, исполнитель завершается, и только после этого освобождаются захваченные ресурсы. Повторная регистрация создаёт отдельного слушателя.

Если JS требует немедленного действия, например решения о стандартном действии события, асинхронная часть не может гарантировать своевременный ответ. Решение сразу возвращает чистая функция, а обработка в области начинается после него.

### Функции обратного вызова с полиморфизмом высших рангов

`(forall a. a -> a)` экспортируется как функция TypeScript `<A>(value: A) => A`. Полиморфизм принадлежит самой функции обратного вызова, а не только внешней функции. Ограничения классов типов передаются словарями; тип `.d.ts` не доказывает параметричность поведения неизвестной реализации.

Для всех семейств привязка сохраняет число аргументов JS, `this`, идентичность обработчика для снятия с регистрации и согласованное преобразование исключений. Отмена требует реального протокола, например `AbortSignal`, и не возникает из самого типа Promise.

Прямой FFI и проверка данных решают разные задачи. Чтобы передать доверенный `HTMLElement` как непрозрачный дескриптор, кодек не нужен. Данные HTTP, конфигурацию или неизвестный JS-объект нужно проверить, прежде чем превратить в `User`. Сигнатура `.d.ts` сама по себе не проверяет значение и не доказывает отсутствие мутаций.

**`Unknown` и `JsValue`** — разные типы. `Unknown` — неизвестное значение Flick: доступная для структурного обхода часть инертна и неизменяема, а непрозрачные значения на концах графа остаются непрозрачными. `JsValue` — произвольный граф JS-объектов, в котором могут быть геттеры, прокси, изменяемые объекты с несколькими ссылками и функции обратного вызова. `Unknown^{s}` не может скрыть право доступа `s` от проверки областей.

`Js.snapshot : JsValue ->{; SnapshotError} Unknown` копирует поддерживаемые данные — примитивы, простые объекты, плотные массивы — и замораживает копию; глубина не больше 64, число значений не больше 100 000 (`Js.snapshot_with` задаёт оба предела). Свойства читаются через дескрипторы, поэтому геттер никогда не выполняется; геттер, функция, цикл, объект другого прототипа, дыра в массиве, прокси, выбрасывающий исключение, или превышение пределов дают `SnapshotError` с путём к значению. Поддерево, общее для двух мест, копируется один раз. Чтение Proxy может выполнить внешний код, поэтому снимок — эффектный вызов, а не чистая функция.

## Публичные интерфейсы TypeScript

| Исходный экспорт | TS API |
| - | - |
| Чистая функция | Обычная функция с представимыми TS-типами, по одной стрелке на стадию |
| Эффектная функция | Функция с результатом `Effect<A, E, R>` |
| Значение с ограничениями классов | Сначала принимает словарь каждого класса с типом интерфейса этого словаря |
| Непрозрачный или абстрактный номинальный тип, сервис | Интерфейс с меткой его квалифицированного имени |
| Тип или сервис с формой `@ts` | Его форма, записанная там, где тип объявлен; сам тип не объявляется |
| Перечисление | Объединение его литералов; у непрозрачного — `string` или `number` с меткой его квалифицированного имени |
| Переменная высшего кинда, регион, открытая запись | Проекции нет: `FLICK-F004` при `--emit-dts` |

Каррированный экспорт сохраняет стадии исходной функции. Для `f x y` первая стадия `f x` выполняется до вычисления `y`, а JS сначала вычисляет все аргументы обычного вызова. Поэтому некаррированная функция `f$n` создаётся только для функции, стадии которой до последней лишь создают замыкания: если первая стадия может не завершиться, завершиться сбоем или выполнить эффектную операцию, объединение стадий могло бы изменить поведение.

По умолчанию экспортируемая эффектная функция возвращает Effect и ничего не запускает при импорте библиотеки. Фасад Promise подключается явно (`--promise-facade`) для экспортируемой эффектной функции, которой не нужны сервисы и предыдущие стадии которой лишь создают замыкания: `f(a, b, options?)` выполняет функцию под собственным владельцем и возвращает `Promise<Result<A, E>>`. Ожидаемая ошибка даёт неуспешный `Result`, а дефект или прерывание отклоняет Promise с `RuntimeFailure`, содержащим инертный отчёт о причине. `options.signal` прерывает выполнение, и Promise завершается после очистки. Promise не получает фиктивной типизации отклонений. См. [TypeScript](../../reference/codegen/#typescript).

Собственный `.iface` сохраняет кинды, ограничения классов типов, стрелки, строки, номинальную идентичность, захваты, время жизни и ABI словарей. `.d.ts` — проверяемая ограниченная проекция. О гарантии, которую TypeScript не может выразить, компилятор сообщает, а не удаляет её молча.

## Оптимизации профиля release

Профиль release (`--profile release`) запускает оптимизатор над типизированным IR до генерации кода, после проверки типов, эффектов, экземпляров классов и регионов. Он использует ту же среду выполнения, что и профиль debug, и сохраняет всё наблюдаемое поведение программы: вывод, порядок эффектных вызовов, границы обработчиков, `provide` и `scope`, регистрацию финализаторов, сбои, `Exit`, коды завершения и `.iface` каждого модуля. Проходы перечислены в разделе [Профиль выпуска](../../reference/codegen/#профиль-выпуска).

Переписывается только чистый код. Ни один проход не меняет группировку арифметических операций (`(a + b) + c`), не сворачивает `x * 0`, не выполняет и не мемоизирует задачу, не объединяет два построения `Layer`, не переносит поиск сервиса через `provide`, не убирает проверку схемы и не удаляет эффектный вызов с неиспользуемым результатом. Тело `task` не выполняется при построении; два запуска остаются двумя запусками. Точное число выделений памяти и автоматическое расписание файберов — в том числе победитель гонки между одновременно готовыми ветками — не входят в контракт; обязательные точки отмены, явные уступки управления и однократное выполнение финализаторов входят.

Семантика чисел и равенства задаёт разные ограничения: даже если `Eq` считает положительный и отрицательный ноль равными, оптимизация сохраняет различимые арифметические результаты.

### Вычисление литеральных выражений

Выражения только из литералов вычисляются при компиляции — проверкой типов там, где ей нужна константа, и свёрткой констант в профиле release: `60 * 60 * 24` становится `86400`, `"Hello, " ++ "world"` — одной строкой, `not false` — `true`, а `if` с константным условием — выбранной веткой. Результат побитово совпадает с выполнением в JS: IEEE 754 для `+ - * / %` на Float, SameValueZero для `==` на Float, порядок кодовых единиц UTF-16 для `<` на String, усечение к нулю для `/` и `%` на BigInt.

| Выражение | Вычисляется при компиляции |
| - | - |
| Литералы Float, BigInt, String, Bool; скобки | Значение литерала |
| Унарные `-`, `not`; `+ - * / %` на Float | Да |
| `**` на Float | Только при нулевой степени или целом результате, точно представимом в binary64; иначе выражение вычисляется при выполнении, потому что `Math.pow` разных движков может отличаться в последнем бите |
| `+ - * / % **` на BigInt | Пока результат помещается в 128 бит; `/` и `%` на `0n` дают `0n`, как и при выполнении; отрицательная степень остаётся исключением `RangeError` во время выполнения, то есть дефектом |
| Арифметика `Int` | Да, с переполнением по модулю 2³² |
| `==`, `!=`, `<`, `<=`, `>`, `>=` | На Float, BigInt и String; на Bool — только `==` и `!=` |
| `&&`, `\|\|`, `++` | Только когда оба операнда константны |

Свёртка применяется к проверенной программе: смешение типов, например `1 + 1n`, отвергается при проверке типов, а не при оптимизации.
