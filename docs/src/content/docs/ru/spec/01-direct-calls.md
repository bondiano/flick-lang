Эффектная функция вызывается в обычном выражении, а `let` связывает его результат. Для записи последовательности операций достаточно обычных выражений и привязок значений.

```flick
# type UserId = UserId String
# type alias User = { id : UserId; name : String }
# type error NotFound = NotFound UserId
# service Users =
#   get : UserId ->{; NotFound} User
# service Log =
#   info : String ->{} Unit
# normalize_name : String -> String
# let normalize_name name = String.trim name
#
load_name : UserId ->{Users, Log; NotFound} String
let load_name id =
  let user = Users.get id
  let name = normalize_name user.name

  Log.info name

  name
```

Аннотация стрелки: `a ->{r; e} b`, где `r` — требования к сервисам, `e` — ожидаемые ошибки. Такая стрелка обозначает эффектный вызов; обычная `a -> b` — чистый. Пустые `r` и `e` не делают эффектный вызов чистым.

Аннотация пишется слитно со стрелкой: `->{r; e}`, `->{}`. Стрелка с пробелом перед фигурной скобкой, `a -> { name : String }`, — обычная чистая стрелка, которая возвращает запись. Так эффектная стрелка и тип записи различаются уже на уровне лексем, без учёта контекста.

```text
normalize_name : String -> String

Users.get :
  UserId ->{Users; NotFound} User

load_name :
  UserId ->{Users, Log; NotFound} String
```

Результат выражения `Users.get id` — `User`, а эффект его вычисления учитывается отдельно. Компилятор генерирует нужное связывание, в том числе для самостоятельных выражений вроде `Log.info name`.

`let` связывает значение выражения без дополнительного преобразования: значение типа `Eff` остаётся `Eff`, `Option` — `Option`, `List` — `List`, `Result` — `Result`. Эффект правой части определяется исходной сигнатурой вызываемой функции.

Блоки функций и `match` задаются отступами. `in` не нужен; последнее выражение — результат блока. Самостоятельное промежуточное выражение должно иметь тип `Unit`; иной результат отбрасывается явно через `ignore`.

Фигурные скобки ограничивают записи и блоки `task`, `scope`, `provide`, `sql`, `ui`, `cli`, `codec`, `do`, `for` и `rec` (см. [Правила отступов](../../reference/grammar/#правила-отступов)). Внутри них переводы строк разделяют привязки и выражения; для компактной записи разрешён `;`. Аргументы и поля вычисляются слева направо.

Саморекурсия помечается `let rec`; взаимная рекурсия функций — `rec { ... }`, где у каждого определения своя полная сигнатура. Рекурсивное значение, которое вычислялось бы во время собственного определения, — ошибка (`FLICK-T012`).

## Полная сигнатура над каждой функцией

Каждая именованная функция имеет полную сигнатуру непосредственно над определением. Правило одинаково для публичных, внутренних и локальных функций, методов экземпляров классов и функций, полученных частичным применением. В заголовке `let` остаются имена аргументов; второй стиль с типами параметров и результата в заголовке не используется.

```flick
# type UserId = UserId String
# type alias User = { id : UserId; name : String }
# type error NotFound = NotFound UserId
# service Users =
#   get : UserId ->{; NotFound} User
# service Log =
#   info : String ->{} Unit
# type alias UserView = { id : UserId; title : String }
#
render : Show a => a -> String
let render value =
  show value

to_view : User -> UserView
let to_view user =
  {
    id = user.id;
    title = String.trim user.name;
  }

load_view : UserId ->{Users, Log; NotFound} UserView
let load_view id =
  let user = Users.get id
  let view = to_view user
  Log.info view.title
  view
```

Сигнатура содержит ограничения, весь функциональный тип и эффект каждой стрелки. Например, `A -> B ->{R; E} C` означает чистое частичное применение первого аргумента и эффектный вызов после второго. У `A ->{R; E} (B -> C)` эффектный вызов происходит уже после первого аргумента.

```flick
greet : String -> String -> String
let greet prefix name =
  prefix ++ ", " ++ name

hello : String -> String
let hello =
  greet "Hello"
```

Для анонимной функции компилятор либо выводит вид каждой стрелки и обе строки, либо проверяет функцию по ожидаемому типу. `fun x -> normalize_name x` — чистая функция, `fun x -> task { Users.get x }` — чистая функция, которая строит `Eff`, `fun x -> Users.get x` — эффектная функция. При вложенных анонимных функциях эффект относится к той стадии, которая его выполняет. Привязки, которые не определяют функции, не обязаны иметь отдельную сигнатуру; локальные подсказки типов остаются доступны.

Если контекст требует эффектного тела или функции, допускается чистый вариант: анализатор типов вставляет проверяемый узел lift в IR, а бэкенд откладывает тело и оборачивает результат в Effect. Это адаптация представления, а не равенство стрелок. Lift не запускает возвращённое значение `Eff` и не снимает дополнительный слой. Обратное превращение эффектного вызова в чистый по пустым строкам запрещено; захваты при lift сохраняются.

## Синхронные стадии

Эффектная стрелка, у которой строка сервисов закрыта и состоит из синхронных сервисов (сейчас это только `Atom.Read`), а строка ошибок пуста, — *синхронная* стадия (Sync): `Atom a ->{Atom.Read;} a`, render у `Ui.view`, вычисление `Atom.derived`. Её тело компилируется в обычную JS-функцию без `Effect.gen`. Вызовы других Sync-функций и операций `Atom.Read` — обычные вызовы: они читают сервисы контекста, который среда выполнения установила вокруг вызова (читателя рендера или производного атома). Стадия определяется там, где стрелка записана. Поэтому переменная строки, которая позже решилась в `Atom.Read`, как в `forall r. (a ->{r} b) -> …`, сохраняет эффектную стадию, с которой скомпилирована её функция. Внешняя (foreign) функция возвращает Effect, поэтому её стрелки никогда не Sync.

```flick
# count : Atom.Writable Float
# let count = Atom.make 0
#
doubled : Unit ->{Atom.Read;} Float
let doubled () = Atom.value count * 2

twice : (Unit ->{r; e} Float) -> Unit ->{r; e} Float
let twice f () = f () + f ()

quadrupled : Unit ->{Atom.Read;} Float
let quadrupled () = twice doubled ()
```

Lift из предыдущего раздела покрывает все пары стадий. Чистая функция вызывается так же, как Sync. Sync-функция в эффектной позиции становится Effect, который вызывает её с сервисами fiber (`doubled` выше). Эффектная функция в Sync-позиции и эффектный вызов в Sync-стадии (`twice doubled ()`) выполняют свой эффект сразу, с сервисами контекста. Если такой вызов приостанавливается, это дефект, как и ожидание внутри рендера. Sync-функции унифицируются только с Sync-функциями того же типа.

Новые свободные переменные типов в сигнатуре функции неявно универсально квантифицируются; кинд выводится из позиции. Во вложенной сигнатуре имена переменных внешней сигнатуры обозначают те же переменные. Сигнатура проверяется и не отменяет ограничений на обобщение значений, инвариантности изменяемых контейнеров или ограничений времени жизни.

Полиморфная рекурсия разрешена только при явно написанном полном `forall` у рекурсивной функции: анализатор типов проверяет тело по сигнатуре, но не выводит её. Инстанцирование остаётся предикативным: переменная типа заменяется мономорфным типом. Тип метода экземпляра класса проверяется по сигнатуре класса после подстановки его параметров; незаметно добавить новые требования к вызывающему коду нельзя.
