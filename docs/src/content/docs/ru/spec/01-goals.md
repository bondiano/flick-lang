---
title: "1. Цель и подтверждённые требования"
---

| Требование | Смысл |
| - | - |
| Имя и инструменты | Flick, CLI `flick`, исходники `.fl`; общее ядро на Rust для компилятора и LSP |
| ML-подобный синтаксис | Функции, `let`, ADT, сопоставление с образцом и компактная запись прикладного кода |
| HKT | Абстракции над конструкторами типов, включая `Functor`, `Foldable`, `Traversable` |
| Классы типов | Ограничения в сигнатурах, экземпляры классов и выбор реализации по типам |
| Собственная семантика исполнения, несколько бэкендов | Flick сам определяет, как исполняется программа; JS-бэкенд исполняет её через Effect, его стандартные типы и контракты среды выполнения и оптимизирует чистые участки до обычного JS/TS; запланирован нативный бэкенд с генерацией Go |
| Правила исполнения в языке | Встроенные правила восстановления после типизированных ошибок, предоставления сервисов, лексического владения и структурированной конкурентности, одинаковые на каждом бэкенде |
| Прямые эффектные вызовы | Обычный `let` связывает результат выражения; эффект вызова учитывается в типе функции |
| Эффект в стрелке | `a -> b` для чистого вызова; `a ->{r; e} b` для эффектного вызова |
| Единый стиль функций | Полная сигнатура непосредственно над каждой именованной функцией |
| Полиморфизм высших рангов у функций обратного вызова | Полиморфные параметры функций с явным вложенным `forall` |
| Числа и строки | `Int` на 32 бита с переполнением по модулю, `Float` — IEEE 754 binary64, `BigInt` произвольного размера, с арифметикой их аналогов в JS; `==` на числах — SameValueZero; длина и индексы строк считаются в кодовых единицах UTF-16; на каждом бэкенде одинаково. BigDecimal и другие специальные типы отдельно |
| Полноценный deriving Schema | Генерация схем для всех поддерживаемых форм данных, включая обобщённые и рекурсивные типы, с явными правилами и расширениями |
| Значения вычислений | `task { ... }` создаёт Eff; `await` исполняет его в текущей задаче; приложение запускается в точке входа |
| Статическая безопасность ресурсов | Значения, зависящие от области владения, и связанные задачи не могут выйти за её пределы; выбраны свежие регионы, транзитивные захваты и двухфазное закрытие |
| Доступ к экосистеме JS | На JS-бэкенде: явные привязки и фиксированный ABI; генерация привязок из проверяемого подмножества `.d.ts` |
| Оптимизация | Применимые проходы оптимизации и приёмы ReScript с сохранением выбранной семантики Effect и Float |
| Интеграции Schema | Расширяемые компиляторы и экспортёры; если формат обмена не поддерживается, выдаётся явная диагностика |
| Проверка выразительности системы типов | SQL и типизированный UI eDSL как реальные задачи для строк, классов, функций обратного вызова и времени жизни |

Обобщённый `do` над `Monad`, генераторы `for … yield` и списковые выражения `[for … yield]` — сахар над обычными вызовами; `let*` и единый полиморфный по эффектам `map` в язык не входят. Блоки функций задаются отступами, специальные блоки `task`, `scope`, `sql`, `ui`, `cli` — фигурными скобками; последнее выражение возвращает результат. Имена `task` и `await`, а также явная точка входа зафиксированы.

Фронтенд Flick проверяет программу и переводит её в один типизированный IR, общий для бэкендов; JS-бэкенд генерирует исполняемый JS/TS на Effect, а его Content Mapper создаёт TS-проекцию и обеспечивает интеграцию с инструментами. Чистые и эффектные вызовы проходят через один IR. Где следующие главы называют Effect, они описывают, как правило реализовано на JS-бэкенде; само правило — контракт для каждого бэкенда. Система типов Flick развивается независимо от выразительности TypeScript.
