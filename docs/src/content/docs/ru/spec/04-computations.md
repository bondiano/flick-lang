## Два разных типа функций

```text
make_request : UserId -> Eff {Users} {NotFound} User
get_user : UserId ->{Users; NotFound} User
```

`make_request` — чистая функция, которая строит описание вычисления. `get_user` по семантике Flick выполняет операцию при вызове. Обе функции могут иметь одно TS-представление `(id) => Effect<User, E, R>`, поэтому различие должно храниться в типизированном IR и интерфейсах модулей. Восстановить его только по сгенерированному TS-типу нельзя. Sync-функция (`->{Atom.Read;}`, [раздел 3](../03-direct-calls/#синхронные-стадии)) — третий вид: она читает при вызове, но представлена как `(id) => User`, без Effect.

## Task и выполнение сохранённого значения

```flick
load_user : UserId ->{Users; NotFound} User
let load_user user_id =
  let request = task {
    Users.get user_id
  }

  let same_request = identity request

  await same_request
```

`task` откладывает тело и возвращает `Eff`. `identity request` только передаёт значение. `await` выполняет сохранённое вычисление в текущем файбере и извлекает один слой: если успешным результатом был ещё один `Eff`, он остаётся значением. Создание задачи само не запускает новый файбер и не запоминает результат: два `await` обычно означают два выполнения тела.

Обычные лексические значения захватываются при построении задачи. Сервисы ищутся при выполнении в текущем окружении, если автор явно не сохранил отдельный сервис. Захваченные значения, связанные с областью владения, дополнительно ограничивают время жизни самой задачи.

Приложение запускается через отдельную внешнюю точку входа. `await` внутри языка не превращается во вложенный `Effect.runPromise`. Инициализация модуля Flick остаётся чистой; ввод-вывод начинается в точке входа. Значения `task` допустимы на верхнем уровне, потому что их тела отложены. Статический импорт FFI требует доверенного контракта чистой инициализации внешнего модуля: ESM может выполнить код при импорте. Модуль с эффектной инициализацией загружается через явную эффектную операцию.

Порядок вычисления — строгий, слева направо, с учётом каждой стадии каррирования. `f x y` означает `(f x) y`: сначала вычисляются `f` и `x`, затем выполняется применение `f x`, затем вычисляется `y` и выполняется второе применение. Если первая стрелка эффектная, её эффект завершается до вычисления второго аргумента.

Тело `task` вычисляется при запуске; повторный запуск заново выполняет его тело. Совместное использование ресурсов, кеширование и мемоизация задаются явными операциями. Чистота не гарантирует завершения и отсутствия дефектов — неожиданных сбоев. Поэтому перенос чистого выражения за границу запуска тоже требует доказательства сохранения поведения.

### Повторный запуск и значение await

```flick
load_twice :
  UserId ->{Users; NotFound} (User, User)
let load_twice id =
  let request = task { Users.get id }
  let first = await request
  let second = await request
  (first, second)
```

Вызов `Users.get` происходит дважды. Сохранение `request` не кеширует результат и не создаёт Promise. Чтобы получить результат один раз и использовать его повторно, достаточно написать `let user = Users.get id` и затем обращаться к готовому `user`. Мемоизация вычисления — отдельная эффектная операция с явно заданными правилами совместного использования результата.

`await` нужен только для уже имеющегося значения `Eff`. Обычный эффектный вызов `let user = Users.get id` остаётся прямым и не требует дополнительного `await`.

## Чистота отделена от строк ошибок и сервисов

Анализатор типов должен отдельно различать чистое выражение и эффектное вычисление, например с помощью `Pure` и `Runtime(r, e)` либо эквивалентной модели. Пустые `r` и `e` не делают эффектное вычисление чистым.

`none` обозначает пустую строку требований или ошибок. Отсутствие сервисов и типизированных ошибок не исключает ввод-вывод, состояние, дефекты или прерывание. `provide` обеспечивает зависимость, но не делает вычисление чистым.

## Unit Never и пустые строки

`Unit` — обычный тип с единственным значением `()`: операция завершилась, полезного результата нет. `Never` — обычный тип без значений. Отдельный исходный `Void` не вводится. `none` — литерал пустой строки, а не тип результата и не конструктор `Option.None`.

| Запись | Смысл |
| - | - |
| `a -> Unit` | Чистый вызов с результатом `()` |
| `Unit ->{} a` | Принимает `()`, выполняет эффектное вычисление, не требует сервисов и не имеет типизированных ошибок |
| `a ->{Users; none} Unit` | Эффектный вызов требует `Users`, не имеет типизированных ошибок и возвращает `()` |
| `a ->{none; FsError} b` | Эффектный вызов без сервисов с ошибкой `FsError` |
| `a ->{; FsError} b` | То же: пропущенная сторона стрелки — пустая строка |
| `Eff none none a` | Сохранённое эффектное вычисление с пустыми строками требований и ошибок |

В стрелке любую сторону можно не писать: `->{; E}` равно `->{none; E}`, `->{R;}` равно `->{R; none}`. Разделитель `;` обязателен, поэтому `->{E}` — синтаксическая ошибка: компилятор не угадывает, к какой строке относится `E`. `->{}` — сокращение эффектной стрелки с двумя пустыми строками; оно не сокращается до чистой `->`. `Eff Unit Unit a` отвергается из-за несовпадения киндов. Во внутреннем JS/TS-представлении `Unit` соответствует `undefined`, а пустые `E` и `R` — `never`. Публичный TS API может использовать `void` для игнорируемого результата; при входе в язык адаптер нормализует такой результат в `()`.

В [TypeScript](https://www.typescriptlang.org/docs/handbook/2/functions.html) `void` и `undefined` различаются. В [Effect](https://effect.website/docs/v4/getting-started/the-effect-type) отсутствие ожидаемых ошибок и требований обозначается `never` в соответствующих параметрах.

Это согласуется с Effect: его требования отражают контекстные зависимости; некоторые сервисы предоставляются по умолчанию и не появляются в пользовательском `R`. [Тип Effect](https://effect.website/docs/v4/getting-started/the-effect-type), [сервисы по умолчанию](https://effect.website/docs/v4/requirements-management/default-services).

## Пример конкурентного выполнения

```flick
load_name_pair : UserId -> UserId ->{Users; NotFound} (String, String)
let load_name_pair first_id second_id =
  let first = task { Users.get first_id }
  let second = task { Users.get second_id }

  let (first_user, second_user) =
    parallel first second

  (first_user.name, second_user.name)
```

В прямом стиле `parallel (Users.get first_id) (Users.get second_id)` сначала вычислял бы оба аргумента. Отложенные блоки позволяют операции `parallel` самой управлять началом выполнения.

Имена и основной контракт зафиксированы: `task` строит описание, `await` выполняет его в текущем файбере, приложение запускается через внешнюю точку входа. Для выполнения вложенного `Eff` нужен следующий явный `await`; вложенные вычисления автоматически не разворачиваются.
