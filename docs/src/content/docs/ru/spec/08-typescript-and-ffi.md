## Чистые функции

```flick
identity : a -> a
let identity value =
  value

greet : String -> String -> String
let greet prefix name =
  prefix ++ ", " ++ name

hello : String -> String
let hello =
  greet "Hello"
```

```ts
export const identity = <A>(value: A): A =>
  value

export const greet =
  (prefix: string) =>
  (name: string): string =>
    prefix + ", " + name

const hello = greet("Hello")
```

Чистые функции становятся обычными функциями JavaScript или TypeScript. Каррирование изначально сохраняется без изменений; оптимизация полного применения не должна менять порядок и момент вычисления аргументов.

## ADT и сопоставление с образцом

```flick
with_default : a -> Option a -> a
let with_default fallback value =
  match value with
  | None -> fallback
  | Some x -> x
```

```ts
import { Option } from "effect"

const withDefault =
  <A>(fallback: A) =>
  (option: Option.Option<A>): A => {
    switch (option._tag) {
      case "None":
        return fallback
      case "Some":
        return option.value
    }
  }
```

В этом примере `Option` — стандартный тип с нативным представлением Effect. Пользовательский ADT с похожим именем или тегами остаётся другим типом. Фронтенд компилятора проверяет исчерпываемость сопоставления и номинальную идентичность типов. `readonly` в TypeScript описывает внешний интерфейс, но гарантия неизменяемости зависит также от FFI и доступных примитивов.

### Варианты, условия веток и альтернативные образцы

Конструктор содержит ноль, одно или несколько полей. Они перечисляются после его имени так же, как аргументы при применении конструктора и в образце: `| Circle Point Float`. Поле задаётся атомарным типом, поэтому применение типа и стрелку берут в скобки: `| Branch (List (Tree a))`, `| Handler (a -> b)`. `Circle (Point, Float)` — одно поле-кортеж, а не два поля. В ABI поля занимают `_0`, `_1` и далее в порядке объявления.

Правая часть `type` всегда перечисляет варианты; ведущий `|` необязателен. Например, `type Wrapper = Wrap Float` — ADT с одним конструктором. Прозрачный псевдоним типа, в том числе типа записи, объявляется через `type alias`: `type alias UserId = Float`. `opaque type alias` скрывает представление за пределами модуля, а `opaque type` с вариантами скрывает конструкторы. `alias` — ключевое слово только сразу после `type`.

```flick
type Shape =
  | Circle Point Float
  | Rect Float Float
  | Empty

area : Shape -> Float
let area shape =
  match shape with
  | Circle _ radius -> Float.pi * radius ** 2
  | Rect width height when width == height -> width ** 2
  | Rect width height -> width * height
  | Empty -> 0

is_round : Shape -> Bool
let is_round shape =
  match shape with
  | Circle _ _ | Empty -> true
  | Rect _ _ -> false
```

Ветка `match` или `try` может иметь условие `when e`, а образец — альтернативы `p | q`. Ограничения следуют правилам Rust:

| Правило | Где проверяется |
| - | - |
| Все альтернативы `p \| q` связывают одинаковые имена одинаковых типов | Имена — парсер (`FLICK-S012`), типы — проверка типов |
| Одно имя связывается образцом или параметрами одной функции не более одного раза | Парсер (`FLICK-S012`) |
| Образец с альтернативами допустим в ветке `match`/`try` и вложенно: в скобках, полях записи и элементах List | Грамматика |
| Условие относится ко всей ветке, включая все её альтернативы, видит имена её образца и не связывает новых | Грамматика |
| Условие ветки — чистое выражение типа `Bool`; эффектный вызов в нём запрещён, иначе порядок проверки веток стал бы наблюдаемым | Проверка типов |
| Ветка с условием не учитывается при доказательстве исчерпываемости | Проверка типов |

Ветки проверяются сверху вниз, альтернативы — слева направо. Выполняется первая ветка с подходящим образцом и истинным условием.

## Эффектная функция

```flick
load_name : UserId ->{Users, Log; NotFound} String
let load_name id =
  let user = Users.get id
  let name = normalize_name user.name

  Log.info name

  name
```

```ts
export const loadName = (
  id: UserId
): Effect.Effect<string, NotFound, Users | Log> =>
  Effect.gen(function* () {
    const user = yield* getUser(id)
    const name = normalizeName(user.name)

    yield* logInfo(name)

    return name
  })
```

`getUser` и `logInfo` здесь — сгенерированные функции доступа к сервисам. Генератор кода вставляет `yield*` при эффектных вызовах и оставляет чистые вызовы обычными. Генераторы — один из способов композиции Effect, а не требование к исходному синтаксису. [Effect.gen](https://effect.website/docs/v4/getting-started/using-generators).

## HKT на границе TypeScript

Фронтенд компилятора проверяет HKT и кинды исходных типов. При генерации JavaScript они стираются либо сохраняются в передаваемых словарях. Публичный API TypeScript первой версии экспортирует конкретные применения HKT и словари, которые можно представить записями. Для абстрактного экспорта с типами высших порядков, который TypeScript не может выразить точно, нужен явно заданный фасад с конкретными типами. Средства импорта и экспорта не подменяют такой тип ложным `F<A>` или `any`.

TypeScript не поддерживает запись `F<A>` для произвольного параметра типа `F`. Поэтому успешная проверка проекции в TypeScript не заменяет проверку исходной программы. [TypeScript для функциональных программистов](https://www.typescriptlang.org/docs/handbook/typescript-in-5-minutes-func.html).

## FFI

| Категория | Контракт |
| - | - |
| Чистая привязка | Явное доверенное утверждение о чистоте вызова и инициализации модуля |
| Синхронная операция | Откладывается до запуска; исключения преобразуются только по явно заданному правилу |
| Асинхронная операция | Promise создаётся при запуске; политика определяет отмену и ожидание фактической остановки работы |
| Функция, возвращающая Effect | `foreign effect` откладывает вызов JS-фабрики и выполняет её результат в текущем файбере |
| Готовое значение Effect | Импортируется как холодный Eff; эффектная загрузка модуля по-прежнему происходит во время выполнения |
| Внешние данные | Произвольный вход имеет тип JsValue; для записей и ADT языка нужен адаптер с проверкой данных |

Если создать Promise заранее, `task` перестанет быть холодным. Если внешняя работа использует право доступа к ресурсу области, при отмене адаптер обязан дождаться подтверждённой остановки или завершения внешней операции. Сам `AbortSignal` и завершение прерванного файбера этого не доказывают. Неотменяемая операция удерживает владельца до своего окончания. Отсоединить её можно, только если у неё нет захватов с более коротким временем жизни или владение явно и безопасно передано.

Основной способ интеграции — явные привязки к Effect и JS API. Также запланировано средство импорта поддерживаемого подмножества `.d.ts`. Оно генерирует те же привязки, явно сообщает о неподдерживаемых объявлениях и допускает локальные исправления контракта. Чтобы подключить npm-пакет, не нужно ждать полного переноса системы типов TypeScript.

В первой версии генератор кода превращает прямую хвостовую рекурсию чистой функции в цикл, сохраняя порядок вычисления аргументов. Обычная нехвостовая и взаимная рекурсия чистых функций не получают общей гарантии работы без переполнения стека; для них доступен явный API циклов и трамплинов. Рекурсивное эффектное выполнение строится через отложенное вычисление и продолжения, а не через немедленное рекурсивное построение всей цепочки Effect. Чистые циклы не получают автоматических точек отмены. Поэтому неограниченную последовательность эффектных шагов запрещено превращать в такой цикл.

## Прямой FFI и цена автоматизации

Основной подход — прямые типизированные привязки к JavaScript, фиксированный ABI данных и ограниченная проекция в TypeScript. Генератор из `.d.ts` дополняет его. Явный тип внешней функции и привязка к JS-экспорту близки к подходу [PureScript FFI](https://book.purescript.org/chapter10.html). [Порты Elm](https://guide.elm-lang.org/interop/ports.html) показывают другой подход: обмен сообщениями вместо прямых вызовов.

| Подход | Выигрыш | Цена |
| - | - | - |
| Порты для обмена сообщениями | Явное разделение владения состоянием и сообщениями | Каждый небольшой вызов требует протокола; трудно свободно использовать JS API |
| Явные внешние привязки | Предсказуемая связь типов, эффектов и JS-вызова | Автор привязки пишет и проверяет контракт |
| Генерация привязок из поддерживаемых `.d.ts` | Меньше ручной работы для типичных библиотек | Не выводит чистоту, проверку данных во время выполнения, отмену и владение данными |
| Импорт всех возможностей TypeScript | Максимальный охват npm | Требуется сложное согласование двух систем типов; условные типы, перегрузки и HKT не переносятся автоматически |

Средство импорта `.d.ts` строит явные привязки и использует TypeScript для разрешения деклараций. Поддерживаемое подмножество расширяется под конкретные пакеты. Для неподдерживаемого экспорта сохраняются имя и причина блокировки; независимые корректные экспорты пакета остаются доступны. Непроверенные типы не подменяются `any` или чистыми типами языка. Сгенерированный файл хранится отдельно от проверенных переопределений, чтобы обновление пакета не стирало принятые контракты.

### Поддерживаемое подмножество d.ts

| Что поддерживает первая версия | Результат импорта | Явный контракт |
| - | - | - |
| Примитивы, литеральные типы, кортежи, массивы, формы объектов, непрозрачные внешние классы | Представимый тип языка или дескриптор внешнего объекта | ABI, изменяемость, владение и проверка данных |
| Необязательные и допускающие null значения, размеченные объединения | Только однозначное отображение в выбранный ABI | Различие отсутствующего значения, null и undefined; теги конструкторов |
| Обычные параметрические типы первого ранга | Поддерживаются, если параметризация и представление сохраняются | `.d.ts` не доказывает параметричность поведения |
| Конечные однозначные перегрузки | Обёртки с отдельными именами | Неразрешимая неоднозначность блокирует экспорт |
| Конкретные отображённые, условные и индексированные типы | Только после полного сведения средствами TypeScript к поддерживаемой форме | Зависимые операции над типами, которые не удалось свести, не поддерживаются |
| Promise и функции обратного вызова | Форма привязки генерируется; для использования нужна политика адаптера | Ошибки, владелец, удержание, отмена, ожидание остановки и супервизор |
| `any` и TS `unknown` | `JsValue` | Не превращаются в доверенный Unknown языка |
| HKT, классы типов языка, регионы и захваты | Собственный `.iface` или фасад с конкретными типами | Одного `.d.ts` недостаточно для полного интерфейса языка |

Для каждого выбранного экспорта средство импорта сообщает один из трёх статусов: поддерживается; нужна политика или адаптер; не поддерживается. Независимые поддерживаемые экспорты доступны, даже если другой экспорт заблокирован. Простая форма объекта TypeScript по умолчанию остаётся формой внешнего объекта, доступ к которому выполняется эффектно. Она не становится неизменяемой записью языка из-за `readonly`: нужен проверяемый снимок или адаптер. Новые версии средства импорта могут расширять поддержку, но не меняют смысл уже проверенной привязки.

### Пример импортируемой функции

Гипотетическая библиотека объявляет:

```ts
export declare function lookup(
  id: string
): Promise<string | undefined>;
```

При явных правилах `undefined -> None` для результата и `-> JsError` для отклонения Promise средство импорта может создать:

```flick
lookup : String ->{; JsError} Option String
foreign async lookup from "package" "lookup"
  arity 1
  catch JsError.from_js
  nullable
```

Преобразование результата задаётся метаданными или адаптером привязки. В ABI `Option` — нативное значение Effect, поэтому `undefined -> None` указывается строкой `nullable`, а не выводится из типа результата.

Политики пакета средство импорта читает из `policy.toml` рядом со сгенерированным модулем (`undefined = "none"`, `catch = "JsError"`, `retention`, `cancel`, `mode = "pure"`, `strict`) и никогда не изменяет этот файл. Заблокированный экспорт генерируется как `foreign blocked name "причина"`: его использование приводит к ошибке компиляции, а остальные экспорты пакета доступны.

Проверенная вручную привязка содержит метаданные `reviewed "<pkg>@<ver> sha256:…"` — отпечаток декларации, по которой её проверяли. `ffi check` сравнивает его с установленной версией. Promise создаётся при выполнении Effect, а не при построении task. Эта сигнатура не доказывает возможность отмены; сигнал добавляется только для JS API, которое действительно его поддерживает.

Другой экспорт:

```ts
export declare function nextId(): number;
```

консервативно получает `Unit ->{} Float`. Функция может читать часы или менять счётчик. Чистая стрелка требует проверенного контракта; вывести её только по возвращаемому типу нельзя.

### Диагностика и обновление пакетов

Средство импорта выдаёт отчёт по выбранным экспортам пакета и указывает причину для каждого заблокированного экспорта. `any` и TS `unknown` отображаются в `JsValue` либо отклоняются строгим режимом пакета; тип языка не ослабляется молча. Переопределения хранятся отдельно от генерируемого файла и проверяются после обновления зависимости.

Контракт хранит происхождение декларации и версию зависимости. После обновления повторно проверяются форма декларации и совместимость переопределений. Перегрузки можно импортировать как привязки с отдельными именами, если безопасное автоматическое разрешение не определено.

Функция обратного вызова с неизвестным сроком удержания не принимает дескриптор ресурса области или замыкание, которое его захватывает. Нужен контракт «только на время вызова», регистрация с владельцем-областью либо явно обозначенная небезопасная граница. TS `readonly` не исключает изменения объекта через другую ссылку на него; это прямо разобрано в [типах объектов TypeScript](https://www.typescriptlang.org/docs/handbook/2/objects.html).

[ReScript FFI](https://rescript-lang.org/docs/manual/bind-to-js-function/) служит примером декларативного описания JS ABI: методов, `this`, числа аргументов и вызовов с переменным числом аргументов. Эти подходы не зависят от системы типов исходного языка.

Content Mapper связывает исходники и проекцию в TypeScript. Поддержку импортируемых типов, проверку регионов и корректность адаптера среды выполнения обеспечивает фронтенд компилятора. Расширение возможностей Mapper само по себе не переносит семантику TypeScript во Flick.

## Сигнатура и режим внешнего вызова

Доступны режимы `foreign pure`, `foreign sync`, `foreign async`, `foreign effect`. Полная сигнатура Flick ставится над объявлением. Метаданные привязки задают `arity`, `this`, `catch`, преобразование допускающих null значений, удержание и отмену. Запись `cancel signal` и расположение сигнала определяют, как передаётся аргумент, но не заменяют контракт фактической остановки работы.

```flick
hypot : Float -> Float -> Float
foreign pure hypot from global "Math.hypot"
  arity 2

now_millis : Unit ->{} Float
foreign sync now_millis from global "Date.now"
  arity 0

read_text : Path ->{; FsError} String
foreign async read_text from "./fs.js" "readText"
  arity 1
  catch FsError.from_js
  cancel signal

fetch_user : UserId ->{Http; HttpError} User
foreign effect fetch_user from "./users.js" "fetchUser"
  arity 1
```

`arity` задаёт число обычных позиционных аргументов JS-вызова. `arity 2` адаптирует две стадии каррирования; `arity 0` принимает исходный `()` и вызывает JS без аргументов. Пара `(Float, Float)` сама по себе не разворачивается в два аргумента. `cancel signal` отдельно добавляет сигнал по правилам привязки — в этом примере последним аргументом.

Источник задаётся как `from global "Math.hypot"` для глобального JS-значения или `from "./fs.js" "readText"` для экспорта ESM-модуля. Метаданные записываются с отступом под объявлением: по одному элементу на строку, имя и атомарные аргументы. Известные имена: `arity N`, `this`, `catch f`, `cancel signal`, `nullable …`, `retention …`, `optional …`, `variadic …`. Неизвестное имя приводит к ошибке `FLICK-S011`. Парсер проверяет только форму «имя и аргументы»; допустимость аргументов для конкретной сигнатуры и режима проверяется при проверке типов FFI.

Если аргумент `Unit` не передаётся в JS-вызов, вычисление, которое его произвело, всё равно сохраняется: `now_millis (Log.info message)` сначала выполняет логирование в исходном порядке.

JS-адаптер `readText` принимает путь и `AbortSignal`, а `FsError.from_js` явно преобразует отказ в ошибку без зависимости от региона. Promise создаётся только при выполнении. Ниже показан допустимый способ генерации кода для операции, которой не передан дескриптор ресурса области. Это не универсальная реализация безопасного асинхронного FFI с захваченным ресурсом:

```ts
export const readText = (
  path: string
): Effect.Effect<string, FsError> =>
  Effect.tryPromise({
    try: (signal) => readTextJs(path, signal),
    catch: toFsError
  })
```

`foreign effect` обязан отложить весь вызов JS-фабрики: тип TypeScript с результатом Effect не доказывает, что построение этого результата чистое.

```ts
const fetchUser = (id: UserId) =>
  Effect.suspend(() => fetchUserJs(id))
```

Вызов выполняется при запуске в текущем файбере. Исключение фабрики становится дефектом, если привязка явно не преобразует его в типизированную ошибку. Отдельный доверенный `foreign pure` может чисто строить `Eff`, но требует более сильного контракта. Эти объявления Flick различаются, даже если их типы TypeScript совпадают. [Effect.suspend](https://effect.website/docs/v4/getting-started/creating-effects).

Исключение и отклонённый Promise преобразуются в типизированную ошибку только по объявленному правилу; иначе они остаются дефектами. Преобразование не может поместить в данные ошибки право доступа к ресурсу области. Для аргументов, привязанных к области, обязательны контракты удержания и фактической остановки работы. Ошибка импорта или инициализации внешнего модуля тоже возникает во время выполнения и обрабатывается его привязкой. [Создание Effect](https://effect.website/docs/v4/getting-started/creating-effects).

## Представление значений и функции обратного вызова

| Значение Flick | ABI первой версии |
| - | - |
| Unit | JS `undefined`; успешный внешний результат void нормализуется в `()` |
| Float, BigInt, Bool, String | Соответствующие примитивы JS |
| Кортеж | Плотный JS-массив фиксированной длины |
| List | Плотный JS-массив с неизменяемым API языка |
| Запись | Обычный JS-объект с точным набором собственных полей данных |
| Пользовательский ADT | Объект с `_tag` = `Имя#hash`, где hash — 48 старших бит FNV-1a 64 от квалифицированного идентификатора конструктора; данные находятся в `_0`, `_1` и далее |
| Номинальная обёртка | По умолчанию — настоящий объект с тегом; `unboxed type` задаёт представление полем, `untagged type` — полями, различимыми по JS-типу |
| Нативные типы Effect | Нативный ABI закреплённой версии, настоящие конструкторы и протоколы |
| Неизвестные входные данные из JS | Непрозрачный JsValue до импорта с проверкой во время выполнения |
| Допускающие null и необязательные значения | Явный адаптер различает null, undefined и отсутствие ключа |
| Методы | Сохраняются this, число аргументов, порядок вычисления и идентичность обработчика |
| Функции обратного вызова | Четыре явных семейства: чистые, Effect, Promise и обработчики событий области |

FFI поддерживает некаррированные вызовы с фиксированным числом аргументов, `this`, необязательные аргументы и переменное число последних аргументов через явный адаптер List. Каррирование Flick сохраняется. Идентификатор конструктора включает номинальную идентичность пакета, модуля, типа и конструктора и фиксируется в `.iface` — поле `id` рядом с `tag`. `_tag` содержит имя конструктора и хеш этого идентификатора. Это короче полного идентификатора в бандле, но не сводит идентичность к одному имени.

Неизменяемые данные по умолчанию копируются при передаче из недоверенного кода и в него: каждая привязка вне `@flick-lang/runtime` получает и отдаёт списки, кортежи, записи и значения конструкторов копией, включая её функции обратного вызова. Непрозрачные нативные дескрипторы передаются только через свой адаптер, без попытки скопировать изменяемое внутреннее состояние. [Привязки ReScript](https://rescript-lang.org/docs/manual/bind-to-js-function/) показывают примеры таких соглашений о вызове.

Для функций обратного вызова JavaScript выбраны **четыре явных семейства адаптеров**. Дополнительный синхронный режим и автоматическое превращение функции обратного вызова с результатом `void` в запуск Effect не входят в первую версию. Эффектная стрелка с пустыми строками не доказывает синхронность.

| Семейство | Что получает JS | Кто управляет выполнением | Где использовать |
| - | - | - | - |
| Чистая функция | Обычное значение результата | Прямой вызов | Функция сравнения, `map`, предикат, синхронное преобразование |
| Функция Effect | Ленивое значение `Effect<A, E, R>` | Принимающий API Effect | Нативные операции композиции Effect; сохраняются текущий файбер и окружение |
| Функция Promise | `Promise<A>` | Явно предоставленные среда выполнения и адаптер | API, которое действительно ожидает Promise |
| Обработчик событий области | Обычно `void`; файбер или очередь принадлежат подписке | Владелец Scope и супервизор | События DOM, WebSocket, генератор событий, внешние уведомления |

<div id="цена-выбранного-callback-abi"></div>

### Цена выбранного ABI функций обратного вызова

| Подход | Польза | Цена |
| - | - | - |
| Четыре явных семейства — выбранный вариант | Контракт виден в привязке; ошибки, отмена и время жизни управляются явно | Нужно больше объявлений адаптеров; не любую стрелку можно передать на место любой функции обратного вызова |
| Синхронный режим вне первой версии | Можно безопасно допускать ограниченные синхронные действия с немедленным результатом | Одних `r/e` недостаточно: нужны доказательство отсутствия приостановки и правила FFI; синхронное действие не становится чистым |
| Автоматическое преобразование вне первой версии | Короткий исходный код для простых интеграций | `void` не говорит, наблюдает ли JS за Promise, ждёт ли его и кто отменяет работу; нужны доверенные аннотации и те же контракты выполнения |

`Effect.runSync` не является универсальным адаптером для `->{}`: при переходе к асинхронной работе он выбрасывает `AsyncFiberError`, а начатое вычисление может продолжить работу. Это поведение прямо описано в [запуске Effect](https://effect.website/docs/v4/getting-started/running-effects).

### Подписки и обработчики событий

```flick
on_message : Message ->{Log; none} Unit
let on_message message =
  Log.write message.text

start_listening : Unit ->{Scope, Log; none} Unit
let start_listening () =
  Events.subscribe_messages
    (Events.queue 64)
    Events.log_failures
    (fun message -> task { on_message message })
```

Здесь `Events.queue 64` задаёт ограниченную FIFO-очередь, `Events.log_failures` — явный супервизор стандартной библиотеки, а переданная функция создаёт холодную задачу. При переполнении новое событие отвергается, а супервизор получает уведомление: очередь не растёт бесконечно.

Адаптер сохраняет окружение и идентичность зарегистрированной функции. Повторный вход во время регистрации допустим только после инициализации владельца и очереди. При закрытии адаптер синхронно запрещает поздние вызовы обработчика, снимает его с регистрации, прерывает задачи и ждёт их завершения. Только после этого он освобождает захваченные ресурсы. Снимок сообщения создаётся до передачи в файбер. Создать среду выполнения за пределами приложения можно лишь через явный адаптер.

Поздний вызов обработчика после начала закрытия не запускает пользовательскую задачу. Повторная регистрация создаёт отдельные владельца и очередь; при снятии с регистрации удаляется именно та JS-функция, которая была зарегистрирована. Привязка не превращает события в независимые запуски `runPromise`, за которыми никто не наблюдает.

Если JS требует немедленного действия, например решения о стандартном действии события, асинхронная часть не может гарантировать своевременный ответ. Привязку можно разделить на две части: чистая функция немедленно возвращает решение, адаптер выполняет нужное синхронное действие, а затем запускает обработку в области.

<div id="higher-rank-callback-на-ffi"></div>

### Функции обратного вызова с полиморфизмом высших рангов

В поддерживаемом подмножестве `(forall a. a -> a)` экспортируется как функция TypeScript `<A>(value: A) => A`. Полиморфизм принадлежит самой функции обратного вызова, а не только внешней функции. HKT и ограничения классов типов требуют явного кодирования и ABI словарей либо фасада с конкретными типами. Тип `.d.ts` не доказывает параметричность поведения неизвестной реализации.

Для всех семейств привязка сохраняет число аргументов JS, `this`, идентичность обработчика для снятия с регистрации и согласованное преобразование исключений. При переходе к Promise отдельно определяются правила для типизированных ошибок, дефектов и прерываний. Отмена требует реального протокола, например `AbortSignal`, и не возникает из самого типа Promise.

Прямой FFI и проверка данных решают разные задачи. Чтобы передать доверенный `HTMLElement` как непрозрачный дескриптор, JSON-кодек не нужен. Данные HTTP, конфигурацию или неизвестный JS-объект нужно проверить, прежде чем превратить в `User`. Сигнатура `.d.ts` сама по себе не проверяет значение и не доказывает отсутствие мутаций.

В языке разделены **`Unknown` и `JsValue`**. `Unknown` — неизвестное значение Flick, которое сохраняет сведения о захватах и их происхождении. Доступная для структурного обхода часть неизменяема и не выполняет пользовательский код; доверенные непрозрачные значения на концах графа остаются закрытыми для обхода. `JsValue` — произвольный граф JS-объектов, в котором могут быть геттеры, прокси, изменяемые объекты с несколькими ссылками и функции обратного вызова. `Unknown^{s}` не может скрыть право доступа `s` от проверки областей.

Преобразование `JsValue -> Unknown` создаёт снимок или декодирует данные во время выполнения с ограничениями размера и глубины. Первая версия копирует поддерживаемый граф данных и отвергает свойства-аксессоры, функции, неподдерживаемые прототипы и циклы. Общие поддеревья допустимы. Чтение дескрипторов свойств Proxy может выполнить внешний код, поэтому импорт не объявляется чистым, а исключения проходят через явное преобразование.

После импорта чистая Schema не читает изменяемое внутреннее состояние непрозрачных значений. Одна проверка метки `Ref` не доказывает тип его содержимого; для параметрического непрозрачного значения нужно проверенное свидетельство. Отдельный `DataValue` в первую версию не вводится.

<div id="публичные-typescript-интерфейсы"></div>

## Публичные интерфейсы TypeScript

| Исходный экспорт | TS API первой версии |
| - | - |
| Чистая функция | Обычная функция с представимыми TS-типами |
| Эффектная функция | Функция с результатом `Effect<A, E, R>` |
| Представимые ограничения классов типов | Явная запись-словарь либо специализированный фасад |
| Абстрактный HKT | Фасад с конкретными типами; непредставимый экспорт сопровождается диагностикой |
| Непрозрачный номинальный тип | Обёртка с меткой типа или тегом и безопасные конструкторы |
| Schema или кодек | Соответствующее нативное значение Effect Schema и ограниченная проекция в TypeScript |
| Право доступа или функция обратного вызова, привязанные к области | Адаптер с владельцем; безусловный экспорт непосредственно в TypeScript запрещён |

Каррированный экспорт сохраняет стадии исходной функции. Автоматический некаррированный фасад допускается, если промежуточные применения лишь создают замыкания либо доказанно завершаются без наблюдаемого сбоя. Одной чистоты начальных стадий недостаточно. Для `f x y` первая стадия `f x` выполняется до вычисления `y`, а JS сначала вычисляет все аргументы обычного вызова. Если первая стадия не завершается, приводит к дефекту или выполняет эффектную операцию, преобразование может изменить поведение. В таких случаях сохраняется API с отдельными стадиями либо используется явный фасад с отдельно описанным порядком. Внутренний генератор кода сохраняет последовательность через IR.

По умолчанию экспортируемая эффектная функция возвращает Effect и ничего не запускает при импорте библиотеки. Фасад Promise подключается явно и требует предоставленных сервисов, явного владельца и политики отмены. Основная форма возвращает `Promise<Result.Result<A, Errors<E>>>`: выбранная ожидаемая ошибка становится Result, а дефект или прерывание отклоняет Promise с непрозрачным `RuntimeFailure` и безопасным CauseReport. Отмена задаётся отдельным сигналом или дескриптором и сохраняет обязательное ожидание остановки работы. Promise не получает фиктивной типизации отклонений. Внешний фасад не может вернуть короткоживущее право доступа к ресурсу после закрытия своего владельца.

Собственный `.iface` сохраняет кинды, ограничения классов типов, стрелки, строки, номинальную идентичность, захваты, время жизни и ABI словарей. `.d.ts` — проверяемая ограниченная проекция. Изменение представления данных, их преобразования при передаче или версии нативного ABI Effect требует проверки совместимости интерфейса. Гарантию, которую нельзя представить, нельзя молча удалить при экспорте.

<div id="оптимизация-единственного-effect-backend"></div>

## Оптимизация кода для Effect

У Flick один генератор кода, а стандартная библиотека ориентирована на Effect. Оптимизация выбирает подходящий способ генерации:

| Исходный код | Генерация |
| - | - |
| Чистая функция | Обычная JS/TS-функция без запуска файбера и обёртки Effect |
| Чистая работа с данными Effect | Вызовы модулей данных Effect без запуска среды выполнения |
| Эффектная функция | Ленивое вычисление Effect, возвращающее исходный результат при выполнении |
| Чистый участок внутри эффектного тела | Обычные выражения внутри отложенного тела |
| `task` | Значение Effect с отложенным телом, которое можно передавать и хранить |
| Внешняя точка входа | Предоставление сервисов и один явный запуск Effect |

```ts
import { Effect } from "effect"

const normalizeName = (raw: string): string =>
  raw.trim()

const readName = (
  readRawName: () => string
): Effect.Effect<string> =>
  Effect.sync(() => normalizeName(readRawName()))
```

Здесь `normalizeName` выполняется как обычный JS. Весь вызов `readRawName` и нормализация результата остаются внутри ленивого эффектного тела. Пример показывает синхронный адаптер, а не отдельный способ выполнения языка.

<div id="профили-оптимизации-одного-effect-backend"></div>

### Профили оптимизации

| Профиль | Что разрешено | Цена |
| - | - | - |
| Консервативная генерация | Прямое отображение эффектных шагов, простые локальные преобразования, обычный JS для чистого тела | Больше замыканий и операций композиции; подходит для эталонного и отладочного режима |
| Типизированный IR с сохранением границ выполнения — выбранный режим release | Подстановка тел функций, специализация словарей и функций обратного вызова, безопасный переход к некаррированным вызовам, удаление служебных обёрток, локальное устранение общих подвыражений (CSE) и слияние вычислений при доказанных условиях | Нужно анализировать чистоту, возможность незавершения и исключений, идентичность, выход значений за пределы области и момент выполнения |
| Агрессивная специализация после первой версии | Дополнительно — локальное состояние, статически известные сервисы, циклы и представления данных | Сложный анализ ссылок на одни и те же объекты и FFI; каждое преобразование нужно обосновывать отдельно |

Все профили используют одну среду выполнения. Чистые функции остаются обычным JS; `->{}` не становится чистой стрелкой. Пустые `r/e` не доказывают отсутствие ввода-вывода, Ref, приостановки, дефекта или наблюдаемого порядка действий.

| Преобразование | Условие допустимости |
| - | - |
| Специализация словаря класса типов | Сохраняет выбранный экземпляр класса, семантику равенства и хеширования, а также моменты вычисления аргументов |
| Переход к некаррированным вызовам | Начальные стадии не расходятся и не выбрасывают исключение до аргумента, чьё вычисление переносится |
| Свёртка констант | Точно сохраняются семантика JS Number/BigInt и момент возможного исключения |
| CSE или удаление вычисления | Доказаны чистота, допустимость преобразования с учётом возможного незавершения и исключений, а также ненаблюдаемость выделения памяти и идентичности через FFI |
| Слияние чистого участка | Выполнение остаётся внутри той же отложенной области; сохраняется порядок наблюдаемых эффектных действий |
| Слияние эффектных шагов | Сохранены обработчики, provide, финализаторы, явные уступки управления и необходимые возможности отмены |

Каждый проход оптимизации также сохраняет лексического владельца, захваты, исходный Cause при повторном распространении и остановку внешней работы до освобождения ресурсов. Точное число выделений памяти и автоматических шагов планировщика не входит в контракт. Но обязательные точки отмены, явные уступки управления и однократное выполнение финализаторов удалять нельзя.

Без отдельного доказательства запрещены, например, преобразования `(a + b) + c -> a + (b + c)` и `x * 0 -> 0`, мемоизация повторного запуска task, объединение отдельных построений Layer, перенос поиска сервиса через provide и удаление проверки Unknown через Schema только на основании имени типа TypeScript.

Тело `task` не выполняется при построении; два запуска остаются двумя запусками. Операции Effect с немедленным вычислением нельзя механически подставлять вместо ленивой композиции. Перенос чистого вычисления, которое может не завершиться или выбросить исключение, тоже может изменить программу: например, исключение возникнет при построении, а не во время выполнения.

Наблюдаемый контракт включает порядок исходных эффектных вызовов, границы обработчиков, provide и Scope, регистрацию финализаторов, явные уступки управления и семантику прерывания. Точное автоматическое расписание файберов и победитель гонки между одновременно готовыми ветками могут различаться между сборками. [Планировщик Effect](https://effect.website/docs/v4/api/effect/Scheduler#MaxOpsBeforeYield) использует счётчик эффектных операций для кооперативного переключения задач, поэтому слияние шагов влияет на моменты переключения. Компилятор обязан сохранять возможность продвижения задач и не превращать неограниченную последовательность эффектных шагов в блокирующий бесконечный JS-цикл.

Семантика чисел и равенства задаёт разные ограничения. Даже если Eq считает положительный и отрицательный ноль равными, оптимизация обязана сохранять различимые арифметические результаты. Более сильные режимы возможны только при явном изменении числового контракта; они не входят в выбранную семантику JS.

### Оптимизации по образцу ReScript

Подходящие оптимизации ReScript адаптируются к собственному типизированному IR. Типы, эффекты, экземпляры классов и регионы проверяются до преобразований; необходимые доказательства и диапазоны исходного кода сохраняются в IR.

В рассмотренной [последовательности проходов ReScript](https://github.com/rescript-lang/rescript/blob/81d63a8b78aa9083fed02df6a3d4706313f23cc0/compiler/core/lam_compile_main.ml#L291-L326) есть устранение псевдонимов, уплощение вложенных конструкций, повторные упрощения и подстановки тел функций, удаление let-привязок и замена объектов отдельными полями. Это ориентир для проходов и их взаимодействия, а не готовый оптимизатор, который сохраняет контракты Effect во Flick.

| Приоритет | Приём | Применение в генераторе кода Flick |
| - | - | - |
| Первый набор | Локальная подстановка тел функций, бета-редукция, распространение псевдонимов и констант | Убирают служебные функции и известные применения, сохраняя порядок и момент выполнения |
| Первый набор | Анализ числа аргументов и прямой вызов внутренней функции | Полные известные применения обходятся без промежуточных замыканий; частичное применение сохраняет каррирование |
| Первый набор | Преобразование прямой хвостовой рекурсии чистой функции в цикл | Чистые обходы без переполнения стека и без зависимости от оптимизации хвостовых вызовов в JS-движке |
| Первый набор | Устранение временных записей и кортежей | Объект заменяется полями, если его представление и идентичность не наблюдаются |
| Первый набор | Удаление мёртвого кода (DCE) и ES-модули, удобные для сборщика | Удаляются недостижимые чистые построения; эффекты и инициализация модулей сохраняются |
| По явному ABI | Номинальные обёртки без упаковки (`unboxed type`) и различимые объединения JS (`untagged type`) | Полезны для FFI; канонические типы Effect сохраняют своё представление |
| Следующий этап | Ограниченная межмодульная подстановка тел функций | Версионируемые сводки с числом аргументов, эффектами, захватами, ABI и ограничением роста кода |
| Следующий этап | Локальное устранение изменяемых блоков | Только после анализа выхода значений за пределы области, общих ссылок и идентичности; это не общее правило для Effect Ref |

#### Прямые вызовы с сохранением каррирования

```flick
add : Float -> Float -> Float
let add left right =
  left + right
```

Возможная внутренняя генерация:

```js
function add$2(left, right) {
  return left + right;
}

const add = left => right => add$2(left, right);
```

Известное полное применение вызывает `add$2(x, y)`, а частичное сохраняет замыкание. Внутренняя функция не обязана становиться публичным экспортом TypeScript.

В [ReScript некаррированные вызовы стали моделью по умолчанию](https://rescript-lang.org/blog/uncurried-mode/). Во Flick сохраняются стадии вызова, принятые в ML-языках. Если первый вызов выполняет эффектное действие, не завершается или выбрасывает исключение до вычисления следующего аргумента, механическое объединение вызовов меняет программу. Поэтому заимствуется оптимизация числа аргументов, а не другая семантика функций.

#### Устранение временных объектов

```flick
sum_pair : Float -> Float -> Float
let sum_pair left right =
  let pair = { left = left; right = right }
  pair.left + pair.right
```

Возможная внутренняя функция:

```js
function sumPair$2(left, right) {
  return left + right;
}
```

[Проход SROA в ReScript](https://github.com/rescript-lang/rescript/blob/81d63a8b78aa9083fed02df6a3d4706313f23cc0/compiler/core/lam_pass_sroa.ml) обрабатывает локальные изменяемые блоки, для которых проверены прямые чтения и записи полей. Это не позволяет заменить произвольный `Effect.Ref` переменной: Ref может быть общим для нескольких файберов, доступным через внешнюю ссылку или иметь наблюдаемую идентичность. Для начала проще устранять неизменяемые записи и кортежи, для которых доказана локальность.

#### Вычисление литеральных выражений

Как и ReScript, компилятор вычисляет при компиляции выражения из литералов: `60 * 60 * 24` становится `86400`, `"Hello, " ++ "world"` — одной строкой, `not false` — `true`, `if true then a else b` — значением `a`. Результат обязан побитово совпадать с выполнением в JS: IEEE 754 для `+ - * / %` на Float, SameValueZero для `==` на Float, порядок кодовых единиц UTF-16 для `<` на String, усечение к нулю для `/` и `%` на BigInt.

| Выражение | Вычисляется при компиляции |
| - | - |
| Литералы Float, BigInt, String, Bool; скобки | Значение литерала |
| Унарные `-`, `not`; `+ - * / %` на Float | Да |
| `**` на Float | Только при нулевой степени или целом результате, точно представимом в binary64; иначе выражение вычисляется при выполнении, потому что `Math.pow` разных движков может отличаться в последнем бите |
| `+ - * / % **` на BigInt | Пока результат помещается в 128 бит; деление на `0n` и отрицательная степень остаются исключением `RangeError` во время выполнения, то есть дефектом |
| `==`, `!=`, `<`, `<=`, `>`, `>=` | На Float, BigInt и String; на Bool — только `==` и `!=` |
| `&&`, `\|\|`, `++` | Только когда оба операнда константны: свёртка не отбрасывает вычисление с эффектом |
| `if` с константным условием | Значение выбранной ветки, если она константна |

Свёртка применяется к проверенной программе: смешение типов, например `1 + 1n`, отвергается при проверке типов, а не при оптимизации.

В строке `"…"` действуют экранированные последовательности `\n \t \r \\ \" \0 \u{…}`. В сырых строках `r"…"`, `r#"…"#` они не обрабатываются. В `"""…"""` убираются перевод строки после открывающих кавычек, последняя строка из одних пробелов перед закрывающими кавычками и общий отступ непустых строк. Строка закрытия тоже учитывается при определении отступа. Экранированные последовательности декодируются после этого, поэтому `\u{20}` — содержимое, а не отступ. Перевод строки внутри литерала всегда `\n`, в том числе в исходнике с `\r\n`. Числовой литерал округляется до binary64 так же, как в JS.

#### Оптимизация классов типов

Единственный канонический экземпляр класса позволяет специализировать словарь, получить прямой вызов метода и затем подставить тело функции. Эта оптимизация адаптирована к классам типов Flick. Если для одного типа есть несколько разных словарей, оптимизатор обязан сохранять выбранный словарь; одного имени ограничения недостаточно.

<div id="что-сохраняет-контракт"></div>

#### Какие гарантии сохраняют оптимизации

[ReScript компилирует хвостовую рекурсию в циклы](https://rescript-lang.org/docs/manual/function/). Для эффектного кода Flick цикл дополнительно сохраняет ленивость, границы обработчиков и Scope, а также кооперативное переключение задач. Неограниченную эффектную рекурсию нельзя безусловно превращать в синхронный JS-цикл.

[ReScript DCE](https://rescript-lang.org/docs/manual/introduction/) использует информацию о чистоте. Во Flick неиспользуемое `task { Log.info message }` можно удалить как чистое описание, если само построение не имеет наблюдаемого действия. Выполненное `Log.info message` нельзя удалить из-за неиспользованного результата `Unit`.

[Варианты ReScript без упаковки](https://rescript-lang.org/docs/manual/variant/) допустимы при различимых представлениях во время выполнения. Для непрозрачного номинального типа Flick стирание обёртки не снимает ограничений Eq/Hash: особое поведение может требовать оболочки или адаптера словаря. Нативные `Option`, `Result`, `Ref`, `Schema` и `Redacted` из Effect не меняют ABI ради этой оптимизации.

Представление объявляется явно и остаётся одинаковым во всех профилях, потому что это ABI, а не решение оптимизатора:

```flick
unboxed type UserId = UserId String
  deriving Eq, Hash, Show, Schema

untagged type Key = ByNumber Float | ByName String | ByPath (List String)
```

Значение `unboxed type` представлено полем его единственного конструктора, у которого должно быть ровно одно поле. `opaque unboxed type` скрывает конструктор от импортирующих модулей так же, как `opaque type`. В `untagged type` каждый конструктор тоже представлен своим полем. Поля различаются по JS-типу (`Float`, `String`, `Bool`, `BigInt`, один вариант со списком или кортежем); пересечения отвергаются при проверке типов (`FLICK-T020`). Сопоставление с образцом проверяет `typeof`/`Array.isArray` вместо `_tag`.

Автоматически выведенные `Eq`, `Ord`, `Hash`, `Show` работают по представлению. Внешняя форма `deriving Schema` у `unboxed type` совпадает с формой поля. Для `untagged type` свидетельство не выводится автоматически: его собирают операциями `Schema`. Проекция в TypeScript — тип поля или объединение типов полей.

В [ReScript int имеет 32-битную семантику](https://rescript-lang.org/docs/manual/primitive-types/). `Float` во Flick следует JS, поэтому преобразование `(a + b) | 0` и замена обычного умножения на `Math.imul` без отдельного доказательства запрещены.

Подстановка тел функций ограничивается по размеру и глубине. Межмодульный проход использует интерфейсы Flick с семантическими сведениями, а не пытается восстановить их из `.d.ts` или Content Mapper.

После оптимизации отдельные модули могут состоять только из обычных JS-функций. Это свойство сгенерированного кода, а не отдельный вариант компиляции. Если появляются эффектные операции, используются Effect, его файберы, области, Context и Layers.

**FFI и генерация кода:** выбранный ABI, четыре семейства функций обратного вызова, инертный Unknown после импорта во время выполнения, проверяемое подмножество `.d.ts`, экспорты Effect и явно подключаемый фасад Promise. Отладочная генерация служит эталоном; режим release использует типизированный IR и подходящие проходы ReScript. Адаптер среды выполнения закрепляет точную версию Effect, проверяет совместимость при обновлении и не подменяет контракты регионов обычными типами TypeScript.
