## Обобщение при наличии Ref

Обобщение означает, что тип привязанного значения можно заново инстанцировать при каждом использовании. У `identity : forall a. a -> a` два вызова могут независимо выбрать `Float` и `String`. У одной изменяемой ячейки должен оставаться один тип содержимого. Явная сигнатура `forall` не может сделать небезопасное совместное использование состояния допустимым.

```flick fail T003
invalid : Unit ->{} String
let invalid () =
  let cell = Ref.make None
  Ref.set cell (Some 42)
  match Ref.get cell with
  | Some value -> String.trim value
  | None -> ""
```

Программа отвергается: запись `Some 42` фиксирует содержимое ячейки как `Option Int`, а `String.trim` требует `String`. Если бы `cell` получила `forall a. Ref (Option a)`, запись и чтение могли бы выбрать разные типы для одного объекта.

Обобщаются **доказанно чистые построения значений** и только по переменным, которые не свободны в окружении и не связаны с локальными жёсткими переменными типов, обязательствами по регионам и захватам или неоднозначными ограничениями. У привязки без сигнатуры нет ограничений классов: переменные её нерешённых ограничений и числовых литералов остаются мономорфными, а полиморфизм с ограничениями задаёт только сигнатура. Результат эффектного выражения не обобщается даже при `->{}` (`FLICK-T013`), в том числе в ковариантном неизменяемом типе вроде `Option a`. Полная сигнатура не отменяет эти проверки. Изменяемые контейнеры инвариантны. Доверенный чистый FFI обязан соблюдать тот же контракт чистоты.

```flick
make_empty : forall a. Unit ->{} Ref (Option a)
let make_empty () =
  Ref.make None

use_separate_cells : Unit ->{} Unit
let use_separate_cells () =
  let numbers = make_empty ()
  let names = make_empty ()
  Ref.set numbers (Some 42)
  Ref.set names (Some "Ada")
```

Значение функции `make_empty` полиморфно: создание замыкания чистое. Каждый эффектный вызов выделяет новую ячейку; сама `numbers` мономорфна и хранит только `Option Int`, а `names` — только `Option String`. Это различие сохраняет полезный полиморфизм фабрик, не разрешая менять тип уже созданного состояния.

Переменная `let mut` — состояние одной функции, а не ячейка: присваивание не является эффектным шагом, и чистая функция может присваивать своим переменным. Для неё действует то же правило, что для ячейки: её тип задаётся там, где она объявлена, никогда не обобщается, и каждое присваиваемое значение проверяется по нему, поэтому запись и чтение не могут выбрать разные типы, а `scope` не может отдать переменной свой регион. Ни функция, ни задача, ни ленивая последовательность, ни ветвь обработчика операций внутри функции не читают переменную и не присваивают ей, поэтому снаружи функция остаётся чистой ([Переменные](../../reference/types/#переменные)).

### Чистые вызовы и холодные описания

```flick
make_identity : Unit -> (a -> a)
let make_identity () =
  fun value -> value

identity_again : forall a. a -> a
let identity_again =
  make_identity ()
```

Правая часть `make_identity ()` — вызов, а не синтаксическое значение, но вызов чистый: состояние не выделяется, переменная `a` не захвачена из окружения. Поэтому `identity_again` обобщается.

```flick
fresh_cell : forall a. Eff none none (Ref (Option a))
let fresh_cell =
  task { Ref.make None }

use_tasks : Unit ->{} Unit
let use_tasks () =
  let numbers = await fresh_cell
  let names = await fresh_cell
  Ref.set numbers (Some 42)
  Ref.set names (Some "Ada")
```

`task` создаёт холодное описание. Поэтому `fresh_cell` можно обобщить: каждый `await` заново выполняет `Ref.make`. Полученные ячейки снова мономорфны. `await` не кеширует результат и не запускает отдельный файбер.

```flick
capture_cell : Ref (Option a) -> Eff none none (Ref (Option a))
let capture_cell cell =
  task { cell }
```

Здесь повторные запуски возвращают одну захваченную ячейку. Тип `a` связан с аргументом `cell`: локальное описание не может обобщить переменную, свободную в окружении. Холодность `Eff` сама по себе не доказывает отсутствия захватов.

## Deriving и законы классов

`deriving Eq, Ord, Hash, Show` создаёт экземпляры классов (`Hash` и `Ord` — только вместе с `Eq`); `deriving Generic` даёт типу его представление как сумму произведений, а `deriving C` для класса с одним параметром и реализацией по умолчанию у каждого метода — экземпляр, который их берёт, так что класс, написанный один раз через `Generic`, выводится для любого типа; `deriving Schema` создаёт свидетельство структуры данных, доступное во время выполнения. Deriving Schema охватывает записи, ADT, кортежи, обобщённые и рекурсивные типы и уточнения; он не объявляет одноимённый класс типов. Контракт — в [Schema и стандартные типы данных](../07-schema/).

Проверка экземпляра подтверждает его тип, но не доказывает законы класса. Выведенные `Eq`, `Ord` и `Hash` используют одни и те же поля. Для пользовательских реализаций нужны отдельные проверки законов; сериализация и формат хранения задаются явным кодеком, а не единственным глобальным экземпляром класса.

## Monad и объединение строк

Прелюдия объявляет `Functor`, `Applicative`, `Monad`, `Alternative`, `Foldable` и `Traversable` над `f : Type -> Type`; у `Functor`, `Applicative` и `Monad` есть экземпляры для `Eff r e`. Метод `Monad` — `flat_map : forall c d a b. (forall v. a^v -> (m b)^(c + v))^c -> ((m a)^d -> (m b)^(c + d))^c`; строки захватов задают верхние границы, а результат сохраняет захваты исходного описания и продолжения.

`Monad (Eff r e)` фиксирует `r` и `e`; допускается их явное или выведенное расширение до общей строки. Для прямых эффектных вызовов используется отдельный встроенный механизм последовательного выполнения, который объединяет строки (`Eff (r1 + r2) (e1 + e2) b`) без обращения к экземпляру `Monad`; анализатор типов вычисляет объединения строк требований и ошибок для прямых вызовов и сохраняет захваты описаний и переданных функций. Обобщённый `do` раскрывается прямо в методы `Monad` и `Alternative` из прелюдии, какие бы имена ни были в области видимости; с `Monad (Eff r e)` строки остаются фиксированными, поэтому для Eff основным стилем остаются прямые вызовы.
