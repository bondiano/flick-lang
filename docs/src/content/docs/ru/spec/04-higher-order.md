## Чистый и эффектный обход

```flick
# type UserId = UserId String
# type alias User = { id : UserId; name : String }
# type error NotFound = NotFound UserId
# service Users =
#   get : UserId ->{; NotFound} User
# normalize_name : String -> String
# let normalize_name name = String.trim name
#
normalize_names : List String -> List String
let normalize_names raw_names =
  List.map normalize_name raw_names

load_users : List UserId ->{Users; NotFound} List User
let load_users user_ids =
  List.map_effect Users.get user_ids

requests_for : List UserId -> List (Eff {Users} {NotFound} User)
let requests_for user_ids =
  List.map
    (fun id -> task { Users.get id })
    user_ids

load_users_parallel : List UserId ->{Users; NotFound} List User
let load_users_parallel user_ids =
  parallel_all 8 (requests_for user_ids)
```

`List.map` принимает чистую функцию, `List.map_effect` выполняет переданную эффектную функцию последовательно слева направо, а `parallel_all` требует явный предел конкурентности. Построение `requests_for user_ids` не запускает запросы. Единого `map`, полиморфного по эффектам, нет.

```text
List.map :
  forall c a b.
  (a -> b)^c -> (List a -> List b)^c

List.map_effect :
  forall c a b r e.
  (a ->{r; e} b)^c ->
  (List a ->{r; e} List b)^c
```

Частичное применение удерживает переданную функцию и её захваты `c`. После немедленного обхода результирующий `List b` сохраняет захваты самого `b`, но не обязан сохранять уже выполненную функцию. Это точнее общего `Functor.map`, который допускает отложенное применение.

Благодаря разделению семейств у каждой переданной функции одно соглашение о вызовах: чистая возвращает обычное значение, эффектная — Effect.

## `do`, `for` и списковые выражения

```flick
pair_optional : Option a -> Option b -> Option (a, b)
let pair_optional left right =
  match left with
  | None -> None
  | Some x ->
    match right with
    | None -> None
    | Some y -> Some (x, y)
```

С `do` вложенные сопоставления превращаются в связывания:

```flick
pair_optional : Option a -> Option b -> Option (a, b)
let pair_optional left right =
  do {
    x <- left
    y <- right
    pure (x, y)
  }
```

`do` — сахар над `Monad` из прелюдии: `p <- e` связывает через `flat_map`, голое выражение выполняется и отбрасывается, `if c` — фильтр через `Alternative`, `let` действует до конца блока, последнее выражение — результат. Продолжения — чистые функции, как требует `flat_map`: эффектный вызов внутри `do` над `Option` — ошибка (`FLICK-E001`) с подсказкой связать его до блока. Опровержимый образец после `<-` — ошибка; для него есть `match`. `do` над `Eff` разрешён, но линт `FLICK-T029` предлагает переписать его в `task` с прямыми вызовами, которые объединяют строки, зафиксированные в `Monad (Eff r e)`.

Связки через `and`, `x <- a and y <- b`, выполняются независимо: ни одно значение не видит того, что связывает другое, а объединяет их `map2` из `Applicative`. Группе, за которой идёт только `pure e`, достаточно `Applicative`, поэтому она подходит и для типов, которые не являются монадами, например для валидации, собирающей все ошибки. Если после группы есть другие утверждения, остаток — `flat_map` над кортежем группы. Над `Eff` `map2` выполняет их по очереди; параллельное выполнение остаётся явным, через `parallel`.

`for { x <- xs; if p x; y <- ys x } yield e` — ленивый `Seq`, который компилируется в один нативный генератор; `[for … yield e]` — строгий `List`, который компилируется в цикл. `x <- source` берёт элементы источника с `Iterable` (`List`, `Seq`), а опровержимый образец там пропускает неподходящие элементы; `if c` пропускает элемент, если `c` ложно, а `let` действует до конца предложений. Без фигурных скобок предложения разделяются `;`, а `if` фильтра начинает новое: `[for x <- xs if x > 0 yield x]`. Тело генератора делает не больше чем Sync-вызовы (`->{Atom.Read;}`, [синхронные стадии](../01-direct-calls/#синхронные-стадии)), и только там, где их может делать стадия, которая его строит. Каждый шаг ленивого `Seq` читает сервисы этой стадии, захваченные при построении `Seq`, а строгий список читает их сразу. Эффектный вызов может приостановиться, поэтому там он — ошибка. Повторная итерация `Seq` снова выполняет его Sync-вызовы и читает атомы такими, какие они в этот момент. `Seq` сохраняет захваты того, что использует, потому что выполняется позже. Тот, чьи шаги читают атомы, держит reader функции, которая его строит; reader кончается, когда функция возвращает, поэтому последовательность не может её покинуть (`FLICK-G001`, `FLICK-G002`): обойдите её там, передайте функции, которая её потребляет, или постройте список.

`for … do body` вместо `yield e` выполняет тело — блок типа `Unit` — для каждого элемента сразу. Его предложения и тело могут делать эффектные вызовы, которые добавляются к строкам объемлющей функции.

Цена — второй стиль рядом с прямыми вызовами; линты удерживают эффектный код на прямых вызовах. Выигрыш — короткий код для `Option`, `Result`, списков, парсеров и пользовательских монад.
