title: "Спецификация Flick"

Эта спецификация — нормативное описание языка Flick в том виде, в каком его реализует этот компилятор. Главы задают правила, которым следует каждая программа, и объясняют их ровно настолько, насколько это нужно, чтобы их применять. Страницы [справочника](../reference/grammar/) описывают тот же язык подробнее: точную грамматику, диагностики анализатора типов, стандартную библиотеку и код, который генерирует каждый target. Если глава и страница справочника касаются одной темы, глава формулирует правило и ссылается на страницу.

## Цели проектирования

- **Имя и инструменты.** Flick, CLI `flick`, исходники `.fl`; одно ядро на Rust обслуживает компилятор и языковой сервер.
- **ML-подобный синтаксис.** Функции, `let`, ADT и сопоставление с образцом. Тела функций и `match` задаются отступами, записи и специальные блоки — фигурными скобками, последнее выражение блока — его результат.
- **HKT и классы типов.** Абстракции над конструкторами типов, такими как `Functor`, `Foldable` и `Traversable`; ограничения в сигнатурах и выбор экземпляра по типам.
- **Прямые эффектные вызовы.** Обычный `let` связывает результат эффектного вызова. Эффект записан в стрелке: `a -> b` — чистый вызов, `a ->{r; e} b` — эффектный вызов, которому нужны сервисы `r` и который завершается ошибками `e`.
- **Единый стиль функций.** Полная сигнатура непосредственно над каждой именованной функцией; полиморфизм функций обратного вызова высших рангов задаётся явным вложенным `forall`.
- **Вычисления — значения.** `task { ... }` строит холодное `Eff`, `await` выполняет его в текущем файбере, а приложение запускается в точке входа.
- **Правила исполнения в языке.** Восстановление после типизированных ошибок, `provide`, лексическое владение и структурированная конкурентность — правила самого Flick, одинаковые на каждом бэкенде.
- **Числа и строки.** `Int` — 32 бита с переполнением по модулю, `Float` — IEEE 754 binary64, `BigInt` — произвольного размера, у каждого арифметика его аналога в JS; `==` на числах — SameValueZero; длина и индексы строк считаются в кодовых единицах UTF-16. Всё это одинаково на каждом бэкенде.
- **Статическая безопасность ресурсов.** Значения, зависящие от области владения, и связанные задачи не могут выйти за её пределы: свежие регионы, транзитивные захваты и двухфазное закрытие.
- **Несколько бэкендов, одна семантика.** Фронтенд переводит проверенную программу в один типизированный IR. JS-бэкенд генерирует JS или TS на Effect и компилирует чистый код в обычный JS; Go-бэкенд собирает по одному нативному исполняемому файлу на точку входа. Где глава называет Effect, она описывает, как правило реализовано на JS-бэкенде; само правило обязательно для каждого бэкенда.
- **Доступ к экосистеме JS.** Явные привязки `foreign` с фиксированным ABI и привязки, сгенерированные из проверяемого подмножества `.d.ts`.
- **Полноценный deriving Schema.** Схемы для всего поддерживаемого языка данных, включая обобщённые и рекурсивные типы; если внешний формат не может выразить схему, выдаётся явная диагностика.

## Ключевые решения

- **Последовательность операций:** прямые вызовы с `let`, `task`/`await`, `do` над `Monad` с чистыми продолжениями, генераторы `for` и списковые выражения ([Прямые эффектные вызовы](./01-direct-calls/), [Функции высшего порядка](./04-higher-order/)).
- **Тип вычисления:** `Eff r e a`, результат последним ([Значения вычислений](./02-computations/)).
- **Стрелки:** чистая `a -> b`, эффектная `a ->{r; e} b` и Sync-стадия `a ->{Atom.Read;} b`, которая компилируется в обычную JS-функцию ([Синхронные стадии](./01-direct-calls/#синхронные-стадии)).
- **Классы:** многопараметрические классы, суперклассы и функциональные зависимости; без перекрывающихся экземпляров, экземпляров-сирот и локальных экземпляров, владение определяется пакетом ([классы](../reference/classes/)).
- **Обобщение:** обобщаются только доказанно чистые построения; результаты эффектных вызовов мономорфны ([типы](./03-types-and-classes/)).
- **Записи и коллекции:** точные структурные записи с полиморфизмом строк и без неявного подтипирования по ширине; `List` — плотный неизменяемый массив, `Chunk` — отдельный тип для многократной конкатенации ([стандартная библиотека](../reference/stdlib/)).
- **API высшего порядка:** `List.map` принимает чистую функцию, `List.map_effect` выполняет эффектную функцию по порядку, `parallel_all` требует явный предел конкурентности; полиморфного по эффектам `map` нет ([Функции высшего порядка](./04-higher-order/)).
- **Время жизни:** свежие регионы и захваты, без досрочного закрытия ([регионы](../reference/regions/)).
- **Ошибки и конкурентность:** восстановление после типизированных ошибок над непрозрачными `Failure`, `Exit` и `RawCause`, полный `Cause` на каждом бэкенде; структурированные комбинаторы, супервизор с областью владения, `race` и `timeout`; атомарный `Ref`; слои, разделяемые по идентичности и мемоизируемые ([Ошибки, сервисы, ресурсы и конкурентность](./05-errors-and-concurrency/)).
- **FFI:** объявления `foreign` с режимами `pure`, `sync`, `async`, `effect` и `blocked`, сверяемые с `.d.ts` ([FFI](../reference/ffi/)).
- **Schema:** `deriving Schema`, явные кодеки, строгие экспортёры ([схемы](../reference/schema/)).
- **SQL:** типизированный eDSL для PostgreSQL, запросы которого — чистые значения ([SQL](../reference/sql/)).
- **UI:** `ui { ... }` на React, состояние в атомах `effect/reactivity`, actions с явной политикой событий, серверный рендер с реестром на запрос; без JSX и без хуков React ([пользовательские интерфейсы](../reference/ui/)).
- **Компоненты:** `component name (props : P) = body`; подготовка выполняется один раз на экземпляр, последнее выражение рендерит ([компоненты](../reference/ui/#компоненты)).
- **Серверные функции:** `server fn`, блок плагина `server` пакета std, объявляет функцию, которая выполняется на сервере и которую клиент вызывает по имени; эндпоинт и кодеки генерируются из одного объявления ([серверные функции](../reference/server-fn/)).
- **RPC и HTTP API:** `Rpc` и `HttpApi` один раз описывают контракт значениями, общими для клиента и сервера; недостающий или лишний обработчик — ошибка типов ([RPC](../reference/rpc/), [HTTP API](../reference/http-api/)).
- **Маршруты и формы:** `deriving Url` делает URL страницы типизированным значением, `deriving Form` — запись текстовой формой ([маршруты](../reference/route/), [формы](../reference/form/)).
- **Наблюдаемость:** трассировки, логи и метрики через обычные эффектные функции, с экспортом через OTLP, DevTools или Prometheus ([наблюдаемость](../reference/observability/)).
- **CLI-приложения:** `cli "name" { ... }` — плагин пакета `std` — на Effect CLI с точной записью опций ([приложения командной строки](../reference/cli-dsl/)).
- **Компилятор:** ядро на Rust, типизированный IR, языковой сервер для исходного кода, версионируемый JSON-интерфейс `.iface` для каждого модуля ([Архитектура компилятора](../contributing/implementation-decisions/#архитектура-компилятора)).
- **Бэкенды:** `[build] emit` выбирает `"js"` (по умолчанию), `"ts"` или `"go"`; импорт модуля, который target не поддерживает, — ошибка компиляции ([Go-target](../reference/codegen/#go-target)).
- **Оптимизация:** отладочный профиль — эталонная генерация кода; профиль release выполняет типизированные проходы над IR ([профиль выпуска](../reference/codegen/#профиль-выпуска)).
- **Инструменты:** `flick` с `flick.toml` и одним lock-файлом pnpm; `check`, `build`, `run`, `dev`, `test`, `fmt` и инструменты FFI и Schema используют один анализатор типов ([CLI компилятора](../reference/cli/)).
