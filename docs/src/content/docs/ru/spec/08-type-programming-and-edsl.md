title: "Программирование на уровне типов и eDSL"

DSL Flick для SQL, UI и командной строки — `sql params { … }`, `ui { … }` с объявлениями `component` и `cli "name" { … }` — это библиотеки над общим ядром типизации: строками, метками, конечными киндами, HKT и многопараметрическими классами с функциональными зависимостями. Их реализации — PostgreSQL, React (в браузере и на сервере) и Effect CLI.

## Возможности уровня типов

| Механизм | Что выражает | Граница |
| - | - | - |
| Кинды `Type`, `Row k`, `Symbol`, `Constraint`, `Region`, `CaptureRow`, `ServiceRow`, `ErrorRow` | Данные, поля, метки, ограничения и время жизни | Строки разных киндов не смешиваются |
| Пользовательские конечные кинды (`kind`) | Замкнутые индексы, например допустимость NULL или фаза | Только нульарные конструкторы; без общего переноса значений на уровень типов |
| Точные структурные записи и полиморфизм строк | Известные поля и открытый хвост | Нет неявного подтипирования по ширине |
| Примитивы строк `HasField`, `Lacks`, `Remove`, `Project`, `UnionDisjoint`, `Map`, `Labels` | Доступ, отсутствие, удаление, проекция, объединение без пересечений, преобразование типа каждого поля, канонические метки | Решаются компилятором по известным записям; программа не может объявлять их экземпляры |
| Многопараметрические классы, суперклассы, функциональные зависимости | Связи AST, его проекций и параметров | Покрытие, непересечение и бюджет решателя |
| Непрозрачные индексированные типы | Область видимости, фаза, допустимость NULL и проверенный запрос | Нет публичного конструктора, через который их можно обойти |
| GADT и `TypeEq` | Типизированные AST и интерпретаторы, свидетельства равенства типов | Уточнение — только в ветви `match` под полной сигнатурой; индексы — типы, конечные кинды и `Symbol` |
| Функции обратного вызова с полиморфизмом высших рангов и захваты | Новые области DSL и переданные функции | Явные `forall`; захваты сохраняются |

Примитивы строк описаны в разделе [Примитивы строк](../../reference/classes/#примитивы-строк). HKT сам по себе не вычисляет, какие поля появятся после JOIN, а полиморфизм высших рангов сам по себе не преобразует запись: DSL нужны именно операции над структурой типов.

Конечный кинд объявляется, например, так: `kind Nullability = NonNull | Nullable`; его конструкторы — только индексы на уровне типов и не создают значений при выполнении. Во Flick нет семейств типов, ассоциированных типов, цепочек экземпляров, импредикативности и зависимых типов. Если отношение не проходит правила покрытия, библиотека переносит вычисляемый тип в параметр своего типизированного AST или использует примитив строк.

У решения ограничений есть бюджет на каждое проверяемое определение: `solver-steps` (100 000) и `solver-depth` (256 вложенных ограничений) в разделе `[build]` файла `flick.toml`. Превышение — ошибка `FLICK-C009` с цепочкой ограничений; исчерпание бюджета никогда не считается успехом. Вычисления на уровне типов не запускают JS и не обращаются к сети или БД.

## SQL: короткая сигнатура, полный вывод результата

`sql table Name "table" { … }` объявляет тип строки `Name` и его таблицу; компилятор никогда не подключается к БД. `sql [p] { … }` — чистый проверенный `Sql.Template Pg params row`. Имя после `sql` связывает параметры, типы которых выводятся из мест использования; `$name` захватывает значение программы как место для подстановки.

```flick
# import Sql exposing (Pg, EncodeError, DbError, DecodeError)
# import Database exposing (Database)
# import BigDecimal exposing (BigDecimal)
# type UserId = UserId BigInt
# user_id : PureCodec BigInt UserId
# let user_id = Sql.codec (fun n -> Ok (UserId n)) (fun (UserId n) -> n)
# sql table Users "users" {
#   id : bigint primary key generated always as UserId via user_id
#   name : text not null as String
# }
# sql table Accounts "accounts" {
#   id : bigint primary key generated always as BigInt
#   user_id : bigint not null as UserId via user_id
#   balance : numeric not null as BigDecimal
# }
#
type alias BalanceRow = {
  name : String;
  balance : Option BigDecimal;
}

balances : Sql.Template Pg { user_id : UserId } BalanceRow
let balances = sql params {
  from user in Users
  left_join account in Accounts on account.user_id == user.id
  where user.id == params.user_id
  select {
    name = user.name;
    balance = account.balance;
  }
}

load_balances : UserId ->{Async, Database; EncodeError, DbError, DecodeError} List BalanceRow
let load_balances user_id =
  let query = Sql.bind balances { user_id = user_id }
  Database.query query
```

Блок состоит из частей запроса — по одной на строку или через `;`; продолжение части пишется с большим отступом. `from x in T`, `join x in T` и `left_join x in T` вводят псевдоним; `on e` уточняет предыдущее соединение. Остальные части начинаются со слова, за которым следуют выражения через запятую: `where`, `group_by`, `having`, `order_by`, `limit`, `offset`, `select`, `union`, `union_all`, `insert_into`, `values`, `update`, `set`, `delete_from`, `returning`. Внутри блока эти слова завершают применение функции, поэтому новая часть может начинаться без разделителя. Блок — плагин `sql` из std: он читает части запроса из токенов блока, проверяет их по таблицам, которые опубликовал плагин, а правила типов, которые оставляет проверке типов, записывает в своём коде:

| Проверка | Код |
| - | - |
| Неизвестная колонка, неизвестный или недоступный в этой области псевдоним, неоднозначная колонка | `std/Q001`, `std/Q002`, `std/Q003` |
| Два результата с одним именем | `std/Q004` |
| Колонка, которая не входит в группировку и не агрегирована; агрегат там, где он запрещён | `std/Q005`, `std/Q006` |
| INSERT без обязательной колонки; запись в генерируемую колонку | `std/Q007`, `std/Q008` |
| Неизвестный параметр; конструкция вне поддерживаемого подмножества | `std/Q009`, `std/Q010` |
| Сравнение значений разных типов Flick | Ошибка типов, даже если в SQL оба значения — числа |

Результат, который может быть `NULL` (колонка, допускающая NULL, колонка таблицы из `left_join`, агрегат, кроме `count`), имеет тип `Option t` ровно один раз: два LEFT JOIN не дают `Option (Option t)`. `==` — сравнение SQL, и `where` оставляет только строки, где условие истинно; `is_null`, `is_not_null` и `is_not_distinct_from` — отдельные функции.

`Sql.bind` связывает параметры без ввода-вывода; с БД работают только `Database.query` и `Database.execute`. Значения никогда не попадают в текст SQL: каждый параметр и литерал — место для подстановки, а таблицы, псевдонимы и колонки берутся из метаданных. Отвергнутый параметр — `EncodeError`, ответ, не соответствующий запросу, — `DecodeError`, отказ сервера или драйвера — `DbError`. Коррелированные подзапросы и `LATERAL`, рекурсивные CTE, оконные функции, `RIGHT` и `FULL` JOIN и DDL находятся вне проверяемого подмножества; `Sql.unsafe_query` выполняет произвольный SQL с явным декодировщиком, и таблицу или колонку там называет только `Sql.Identifier`. Таблицы, транзакции, миграции и отмена описаны в справочнике [SQL](../../reference/sql/).

## UI eDSL: свойства, дочерние узлы и действия

`Ui` — чистое описание интерфейса с отложенными обработчиками. Задача обработчика только изменяет атомы через `Atom.Write`; другие сервисы она предоставляет себе сама и свои ошибки обрабатывает сама, поэтому у `Ui` нет строк сервисов и ошибок. Построение `Ui` не запускает обработчики, не читает состояние и не обращается к DOM.

```flick
type alias SaveButtonProps c = {
  label : String;
  disabled : Bool;
  on_save : (Unit ->{Atom.Write} Unit)^c;
}

save_button : SaveButtonProps c -> Ui^c
let save_button props = ui {
  button
    {
      disabled = props.disabled;
      on_click = Ui.Event.exhaust (fun _ -> task { props.on_save () });
    }
    (text props.label)
}
```

`ui { … }` — блок, в котором имена модуля `Ui` пишутся без `Ui.`: сначала учитывается локальная привязка, затем имя из `Ui`, затем имена самого модуля. Дети элемента идут в нём по одному, каждый — аргумент на строке вызова или отдельная строка под ним, и вызов функции, чей последний параметр — `List Ui`, собирает их в этот список; один аргумент-список и есть этот список, а литерал списка — `FLICK-T073`. Он компилируется в то же IR, что и вызовы `Ui.button … [Ui.text …]`, а применение `Ui.Component p` к свойствам внутри блока означает `Ui.component value props`, в том числе в форме `props |> value`. JSX в язык не входит.

Свойства — точные записи: отсутствующее поле, лишнее поле или неверный тип — ошибка. Вне `ui` и для любой другой формы детей это обычный аргумент выбранного типа (`List Ui`, `Ui`, `Option Ui`, именованные места, `NonEmpty Tab`), а ключ — метаданные, которые задаёт `Ui.keyed`, а не свойство. Обработчики сохраняют то, что им нужно: кнопка, обработчик которой использует файл области, не может покинуть эту область (`FLICK-G001`). `Ui.text` вставляет текст через безопасный канал; URL имеет тип `SafeUrl`, а HTML без экранирования — `SanitizedHtml`, и обычная `String` не является ни тем, ни другим.

### Атомы, представления и компоненты

Состояние хранится в атомах: `Atom.make value` — состояние, `Atom.derived` — атом, вычисляемый из прочитанных им атомов, а `Atom.set`/`Atom.update` изменяют атомы через сервис `Atom.Write`. Представление (`component`, тип `Ui.View p`) — компонент, рендер которого читает атомы через `Atom.Read` и повторяется только при изменении прочитанного атома. Рендер — Sync-стадия: запись, другой сервис или ошибка в нём — `FLICK-U004`. Во время рендера ничего не создаётся: атом, действие или представление, созданные при рендере, — ошибка `FLICK-U006`.

`component name (props : P) = body` объявляет представление типа `Ui.View P`, которое размещает `Ui.render name props`. Тело — блок: его последнее выражение — рендер, который повторяется при изменении прочитанного атома или свойств; инструкции перед ним — настройка каждого экземпляра, которая выполняется один раз при монтировании экземпляра с сервисом `Setup s` региона экземпляра. Там `Atom.local` создаёт атом экземпляра, а конструкторы `Action` — его действия.

```flick
component counter (start : Float) =
  let count = Atom.local start
  let bump = Action.exhaust (fun _ -> task { Atom.update count (fun n -> n + 1) })
  ui {
    let n = Atom.value count
    button { on_click = bump; disabled = false } (text (show n))
  }
```

При размонтировании экземпляра действия, созданные при настройке экземпляра, перестают принимать события, а их задачи прерываются. Действие (`Action.exhaust`, `latest`, `queue`, `concurrent`) — обработчик, объявленный один раз и переданный любому числу элементов; в пределах корня они разделяют состояние его политики, а `Action.with action arg` даёт каждому элементу собственный аргумент и состояние. См. [Атомы и представления](../../reference/ui/#атомы-и-представления), [Компоненты](../../reference/ui/#компоненты) и [Действия](../../reference/ui/#действия).

### Обработка событий и время жизни

Поле обработчика имеет непрозрачный тип `Ui.Handler snapshot`, который создаёт только политика, поэтому неуправляемых обработчиков без наблюдения за завершением нет:

| Конструктор | Событие, пришедшее, пока выполняются прежние задачи |
| - | - |
| `Ui.Event.exhaust` | Игнорируется |
| `Ui.Event.latest` | Прерывает выполняемую задачу, ждёт её остановки и запускается; ждёт не больше одного события — последнего |
| `Ui.Event.queue capacity` | Ждёт в очереди, не больше `capacity` событий; сверх этого отвергается |
| `Ui.Event.concurrent limit` | Запускается, не больше `limit` задач одновременно; сверх этого отвергается |

`capacity` и `limit` — положительные целые: неподходящая константа — ошибка `FLICK-U001`, вычисляемое значение проверяется при создании обработчика. Отвергнутое событие — инфраструктурный дефект для супервизора, а не ошибка типизированной строки. Обработчик получает инертный снимок, сделанный внутри DOM-обработчика; `Ui.Event.prevent_default decide h` синхронно вызывает чистую функцию `decide`, чтобы определить, нужно ли отменить действие по умолчанию.

`Ui.Dom.mount container supervisor ui` отображает `ui` с предоставленным реестром атомов (`Atom.layer`); первое монтирование DOM синхронно, а последующие рендеры планирует React 19. Супервизор получает `Failure none`: сбои задач и отвергнутые события. Закрытие проходит в две фазы: очистка React прекращает приём событий и размонтирует дерево, затем задачи обработчиков прерываются и ожидаются, и только после этого `mount` завершается, поэтому область освобождает ресурсы после остановки задач. `Ui.mount_with renderer supervisor ui` следует тому же контракту, но использует непрозрачный `Ui.Renderer` вместо DOM-контейнера.

`Ui.Server.render ui` отображает на сервере разметку начального представления; его представления читают атомы из реестра запроса, а обработчики на сервере не запускаются. Контейнер с пометкой `data-flick-ssr` `Ui.Dom.mount` гидратирует, а не очищает. См. [серверное начальное представление](../../reference/ui/#серверное-представление-при-открытии).

## CLI eDSL: флаги, аргументы и подкоманды

Приложение командной строки — значение `Cli.Command r e`: чистое описание флагов, позиционных аргументов, подкоманд и обработчика, которому нужны сервисы `r` и который может завершиться ошибками `e`. Построение команды ничего не разбирает и не запускает.

```flick
import Cli

greet : Cli.Command none none
let greet = cli "greet" {
  description "Prints a greeting"
  /// Print in capitals
  flag loud : Bool
  /// How many times
  flag times "n" : Int = 1
  /// Who to greet
  arg name : String
  handle fun { loud; times; name } ->
    let text = "Hello, " ++ name
    let line = if loud then String.to_upper text else text
    Platform.stdout_line (String.join "\n" (List.repeat times line))
}
```

`cli "name" { … }` — блок плагина пакета `std` (см. [Плагины](../../reference/plugins/)), который файл импортирует. Это синтаксический сахар над комбинаторами `Cli.command`, `Cli.flag`, `Cli.arg`, `Cli.description`, `Cli.subcommand` и `Cli.handled` — в эти вызовы компилятор преобразует блок. Блок состоит из конструкций — по одной на строку или через `;`; их ключевые слова особые только в начале конструкции:

| Конструкция | Смысл |
| - | - |
| `description e` | Текст справки команды, `e : String`; не больше одной |
| `flag name "alias"… : T [= default]` | Именованный параметр `--name`; строки после имени — дополнительные имена |
| `arg name : T [= default]` | Следующий позиционный аргумент |
| `subcommand e` | Вложенная команда, `e : Cli.Command r e` |
| `handle f` | Обработчик, `f : Options ->{r; e} Unit`; не больше одного |

Комментарий `///` непосредственно над `flag`, `arg` или `subcommand` — его текст в справке. Обработчик получает точную запись с полем для каждого `flag` и `arg`, поэтому опечатка в его образце — обычная ошибка типов. Тип задаёт разбор и кратность: `Bool` — переключатель, `T` обязателен, если нет значения по умолчанию, `Option T` необязателен и не принимает значения по умолчанию, `List T` и `NonEmpty T` повторяются (у `arg` — только у последнего). Значение разбирает класс `Cli.Value T`. Сервисы и ошибки команды — объединение строк её обработчика и подкоманд; команде нужно то, что использует её обработчик (`FLICK-G001`).

`Cli.run command args` разбирает аргументы и только после этого выполняет обработчик в текущем файбере. `--help`, `--version` и `--completions` не запускают обработчик; неверный ввод завершается `Cli.CliError`, и обработчик тоже не запускается. Повтор имён, значение по умолчанию у `Option`, многозначный `arg` не последним, повтор `description` или `handle`, команда без обработчика и без подкоманд и `arg` рядом с подкомандами — ошибки компиляции (ошибки плагина `std/L001`–`std/L007`). См. [Приложения командной строки](../../reference/cli-dsl/).

## `do` и библиотечные комбинаторы

Каждый блок DSL — сахар над обычными библиотечными функциями, которые программа может вызывать напрямую. Обобщённый монадический код использует `do { … }` над `Monad` из Prelude, а `and` — для независимых привязок через `Applicative` (см. [`do`, `for` и списковые выражения](../04-higher-order/#do-for-и-списковые-выражения)); обычный `let` не связывает значения через монаду.
