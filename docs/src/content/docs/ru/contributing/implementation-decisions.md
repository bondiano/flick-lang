## Архитектура компилятора

Компилятор написан на Rust: крейт `flick-core` — сам компилятор, `flick` —
командная строка поверх него. Один анализ модуля служит для всех выходов:
кода обоих бэкендов, деклараций TypeScript, проекции для редактора и языкового
сервера, поэтому они не могут разойтись в типах. Источник истины для типов,
эффектов и диагностики — проверка Flick; TypeScript никогда не решает,
каков тип Flick.

```text
.fl ─> syntax ─> resolve ─> types ─> ir ─> opt (release) ─┬─> codegen/js ─> ESM over Effect
                               │                          └─> codegen/go ─> Go over flickrt
                               ├─> .iface, codegen/ts (.d.ts, Promise façades)
                               └─> ide, projection ─> flick lsp, flick content-mapper
```

| Компонент | Где | Ответственность |
| - | - | - |
| Парсер | `flick-core/src/syntax` | парсер с учётом раскладки строит CST без потерь и AST поверх него; `fmt` форматирует CST |
| Разрешение имён | `flick-core/src/resolve` | модули, импорты, экспорты и имена; предупреждения о неиспользуемом коде |
| Проверка | `flick-core/src/types` | кинды; двунаправленная проверка типов с высшими рангами; строки записей и эффектов; сервисы и слои; классы, экземпляры и `deriving`; регионы и захваты; блоки `sql`, `ui` и `cli` |
| Типизированный IR | `flick-core/src/ir` | проверенный модуль, в котором явно выражены стадии применения, словари, подъёмы и диапазоны исходного кода; `ir/lower` разворачивает `do`, включения, `sql`, `cli` и `server fn` |
| Вычисление констант | `flick-core/src/consteval` | выражения из литералов сворачиваются с семантикой JS бит в бит |
| Оптимизатор | `flick-core/src/opt` | проходы профиля release над типизированным IR (специализация, встраивание, слияние, скалярная замена, свёртка), сохраняющие все наблюдаемые контракты отладочной трансляции; их выполняют оба бэкенда (см. [Профиль выпуска](../../reference/codegen/#профиль-выпуска)) |
| JS-бэкенд | `flick-core/src/codegen/js`, `runtime/` | ESM с картами исходного кода: чистый код — обычный JS, стадия среды выполнения — `Effect.gen` поверх `@flick-lang/runtime` |
| Go-бэкенд | `flick-core/src/codegen/go`, `flick-core/src/build/go.rs`, `runtime-go/flickrt` | `[build] emit = "go"`: Go-модуль для каждого входа поверх пакета среды выполнения `flickrt`, который компилирует `go build` (см. [Go-target](../../reference/codegen/#go-target)) |
| Генератор TypeScript | `flick-core/src/codegen/ts` | типы для `--emit ts`, `.d.ts` для `--emit-dts` и Promise-фасады для `--promise-facade`; тип без формы в TypeScript отвергается и никогда не записывается как `any` |
| Интерфейсы | `flick-core/src/iface.rs`, `flick-core/src/build` | версионируемый JSON `.iface` каждого модуля с ABI данных и словарей и отпечатками, которые добавляет сборка (см. [Интерфейсы](../../reference/iface/)) |
| Импорт FFI | `flick-core/src/ffi`, `tools/dts-importer` | `flick ffi import` и `ffi check` над описанием, которое вспомогательная программа на Node читает из `.d.ts` с помощью TypeScript |
| Редактор | `flick-core/src/ide`, `flick-core/src/projection.rs`, `flick/src/lsp`, `flick/src/mapper.rs` | подсказки, переход к определению, ссылки, автодополнение, переименование и действия над кодом по одному анализу; их обслуживает `flick lsp --stdio`, а `flick content-mapper` — проекцию TypeScript с картами диапазонов (см. [Редакторы](../../reference/editor/)) |

JS-бэкенд рассчитан ровно на Effect 4.1.2; эту версию вместе с версиями среды
выполнения, pnpm и Node закрепляет `flick/src/toolchain.rs`. Установленный
`effect` или `@flick-lang/runtime` другой версии останавливает сборку
(`FLICK-P015`). `flick-wasm` запускает то же ядро во встроенной демонстрации
в браузере, а `flick-model` — эталонная модель формального ядра (`docs/formal/`).

## Решения, оставленные на усмотрение реализации

| Вопрос | Решение |
| - | - |
| Парсер | Рукописный рекурсивный спуск и метод Пратта для операторов; CST без потерь сохраняет пробелы и комментарии для `fmt` и LSP |
| Инкрементальность | Без фреймворка запросов. Сборка кешируется целиком в `.flick/cache/` по ключу от всех входных данных, включая исходники и интерфейсы установленных зависимостей (см. [Выходные файлы и кеш](../../reference/cli/#выходные-файлы-и-кеш)); `.iface` хранит отпечатки интерфейсов, с которыми собран модуль |
| Диапазоны исходного кода | Диапазоны байтов UTF-8 (см. [Потоки и коды выхода](../../reference/cli/#потоки-и-коды-выхода)); LSP переводит их в UTF-16 |
| Тесты по снимкам | `insta` для диагностики, IR и сгенерированного JS (см. [Тестирование](../testing/)) |
| Платформа Node | Node.js 24.18.0 — минимальная поддерживаемая версия; её проверяет `flick doctor` |
| Браузерная среда | Переносимые адаптеры среды выполнения и Effect загружаются без Node.js. Встроенные модули Node и платформенные пакеты загружаются только при выполнении соответствующей операции; в браузере такая операция сообщает, что ей нужен Node.js |
| pnpm | Шаблон проекта закрепляет версию через `packageManager` (`pnpm@12.16.1`); `flick doctor` сверяет с ней установленный pnpm. Команды зависимостей отключают автоматическую загрузку, смену и закрепление менеджера перед его проверкой и запуском, поэтому отказ установки с `--locked` не переписывает метаданные менеджера в lockfile |
| Effect | Ровно 4.1.2, commit `506eef143bcc1750ce58920aac1e45da7265d103` (см. [Сложный Cause](../../spec/05-errors-and-concurrency/#сложный-cause-что-обещает-строка-ошибок), [Архитектура компилятора](#архитектура-компилятора) и [Версия Effect](../../reference/runtime/#версия-effect)) |
| Покрытие Effect API | Каждый экспорт `effect`, `effect/cli`, `effect/http`, `effect/http-api` классифицирован в манифесте; линтер в `cargo test` завершается с ошибкой при неклассифицированном, устаревшем или изменившем сигнатуру экспорте (см. [Покрытие Effect](../../reference/effect-surface/)) |
| Бэкенды | Контракт — правила исполнения Flick: Effect — то, как их реализует JS-бэкенд, а `runtime-go` — то, как их реализует Go-бэкенд. `[build] emit = "go"` стоит рядом с `js` и `ts`, чтобы один ключ задавал, что пишет компилятор; неизвестное значение даёт ошибку конфигурации (см. [Go](../../reference/codegen/#go-target)). Типизированный IR хранит числовые литералы как значения (`Int`, `Float`, цифры `BigInt`), а не исходный текст JS, поэтому каждый бэкенд печатает их своим синтаксисом; привязки `foreign` остаются соглашением о вызовах JS, их выводит только JS-бэкенд |
| Платформа Node для Effect | Серверный HTTP и `Terminal`/`FileSystem`/`Path` для CLI предоставляет `@effect/platform-node`. Пакет закреплён на 4.1.2 вместе с Effect как зависимость `@flick-lang/runtime` |
| Драйвер PostgreSQL | `pg` (node-postgres) — необязательная peer-зависимость `@flick-lang/runtime`, привязанная через `foreign` в модуле стандартной библиотеки `Database` (`Database.pg`) |
| React | React 19 и `react-dom/client` — необязательные peer-зависимости `@flick-lang/runtime` |
| Состояние UI | Атомы `effect/reactivity` (unstable, закреплены вместе с Effect) вместо собственного реестра Flick; реестр предоставляет корень или серверный запрос. Именно реестр делает возможными серверный рендеринг и полную hooks-модель: `Ref`, локальный для корня, не даёт серверному рендеру отдельного состояния на запрос и не передаёт это состояние клиенту, а реестр, сериализация и `Hydration` Effect это уже умеют. Цена — около 25 KB gzip, она учтена в бюджетах бандла (см. [Пользовательские интерфейсы](../../reference/ui/)). `effect/reactivity` импортируют только `runtime/src/atoms.ts` и `runtime/src/effect/reactivity/` (в других местах это запрещает правило oxlint), поэтому собственный реестр Flick, если его потребуют бюджет бандла или ломающий релиз Effect, заменит только этот слой |
| Обработчики UI | Задача обработчика имеет строку `{Atom.Write}` и не имеет ошибок, поэтому у `Ui`, `Action` и `View` нет строк сервисов и ошибок: другой сервис задача предоставляет себе сама и свои ошибки обрабатывает сама, а супервизор корня получает `Failure none` — её дефекты. Со строками каждый тип представления, слота и свойства повторял `r e`, хотя обработчики стали action верхнего уровня; action, которому нужен сервис или который может упасть, указывает это в своей задаче, там и обрабатывает |
| Трейсинг UI | Каждый запуск action — span с его меткой, а каждая запись `Atom.Write` пишется в лог на уровне debug с причиной и местом `Module:line`, которое компилятор передаёт `Atom.set`/`update`/`modify`. Оба механизма всегда в рантайме, а не за отдельным слоем: они стоят около 4,4 KB gzip (span'ы 2,3 KB, логгер Effect 1,7 KB), что несут бюджеты UI-бандлов (counter — 118 KB, atoms — 117 KB, playground — 126 KB) |
| Точки входа | Приложение называет свои программы в `entries`, и каждая собирается в раннер `flick-<name>.js` рядом с модулями, которые пишутся один раз; `entry` — это вход `main`, его раннер сохраняет имя `flick-main.js`. Модуль, который только реэкспортирует `main`, тоже может быть входом: реэкспорт — та же сущность, поэтому раннер импортирует `main` из модуля, где он определён, как это делает любой импортёр, ведь JavaScript модуля содержит только его собственные определения. Реэкспортированный `tests` не делает модуль тестовым, иначе тесты другого модуля запускались бы дважды. Веб-страницы — не входы: бандлер принимает JavaScript-модули, импортирующие `.fl` |
| Разработка страниц | `flick dev` перезапускает серверные входы при изменении, как любое приложение, а для клиентских запускает Vite. Скрипт входа страницы принимает собственную замену: `hotDispose` из `Runner.Browser` читает значения помеченных состояний (каждый top-level `let` атома и тексты черновика формы, `Type.field`) смонтированных корней и прерывает работающую программу, финализаторы которой размонтируют корни, так что ни один наблюдатель или подписка не остаётся дважды; `hotCarry` заставляет первый корень следующей программы начать с этих значений. Атом, найденный по метке в новом модуле, получает старое значение; переименованный или удалённый начинается заново. Task-атомы запускаются снова |
| Библиотеки без Effect | Библиотека на Effect пишет и `_core/` — модули, которым Effect не нужен, собранные на `@flick-lang/runtime/core`; одна сборка не годится обоим бэкендам. `Option`/`Result` из `core` — простые объекты, которые `Equal.equals` и `Hash.hash` Effect не считают равными своим, а Effect-сборка модуля импортирует Effect, который приложению с `effect = "none"` грузить нельзя. Замер: `_core/` пакета `@flick-lang/dts-importer` — 13% его модулей |
| Сборка документации | Потоки выполнения программ используют ESM, а код зависимостей разбивается на чанки с сохранением порядка выполнения модулей Effect. Отдельная страница Starlight для ошибки 404 содержит ссылки на английскую и русскую документацию и не попадает в список документов или поиск |
| Блокировки поколений запуска | Атомарная резервация каталога `<pid>-<n>` защищает сборку до появления блокировки дочернего процесса. В Unix наличие владельца и дочернего процесса проверяется без отправки сигнала; некорректные блокировки, ошибки доступа и неизвестные состояния сохраняются. На других платформах действует консервативное поведение |
| Разрешение `.d.ts` | npm-пакет `typescript` во вспомогательном Node-модуле `@flick-lang/dts-importer`; JSON-запрос поступает через stdin, описание экспортов пакета возвращается в JSON через stdout (см. [Импорт `.d.ts` пакета](../../reference/ffi/#импорт-dts-пакета)) |
| Область имён npm-пакетов | `@flick-lang/*` (`@flick-lang/runtime`, `@flick-lang/dts-importer`); стандартная библиотека входит в компилятор |
| Сгенерированные имена | Словарь экземпляра — `$i_<Класс>_<Тип>`, если его заголовок — имена через пробел (`Show Float`): по такому имени заголовок восстанавливается однозначно; другой заголовок (`Show (List a)`) сохраняет 8-значный hex-суффикс хэша FNV. Теги конструкторов сохраняют 48-битный хэш (`Circle#d930eed2c811`) во всех профилях, в том числе у приватных типов: тег — идентичность значения между пакетами и модулями, `derive`, `show` и `equals` читают его во время выполнения, а debug- и release-сборки должны в нём совпадать. Замер: без хэша плейграунд был бы меньше на 138 байт после gzip (17 тегов), остальные отслеживаемые программы — не более чем на 24, поэтому хэш остаётся |
| Проверки релиза | Release вызывает общий CI для коммита тега; сборка бинарных файлов и публикация зависят от его успешного завершения |

## Детали, не заданные спецификацией

Спецификация фиксирует семантику, но не задаёт некоторые детали синтаксиса и API.
Принятые решения перечислены ниже и описаны в справочнике.

| Вопрос | Решение |
| - | - |
| Комментарии | `//` — строчный, `/* */` — блочный с вложенностью, `///` — комментарий документации для `flick doc`. Внутри `sql { }` тоже используется `//` (см. [Пробельные символы и комментарии](../../reference/grammar/#пробельные-символы-и-комментарии)) |
| Строки | Экранирующие последовательности `\n \t \r \\ \" \0 \u{…}` (только форма с фигурными скобками, от 1 до 6 шестнадцатеричных цифр, без суррогатных кодовых точек; после `\0` не может идти цифра); строки без обработки экранирования `r"…"`, `r#"…"#`, `r##"…"##`…; многострочные `"""…"""` с удалением общего отступа; интерполяции нет (см. [Строковые литералы](../../reference/grammar/#строковые-литералы)) |
| Операторы | Фиксированная таблица, пользовательских операторов нет. В порядке возрастания приоритета: `\|>` (лев.), `\|\|` (прав.), `&&` (прав.), `== != < <= > >=` (неассоц.), `++` (прав.), `+ -` (лев.), `* / %` (лев., `%` — остаток по правилам JS), `**` (прав.), префиксные `-`, `not`, `await`, `ignore`, применение, `.field` / `M.x`. Битовые операции — именованные функции `Float.bit_*` (см. [Таблица операторов](../../reference/grammar/#таблица-операторов)) |
| Bool и `if` | `Bool` — логическое значение JS; литералы `true`/`false` допустимы и в образцах. `if c then a else b` — выражение, `else` можно опустить, если ветвь имеет тип `Unit`; поддерживаются цепочки `else if` и многострочная форма с отступами (см. [Правила отступов](../../reference/grammar/#правила-отступов) и [Выражения](../../reference/grammar/#выражения)) |
| Числовые литералы | Грамматика JS `NumericLiteral`: десятичные числа, экспонента `1e-3`, `0x`/`0o`/`0b`, разделитель `_` по правилам JS (не в начале или конце группы цифр, не двойной, не рядом с `.`/`e`/префиксом), суффикс BigInt `n` (без дроби и экспоненты). Устаревшая восьмеричная форма `010` и ведущий ноль вроде `09` запрещены. В отличие от JS, формы `.5` и `5.` запрещены из-за конфликта с доступом `.field` (см. [Числовые литералы](../../reference/grammar/#числовые-литералы)) |
| Тесты | Нового синтаксиса нет: модуль из корневого каталога тестов экспортирует `tests : List Test.Test`; `Test.test`, `Test.effect_test`, `Test.property`, `Test.group` и генераторы `Gen.*` — функции библиотеки (см. [Тесты](../../reference/stdlib/#тесты)) |
| API платформы | `Platform.args`, `Platform.env`, `stdout_line`/`stderr_line`/`stdout_write` — модуль стандартной библиотеки (см. [Модули](../../reference/stdlib/#модули)) |
| `AppError` | Тип Prelude: `type error AppError = AppError { message : String; details : Option String }`; `App.fail : String ->{; AppError} a`; средство запуска безопасно печатает `error: <message>` и выходит с кодом `1` (см. [Средство запуска точки входа](../../reference/runtime/#средство-запуска-точки-входа)) |
| Метаданные таблиц SQL | Блок `sql table Name "table" { col : sql_type [not null \| null] [primary key] [unique] [default] [generated always \| generated by default] as T [via codec] }` объявляет тип строки `Name` и таблицу `Name$table : Sql.Table "table" { … }` из `Sql.Column`; таблицы, сгенерированные из миграций, имеют ту же форму (см. [Таблицы](../../reference/sql/#таблицы)) |
| Переопределения FFI | Средство импорта пишет только `<Pkg>/Generated.fl`; собственный модуль, обычно `<Pkg>.fl`, содержит обычные объявления `foreign` с `reviewed "<pkg>@<ver> sha256:…"` и повторный экспорт остальных имён. `flick ffi check` сверяет отпечаток (см. [Проверенные привязки и `ffi check`](../../reference/ffi/#проверенные-привязки-и-ffi-check)) |
| Затенение и неоднозначность | Локальные связывания затеняют всё без диагностики. Определение верхнего уровня с именем из `import … exposing (name)` — ошибка `FLICK-R009`; имена из `exposing (..)` оно затеняет без диагностики. Два импорта одного имени для разных сущностей — `FLICK-R010` сразу; конфликт между `(..)`-импортами — `FLICK-R010` только в месте использования; два импорта под одним квалификатором — `FLICK-R010`. Повторный экспорт той же сущности не создаёт конфликта. Порядок `import` ни на что не влияет (см. [Затенение и неоднозначность](../../reference/modules/#затенение-и-неоднозначность)) |
| HTTP | Собственного синтаксиса нет (см. [Граница языкового ядра](../../spec/05-errors-and-concurrency/#граница-языкового-ядра)): `Http.*` и `HttpApi.*` — библиотечные комбинаторы; части эндпоинтов описывают кодеки из `Schema a` (см. [Типизированные HTTP API](../../reference/http-api/)) |
| CLI eDSL | См. [CLI eDSL](../../spec/08-type-programming-and-edsl/#cli-edsl-флаги-аргументы-и-подкоманды). Блок `cli "name" { … }` с конструкциями `description`, `flag`, `arg`, `subcommand`, `handle` преобразуется в библиотечные `Cli.*` на основе `effect/cli`; эти функции доступны и напрямую (см. [CLI eDSL](../../reference/cli-dsl/) и [грамматику](../../reference/grammar/#выражения)) |
| Методы класса | Метод объявляется обычной сигнатурой `name : T` (ключевого слова `val` нет, старая запись даёт `FLICK-S010`). Метод по умолчанию задаётся сигнатурой и `let name … =` прямо под ней в теле класса; экземпляр класса может его не определять. Сигнатура без `let` объявляет абстрактный метод; экземпляр класса обязан его определить, иначе возникает `FLICK-C011` (см. [Экземпляры классов](../../reference/classes/#экземпляры-классов)) |
| Пакеты с модулями Flick | Библиотеку Flick зависимый проект компилирует из исходников: по пути, по тегу git или из tar-архива с sha256. `flick install` скачивает её в хранилище пакетов и закрепляет в `flick.lock`; `.iface` чужих пакетов не читаются (см. [Зависимости Flick](../../reference/project/#зависимости-flick)) |

## Экземпляры пользовательских типов

[Пример MTL](https://github.com/bondiano/flick-lang/tree/main/examples/mtl/src/Mtl)
реализует Identity и пять трансформеров — MaybeT, StateT, ReaderT, WriterT,
ExceptT — обычными конструкторами, образцами и `do`, без примитивов компилятора
и foreign-реализаций. Их Functor/Applicative/Monad сохраняют
[захваты](../../reference/regions/#захваты): граница целого значения не стирает
сохранённые квалификаторы, а колбэк полиморфен по захватам каждого вызова,
включая состояние или окружение, переданные позже.

[Планировщик](https://github.com/bondiano/flick-lang/blob/main/examples/mtl/src/App/Plan.fl)
сохраняет прежний стек:

```flick
type alias Planner a = MaybeT (StateT PlanState (ReaderT Config Identity)) a
```

Он импортирует `ask`, `get`, `put` из `Mtl.Classes`; унаследованные экземпляры
возможностей проходят промежуточные слои автоматически. Единый
`MonadTrans.lift` явно поднимает типизированное внутреннее действие.
Снятие слоёв прежнее: `MaybeT.run`, `StateT.run` с начальным состоянием,
`ReaderT.run` с конфигурацией, `Identity.run`. Сбой сохраняет завершённый
префикс; интерфейс CLI не меняется.

MonadState/MonadReader/MonadWriter/MonadError ставят монаду первым параметром;
FD связывает её с типом состояния, окружения, лога или ошибки. Покрытие
замыкается по зависимостям контекста и подставленных суперклассов. Выбор
экземпляра идёт только по полной голове, не по контексту; структурные
ограничения и лимиты решателя обязательны. Экземпляры принадлежат модулю
своего трансформера; при повторении возможности выбирается внешний
собственный слой.

`pass` хранит мономорфный модификатор `(w -> w)^c` независимо от границы
действия; `forall` внутри кортежа потребовал бы непредикативной подстановки.
Локальные аннотации преобразований сохраняют квалификатор. Захваты позднего
состояния/окружения по-прежнему попадают в результат. `catch_error` принимает
обработчик первым и ловит доменную ошибку, но не типизированный сбой Eff,
дефект или прерывание. StateT над ExceptT начинает обработчик с исходного
состояния; WriterT над ExceptT теряет пару лога при сбое. Обратный порядок
сохраняет изменения состояния или лог до ошибки.

Пример MTL включает пять экземпляров MonadTrans, 20 путей возможностей, законы и
`App.Capabilities` над Identity и холодным Eff. Это перечисленный набор,
а не все трансформеры Haskell. Ни квантифицированный суперкласс MonadTrans,
ни адаптер ошибок runtime для него не нужны.
