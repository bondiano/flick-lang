Конструктор типа с `@native when <cond>` строится или разбирается там, где тип
может быть собственным типом бэкенда.

Там, где условие типа выполняется, его значения приходят из привязок бэкенда, и
конструкторов, которые можно разобрать, у них нет. Называть их может только тело
на Flick определения, чьи строки `@native` выполняются везде, где выполняется
условие типа: там нативная строка заменяет тело, и тело работает только там, где
конструкторы и есть представление типа. Всё остальное — определение без
`@native`, метод экземпляра или выведенный экземпляр — может встретить значение,
которое не сумеет прочитать.

Представление к тому же принадлежит пакету типа: покрывающее тело в другом
пакете не может назвать конструкторы, иначе оно сделало бы значение, например
свидетеля хеш-таблицы, какого собственные функции типа никогда не делают.

Дайте определению строку `@native`, которая покрывает условие типа, или
обращайтесь к представлению через такое определение:

```flick
type Box a =
  | Box a
  @native when js || go

make : a -> Box a
let make x = Box x
  @native "./box.mjs" "make" when js || go
```
