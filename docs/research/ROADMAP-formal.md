# Роадмап: формальная семантика, контракт рантайма и доказательства

Статус: рабочий; сделаны M1–M5, X1, X2. Решения §6 приняты 2026-10-29. Основание — спецификация (`spec/05`, `spec/07`), рантаймы `runtime/src` и `runtime-go/flickrt`, харнесс паритета `tests/run/portable.txt`.
Язык не в релизе: если модель найдёт противоречие в спеке, меняется спека, а не модель.

Обозначения: ✅ сделано (коммит), 🔶 частично / в работе, ⬜ не начато, ⏸ условный пункт.

## 1. Цели и принципы

1. **Модель — источник истины для семантики.** Спека в прозе остаётся пояснением; там, где они расходятся, правит модель, а проза догоняет.
2. **Рантайм — часть языка, а не чужая библиотека.** Владельцы областей, файберы, Cause, финализаторы, `Layer`, `Ref` — наш контракт, одинаковый для JS и Go. Effect — одна реализация этого контракта. Его свойства формулируются и доказываются на модели, а оба рантайма проверяются на соответствие ей.
3. **Сначала исполняемое, потом доказанное.** Каждый кусок модели сначала становится эталонным интерпретатором и генератором тестов (дёшево, ловит баги в `flick-core`), и только потом механизируется.
4. **Связь модели с кодом обязательна.** Доказательство про модель без дифференциальных тестов против `flick-core` и обоих рантаймов ничего не гарантирует про компилятор. Тесты связи живут в CI.
5. **Явные гипотезы.** Доверенный FFI (`foreign pure`, контракты удержания), корректность Effect относительно контракта и корректность кодгена — допущения, перечисленные в теореме, а не умолчания.
6. **Ядро маленькое.** Поверхностный язык (классы, `do`, `for`, записи с сахаром, блоки `sql`/`ui`) сводится в ядро elaboration'ом; доказывается ядро и сохранение типов при сведении.

## 2. Целевой вид

```
docs/formal/                  текст модели (markdown, правила вывода)
  core.md                     λFlick: синтаксис, типы, редукция
  regions.md                  регионы и захваты
  runtime.md                  λRT: владельцы, файберы, Cause, Layer, Ref
  elaboration.md              классы → словари, сахар → ядро
flick-model/                  крейт: эталонный чекер и интерпретатор λFlick/λRT
formal/                       проект Lean 4 (lake), модули ≤ 20 KB
```

Теоремы, к которым идём:

| Теорема | Утверждение |
| - | - |
| T1 Type safety ядра | Хорошо типизированная программа не застревает: значение, ожидаемая ошибка из строки `e`, дефект или прерывание |
| T2 Строки эффектов | Вычисление типа `Eff r e a` обращается только к сервисам из `r` и падает ожидаемой ошибкой только из `e`; чистая стрелка не исполняет эффектов |
| T3 Обобщение | Обобщённая привязка не разделяет изменяемое состояние между инстанциациями (нет полиморфного `Ref`) |
| T4 Регионы | Ни один дескриптор региона `s` не используется после закрытия `s` — ни напрямую, ни через замыкание, задачу, `Ref`, данные ошибки |
| T5 Контракт рантайма | Свойства R1–R8 (§3, трек M3) выполняются на любой допустимой перестановке файберов |
| T6 Elaboration | Сведение поверхностного языка в ядро сохраняет типы; когерентность: выбор словаря не зависит от пути вывода |

## 5. Риски

1. **Модель уходит от кода.** Митигация: X1–X6 в CI; изменение правила чекера без правки `docs/formal` — замечание ревью.
2. **Регионы противоречивы** (много путей утечки, захваты в словарях и экзистенциалах). Митигация: M2 до P2, контрпример на каждый путь.
3. **Конкурентность трудно доказывать.** Митигация: недетерминированная small-step семантика вместо модели планировщика; X4 до P3, чтобы доказывать уже проверенные свойства.
4. **Поведение Effect не под нашим контролем.** Митигация: свойства, которые держит Effect, — явные гипотезы M3; X4 проверяет их на закреплённой версии 4.0.5 при каждом обновлении.
5. **Стоимость Lean.** Митигация: трек P запускается только после X; X ценен и без доказательств.

## 6. Решения (приняты 2026-10-29)

1. **Механизация — Lean 4.** Готовые результаты Coq (Iris, CC<:) служат ориентиром, а не зависимостью.
2. **`flick-model` не входит в `just test`.** Это отдельная цель CI со своим рецептом: X1–X5 не замедляют обычный прогон.
3. **Модель не публикуется на сайте.** Она живёт только в `docs/formal/`; раздел `spec/` остаётся прозой и ссылается на модель лишь в репозитории.
